# E2E-тесты (Playwright, TypeScript)

Проверяют Leptos-фронт (`frontend-rs`) вместе с `backend-rs` (база в памяти, курс сидится из `backend/app/data`). Порядок: сборка → запуск.

```bash
cd e2e && npm install && npx playwright install chromium   # один раз
npm run build                                              # trunk build → e2e/.dist и cargo build бэкенда
npm test                                                   # всё; одна глава одной книги за раз (workers = 1)
npx playwright test tests/books/dm.spec.ts                 # одна книга
E2E_PORT=8102 npx playwright test tests/labs                # свой порт: несколько запусков не мешают друг другу
```

- Тесты не делят прогресс: каждый берёт нового пользователя (`loginFresh`) и сам сидит нужное состояние через API.
- Консоль браузера охраняется (`guard.assertClean()`): паника Rust или `console.error` — провал.
- Содержимое курса (книги, главы, упражнения, эталоны лабораторий) тесты читают из `backend/app/data`, а не дублируют.

## Состав

| Каталог | Что проверяет |
|---|---|
| `tests/shell` | вход и регистрация, дашборд (три полосы и квадратики глав), меню, страница книги, настройки, полный экран, плеер и окно «За кадром» |
| `tests/learning` | вопросы, упражнения с вводом ответа (ДМ), практика с кодом (подставной воркер; `E2E_WORKER=1` — реальная песочница в Docker), оболочка практики |
| `tests/labs` | пять лабораторий: системный дизайн, сети, виртуализация, схемы и ассемблер Мини-8, RISC-V — эталон через черновик (конвейер «данные → движок → сервер»), руками, отказ сервера. `E2E_ARCH_ALL=1` — все 95 схемных упражнений |
| `tests/books` | **по файлу на книгу, по тесту на главу**: все слайды и шаги схем, вкладки, прогресс, консоль (302+ глав, около 30 минут) |

Запуск по одной книге: `E2E_PORT=8101 npx playwright test tests/books/09-db.spec.ts --reporter=list --output=/tmp/pw-books`.
При параллельных запусках у каждого свой `E2E_PORT` и свой `--output` (общая папка `test-results` портится).
