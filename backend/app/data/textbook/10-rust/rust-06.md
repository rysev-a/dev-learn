#CHAPTER 6 | Трейты и обобщённые типы
Изучаем Раст. Глава 6. Трейты и обобщённые типы. В прошлых главах мы научились описывать данные, хранить их в коллекциях и честно обрабатывать ошибки. Но стоит программе вырасти, как появляется вопрос: как не писать один и тот же код отдельно для целых чисел, дробных и строк? Как сказать, что «подойдёт любой тип, который умеет сравниваться» или «любой, который умеет печататься»? Ответ Раста состоит из двух идей. Обобщённые типы позволяют писать код один раз для множества типов, а трейты описывают, что именно тип умеет. Сегодня мы разберём оба механизма, увидим, как компилятор превращает их в быстрый машинный код без накладных расходов, и познакомимся с динамической диспетчеризацией, когда выбор метода откладывается до запуска.\n\nНачнём с проблемы. Допустим, нужна функция, возвращающая наибольший элемент среза. Для целых чисел мы напишем одну версию, для символов другую, для дробных чисел третью, и тела будут совпадать до буквы. Это дублирование. Решение — обобщённая функция: после имени в угловых скобках объявляется параметр типа, обычно называемый буквой «т», и дальше он используется как обычный тип. Но просто так сравнить два значения неизвестного типа нельзя: компилятор не знает, умеет ли он вообще сравниваться. Поэтому рядом пишется ограничение: тип должен реализовывать трейт частичного порядка и быть копируемым. После этого функция работает с числами, символами и дробными значениями.\n\nОбобщёнными бывают и структуры. Точка с двумя координатами одного типа описывается как структура с параметром типа: в ней два поля типа «т». Блок реализации тоже объявляет параметр заново, и методы пишутся один раз для всех типов. А ещё можно написать блок только для конкретного типа: например, метод расстояния до начала координат нужен лишь точкам с дробными координатами, и тогда он появится только у них. Примеры вы уже видели: опшен, резалт, вектор и хеш-таблица — всё это обобщённые типы стандартной библиотеки, а угловые скобки с типами внутри — просто их параметры.\n\nТеперь трейты. Трейт — это контракт: набор методов, который тип обязуется предоставить. Он объявляется ключевым словом трейт, внутри перечисляются сигнатуры. Дальше любой тип может реализовать этот контракт в блоке «имплементация трейта для типа». Например, трейт с методом «краткое описание» можно реализовать и для поста в блоге, и для короткого сообщения, и вызывать у обоих один и тот же метод. Если вы работали с интерфейсами в джаве или го, это очень близко, но с важной особенностью: трейт можно реализовать для типа, написанного другими людьми, с одним условием, о котором мы скажем в конце.\n\nМетоды трейта могут иметь реализацию по умолчанию. Тогда типу достаточно реализовать только обязательные методы, а остальные придут бесплатно. Внутри метода по умолчанию можно вызывать другие методы того же трейта, даже те, у которых реализации нет: они появятся у конкретного типа. Так устроен, например, трейт итератора: нужно описать один метод «следующий», а десятки остальных, вроде сложения или фильтрации, получаются сами. Конкретный тип при желании переопределяет метод по умолчанию, как это сделал бы, скажем, русскоязычный приветственный объект.\n\nТрейты нужны и там, где мы принимаем значения. Запись «принимает любой тип, реализующий трейт» можно сделать двумя способами. Полная форма с параметром типа и ограничением после двоеточия подходит для сложных случаев, а при длинных условиях ограничения выносят в отдельное предложение «где». Короткая форма пишет прямо в типе параметра слово «имплемент» и название трейта. Обе записи почти равнозначны, но у полной есть преимущество: так можно потребовать, чтобы два параметра были одного типа. Любой вызов с типом, не удовлетворяющим ограничению, компилятор отвергнет с понятным сообщением.\n\nТу же краткую запись можно использовать в возвращаемом значении: функция обещает вернуть «что-то, реализующее трейт», не раскрывая, что именно. Так возвращают замыкания и итераторы, чьи настоящие типы нельзя или неудобно писать. Ограничения можно комбинировать плюсом: тип должен уметь и печататься для пользователя, и для отладки. Важно одно правило: из функции можно вернуть значение только одного конкретного типа. Если в разных ветках получаются разные типы, нужно либо привести их к общему, либо воспользоваться динамической диспетчеризацией, о которой мы скоро поговорим.\n\nСтандартная библиотека построена на трейтах. Отладочный вывод, копирование, клонирование, сравнение на равенство и на порядок, значение по умолчанию — всё это трейты, и для обычных структур их реализацию можно получить одной строкой атрибута «дерайв», перечислив нужные. Компилятор сам сгенерирует код. Копируемым тип можно сделать, только если все его поля копируемые. Для сравнения на порядок нужно сначала сравнение на равенство. Это не прихоть: так в системе типов записаны математические свойства, на которые опираются алгоритмы вроде сортировки и поиска.\n\nКогда автоматической реализации мало, трейт пишут вручную. Трейт форматированного вывода определяет, как значение выглядит для пользователя: в нём единственный метод, принимающий форматтер и возвращающий результат записи. Ровно так же перегружаются операторы: сложение — это трейт с типом результата и методом «сложить», и после реализации двух векторов можно складывать знаком плюс. Здесь Раст отличается от многих языков тем, что операторы не магия, а обычные трейты с обычными правилами, поэтому их легко читать и искать в документации.\n\nПока мы везде знали конкретный тип на этапе компиляции. Но иногда в одной коллекции нужно хранить разные типы с общим поведением: фигуры, плагины, обработчики. Для этого есть трейт-объекты: значение за ссылкой или внутри коробки с пометкой «дин» и названием трейта. Вектор коробок с динамическими фигурами хранит и квадраты, и круги, а вызов метода выбирается во время работы программы по таблице функций, спрятанной рядом с указателем. Это называют динамической диспетчеризацией, и она слегка медленнее, зато даёт гибкость, которой не даёт обобщённая функция.\n\nОбычные обобщённые функции работают по-другому: компилятор создаёт отдельную копию функции для каждого конкретного типа, с которым её вызвали. Это называется мономорфизацией. Результат — скорость такая, как будто вы вручную написали отдельные версии, без таблиц и косвенных вызовов. Цена — немного больший размер бинарника. Простая проверка различий: ссылка на конкретный тип занимает одно машинное слово, а ссылка на трейт-объект — два, указатель на данные и указатель на таблицу методов. Выбирайте обобщения по умолчанию, а динамические объекты — когда разнородность реально нужна.\n\nОстались две тонкости. Первая — связанные типы: трейт итератора объявляет, какого типа элементы он выдаёт, и это тип, который выбирает реализация, а не вызывающий код. Достаточно описать структуру «обратный счётчик», реализовать метод «следующий» — и по ней можно собрать вектор. Вторая — правило сирот: трейт можно реализовать для типа, только если свой хотя бы один из двух: либо трейт, либо тип. Нельзя реализовать чужой трейт для чужого типа. Это защищает от конфликтов между библиотеками, ведь иначе две разные библиотеки реализовали бы один и тот же трейт для одного типа по-разному.\n\nПодведём итоги. Обобщённые типы пишут код один раз для многих типов, ограничения через трейты говорят, что именно нужно от параметра. Трейт — контракт с методами, возможно с реализациями по умолчанию, его можно реализовать для любого типа — при условии, что трейт или тип ваш собственный. Через трейты в стандартной библиотеке устроены печать, копирование, сравнение и перегрузка операторов, а атрибут дерайв реализует их автоматически. Обобщённые функции разворачиваются в код под каждый тип без накладных расходов, а динамические объекты нужны для разнородных коллекций. В следующей главе мы применим трейты в самом узнаваемом месте Раста: итераторах и замыканиях.
