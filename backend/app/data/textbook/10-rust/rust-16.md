#CHAPTER 16 | Данные и постгрес
Изучаем Раст. Глава 16. Данные и постгрес. Ни один серьёзный веб-сервис не обходится без базы данных, и в нашем курсе роль базы играет постгрес. На практике подключаются готовые библиотеки: «эс-кью-эль-экс», «токио-постгрес» или синхронный «постгрес». Но у них нет магии: под капотом бинарный протокол поверх сокета, преобразование текстовых значений в типы Раста, пул соединений, транзакции с откатом при ошибке и версионируемые миграции. Сегодня мы строим эти механизмы на стандартной библиотеке, чтобы понимать, что делают библиотеки. Разберём формат сообщений протокола, отображение строк результата на структуры, защиту от внедрения запросов, построитель запросов, пул, транзакции с автоматическим откатом, миграции, паттерн репозитория и разбор адреса подключения.\n\nНачнём с идеи типизации. Реляционная база возвращает строки, где каждое значение — текст, а пустое значение обозначает отсутствие данных. Раст описывает ту же схему структурой с полями нужных типов. Целое число становится целым типом, булево значение — булевым, а колонка, в которой допустим пропуск, — опшеном. Преобразование строки результата в структуру — это функция, которая для каждой колонки пробует разобрать значение и собирает ошибки. Такой слой называют отображением, и его пишут один раз для каждой сущности. Важное свойство Раста: забыть обработать пустое значение нельзя, ведь тип без опшена не примет пропуск.\n\nПротокол постгреса бинарный, но устроен просто. Каждое сообщение сервера начинается с одного байта-метки, затем следует длина, четыре байта в сетевом порядке, считая и сами эти четыре байта, а затем содержимое. Клиентские сообщения устроены так же, за исключением самого первого, стартового: у него нет метки, зато есть длина, номер версии протокола и пары «имя, значение» в виде строк с нулевым байтом на конце. Простой запрос — это метка «ку», длина и текст запроса с нулём в конце. Все числа передаются старшим байтом вперёд, а строки заканчиваются нулём, а не хранят длину.\n\nОтвет сервера — последовательность сообщений. Описание строки перечисляет колонки, строка данных содержит число колонок и для каждой четырёхбайтную длину значения и сами байты; длина минус один означает пустое значение. Сообщение «команда завершена» несёт тег вроде «выбрано три строки», а сообщение «готов к запросу» сообщает состояние транзакции. Сообщение об ошибке состоит из полей с однобайтными метками: серьёзность, пятизначный код состояния и текст. Читающий цикл берёт из потока заголовок, проверяет, что пришло достаточно байтов, и отдаёт метку с содержимым; неполное сообщение — повод подождать ещё данных.\n\nЗначения в текстовом формате — строки, и разбор в типы выполняется через трейт «из колонки». Для целых чисел вызывается разбор строки, для булевых значений постгрес присылает «т» и «ф», для текста значение просто копируется. Ошибка разбора превращается в понятное сообщение с названием колонки. Для опшена пустое значение даёт «ничего», а непустое разбирается внутренним типом. Реализация трейта для обобщённого опшена пишется один раз и работает для любых типов, которые умеют разбираться сами. Так же поступают библиотеки с макросом «дерайв» для структур: он генерирует именно такие вызовы по полям.\n\nТеперь безопасность. Если собирать запрос склейкой строк, злоумышленник отправит имя с кавычкой и дополнительным условием, и запрос поменяет смысл: это внедрение. Есть два способа защиты. Экранирование литерала удваивает кавычки внутри значения и оборачивает его в кавычки, но его легко забыть где-то применить, и оно зависит от настроек сервера. Правильный способ — параметры: текст запроса содержит метки «доллар-один», «доллар-два», а значения передаются отдельно, в самом протоколе, и сервер никогда не смешивает их с кодом. Любая библиотека работы с базой строится на параметризованных запросах, и склеивать значения в запрос вручную нельзя.\n\nПостроитель запросов помогает собирать текст запроса по частям и сохранять параметры отдельно. Метод добавления условия принимает колонку, операцию и значение: значение кладётся в список параметров, а в тексте появляется метка со следующим номером. Затем добавляются порядок сортировки и ограничение числа строк. Метод сборки возвращает пару из текста и списка значений. Имена колонок и таблиц в запрос подставлять из пользовательского ввода нельзя: параметрами передаются только значения, а имена выбирают из заранее известного набора. Обратите внимание: построитель владеет данными и получает самого себя по значению, что позволяет писать цепочки вызовов.\n\nСоединение с базой дорого устанавливать, поэтому используют пул. Он хранит готовые соединения в списке под мьютексом. Запрос соединения забирает одно, а если пул пуст, поток ждёт на условной переменной. Возвращаемая обёртка соединения реализует трейт «дроп»: при уничтожении она сама кладёт соединение обратно и будит ждущего. Пользователь не может забыть вернуть соединение, потому что освобождение привязано к области видимости. Размер пула подбирают так, чтобы он не превысил допустимое число соединений сервера: тысячи потоков не нужны, достаточно десятка соединений.\n\nТранзакции выражаются тем же приёмом. Функция начала посылает команду начала и возвращает охранный объект. Метод фиксации забирает объект во владение, посылает команду фиксации и помечает транзакцию завершённой. Если же функция вышла по ошибке или с паникой и объект уничтожается без фиксации, его деструктор отправляет откат. Больше не нужно помнить об откате в каждой ветке с оператором вопросительный знак: любая ошибка, пока объект жив, автоматически отменяет изменения. Это один из лучших примеров того, как владение и деструкторы Раста делают код надёжнее, чем явные блоки «попробовать, наконец».\n\nСхему базы тоже нужно версионировать. Миграция — это пронумерованный файл с командами изменения схемы. Таблица служебных записей хранит номера уже применённых миграций. При запуске приложение сортирует миграции по номеру, пропускает применённые и выполняет остальные по одной, каждую в транзакции, записывая номер после успеха. Повторный запуск ничего не делает. Это называют идемпотентностью и она позволяет безопасно запускать миграции при каждом старте. Откат на предыдущую версию описывают парными файлами, но на практике предпочитают двигаться только вперёд и исправлять ошибки новой миграцией.\n\nРазделение ответственности завершает картину. Бизнес-логика не должна знать, где лежат данные, поэтому доступ к ним скрывают за трейтом репозитория с методами «добавить» и «найти». Одна реализация работает с настоящей базой, другая — с таблицей в памяти. Функции приложения принимают любой тип, реализующий трейт, и поэтому проверяются быстрыми тестами без базы и без сети. Ошибки хранилища преобразуются в ошибки уровня приложения в одном месте. Именно такая структура позволяет заменить библиотеку работы с базой, не трогая остальной код.\n\nНа практике подключение описывается адресом: схема, имя пользователя, пароль, хост, порт и имя базы. Его разбирают по частям: отрезаем схему, делим по знаку «собака», потом по двоеточию и по косой черте. Порт по умолчанию — пять тысяч четыреста тридцать два. Адрес берут из переменной окружения, а не из кода: пароли не должны попадать в репозиторий. С настоящей библиотекой «эс-кью-эль-экс» создание пула и запрос с привязкой параметра выглядят в одну-две строки, но под ними лежат ровно те механизмы, которые мы разобрали. Запустить сам постгрес удобно в контейнере, и тогда ваше приложение подключается к нему по адресу локального хоста.\n\nПодведём итоги. Протокол постгреса состоит из сообщений вида «метка, длина, содержимое» с числами в сетевом порядке и строками с нулём на конце. Строки результата превращаются в структуры трейтом разбора колонок, а пустое значение — это опшен. Склеивать значения в запрос нельзя: параметры передаются отдельно, а построитель запросов хранит их в списке. Пул соединений и транзакции опираются на деструкторы, миграции записывают применённые версии, а репозиторий отделяет бизнес-логику от хранилища. Адрес подключения читается из окружения и разбирается по частям. На этом мы завершаем книгу про Раст: у вас есть язык, алгоритмы, система, сервер и данные. Дальше — язык для интерфейса этого сервера, джаваскрипт.
