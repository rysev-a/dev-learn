#CHAPTER 5 | Conditions and loops
Learning Rust. Chapter 5. Conditions and loops. A program that only runs its lines from top to bottom quickly gets boring. For code to make decisions and repeat actions, you need branching and loops. Rust gives you if and else, three kinds of loops, loop, while, and for, and the powerful match construct. All of them are built from blocks in curly braces, just like functions. For a Python programmer the main difference is that indentation means nothing, while braces are required. On the other hand, parentheses around the condition, as in C and Java, are not needed at all.\n\nA condition is written like this: if x is greater than zero, then curly braces. The expression in the condition must be of type bool, as we said in the chapter on types. Parentheses around it are not needed, but curly braces around the body are required even for a single line. Extra branches are added with the words else if, and at the end you put else if you need a branch for all the remaining cases. Rust checks branches from top to bottom and runs the first one that fits, so the order of checks matters, just as with elif in Python.\n\nIn Rust, if is an expression; we have already seen that. Let sign equal if x is greater than zero, one, else, minus one. Both branches must have the same type, and if there is no else branch, the whole construct gets the unit type, and you cannot get a value out of it. This is handy for short computations: choosing a color, the absolute value of a number, the larger of two. For complex checks you write an ordinary if with a body of several lines that returns nothing and simply performs actions: printing, changing mutable variables.\n\nThe simplest loop is called loop, and it repeats forever. The body runs again and again until you leave with the word break. It looks strange, but it is the foundation for programs like servers, which have to wait for events indefinitely, and for algorithms where the exit condition sits in the middle. A feature of Rust: after the word break you can write a value, and it becomes the result of the whole loop. Let result equal loop, open brace, break forty-two. That is how a loop becomes an expression that computes something until it finds the answer.\n\nThe while loop checks the condition before every step and runs the body as long as it is true. It is exactly the same as while in Python, only without the colon and with the braces of a block. It suits countdowns, searching for the first number that fits, and processing data as it arrives. You have to make sure something changes inside the loop, otherwise the condition stays true forever and the program hangs. For that, the loop variable must be mutable, that is, declared with the word mut, and it is convenient to change it with plus-equals or minus-equals.\n\nThe for loop in Rust works only over iterators, that is, over sequences of values, and it looks as it does in Python: for i in zero to ten. A range is written with two dots: zero dot dot ten means the numbers from zero to nine, and the right bound is not included. And zero dot dot equals ten includes ten. You do not need to declare the loop variable; it is created automatically at every step. The method rev reverses a range, and step_by sets the step. That is how you count backwards or skip every other number. The for loop is the most common and the safest: going out of bounds in it is impossible.\n\nFor can walk over more than numbers. You can go through the characters of a string, the elements of an array, a vector, or any iterator. For c in the string's chars gives the characters one at a time. For element in a reference to a vector reads the elements in turn. We will meet arrays and vectors in detail in chapter 7, but for now just remember that the for loop is a universal way to go through a collection. If you need both the index and the value, you add the method enumerate, which produces pairs: a number and an element, as in Python.\n\nTwo commands work inside a loop. Break ends the loop completely, and continue skips the rest of the body and goes straight to the next step. In Python a loop has an unusual else branch that runs if break did not fire. Rust has no such branch: you use a flag or iterators instead. Also, in Rust you can give a loop a label, for example a single quote, outer, a colon, and for, and leave nested loops with one command: break with a single quote and outer. Python has no such feature, but here it is useful for searching in tables.\n\nNow for some typical patterns. Accumulating a sum: a mutable variable starts at zero, and in the loop you add to it. Counting: the counter is increased when a condition holds. Maximum: you remember the first value and compare every following one. Searching: you go through the values and exit with break when you find it. These four patterns cover half of all practice problems, and you will write them many times. Remember the starting values: zero for a sum, one for a product, for a maximum the first element or the minimum value of the type, and for a minimum the maximum value.\n\nThe match construct compares a value against patterns. Match number, open brace: one, arrow, the text one; two or three, arrow, the text other; four to nine inclusive, arrow, more; underscore, arrow, rest. A pattern can be a number, several options separated by a vertical bar, a range, and an underscore for everything else. Rust checks that you have covered all cases: a missing variant is a build error. Match is an expression too and returns the value of the chosen branch. In Python there is a similar construct called match-case, but in Rust it has been there from the start and is much more powerful.\n\nA few traps. The first is the off-by-one error: you wrote two dots instead of an inclusive bound, and the last number disappeared. The second is that usize cannot be negative: if you subtract one from zero, you get a panic in debug mode. The third is overflow in an accumulator: a sum of large numbers in an i32 may not fit, and you should use an i64. The fourth is an infinite while loop when you forgot to change the variable. And the fifth is that you cannot write a single equals sign instead of a double one in a condition: an assignment does not give a bool, and the build will stop.\n\nLet us compare with Python. For i in range becomes for i in zero to n, elif becomes else if, while True becomes loop, and the else on a loop does not exist. The ternary operator is replaced by if-else as an expression, and match-case by match. Parentheses in a condition are not needed, braces are mandatory. There is no notion of truthy and falsy: a condition is always a bool. In return, you get break with a value and loop labels. Otherwise the feel is the same: familiar loops, familiar operations, and familiar algorithms, only the compiler watches the types more strictly.\n\nLet us sum up. If accepts only a bool, the branches have the same type, and if is an expression. There are three loops: loop for endless repetition with a break to leave, while for a condition, and for over a range or a collection. A range with two dots does not include the right end, and with equals it does. Break and continue steer the flow, and labels help to leave nested loops. Match compares a value against patterns and requires you to cover all cases. In the next chapter we will learn to work with strings: creating, joining, splitting, and iterating over them.
