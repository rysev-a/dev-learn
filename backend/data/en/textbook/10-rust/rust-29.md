#CHAPTER 29 | Standard Library Traits: A Catalog
Learning Rust. Chapter 29. Standard Library Traits: A Catalog. Traits are the vocabulary of the language. When you read someone else's function with bounds on its parameters, you are reading a description of what it needs: the ability to be copied, compared, turned into a string, iterated over. This chapter gathers the main traits of the standard library into one map: copying, comparison, hashing, conversions, dereferencing, iteration, closures, errors, markers, and the Any type. For each one we will note what it promises, when you derive it with an attribute, and when you write it by hand. Knowing the catalog makes other people's code readable and tells you what to implement in your own.\n\nCopying. Clone makes an explicit copy of a value: a call to clone can be expensive, which is why it is written out in plain sight. Copy is a marker saying that copying is trivial, as with numbers: assigning such a value does not move it, it copies it bit by bit. You can derive Copy only if all the fields are Copy, and you cannot if the type has a Drop. String and Vec are not Copy, because they own heap memory. The Drop trait is called when a value is destroyed and releases its resources. It is automatic: you cannot call it by hand, but you can destroy a value early with the function drop. The rule of thumb for small types: if a type consists of numbers and characters, make it Copy.\n\nComparison. PartialEq defines the operators equals and not equals. Eq is a marker that equality is total, meaning a value equals itself: for floating-point numbers that is not true because of NaN, so they implement only PartialEq. PartialOrd defines an order that may be undefined: comparing NaN with a number returns None. Ord is a total order, and it is needed for sorting, for BTreeMap, and for BinaryHeap. All four can be derived automatically: the fields are compared in the order they are declared. The Hash trait must agree with Eq: equal values are required to produce equal hashes, otherwise a hash map will lose its keys.\n\nDefault values. The Default trait returns a sensible value of the type: zero for numbers, an empty string, an empty vector, false for a boolean. You derive it with an attribute if all the fields implement Default themselves, and write it by hand for special cases, for example for settings. The syntax with two dots followed by Default dot default fills in the remaining fields with standard values, which makes it handy to create structs where only a few fields are non-standard. The method unwrap or default on Option and Result, and the method or default on a hash map entry, also rely on this trait.\n\nConversions. From defines an infallible conversion from one type to another, and Into comes from it automatically: implement From, but use Into. TryFrom returns a Result: the conversion may fail. AsRef and AsMut accept a value as a reference to another type, which functions need when they want to accept a string, a slice, and a path alike. Borrow is similar to AsRef, but it promises that hashing and equality stay consistent: that is exactly how a hash map with String keys is searched by a str. ToOwned creates an owning version, and Cow, short for clone on write, postpones copying until it is really needed.\n\nFrom a string and to a string. The FromStr trait defines parsing from text, and the method parse is built on it. ToString gives the opposite conversion, and it is implemented automatically for any type with Display. Display and Debug are responsible for formatting, which we covered in the chapter about text. There are other formatting traits too: LowerHex, UpperHex, Binary, Octal, and Pointer, each for its own specifier. If your type holds a number, it makes sense to implement the ones you need, so it can be printed in different number systems without conversion.\n\nDereferencing. The Deref trait turns a type into a smart reference: it says what the value dereferences to. Box, Rc, Arc, and String implement it, and that is why str methods work on a String and slice methods work on a Vec. The compiler applies Deref automatically wherever a reference to another type is needed, and this is called deref coercion. DerefMut is the mutable variant. Do not abuse it to imitate inheritance: it is meant for smart pointers. Index and IndexMut define the square brackets for your collections, and alongside them go the operators and traits from the ops module.\n\nIteration. Iterator requires a method called next, and dozens of ready-made methods grow out of it. IntoIterator lets a type be used in a for loop, and FromIterator lets you build it with the method collect. Extend adds values into a collection that already exists. DoubleEndedIterator adds going from the back: it is what makes the method rev possible. ExactSizeIterator reports the length, and the traits Sum and Product provide summing and multiplying for your own types. By implementing these traits for your collection you get the whole power of iterator chains for free, and almost every crate with containers does exactly this.\n\nClosures. Every closure has its own anonymous type, and it implements one, two, or all three of the function traits. FnOnce can be called one time and takes ownership of the captured values. FnMut is called many times and may change state. Fn is called many times and changes nothing. Each next trait is stricter than the previous one: whatever implements Fn also fits FnMut and FnOnce. In a parameter you write the loosest of the suitable ones, to accept as many closures as possible. To store different closures in one place, use Box dyn Fn, and ordinary functions fit the same interface.\n\nErrors. The Error trait requires Display and Debug, and optionally a method source that returns the cause: this is how a chain of errors is built. The type Box dyn Error accepts any such error, and adding Send and Sync makes it suitable for threads. The question mark operator uses From to turn different errors into a common type. Writing the implementations by hand is tedious, so the crate thiserror derives them with attributes, and the crate anyhow provides a universal error type with context. For libraries you choose the first, for applications the second.\n\nMarker traits. Send means a value can be passed to another thread, and Sync means it can be referenced from several threads. These traits are automatic: the compiler derives them from the fields. Rc is not Send because its counter is not atomic, while Arc and Mutex are both Send and Sync. Sized says the size is known at compile time, and a question mark in front of it relaxes the requirement for slices and trait objects. Unpin is needed for asynchronous code. PhantomData is not a trait but a marker type for unsized relationships: it lets you declare a type parameter without storing any values of that type.\n\nThe Any type and dynamic types. The Any trait lets you ask a value, while the program is running, what type it is. The method downcast ref turns a dyn Any into a concrete type or returns None. TypeId can be compared, and type name returns the name of a type for messages. Plugins and containers with mixed contents use this feature, but it is often better to get by with an enum or a trait: static checking is more reliable. Dynamic features in Rust are narrow on purpose, so that the language stays fast and predictable, and programs stay checkable by the compiler.\n\nLet's sum up. Clone and Copy are copying; PartialEq, Eq, PartialOrd, Ord, and Hash are comparison and keys; Default is default values; From, AsRef, and FromStr are conversions; Deref and Index are dereferencing and square brackets; Iterator and its relatives are traversal; the Fn traits are closures; Error is errors; Send and Sync are threads; Any is dynamic types. Derive automatically everything you can, and implement by hand only the things where the behavior is special. This ends the section on the standard library.
