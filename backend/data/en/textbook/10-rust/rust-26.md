#CHAPTER 26 | Text and formatting: char, str, fmt and parsing
Learning Rust. Chapter 26. Text and formatting: char, str, fmt and parsing. You already know the basics of strings from chapters six and eleven. Here we will go systematically through what the standard library gives you for working with text: the methods of a character, the rich family of string methods, search patterns, the formatting macros and their specifiers, your own implementations of Display and Debug, and parsing of numbers and compound values. This is the toolkit on which config parsers, log processors, command-line tools and formatters are built. You can do a surprising amount without external crates.\n\nThe character. The type char is a Unicode scalar value, a number from zero to ten FFFF without the range of surrogates. The methods is alphabetic, is numeric, is alphanumeric, is whitespace, is control, is uppercase and is lowercase check the category by the Unicode rules, while the variants with ASCII in the name are faster and work only with Latin letters. To digit takes a radix and returns an Option, and from digit does the opposite. The method len UTF-8 tells you how many bytes the character takes, encode UTF-8 writes it into a buffer, and escape debug and escape default return an escaped representation that is handy for error messages.\n\nA string can be split into parts in many ways. Split cuts on a separator, splitn limits the number of pieces, and rsplitn goes from the right. Split terminator leaves no empty tail after the last separator, and split inclusive keeps the separator at the end of each piece. Split once divides at the first separator and returns a pair. The method matches finds all the matches, and match indices finds them together with their positions. Find and rfind return the position of the first and the last occurrence. Strip prefix and strip suffix remove the beginning or the end if they match, and return an Option: this is exactly the convenient way to parse commands like key equals value.\n\nPatterns. All these methods accept a pattern, and it can be anything that implements the trait Pattern: a character, a string, an array of characters, a reference to a string, or a closure that returns a bool for a character. So you can cut on any of several letters, on a string, or on a condition: for example, split on a vertical bar or on any whitespace character. The methods trim matches, trim start matches and trim end matches remove extra characters by a pattern, for example only the commas at the edges. That is why many tricks for which other languages pull in regular expressions are solved in Rust without them.\n\nString is changed with its own set of methods. Insert and insert str put a character and a string at a byte position, remove deletes a character and returns it, and pop removes the last one. Truncate cuts down to a length, clear empties, and retain keeps the characters that match a condition. Drain takes out a range, and replace range swaps a range for other text in place. The method extend accepts an iterator of characters or strings. To turn it into bytes there is into bytes, and back, from UTF-8. All positions are in bytes and must land on character boundaries, otherwise there is a panic, and is char boundary lets you check a boundary.\n\nNow formatting. The macros println, format, write, writeln and panic all take the same format language. After the colon comes the specification: an optional fill and alignment, a sign, a hash, a zero, a width, a precision and a type. The width and the precision can be passed in as an argument: colon, angle bracket, width, dollar sign takes the width from a named variable, and dot star takes the precision from the previous argument. The types are these: empty means Display, a question mark means Debug, x and capital X mean hexadecimal, b means binary, o means octal, and e means scientific notation. The hash adds prefixes and turns on pretty Debug.\n\nFor your own types you implement Display and Debug. The method fmt receives a formatter that holds the requested parameters: width, precision, fill and flags. The usual way is to call the macro write and write the parts. If you need to respect the width and alignment, you use the method pad on the formatter, which adds the right spaces by itself. For Debug there are the helpers debug struct, debug list, debug map and debug tuple; they make the output consistent, including with the pretty-print flag. The interface fmt Write lets you write into a String with the write macro without creating extra strings: bring the trait into scope and write straight into the buffer.\n\nParsing numbers. The method parse uses the trait FromStr. For integers an optional sign is allowed, but not spaces or underscores. The error has the type ParseIntError, and its kind can be found with the method kind: an empty string, an invalid digit, an overflow. To parse in an arbitrary number system there is the function from str radix. Floating-point numbers understand the dot and the exponent, and also the words inf and nan regardless of case. Integers with the prefixes zero x and zero b are not understood by parse: you have to strip the prefix and call with a radix. The boolean type parses only the words true and false, and a char parses a string of one character.\n\nCase and comparison. The methods to uppercase and to lowercase follow the Unicode rules and return a new string: the German sharp s in uppercase turns into two letters, and the Greek sigma at the end of a word is written differently. For Latin letters there are fast variants, to ASCII uppercase and make ASCII uppercase, which change the string in place. Case-insensitive comparison of ASCII strings is done by eq ignore ASCII case. For arbitrary Unicode you first bring both strings to lowercase, and for tricky cases you need normalization. The order of strings is determined by bytes, not by the alphabet of a human language, and to sort Russian correctly you need locales from external crates.\n\nPractical tricks. Line-by-line processing: lines returns lines without the line-ending character. Tokenizing: split whitespace, or character-by-character parsing with a peekable iterator. Parsing the key equals value format: split once, trim and parse. Parsing a line of comma-separated numbers: split, map, parse, and collect into a Result. Joining: join for slices of strings and concat for nested ones. Table alignment is done with a format whose width is computed from the longest word. The standard library does not know the Unicode display width, and for consoles with Chinese characters you bring in the crate unicode width. All these tricks work without regular expressions, fast and without dependencies.\n\nWhat stays outside the standard library. Regular expressions live in the crate regex, which does not use backtracking and guarantees linear time. Grapheme clusters are in unicode segmentation, normalization is in unicode normalization, and recoding from other encodings is in encoding rs. For parsing complex formats such as JSON, TOML and CSV there is serde and specialized crates, and for your own grammars, nom and pest. For nice output of tables and colors in the console, there are comfy table and colored. Bring them in when the standard features stop being enough, but not before: often a couple of string methods are all you need.\n\nLiterals and compile-time macros. Double quotes make a string with escaping: a newline, a tab, a backslash, a Unicode character in curly braces. Raw strings, with the letter r and hashes, escape nothing. Strings with the prefix b give byte slices: they are handy for binary data and protocols. The macro concat glues literals together at build time, stringify turns code into a string, include str inserts the contents of a file into the program at build time, and env takes the value of an environment variable at compile time. The macros file, line and module path give the place in the code, and together with a panic they make debug messages precise.\n\nLet's sum up. A char has methods for categories, digits and escaping. A str is split and trimmed by patterns: a character, a string, a set of characters or a closure. A String is changed by insertion, removal, retain and range replacement. Formatting uses a single language: width, alignment, precision, type. Your own types get Display and Debug, parse uses FromStr, and parsing errors can be told apart by their kind. External crates cover regular expressions, Unicode and complex formats. In the next chapter we will deal with input and output: readers and writers, files, paths and the standard streams.
