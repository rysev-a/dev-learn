#CHAPTER 24 | The Standard Library: core, alloc, std and the Prelude
Learning Rust. Chapter 24. The Standard Library: core, alloc, std and the Prelude. You have already used dozens of types and functions from the standard library, but you probably did not wonder where they come from. In this part of the book we will go through it systematically: its structure, collections, text, input and output, time, numbers, memory and the catalog of traits. In this first chapter we walk over the map and meet the idioms that appear everywhere: the prelude, method names, the combinators of Option and Result, and the functions for working with memory and comparison. This chapter is like the table of contents of a book that is worth keeping open while you write Rust.\n\nThe Rust library consists of three layers. The lowest is called core: types and traits that need neither an operating system nor a heap, such as Option, Result, iterators, slices, numbers and formatting. The middle one is called alloc: everything that requires a heap, such as Box, Vec, String, Rc, Arc and BTreeMap. The top one is std, which includes the first two and adds the operating system: files, network, threads, time, processes and the HashMap. Names from core and alloc are also available through std, so in ordinary programs you can forget about the layers. For microcontrollers without an operating system people write no standard: the program uses only core, and, if there is a memory allocator, alloc as well. HashMap, though, lives in std, because it needs a source of randomness.\n\nThe prelude is a set of names that the compiler brings into every file automatically. Thanks to it you write Option, Result, Vec, String and Box without a single use line. It includes traits too: Clone, Copy, Drop, Iterator, ToString, Into, From, PartialEq, PartialOrd and Default, as well as the macros println, format, vec and others. Everything else has to be imported explicitly: the HashMap, files, time, threads. A method not found error often means that a trait is not imported, rather than that the method does not exist.\n\nA map of the main modules. Collections live in the std collections module: HashMap, BTreeMap, HashSet, VecDeque, BinaryHeap and LinkedList. Input and output are in std io and std fs. Paths are in std path. Time is in std time. Threads and synchronization are in std thread and std sync. Smart pointers are in std rc and std cell. The environment and processes are in std env and std process. The network is in std net. Numbers are in std num, and formatting is in std fmt. Knowing this list by heart is not required, but understanding where to look is useful.\n\nOption and Result. They have dozens of methods, and this is the best way to write code without nested matches. Map applies a function to the value inside, and and then chains operations that return an Option. Filter keeps the value if it passes a test. Ok or turns an Option into a Result with a given error. Unwrap or substitutes a default value, unwrap or else computes it lazily, and unwrap or default takes it from the type. Take pulls the value out and leaves None behind. The methods as ref and as mut turn an Option of a value into an Option of a reference, and copied and cloned turn it back.\n\nResult has a similar set. Map err transforms the error: that is how, for example, different errors are turned into one. The method or else substitutes another Result on an error. The method ok turns a Result into an Option, and err does the opposite. Unwrap or default and unwrap or else replace an error with a value. The question mark operator returns the error upward and applies the From conversion to it, so different error types can be merged into one if the needed implementations are defined. The method expect works like unwrap, but with your message in the panic: use it in examples, but not in real code.\n\nMethod names follow conventions, and they tell you about cost. The prefix as means a cheap conversion from reference to reference: as str, as bytes. The prefix to means a potentially expensive conversion that creates a new value: to string, to vec. The prefix into takes ownership: into iter, into box. The prefix is asks a question: is empty, is ok. Try means that the operation may fail and will return a Result or an Option. The suffix mut speaks of the mutable version: iter mut, get mut. When you meet a new method, its name already tells you a lot.\n\nThe mem module is responsible for working with memory. The function swap exchanges two values without copying. Replace puts in a new value and returns the old one. Take grabs the value and leaves a default one behind, for example an empty vector. These functions are indispensable when you need to pull something out of a mutable reference: simply assigning is not allowed, because the old value would be lost. Size of and align of report sizes. Drop frees a value early, and forget forgets it without calling the destructor, which is almost never what you want, and that knowledge is only useful when dealing with someone else's memory.\n\nComparison. The cmp module has the functions min and max for any ordered values, and the clamp method limits a value to a range. The Ordering enum has the variants Less, Equal and Greater, and it is returned by the methods cmp and partial cmp. The method then glues comparisons across several fields: first by one, and if they are equal, by the second. The Reverse wrapper flips the order, and it is used to make a descending sort and a min-heap out of BinaryHeap. For floating-point numbers you use partial cmp or the method total cmp, which establishes a full order even with NaN.\n\nConversions. The convert module contains the traits From, Into, TryFrom, TryInto, AsRef and AsMut. If you have implemented From, Into appears automatically. Functions that need a string in any form accept impl AsRef of str or impl Into of String. The trait FromStr defines parsing from a string and gives your type the parse method, and the trait ToString gives the reverse conversion, obtained automatically from Display. These traits set a single shape for conversions, and both the standard library and third-party packages follow it.\n\nIterators are created not only from collections. The functions of the iter module produce them: once yields a single value, repeat repeats it endlessly, empty yields nothing, successors builds a sequence by the rule next from previous, and from fn calls a closure on every step. The adapters chain, zip, cycle, skip, take and step by are assembled into chains. The consumers sum, product, count, last, min, max, fold and collect finish them. All of this is lazy evaluation, which the compiler turns into a fast loop, and it makes code compact.\n\nEnvironment and processes. The env module reads command-line arguments through args and environment variables through var. The process module can end the program with the function exit and a return code, and launch other programs through Command. The fs module works with files and directories, and we will talk about it in a separate chapter. The standard library documentation is opened with the command rustup doc and is on the website doc dot rust-lang dot org. All the examples in it run as tests. Read it as a reference: finding the type you need by search is faster than inventing the code yourself.\n\nLet us sum up. The standard library consists of core, alloc and std. The prelude brings in the most frequent names and traits. The map of modules will help you know where to look. Option and Result contain dozens of combinators, and the naming conventions tell you the cost of an operation. The modules mem, cmp, convert and iter give you tools you will use every day. In the next chapter we will look at collections in more detail: the vector, the queue, the hash map, the tree and the heap, and find out which of them to choose.
