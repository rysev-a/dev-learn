#CHAPTER 17 | Structs, enums and pattern matching
Learning Rust. Chapter 17. Structs, enums and pattern matching. In Python you describe data with classes, and you express "this or that" with a type check or with a None value. Rust separates these two ideas. A struct combines several fields at once: it is a product type, like a tuple with names. An enum chooses exactly one variant out of several: it is a sum type. And the match operator takes a value apart by variant and checks that you did not forget a single one. Together they give you a language where the model of your problem domain is written straight into the types, and the compiler will not let a state you did not plan for slip through.\n\nA struct describes a set of named fields. You create it with a literal, you read fields with a dot, and if a variable has the same name as the field, you do not have to repeat the name. There are also tuple structs, whose fields have no names, and empty structs with no fields at all, whose size is zero. A struct lives on the stack as a whole, and its size is determined by its fields. The processor likes aligned addresses, so sometimes empty bytes appear between the fields. Rust is allowed to reorder the fields to save space, and if you need the order to match C, for example to talk to foreign code, you add the repr C attribute.\n\nBehavior is attached to a type with an impl block. Methods take self in one of the three forms we discussed in the previous chapter: read, modify, or take. Functions without self are called associated functions, and you call them with a double colon, for example, the type, double colon, new. This is the usual way to create values: the language has no constructors, and new is simply a conventional name. To make debug output work, it is enough to put the derive Debug attribute on the type, and it will print with curly braces, a colon, and a question mark. The same attribute gives you cloning, equality comparison, and default values.\n\nAn enum in Rust is not just a set of named numbers, like in C. Each variant can carry its own data, and different data at that. A shape can be a circle with a radius, a rectangle with two sides, or a point with no data at all. In Python you would have to write several classes, or a union of types with an isinstance check. Here it is a single type, and at any moment the value is in exactly one variant. You can get at the data only by checking which variant it is, so reading the radius of a rectangle is impossible by construction.\n\nHow does this work in memory? You remember the tagged union from the chapter on computer architecture: a tag, some bytes of payload, and those fields share the same space. A Rust enum is exactly that. The size equals the tag plus the largest variant, taking alignment into account. An enum with no data takes one byte. And an Option of a Box, of a reference, or of any other pointer needs no tag at all: a pointer has a value that is never a real address, zero, and it is handed over to None. This niche makes an Option of a pointer exactly as small as the pointer itself.\n\nThe match operator takes a value and a list of arms, each of which consists of a pattern and an expression. The first arm that fits is executed, and match itself is an expression, so it has a value. The main rule is that the arms must cover all the variants. If you add a new variant to the enum, the compiler shows you every place where you forgot to handle it, whereas in Python you would find those places when the program crashes. Under the hood this is usually a jump table indexed by the tag, or a chain of comparisons, and there is no falling through to the next arm, like in a switch. The underscore accepts everything that is left.\n\nPatterns are richer than just variant names. You can take apart tuples and structs right in the arm header, nest patterns inside each other, bind parts of the value to names, and skip the rest with two dots. Ranges set boundaries, for example from one to nine, a vertical bar combines several variants, and a name followed by an at sign binds the value while checking it against a pattern. After the pattern you may add an if condition, which is called a guard. Patterns work on slices too: you can take apart the beginning and the end of a vector without touching indexes.\n\nNow for the most important enum in Rust, Option. In Python any variable can turn out to be None, the check is easy to forget, and the result is an exception in the middle of the work. In Rust there is no value that fits any type. If a value may be missing, its type is Option of T: either Some with the data, or None. You cannot use the value without checking: the types do not match. Option has many methods: map transforms the value inside, and_then chains several steps together, unwrap_or sets a default value, and the question mark returns None from the function immediately if it meets one. The unwrap method pulls the value out but panics on None, so it is kept for tests and for cases that are truly impossible.\n\nWhen you need only one variant, a full match is too bulky. For that there is if let: a condition that checks a pattern and binds names. For an early exit there is let else: it either binds the value or obliges you to leave right away, for example by returning from the function, which keeps the main code flat and free of nesting. While the pattern keeps matching, you can run a while let loop, and that is the usual way to empty a stack. And the matches macro answers the question of whether a value fits a pattern with a single boolean expression. All these forms expand into the same match, they are simply shorter to write.\n\nThere is an important subtlety connected with ownership. A match on a value moves data out of the variant into the bindings, and afterwards the value is partly or fully unavailable, just as after an ordinary assignment. If you still need the data, apply the pattern to a reference: Rust automatically turns the bindings into references, and the value stays where it is. With a mutable reference you can change the data inside a variant in place. The error saying you cannot move out of borrowed content is very common, and this is exactly how you cure it: match on an ampersand, or call the as_ref method on the Option. The familiar rules from previous chapters work without exceptions.\n\nEnums describe states beautifully. A door can be open, closed, or locked with a code, and the locked one has data that the others do not. The method that moves the door to its next state takes self by value and returns a new one: the old state ceases to exist, and you cannot use it by mistake. This technique is called a state machine, and the idea is to make impossible states unrepresentable. Instead of a bunch of boolean flags that can contradict each other, you have one type, and every valid combination has a name. You do not need to write tests for combinations that do not exist.\n\nNow about comparison and ordering. The derive attribute with PartialOrd and Ord gives a type comparison: structs are compared field by field, lexicographically, in the order in which the fields are written in the definition, and enums are compared by variant number, then by data. This means the order of the fields is the sort order, and it is easy to break by swapping lines. A wrapper type with one field, a newtype, costs zero extra bytes: a user ID struct around a number is no different from the number at the machine level, but it will not let you confuse a user with an order. One more derive, Default, builds a default value from the default values of the fields.\n\nLet us sum up. A struct collects fields, an enum chooses a variant, and match takes the value apart and forces you to account for everything. The size of an enum is the tag plus the largest variant, and for pointers the tag hides in zero. Option replaces None and demands a check, and when you need just one variant, if let and let else will do. Match by value moves, match by reference borrows. Describe states with enums, and invalid combinations simply will not build. Next we have collections and error handling: the vector, the hash map, and the Result type, on which all work with errors rests.
