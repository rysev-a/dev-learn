Learning Rust. Chapter 14. Python Dictionaries, Rust HashMap, and Sets. The dictionary is the second most common Python structure after the list, and every serious program has a key-value table somewhere. In Rust, that role is played by the hash map from the standard library. Next to it stand the ordered map and two kinds of sets. In this chapter we will compare them across all the familiar operations: creating, reading, updating, counting, iterating, sets, and set operations. This is the last chapter of the section Rust After Python: after it we move on to the main feature of the language, ownership and borrowing.\n\nCreating. A Python dictionary is written as a literal in curly braces. Rust has no literal: you create an empty hash map with HashMap, double colon, new, and add pairs with the insert method. For a ready-made set there is HashMap, double colon, from, applied to an array of pairs, and you can also build a map from an iterator of pairs with the collect method. The type is written in angle brackets: the key and the value. A key can be any type with the traits Hash and Eq: numbers, strings, characters, and tuples of them. Floating-point numbers cannot be keys, because they don't have full equality.\n\nReading. The expression d in square brackets with a key raises a KeyError exception in Python if the key is missing. In Rust a hash map also has square brackets, but when the key is missing they cause a panic, so you should rarely use them. The main way is the get method: it returns an Option with a reference to the value. Python's get method with a fallback value corresponds to a chain of get and unwrap_or. The check key in d turns into contains_key. To change a value in place there is get_mut. Python's pop turns into remove, which returns an Option: you get a value, not an exception.\n\nWriting and updating. The assignment d in square brackets with a key equals a value is replaced by insert, which, if the key already exists, replaces the value and returns the old one in an Option. Instead of a dictionary with a default value, you use the entry interface. Calling entry with a key returns an entry that has the method or_insert: it inserts a value only if the key is missing, and returns a mutable reference. The famous word count in Python with Counter or defaultdict is written in Rust in one line: entry of the word, or_insert zero, then star, plus-equals, one. This is the main idiom, and you need to remember it.\n\nEntry can do more. The or_default method inserts the default value for the type, for example an empty vector or zero. The and_modify method changes the value if the key is already there, and or_insert_with computes the value lazily, only when it is needed. With them you do grouping: a HashMap from string to vector of strings, where for each key you add an element to the list. Python's setdefault and defaultdict with a list turn into entry of the key, dot, or_default, dot, push the value. Notice that the write always takes a single lookup by key, not two.\n\nIterating. The methods items, keys, and values in Rust are called iter, keys, and values, plus iter_mut and values_mut for modifying. The main difference is order. A Python dictionary remembers insertion order, while a Rust hash map yields pairs in arbitrary order, and it can change from run to run: keys are hashed with a random salt to protect against attacks on hash tables. If you need a predictable order, sort the keys or take an ordered map. For insertion order, you bring in an external crate called indexmap. Don't rely on iteration order: it is the most common trap for beginners.\n\nHashing. Python hashes objects with the hash method and doesn't allow mutable keys: lists and dictionaries can't be keys. Rust has no such formal ban, but in practice mutable keys don't arise because of the borrowing rules: while a value sits in the map, you can't change it. The standard hash function is called SipHash: it is slower than simple ones, but protected against malicious inputs. When speed matters more and the data is trusted, you can replace it with FxHash from external crates. For struct keys, the derive attribute with Hash, Eq, and PartialEq is enough.\n\nOwnership. The insert method takes the key and the value: after insertion, the string belongs to the map. If you stored a String as the key, you can look it up through a str reference too: get accepts any reference whose hash and equality match, so calling get on the map with a string literal works without creating a String. If you need the key elsewhere as well, you clone it. Vector values also belong to the map: to get a vector out, you use remove or clone it. These rules seem strict, but they guarantee that there are no dangling references inside the map.\n\nThe ordered map. If you need keys in sorted order or range queries, you take BTreeMap. It stores pairs in a balanced tree, iteration goes in ascending key order, and operations take logarithmic time. The methods first_key_value and last_key_value return the smallest and largest pairs, and range selects the pairs within a range of keys. In Python you would have to bring in the sortedcontainers package for that. For small data, BTreeMap is often faster than a hash map because of cache locality, and for millions of entries the hash map is better.\n\nSets. Python's set in Rust is HashSet, and the ordered variant is BTreeSet. You create them the same way as maps: new, from an array, or with collect. The methods: insert returns a boolean saying whether the element was added, and remove and contains work as expected. Set operations are written as methods: union, intersection, difference, and symmetric_difference return iterators that you collect into a new set. The operators ampersand, vertical bar, minus, and caret exist too, but for references. You don't need a frozenset: immutability is achieved with a plain let without mut.\n\nComprehensions and merging. A dictionary comprehension in Python turns into a chain of iterators ending in collect into a hash map: take the words, iterate, map each word to a pair of the word and its length, then collect. Gluing two lists into a dictionary with zip is written the same way. Merging Python dictionaries with the vertical bar operator or the update method is the extend method: it inserts all the pairs, replacing matching keys. A copy of a map is clone. Converting to a vector is collect, and sorting by value goes through a vector of pairs and sort_by.\n\nPerformance. Insertion, lookup, and removal in a hash map take constant time on average, but in Rust they are faster than in Python thanks to the absence of object wrappers. The hash map grows and rehashes as it fills, just like a Python dictionary, and you can set the capacity in advance with with_capacity. For small sets, up to about ten elements, a vector of pairs with linear search is often faster: there is no hashing, and everything sits side by side. The rule is: profile, don't guess. For debugging, a map is printed with the format that has a question mark, and for pretty output, with a question mark and a hash sign.\n\nLet's sum up. A hash map is the analog of a dictionary, but with no literal, with get instead of square brackets, and with the entry interface for counters and groupings. The iteration order is arbitrary; for ordering there is BTreeMap, and for sets there are HashSet and BTreeSet with the methods union, intersection, and difference. The key belongs to the map after insertion, and lookup is possible by str. Comprehensions are replaced by collect, and merging by extend. That completes the comparison: you now know how to carry the main Python techniques over to Rust. Now we move on to the main topic: ownership and borrowing.
