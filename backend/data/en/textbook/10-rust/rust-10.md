#CHAPTER 10 | Functions and conditionals: def and fn
Learning Rust. Chapter 10. Functions and conditionals: def and fn. In this chapter we take what you write in Python every day, functions, branches and loops, and translate it into Rust. Most of it translates almost one to one: def becomes fn, the colon and the indentation turn into curly braces, elif turns into else if. But in a few places Python gives you a freedom that Rust does not have, and we will work out in advance what to replace that freedom with. The goal is that you can open your own Python program and confidently rewrite it in Rust.\n\nSignatures. In Python you can leave out the parameter types: a function add that takes a and b. You can write annotations, but the interpreter does not check them. In Rust the types are mandatory, and the compiler checks them on every call: a function add that takes two i32 values and returns an i32. The same code cannot work with numbers, strings and lists at once, the way it does in Python. For that kind of universality Rust has generics: you write the function once, for any type that supports the operations you need.\n\nDefault values. The Python function hi with a name parameter that defaults to world is impossible in Rust: parameters have no default values, and arguments are always positional. This shortcoming is usually worked around in three ways. The first is to accept an Option and substitute the value with the unwrap_or method. The second is to write two functions with different names. The third is to collect the parameters into a struct and give it default values; this is called the builder pattern. It is longer, but the call reads clearly, and the compiler catches a typo in a parameter name.\n\nA variable number of arguments. Star args in Python collects the extra arguments into a tuple, and double-star kwargs collects them into a dictionary. In Rust a function takes a fixed number of parameters. If you need many values of the same type, you pass a slice or a vector: a reference to a slice of i32. For different types you make a struct or an enum. Instead of kwargs you use a struct with fields or a hash map. Macros such as println accept any number of arguments, but that is a feature of macros: ordinary functions cannot do this, and you should write your own macros only in rare cases.\n\nReturning a value. In Python, a function without a return returns None, and several values are returned as a tuple. In Rust, a function without an arrow returns the unit type, and several values are also collected into a tuple: an arrow followed by a pair of i32 values. The result is the last expression without a semicolon, and return is needed only for an early exit. If the value may be missing, Python's None turns into an Option, and if an operation may fail, you return a Result. The calling code is obliged to handle both variants.\n\nFunctions as values. In Python you can pass a function to another function and use a lambda: lambda x, x plus one. In Rust this is possible too. An ordinary function is passed by name, and its type is called a function pointer: fn taking an i32 and returning an i32. The short nameless variant is called a closure and is written with vertical bars: bar x bar, x plus one. A closure can capture variables from the surrounding code. We will get to know them properly in the chapter about iterators; for now it is enough to remember the syntax.\n\nDocumentation. In Python, the description of a function is written as a triple-quoted string right after the header, and the help tool shows it. In Rust, a documentation comment starts with three slashes and is written before the function: it supports Markdown. The cargo doc command builds a documentation website out of such comments. If you put an example of code in a block inside the comment, cargo test will run it as a test. This way the documentation cannot go stale: an example that stopped working immediately breaks the check. Python has the doctest module for this, but it is rarely used.\n\nConditions. Python's if, elif and else turn into if, else if and else. Parentheses around the condition are not needed, and the condition must be a boolean: you cannot write if with a list, or if not with an arbitrary value. You need an explicit comparison: if not the vector's is_empty. The operators and, or and not are replaced by a double ampersand, a double vertical bar and an exclamation mark. The conditional expression, x if condition else y, is written in Rust as an ordinary if-else, which returns a value. The in operation is replaced by the contains method, and the check for None by a call to the is_none method.\n\nRust does not understand a chain of comparisons like one less than x less than ten: you have to write both comparisons explicitly joined with and, or check the range with the contains method on the range from one up to ten. The match-case construct from Python three-ten corresponds to match in Rust, which is stronger: it handles ranges, several alternatives in one arm, guards with if, and destructuring of structs. A missing case will not pass the build. That is why match is the main way to choose among several variants in Rust, and long chains of else if are less common.\n\nLoops. The for loop over a range of n turns into a for loop over the range from zero up to n, and a step and reverse order are done with the methods step_by and rev. Python's while stays while, and the infinite while True is replaced by the word loop. Instead of enumerate, zip and reversed, Rust has methods with the same names. A loop has no else branch, so a search is written with a flag or with the find method. The break and continue commands work the same way, but in Rust break can return a value from a loop, and labels let you exit nested loops with a single command.\n\nErrors and checks. In Python, errors are thrown with raise and caught with a try-except block. Rust has given up on exceptions: the returned Result itself tells you about a possible error, and the question mark operator passes it on to the calling function. For unrecoverable situations there is the panic macro, the analog of raise without catching: it stops the program or the thread. Checks of conditions inside programs are done with the assert macros, and the preconditions of public functions are checked by returning an error. We will go through these mechanisms in detail in the chapter about error handling. What matters here is to remember: there are no exceptions.\n\nGenerators and comprehensions. Python generators produce values one at a time with the yield keyword. Rust goes a different way: any value that has a next method is an iterator, and it works with the for loop and with chains of the methods map, filter and collect. A list comprehension is replaced by a chain: first iter, then filter, then map, and at the end collect into a vector. Rust optimizes such a chain into an ordinary loop with no intermediate collections, so it is no slower, and often even faster than a handwritten loop. The any and all constructs correspond to the any and all methods of iterators.\n\nLet's sum up. Def turns into fn, types are mandatory, default values are replaced by Options and structs, and star args by slices. The result is the last expression, several results are a tuple, no result is an Option, and an error is a Result. Branching is if and match, both are expressions, and there are no chains of comparisons. The loops are for, while and loop, and a loop has no else branch. There are no exceptions. Generators become iterators, and comprehensions become chains of methods. In the next chapter we compare strings: str from Python, and String together with str-ref from Rust.
