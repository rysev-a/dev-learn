#CHAPTER 9 | Data types: Python objects and Rust values
Learning Rust. Chapter 9. Data types: Python objects and Rust values. You already know the basics of Rust: variables, functions, loops, strings, vectors, structs. Starting with this chapter we walk through the topics of Python one by one and look at how the same thing works in Rust, and why it works differently. The first topic is data types. In Python, every value is an object with a type, a reference count and other bookkeeping fields, and a variable is just a name pointing to an object. In Rust, the value lives right inside the variable, with no wrappers and no middlemen. Everything else grows out of this difference.\n\nLook at how Python stores the number five. It is an object: it has a header with a reference count, a pointer to the type, and the digits themselves. The getsizeof function in Python returns twenty-eight bytes for such a number. A list of a million numbers is a million pointers to a million objects scattered around memory. In Rust, the number five of type i32 takes four bytes, and a vector of a million of them is four megabytes in a row. The processor reads such a sequence quickly, because it sits side by side and fits into the cache as a whole.\n\nPython integers have no upper limit: two to the power of a thousand is computed without a problem, and overflow simply does not exist. The price is speed, because under the hood the number is stored as an array of digits. In Rust every integer type has its own size, and the arithmetic is done by a single processor instruction. But there are limits too: on overflow in debug mode the program stops. If you need really big numbers, you have to bring in an external library, for example num-bigint. And for reasonable values, i64 and i128 are enough, and i128 holds a number with thirty-eight digits.\n\nDivision and remainder work differently. In Python, the double slash divides rounding down, so minus seven divided by two gives minus four, and the remainder always has the sign of the divisor. In Rust, integer division discards the fractional part, that is, it rounds toward zero: minus seven divided by two gives minus three, and the remainder has the sign of the dividend and equals minus one. If you need the Python result, integers have the methods div_euclid and rem_euclid, which return a non-negative remainder. This is a well-known trap when porting algorithms, especially with circular indexing and modular arithmetic.\n\nWith floating-point numbers it is almost the same story: both languages use the IEEE 754 standard, and zero point one plus zero point two is not equal to zero point three in either of them. The differences are in the details. Python happily adds an integer to a float, while Rust demands an explicit cast. The built-in round function in Python rounds halves to the nearest even number, while the round method in Rust rounds away from zero, so two and a half gives three, not two. There are no complex numbers in the Rust standard library; they come from external packages.\n\nThe Boolean type in Python is a descendant of the integer: True plus one gives two, and an empty string, zero and an empty list are considered false. In Rust, bool is a separate type, you cannot add it to numbers, and only a bool is allowed in conditions. There is no empty value None in Rust either: instead there is Option, with the variants Some and None. The difference is fundamental: if a Python function returned None and you forgot the check, the program crashes when you use the value. In Rust the compiler will not let you use an Option without a check, so forgetting is impossible.\n\nPython strings are sequences of Unicode characters: the length is counted in characters, an index takes a character, and bytes live in a separate type, bytes. In Rust, a String holds bytes in UTF-8 encoding, the length is counted in bytes, and characters have to be iterated explicitly. The Python bytes type corresponds to a slice of u8, and a string is converted to bytes and back with the methods as_bytes and String::from_utf8. The char type in Rust differs from a Python string of length one: it is a separate primitive type four bytes in size.\n\nAssignment in Python copies a reference, not a value. After b equals a, both names point to the same object, and if it is a list, a change made through one name is visible through the other. Immutable objects, numbers, strings and tuples, are protected from this confusion, but mutable ones cause errors for beginners. In Rust, assigning a value either copies it, if the type is simple, or moves ownership, and the old variable becomes unavailable. There are no hidden shared references to mutable data in Rust, and a separate chapter about ownership will be devoted to this.\n\nPython is dynamically typed: the type belongs to the value, not to the variable, and one name can point to a number, then to a string, then to a list. Type annotations in Python are hints for programmers and third-party checkers, and the interpreter does not check them. Rust is statically typed: the type of a variable is fixed at build time and cannot be changed, and the compiler is responsible for type inference. Python's duck typing, where it is enough for an object to have the needed methods, turns into traits in Rust: you declare what a type can do, and the compiler checks it before the program ever runs.\n\nThe memory layout of data in Rust is predictable, and you can measure it. The size_of function returns the size of a type, and align_of returns its alignment. A struct made of a byte and a four-byte number takes not five bytes but eight: padding is inserted between the fields so that the number sits at an address divisible by four. Rust is allowed to reorder fields to reduce the size. If you need the C order, for example for exchanging data with other languages, you mark the struct with the repr C attribute. In Python you never have to think about such details, but you cannot control them either.\n\nLet's recall the stack. Every function call gets a frame: it holds the parameters, the local variables and the return address. In Python the frames live on the heap, and the recursion depth is limited by the interpreter: by default a thousand calls, after which an exception is raised. In Rust the frames live on the real thread stack, about eight megabytes for the main thread on Linux. Recursion a hundred thousand calls deep usually works, but at a million the stack runs out and the program terminates abnormally, with no chance to catch it. For deep traversals it is safer to use a loop with an explicit stack in a vector.\n\nNumbers in memory are laid out the same way in any language, but Rust lets you look at the bytes directly. Integers are stored in two's complement, and on modern processors the byte order goes from the least significant byte to the most significant. The method to_le_bytes returns an array of the number's bytes in that order, and to_be_bytes returns them in the opposite, network order. In Python the same is done by the to_bytes method and the struct module. Knowing these details matters when you work with files and network protocols, and when you debug and need to understand why a number is read incorrectly.\n\nLet's sum up. In Python a value is an object, a variable is a reference, numbers have no limits, and strings are made of characters. In Rust the value lies right inside the variable, integers have a size, and strings consist of bytes. Division rounds toward zero, not down, halves round away from zero, a bool is not a number, and Option replaces None. Data in a vector lies in a row, and the stack is real and finite. These differences are the price of speed and predictability. The next chapter is about functions and conditionals: we will compare def and fn, elif and match, returning values and arguments.
