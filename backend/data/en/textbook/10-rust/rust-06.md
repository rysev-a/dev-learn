#CHAPTER 6 | Strings: A First Look
Learning Rust. Chapter 6. Strings: a first look. In Python there is one kind of string, str, and it is immutable. In Rust there are two, and this confuses every newcomer. The first is called str, and it is usually written with an ampersand in front: it is a reference to text that lives somewhere in memory, which you read but do not own. The second is String: a string owned by the program, which can grow and change. Both keep text in the UTF-8 encoding, more on that in a moment. For now remember a simple rule: we read text through str, and we build and modify it through String.\n\nA string literal in double quotes has the type ampersand str with the static lifetime. Such text is baked into the executable itself and exists for the whole run of the program. You cannot change it, but it is fast and costs nothing: it is just a pointer and a length. Literals are handy for labels, messages and constants. You can split a literal across several lines of code by putting a backslash at the end of a line, and raw strings, written with the letter r and hash signs, let you skip escaping quotes and slashes, for example when writing paths and regular expressions.\n\nThe String type can be created in several ways. The most common is String, two colons, from, with a literal in parentheses. The same result comes from the to string method on a literal, or from the to owned method. An empty string comes from String, two colons, new. It is a mutable string, so you declare it with mut and append to it. The push method adds one character, and push str adds a whole piece of text. A String lives on the heap, while the stack holds a pointer, a length and a capacity, and the capacity grows as needed, so appending is fast, just like appending to a Python list.\n\nConcatenation in Rust works differently from Python. The plus operator works, but the left side must be a String and the right side a reference to a str. Writing s one plus ampersand s two consumes s one and returns a new string, so after the concatenation s one can no longer be used; we will sort that out in the chapter on ownership. The format macro is much more convenient: format, parentheses, a template with curly braces, then the values. It takes nothing away and works like f-strings in Python. For a list of strings there is the join method, which glues them together with a separator.\n\nNow, encoding. UTF-8 stores each character in one, two, three or four bytes: Latin letters take one byte, Cyrillic letters two, Chinese characters three, emoji four. That is why the len method returns the number of bytes, not characters: the Russian word for hello, which has six letters, has a length of twelve. To count characters you write the string, dot, chars, dot, count. It is important to remember this difference: in Python the length is counted in characters, and the habit easily trips you up. If you need the length in characters, call chars.\n\nBecause of the encoding, you cannot access a character of a string by index in Rust: s in square brackets zero will not compile. One character may take several bytes, and a byte index could land in the middle of a character. Instead of indexing, you take a character by its position through chars and the nth method. Slices also work on byte boundaries: a slice from zero to four of a word written in Cyrillic returns its first two letters, but a slice with an odd boundary causes a panic. The safe version is the get method, which returns a value, or nothing if the boundaries are wrong.\n\nYou can iterate over a string in different ways. The chars method yields characters one by one. The bytes method yields bytes, and char indices yields pairs: a byte position and a character. The split whitespace method splits text on spaces and line breaks, and lines splits it into lines. The split method takes any separator, for example a comma. The results are iterators: you can loop over them with for or gather them into a vector with collect. This is a familiar idea from Python, where a string can also be split, but in Rust you have to collect the result explicitly into the collection you want.\n\nStrings have many useful methods, and almost all of the names are easy to recognize. The len method returns the length in bytes, is empty checks for emptiness, contains looks for a substring, and starts with and ends with check the beginning and the end. The find method returns the position of the first occurrence, or nothing. To uppercase and to lowercase change the case, replace replaces substrings, and trim removes whitespace at the edges. All of them return a new value and leave the original text untouched, so you have to store the result in a variable. The last method, parse, turns a string into a number, like int in Python.\n\nSplitting a string into parts and turning them into numbers is a frequent task. For example, a string with the numbers one, two and three separated by commas is split on the comma into three parts, and each part can be processed with trim and converted with parse. The results are gathered into a vector with collect, specifying the type vector of i thirty-two. If even one word is not a number, parse returns an error, and you have to decide what to do: stop the program with unwrap, skip that item, or replace it with a default value. We will cover this topic in detail when we get to error handling.\n\nStrings can be compared with the equals and not equals operators, and a String and a str can be compared with each other without any trouble. The less-than and greater-than order is determined by bytes, so capital letters come before lowercase ones. For case-insensitive comparison of ASCII strings there is the eq ignore ascii case method. Conversions between the types look like this: from String to str, put an ampersand before the name or call as str, and from str to String, use to string or String from. Functions should preferably accept a str, so that both types fit, and return a String when they produce new text.\n\nFormatting macros can do much more than substitute values. Inside the curly braces you can specify the field width, alignment, fill character and precision: colon, right angle bracket, ten, aligns to the right in a field ten characters wide. For floating point numbers, colon, dot, two keeps two digits after the decimal point. A colon with a question mark prints the debug representation, and a colon with a hash and a question mark prints a pretty multi-line one. Variable names can be written right inside the braces, as in Python f-strings, and positional numbers and named arguments help when values repeat.\n\nLet us compare with Python. There, a string is immutable and there is only one kind; here there is str for reading and String for modifying. There, indexing and slices work on characters; here they work on bytes, and indexing is forbidden. There you have f-strings, join and strip; here format, join and trim. There the length is in characters; here len is in bytes, and chars counts characters. The plus operator exists, but it takes the left operand away. In return you get a UTF-8 guarantee: no string in Rust contains invalid sequences, and you will never have to catch decoding errors inside your program.\n\nTo sum up. Str we read, String we own and modify. The length is in bytes, characters come through chars, indexing is not allowed, and slicing is allowed on character boundaries. Concatenate with format, while the plus operator takes the left string away. Methods parse and transform text, returning new values, and parse turns a string into a number, with a possible error. Formatting sets the width, alignment and precision. In the next chapter we will meet compound types: tuples, arrays and vectors, and learn to store many values together.
