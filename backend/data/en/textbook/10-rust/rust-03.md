#CHAPTER 3 | Data types: numbers, characters, logic
Learning Rust. Chapter 3. Data types: numbers, characters, logic. Rust is a statically typed language: the type of every value is known at compile time, and the compiler checks that you are not adding a number to a word. Types fall into two groups: scalar types, which are single values, and compound types, which hold several values. In this chapter we cover the scalar ones. There are four kinds: integers, floating-point numbers, booleans, and characters. In Python a number has one type, int, which grows as large as you like. In Rust it is different: the programmer chooses the size of the number, and that buys speed and predictability.\n\nIntegers are either signed or unsigned. Signed types start with the letter i, unsigned types start with the letter u, and after it comes the number of bits: eight, sixteen, thirty-two, sixty-four, or one hundred twenty-eight. The type i8 stores numbers from minus one hundred twenty-eight to one hundred twenty-seven, and u8 stores numbers from zero to two hundred fifty-five. There are also two special types, isize and usize. Their size equals the size of a pointer on your machine, and usize is what you use for indexes and lengths. If you do not specify a type, the compiler picks i32.\n\nWhat happens when a number does not fit? Say you add one to a u8 that holds two hundred fifty-five. In debug mode the program stops with a panic saying it attempted to add with overflow. In release mode the result wraps around and becomes zero. To avoid depending on the mode, be explicit. The checked_add method returns a value, or nothing if an overflow happened. The wrapping_add method wraps the number around, saturating_add stops at the boundary of the type and goes no further, and overflowing_add returns both the result and a flag saying whether overflow occurred.\n\nIntegers can be written in several ways. Underscores inside a number mean nothing; they are only there for readability, so one million is written with underscores between groups of three digits. A hexadecimal number starts with zero and the letter x, an octal number starts with zero and the letter o, and a binary number starts with zero and the letter b. A byte literal is a letter in single quotes with the prefix b, and it has the type u8. You can also attach a type directly to a number: ten u8 is the number ten of type u8. That is handy when you need to hint the type to the compiler without a separate declaration.\n\nFloating-point numbers come in two sizes: f32 and f64. The second is the default, and it is the one you need almost every time: it has twice the precision, and on modern processors it is just as fast. Floats follow the standard called IEEE 754, so zero point one plus zero point two does not equal exactly zero point three, just like in Python. The special values are infinity and not-a-number, written NaN. NaN is not equal even to itself, and you check for it with the is_nan method.\n\nArithmetic in Rust looks familiar: plus, minus, multiply, divide, and remainder. But there are important differences. Dividing two integers also gives an integer, and the fractional part is thrown away: seven divided by two is three, not three and a half. To get a fractional result, at least one of the numbers must be a float. Dividing an integer by zero causes a panic, while dividing a float by zero gives infinity. There is no exponent operator either: you use the methods pow and powi. And you cannot mix types: the compiler will not accept i32 plus i64, so you have to convert explicitly.\n\nAn explicit conversion is written with the word as: x as f64 turns an integer into a float. But as has subtleties. If you convert a large number to a small type, the high bits are simply cut off: two hundred fifty-six converted to u8 becomes zero. A float converted to an integer loses its fractional part, and one that is too large gets clamped at the boundary. A negative number converted to an unsigned type gives a huge positive number. So use as deliberately, and where safety matters, reach for the functions from and try_from, which do not lose data silently.\n\nThe logical type is called bool, and it has just two values: true and false. The result of any comparison is a bool. The operations and, or, and not work on it, and they are written as a double ampersand, a double vertical bar, and an exclamation mark. Evaluation is lazy: if the left side of the and is false, the right side is not evaluated. The main difference from Python is that the condition must be a real bool. You cannot write if one or if an empty string; the compiler will stop you. There are no truthy or falsy values, and every condition is written as an explicit comparison.\n\nThe char type is a single Unicode character, written in single quotes. Unlike languages where a character takes one byte, in Rust a char takes four bytes and can hold a Russian letter, a Chinese character, or an emoji. Single quotes and double quotes are different things: a character goes in single quotes, a string in double quotes. A character has many methods: you can ask whether it is a letter or a digit, convert it to uppercase, or get the numeric value of a digit. You can turn a character into a number with as, but a number becomes a character only if it is a u8, because not every number is a valid character.\n\nYou often need to get a number from another type or from text. For safe widening there is the function from: i64 from x always works if x is an i32. For narrowing there is try_from, which returns a result with an error if the number did not fit. To get a number from a string, you use the parse method and give the type in angle brackets, for example parse i32. It also returns a result: either the number or a parsing error. Later we will learn to handle these properly, but for now it is enough to call unwrap, so that on an error the program stops with a clear message.\n\nNumbers have dozens of useful methods. The method abs returns the absolute value, pow raises to a power, sqrt on floats takes the square root, floor and ceil round down and up, and round rounds to the nearest. The methods min and max pick the smaller and the larger one. The limits of a type live in constants: i32 colon colon max gives a little over two billion one hundred forty-seven million. You call methods directly on a number, but a literal with a dot sometimes needs a type: two point zero f64. And you can find the size of a type in bytes with the function size_of.\n\nLet us compare with Python. There, an integer grows without bound; here every type has its own size and its own overflow. There, a boolean is a descendant of the integer, and true plus one gives two; here bool is not a number and you cannot add them. There, a one-character string and a character are easy to confuse; here they are two different types. There, a number and a string get combined through a conversion you ask for; here the compiler always demands a conversion. In return you always know how much memory a value takes, and you can rely on types not changing.\n\nLet us sum up. The scalar types of Rust are signed and unsigned integers, the floats f32 and f64, bool and char, plus the unit type. Choose the size of an integer to fit the task, and when in doubt, keep i32 for numbers and usize for indexes. Make overflows and conversions explicit, and use only bool in conditions. In the next chapter we will learn to wrap computations in functions and return values from them, and that is where all these types will come in handy.
