#CHAPTER 12 | Python lists, Rust arrays and vectors
Learning Rust. Chapter 12. Python lists, Rust arrays and vectors. The list is the most used structure in Python, and the first thing any Rust program needs. In chapter seven we met tuples, arrays and vectors one by one. Now we will put them next to the Python list and go through all the familiar operations: adding, removing, slices, copying, sorting, comprehensions, two-dimensional lists and queues. On the way we will look at the typical traps: changing a list while iterating over it, shared references when copying, and the list of lists in which all the rows turned out to be one. In Rust these traps either disappear or are caught at build time.\n\nHomogeneity. A Python list holds anything: numbers, strings, other lists, a mix. A Rust vector is homogeneous: all elements have the same type, and this is both its main limitation and its main advantage. An array is homogeneous too and has a fixed size. A tuple holds different types, but it has a fixed length, and you can access it only by a constant index. If you need a vector of different types, you declare an enum whose variants hold the data you need, and make a vector of enums. This is more precise than a mix: the compiler knows all the variants.\n\nThe main methods. Append becomes push, extend becomes extend, insert becomes insert. Pop with no argument becomes pop, but it returns an Option: an empty vector has no last element. Pop with an index becomes remove. Python's remove, which deletes by value, is done in Rust with retain and a condition, or with position and then remove. Clear stays clear, len stays len, and the in check is contains. Notice that most methods that in Python break with an exception on a bad index either panic in Rust or return an Option.\n\nIndexes and slices. There are no negative indexes in Rust: the last element is taken with the method last, or with the index len minus one. A Python slice creates a copy, while a Rust slice is a reference to part of the vector, with no copying. A Python slice has a step: zero, colon, ten, colon, two. In Rust you get the step through an iterator: the slice, then iter, then step by. For splitting into parts there are chunks and windows: the first cuts into pieces of a given length, the second gives sliding windows. They often replace manual loops with indexes and make algorithms shorter and safer.\n\nCopying. In Python, l2 equals l does not copy the list: both names point to the same object. A copy is made with the method copy or with a slice, and for nested lists with the function deepcopy. In Rust, assigning a vector moves it, and the old variable becomes unavailable, so you cannot accidentally end up with a shared vector. An explicit copy is made by the method clone, and the copy is always deep: nested vectors are copied too. From a slice you get a vector with the method to vec. So the question of whether something is a copy or a reference is always visible in the code.\n\nChanging while iterating. In Python, removing elements from a list inside a loop over the same list leads to strange results: the iterator skips elements, and the bug shows up only on some data. In Rust such code will not even build: the loop holds a reference to the vector, and you cannot change it at the same time. The compiler says: cannot borrow as mutable because it is already borrowed as immutable. The right solutions are the method retain, which removes elements by a condition in a single pass, the method drain, which pulls out a range, or building a new vector with filter and collect.\n\nSorting and finding extremes. Python's sorted and the sort method become sort, which changes the vector in place, and a copy followed by a sort if you need the original. The key argument becomes the method sort by key, and reverse becomes the method sort by with a reversed comparison. For floating point numbers sort does not work, because they have NaN; you need partial cmp. Min and max on an iterator return an Option, and the sum is a number. Bisect becomes binary search, which returns Ok with the position, or Err with the insertion point.\n\nComprehensions and iterators. A list comprehension with a condition turns into a chain: iter, filter, map, collect. Several lists are glued together by zip, and indexes are added by enumerate. Rust is lazy: until you call collect, either directly or through a loop, nothing is computed. The method windows is useful for comparing neighboring elements, and chunks for splitting into batches. The methods any and all return a boolean, and fold builds a result with complex accumulation. Once you get used to them, you will write Rust as compactly as Python with comprehensions.\n\nCapacity. A vector has not only a length but also a capacity: how many elements fit without a new memory allocation. When it runs out, the vector allocates twice as much and copies the old data. A Python list behaves the same way. The difference is that in Rust you can hint the size you need: Vec with capacity of one thousand allocates memory once. The method reserve asks for extra room, and shrink to fit gives back the excess. For large data this noticeably speeds up the program and saves you from repeated copying.\n\nMixed data. If a Python list holds objects of different classes, in Rust this is solved in two ways. The first is an enum: a vector of values of type Shape, where each variant holds its own data. All the variants are known in advance, and match handles them without leaks. The second is a trait object: a vector of Box dyn values, where each element is any struct that implements the needed trait. It suits extensible systems, for example plugins. We will go through both approaches in the chapter about traits, and for now just remember that a mix of types is possible, but it is spelled out explicitly.\n\nQueue and stack. A vector is an excellent stack: push and pop work in constant time at the end. For a queue, where you take from the front, Python has deque, and Rust has VecDeque from the standard library. It lets you add and take from both ends in constant time. Inserting and removing at the front of a vector costs linear time, because all the elements have to be shifted, so a vector is not suitable for queues. A fast maximum or minimum is provided by BinaryHeap, the analog of Python's heapq module. All of these are available in the standard library, with no external crates.\n\nTwo-dimensional lists. In Python, writing a list of zero times n, times m creates a trap: all the rows turn out to be the same list, and changing one changes them all. In Rust you cannot write it that way. A vector of vectors is created with a macro: vec of vec of zero, semicolon, n, semicolon, m. The macro clones the inner vector for each row, so the rows are independent. For fast computation, grids are stored in one flat vector, and the index is computed as row times width plus column. It lies in memory as a single block and is very fast.\n\nLet's sum up. A vector is homogeneous, growable, bounds-checked, with safe access through get. Slices are references, not copies, and steps and windows come from iterators. Copying is explicit through clone and to vec, and there is no shared mutable state by default. Changing while iterating is forbidden by the compiler, and there are retain and drain for that. Different types are gathered into enums. A queue is a VecDeque, and a heap is a BinaryHeap. Two-dimensional data is a vector of vectors or a flat vector. In the next chapter we will compare classes, traits and operator overloading.
