#CHAPTER 2 | Variables: let, mut, and Shadowing
Learning Rust. Chapter 2. Variables: let, mut, and shadowing. A variable is a name under which a program stores a value. In Python you write the name, an equals sign, and the value, and it just works. In Rust you declare a variable with the word let: let x equals five. The word let means, well, let, and then come the name, the equals sign, the value, and a semicolon. After that you can use the name in expressions and print it. It sounds almost the same as in Python, but Rust has three features you need to absorb right from the start: variables are immutable by default, every variable has one type once and for all, and an old name can be covered by a new one.\n\nThe first feature surprises people the most. If you write let x equals five, and then try to assign six to x, the compiler will refuse to build the program and tell you that you cannot assign twice to an immutable variable. This is not a whim. When you see a declaration without the word mut, you know for sure that the value will not change, and you can stop keeping an eye on it. In long programs, and when several threads are at work, that certainty saves you from many mistakes. Rust prefers that changing a value be an explicit decision.\n\nIf a value has to change, add the word mut, short for mutable: let mut x equals five. Now you can write x equals x plus one, or shorter, x plus-equals one. The other operations are written the same way: minus-equals, times-equals, divide-equals. The word mut tells the reader that the value changes here, and it is worth looking for. If you declared a variable as mutable but never changed it, the compiler will remind you with a warning. Try to declare as mutable only the variables that need it.\n\nRust is a statically typed language: every variable has a type, and it is known at build time. Types are inferred automatically: a five with no decimal point gets the type i thirty-two, a fractional number gets f sixty-four, and a word in quotes gets a string reference. But you can also write the type explicitly after a colon: let x colon i sixty-four equals five. That is needed when you want a different size of number or when the compiler cannot guess on its own. The main rule is that the type of a variable never changes. If x is an integer, you cannot assign a string to it, and the compiler will report a type mismatch. In Python that is allowed; in Rust it is not.\n\nNow about shadowing. You can declare a variable with the same name again: let x equals five, let x equals x plus one. This is not a change to the old variable but the creation of a new one that covers the old one. From that point on, the name x means the new variable. Shadowing is handy when you need to transform a value and no longer need the old one. For example, you can replace a string of spaces with the number of spaces: let spaces equals a string of three spaces, let spaces equals spaces dot len. The type changes here from a string to a number, which you cannot do with mut.\n\nHow does shadowing differ from mut? First, it always needs the word let, so you cannot shadow by accident. Second, the new variable can have a different type. Third, after a series of transformations you can make the result immutable: first you worked with a mutable one, and then you covered it with an immutable one of the same name. Mut changes the value in place and keeps the type, while shadowing creates a new value. Use shadowing for transformations, and mut for accumulating a result, like a counter or a running sum in a loop.\n\nEvery variable has a scope. Its boundaries are the curly braces of a block. A variable lives from its declaration to the closing brace, after which it disappears and its memory is released. Inside a nested block you can shadow an outer variable: while you are inside, the name means the new one, and after you leave it means the old one again. This is similar to local variables in Python functions, but a block can be any pair of braces, not just a function body. Such blocks are handy for limiting the lifetime of temporary values.\n\nNext to let there are constants. They are declared with the word const, and a type is mandatory: const MAX colon u thirty-two equals one hundred. By convention, constant names are written in capital letters with underscores. The value of a constant is computed at compile time, so on the right-hand side you can only have expressions made of numbers and other constants. A constant can even be declared outside functions, at the file level, and then everyone can see it. It cannot be made mutable, and unlike let it does not take up space on the stack: the compiler substitutes the value right into the code. Use constants for magic numbers.\n\nA variable can be declared without a value: let x and a semicolon, and assigned later. But you cannot use it before the assignment, and the compiler checks this and will reject code that might read an empty variable. In that case the type most often has to be written explicitly. This form is handy when the value is chosen by a condition: in one branch of an if you assigned one thing, in the other branch something else. After that you can use the variable like any other, and it stays immutable: it was assigned exactly once.\n\nWith let you can take apart a pair or a triple of values right away. Writing let, an opening parenthesis, a, b, a closing parenthesis, equals, an opening parenthesis, one, two, a closing parenthesis, creates two variables at once. This is called destructuring. An underscore in place of a name means that the value is not needed. It is also convenient for swapping two variables: in parentheses a, b, equals, in parentheses b, a. If a variable is declared but not used, the compiler gives a warning; to silence it, start the name with an underscore.\n\nWhat mistakes do beginners make most often? Trying to change an immutable variable: the compiler suggests adding mut. A warning about an unnecessary mut, when the variable was only read. A type mismatch, for example a number and a string in one variable. And using a variable that might not have received a value. All of these messages are easy to read, and in most cases they already say what to fix. Don't be upset when you see red text: it is a normal part of working in Rust.\n\nIf you compare with Python, there a name can be bound to anything at any moment: a number, then a string, then a list. Rust has two replacements for that. If you are changing a value of the same type, use mut. If you need a new type or a new immutable value, shadow it with let. You will never need global or nonlocal, because there are exactly as many scopes as there are blocks. Once you get used to it, you will notice that the code reads more easily: the word mut shows right away where the state changes.\n\nLet's sum up. Variables are declared with the word let and are immutable by default. The word mut allows you to change the value, but not the type. Shadowing creates a new variable with the same name, possibly of a different type. Constants are declared with the word const and must have a type. Scope is limited by a block. In the next chapter we will get to know the data types: integers, floating-point numbers, booleans, and characters, and find out how they are laid out in memory.
