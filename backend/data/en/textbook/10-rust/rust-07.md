#CHAPTER 7 | Tuples, Arrays and Vectors
Learning Rust. Chapter 7. Tuples, arrays and vectors. So far every variable has held a single value. But programs also need to keep many values together: a list of grades, the coordinates of a point, the rows of a table. For this Rust has compound types. A tuple gathers values of different types into one group of a fixed size. An array holds values of one type, and its size is fixed too. A vector is a growable array, the closest relative of the Python list. In this chapter we will go through all three, their similarities and differences, and learn how to choose the right one.\n\nA tuple is written in parentheses: let t equals, in parentheses, three, four point five, and a string. Its type is a list of types in parentheses, and here it consists of i thirty-two, f sixty-four and a reference to a str. Elements are reached by number through a dot: t dot zero and t dot one. There are no square brackets here, because the number is known when the program is built. A tuple can be taken apart into variables at once: let, in parentheses, x, y, z, equals t. The empty tuple with zero elements we have already met: it is called unit.\n\nAn array is written in square brackets: let a equals, in square brackets, one, two, three. Its type is, in square brackets, i thirty-two, a semicolon and three, that is, the type of the elements and the length. The length is part of the type: an array of three elements and an array of four elements are different types. Writing, in square brackets, zero, a semicolon and five creates an array of five zeros. An array lies right on the stack, with no allocation on the heap, so it is very fast. You reach an element by index: a, in square brackets, zero. The length is returned by the len method.\n\nWhat happens if the index goes out of bounds? In Rust you get a panic with a clear message saying that the index is out of bounds, the length is three and the index is five. In C this would mean reading someone else's memory and silently corrupting data, and in Python it would be an IndexError exception. Rust checks the bounds on every access by index, and that protects the program. If the index is known when the program is built, as in a, in square brackets, ten, the compiler rejects the code at build time. The safe way is the get method: it returns a value, or nothing if there is no such index, and the program does not crash.\n\nA slice is a reference to a part of an array. Ampersand, a, in square brackets, one, two dots, three, is a slice of the elements from the first to the second, and the right bound is not included, as in ranges. The type of a slice is written as an ampersand and, in square brackets, i thirty-two: without a length, because the length is known only while the program is running. Slices exist for arrays, vectors and strings, and most functions work with them. A slice copies nothing, it simply points at the start and stores a length. You can change a slice only if it is mutable, that is, ampersand mut. That is why it is better for functions to accept a slice: then an array, a vector and a part of a vector all fit, you just need to put an ampersand.\n\nA vector, written Vec with the element type in angle brackets, is created with the vec macro: vec, an exclamation mark, and in square brackets one, two, three. An empty vector comes from Vec, two colons, new. It can grow: the push method adds to the end, pop removes the last element and returns it, and len shows the number of elements. A vector keeps its data on the heap, so its size can change while the program runs. All the elements of a vector have the same type, as in an array, unlike a Python list, where you can put anything.\n\nAccess to the elements of a vector is the same as for an array: v, in square brackets, zero. Going out of bounds causes a panic. The get method returns a value or nothing: v dot get of five gives None if there are fewer elements. The first and last methods return the first and the last element, also wrapped, because a vector may be empty. A result that may turn out to be nothing is written in Rust with the type Option. It takes two forms: Some, if there is a value, and None, if there is not. We will deal with it in detail in the chapter about enums, and for now you can simply call unwrap.\n\nA vector is iterated with the for loop. Writing for x in ampersand v means look through the elements without taking anything away. If you need to change the elements, you write ampersand mut v, and x becomes a mutable reference: asterisk x plus equals one. The asterisk is needed to reach the value itself, not the reference. If the index matters, you add enumerate. And the iter method returns an iterator that has many useful operations: summing, maximum and minimum, searching, transforming and filtering. You will need them in every program.\n\nA vector can be modified in different ways. The insert method puts an element at a position, remove deletes by index and returns what was deleted, and clear empties the vector. The extend method appends the elements of another vector to the end. Contains checks whether a value is present. Reverse flips the vector in place. The dedup method removes neighboring duplicates, so it is usually called after sorting. All of these methods require the vector to be declared with mut: you cannot change an immutable vector, just as you cannot change an immutable variable. This protects you from unexpected edits.\n\nTo sort a vector, use the sort method, which orders the elements in place, ascending. For sorting by your own rule there are sort by and sort by key: for example, by the length of words or in descending order. Floating point numbers cannot be sorted with sort, because they have NaN, and you have to use partial cmp. The maximum and minimum are the max and min methods of an iterator, and they return an Option. The sum is computed by sum, and in a sorted vector you can look for a value with binary search, in logarithmic time. Sorting in Rust is fast and stable.\n\nTwo-dimensional data is stored as a vector of vectors: a Vec of Vec of i thirty-two is a grid in which every row can have its own length. You reach an element like this: grid, in square brackets, row, in square brackets, column. For fixed sizes an array of arrays will do: in square brackets, in square brackets, i thirty-two, a semicolon and three, then a semicolon and three, is a three by three matrix with no heap. Nested for loops go over its rows and columns. Matrices, game boards and tables in programs are stored exactly like this, although there are special libraries for heavy computations.\n\nLet us compare with Python. A Python list grows, you can put any types in it, and you can use negative indexes. A vector grows, but it has a single element type and only non-negative indexes. For different types together there is the tuple, and for a fixed size there is the array. List comprehensions are replaced by chains of iterators: iter, map, filter, collect. Slices are similar, but they do not copy, they point at part of the data. In return you get a guarantee: every element of a vector has the same type and size, which means the processing is fast and predictable.\n\nTo sum up. A tuple has different types, a fixed size, and access by number through a dot. An array has one type, a fixed size, and lives on the stack. A vector has one type, a growing size, and lives on the heap. Slices give a reference to a part of a sequence. Indexes are checked, and the get method returns a safe result. Iterate with the for loop, change through mut, and sort with the sort methods. In the next chapter we will meet structs and enums, which will let you create your own data types.
