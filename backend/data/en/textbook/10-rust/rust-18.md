#CHAPTER 18 | Collections and errors: Vec, String, HashMap and Result
Learning Rust. Chapter 18. Collections and errors: Vec, String, HashMap and Result. In Python the list, the string and the dictionary are always at hand, and exceptions help with errors: something goes wrong, and execution jumps up the stack to the nearest handler. In Rust the same jobs are done by collections from the standard library, and all of them live on the heap, while a small owner stays on the stack. Errors, though, are never exceptions: they are ordinary values that a function returns, and you can see them in its signature. In this chapter we put everything together: data structures, iterators, and the result type on which all error handling is built.\n\nLet us start with the vector. The type Vec of T keeps three words on the stack, just like String: a pointer to a buffer on the heap, a length, and a capacity. The elements lie in a row, all of one type and without headers, so a vector of numbers in Rust takes exactly as many bytes as the numbers need, and the processor reads it linearly, making excellent use of the cache. A Python list holds pointers to separate objects in its buffer, and that costs noticeable speed. When the capacity runs out, push asks the allocator for a buffer twice as large and moves the elements there, so appending to the end costs a constant amortized. If you know the number of elements in advance, the with_capacity method avoids extra moves.\n\nTraversing a vector and other collections is built on iterators. The iter method gives references to the elements, iter_mut gives mutable references, and into_iter takes the elements along with the collection. The adapters map, filter and zip lazily describe a pipeline, and collect gathers the result into the collection you want, and you have to state the result type explicitly. Thanks to closures with vertical bars, a pipeline fits on one line. A closure captures variables from its environment by reference, or takes them with move, and the usual borrowing rules apply. The compiler folds lazy chains into a single loop, as if you had written it by hand: the abstraction is free.\n\nNow strings. A String owns a buffer of bytes in UTF-8 encoding, and a str is a slice of such a buffer. That is why you cannot index a string with a number: a letter can take from one to four bytes. To work with characters there is the chars method, for bytes there is bytes, and for pairs of offset and character there is char_indices. You join strings with the push_str method, with the plus operator, which takes the left string and accepts the right one by reference, or with the format macro. A literal is turned into a String with the to_string or to_owned methods, or with the function from. Uppercase letters, as before, come from to_uppercase, which works with Cyrillic too.\n\nThe hash table in Rust is called HashMap. It is the very structure we studied in the book about algorithms: an array of buckets, a hash function, and collision resolution, with constant-time insertion and lookup on average. Keys and values move into the table, which means it takes ownership of them. The get method returns not the value but an Option with a reference: the key may be absent. The iteration order is undefined and changes from run to run, because the hash function gets a random seed as protection against attacks. If you need ordering by key, you take BTreeMap, a balanced tree, and for a set of elements, HashSet.\n\nFor the typical job of counting or collecting into groups, HashMap has the entry interface. The entry method returns a slot: either occupied or empty. The call or_insert puts in a default value if the slot is empty, and returns a mutable reference to the value, and an asterisk with plus-equals one increments the counter. That is how you count the words in a text with a single line and a single hash lookup. In the same way, or_insert_with adds a default value such as an empty vector, so that you can then add an element to it. The and_modify method changes an existing value without creating a new one. In Python the same job is done with get or with defaultdict.\n\nNow about errors. Rust distinguishes two kinds: those you can expect and handle, and unrecoverable ones. For the first kind there is the type Result of T and E: either Ok with a result, or Err with a description of the error. It is an ordinary enum, no magic. A function that may fail returns a Result, and you cannot forget to check it: the compiler will warn you, because the type is marked as must be used. In C you have return codes for this, and they are easy to ignore, and in Python an exception arrives unexpectedly. In Rust every place where an error is possible is visible in the signature and in the calling code.\n\nSo that code does not turn into a ladder of matches, the question mark operator was invented. Placed after an expression of type Result, it unwraps Ok into the value, and on Err it immediately returns the error from the current function. If the error types differ, it performs a conversion through the From trait, and errors are converted automatically. You can declare functions with a Result return type, and then the operator works like the familiar raise, only explicit and visible on every line. Main can return a Result too. The ok method turns a Result into an Option, and the ok_or method converts an Option into a Result with the error you give it.\n\nFor your own errors you usually create an enum. Its variants describe exactly what went wrong, and they can carry data: for example, the number parsing error returned by the standard library. To make the error print nicely, you implement the Display trait, and to fit into the ecosystem, the Error trait. An implementation of From for the nested error lets the question mark operator convert it automatically. If there are many error types and you care only about the message, you return Box of dyn Error, an error of any type on the heap. It stores a pointer to the data and a pointer to the table of virtual methods, like interfaces in other languages.\n\nPanic is the second path. A call to panic, a wrong index, unwrap on None, or division by zero interrupts the thread. On a panic Rust unwinds the stack: it walks up through the frames and calls drop for everything that lay in them, so files are closed and locks are released. The process ends with exit code one hundred one. You can catch a panic with the catch_unwind function, but that is not error handling, it is an isolation boundary, for example in a server, so that one request does not bring down the others. The rule is simple: if the error is expected, return a Result; if it is a violated invariant and it is impossible to go on living, panic. For tests and prototypes, the expect method is handy.\n\nThe methods of Result and Option form a whole language of transformations. Map changes the value inside Ok, map_err changes the error, and_then launches the next step, which may also fail. Unwrap_or_else sets a value in case of error, and it is evaluated lazily. An iterator of results can be collected into a Result of a vector: collect stops at the first error and returns it, and if everything is fine, it returns the vector. This is one of the most elegant tricks in Rust, and it replaces a loop with accumulation and checks. For those who do not care about errors, filter_map with the ok method silently throws away the failed results.\n\nHow do you choose a collection? The vector is the default choice: linear memory, fast traversals, and appending to the end in constant time. If you need to remove quickly from the front, you take VecDeque, a ring buffer. If you need lookup by key in constant time on average, use HashMap, and for ordered traversal and ranges, BTreeMap. HashSet and BTreeSet store unique values. The processor likes sequential memory, and a vector often outruns theoretically faster structures on small data. Once you get used to these three types and to Result, you will be able to write a typical Rust program without much difficulty.\n\nLet us sum up. The vector and the string are three words on the stack and a buffer on the heap; HashMap stores pairs and hands out references through an Option, and the entry interface makes counting short. Iterators are lazy and fold into an ordinary loop. Errors are values: a Result is returned explicitly, the question mark operator passes the error up, From converts types, and Box of dyn Error suits the general cases. A panic unwinds the stack and calls drop, but it is meant for unrecoverable errors. This completes the section on data and abstractions. Next we have traits, generics, and a deeper look at lifetimes: the language that builds abstractions without overhead.
