#CHAPTER 13 | Classes, Traits, and Operator Overloading
Learning Rust. Chapter 13. Classes, Traits, and Operator Overloading. Python is an object-oriented language: data and methods live in a class, behavior is extended through inheritance, and special methods with double underscores let objects work with addition, printing, and loops. Rust is built differently. A struct describes the data, an impl block holds the methods, a trait describes behavior shared by different types, and operator overloading is also done with traits from the standard library. There is no inheritance, but almost everything you do with it in Python can be done more simply. In this chapter we will go through the constructs one by one and match each of them to its Python counterpart.\n\nLet's start with the class. A Python class with fields and methods turns into a struct and an impl block. The init method is replaced by an associated function that, by convention, is called new. Rust has no constructors at all; any instance can be created with a struct literal. The first parameter of a method, self, is spelled out explicitly, and it tells you exactly what the method does with the object: reads it, changes it, or takes it away. Privacy works differently too: fields and methods are private by default and visible only inside the module, and the word pub opens access. The leading underscore as a convention is not needed.\n\nProperties and class methods. The property decorator in Python turns a method into an attribute that is read without parentheses. Rust has no such thing: for reading you write a getter method that takes a reference to self, and for writing a setter method that takes a mutable reference to self. The getter usually has the same name as the field, just without the word get. Python's class methods and static methods turn into associated functions without self: they are called through the type name and a double colon, for example User, double colon, new. The same notation is used for constants declared inside an impl block and for helper functions.\n\nInheritance. In Python a child class inherits the fields and methods of its parent, and the order in which methods are looked up is defined by a rather complicated rule. In Rust, structs cannot inherit. Instead there is composition: a struct holds another struct in a field and calls its methods. Shared behavior goes into a trait. This solves the famous diamond problem, where it is unclear whose method to call, and a change to a base class does not break the children, because there are none. To reuse code you will have to come up with good small types and traits instead of deep hierarchies. In practice, the code ends up simpler.\n\nA trait is a description of behavior. Inside it you list the signatures of the methods that every type with this trait must implement. For example, a trait Shape with one method, area, which takes a reference to self and returns a sixty-four-bit float. The implementation is written separately: an impl of Shape for Circle, with the body of the area method. A Rust trait resembles an abstract base class or a Python protocol, but it is implemented after the type is declared, and you can even implement your own trait for someone else's type, for example for a number. This makes the code flexible, and at the same time the compiler makes sure the implementation is complete.\n\nTraits can have default methods. If a trait gives a method with a body, every type gets it for free, but can replace it. Polymorphism of two kinds works through traits. Static, when a function accepts an impl Shape or a generic type with a bound, and the compiler creates a separate version for each type: this is fast, and the call can be inlined. Dynamic, when you store a Box of dyn Shape, that is, a pointer to an object together with a method table, just like in Python. You need it to put different types into a single vector. Choose static until you actually need dynamic.\n\nString representation. The str and repr methods from Python are replaced by two traits. The Display trait is responsible for nice output for the user: you implement it by hand and use it through a format with curly braces. The Debug trait is responsible for debugging output: it is generated automatically by the derive attribute and used through a format with a question mark. The Display implementation uses the write macro and takes a formatter. Once the trait is implemented, the to_string method becomes available automatically. The choice is simple: Display for people, Debug for programmers, and derive gives you the latter in one line.\n\nComparison. The methods eq, lt, le, and the rest turn into the traits PartialEq and PartialOrd. For structs whose fields are all compared in order, the derive attribute is enough: the fields are compared lexicographically. If you need a special order, you implement the partial_cmp method by hand. For hashing, which Python does with the hash method, there is the Hash trait, and again derive. The traits Eq and Ord differ from the partial variants in that comparison is defined for all values: floating-point numbers have NaN, so they implement only the partial ones.\n\nOperator overloading. Python's add, sub, mul, and other methods are, in Rust, traits from the ops module: Add, Sub, Mul, Div, Rem, and Neg. An implementation looks like this: impl Add for Vector, with an associated type Output equal to Vector, and a method add that takes self and other and returns a Vector. For compound operators like plus-equals there are the traits AddAssign and the like. For indexing there are Index and IndexMut. For calls there are Fn, FnMut, and FnOnce, but you can't implement them by hand yet, and closures get them automatically. Rust allows operators only from this fixed set; you can't invent new ones.\n\nPractical details. For arithmetic on vectors and matrices, you usually implement the operators both for values and for references, so that expressions like a plus ampersand b work without extra copies. The result type is written in the associated type Output, and it doesn't have to equal the operand type: the dot product of two vectors returns a number. The coherence rules forbid implementing a foreign trait for a foreign type, so that two libraries don't conflict. You get around this with a wrapper: a struct with a single field, for which you can implement the trait. The pattern is called newtype, and you will meet it all the time.\n\nIterators and context managers. Python's iter and next methods turn into the Iterator trait. It is enough to implement the next method, and your type gets the for loop and dozens of ready-made methods. So that a loop can take a type by value or by reference, you also implement IntoIterator. Context managers, with their enter and exit methods, thanks to which a file closes itself, are replaced by the Drop trait: its method is called automatically when a value goes out of scope. That is why Rust doesn't need with blocks: resources are released without explicit commands, and the order of release is completely predictable.\n\nData classes and default values. A Python dataclass creates the init method, comparison, and printing from a description of the fields. In Rust, the same is given by a set of attributes: derive Debug, Clone, PartialEq, and Default. Default replaces the default values in the constructor: User, double colon, default, with empty parentheses, fills all the fields with standard values, and the syntax with two dots and default lets you set only the ones you need. Clone makes a deep copy, like copy dot deepcopy. Copy makes a type copyable on assignment, as happens with numbers, and suits only simple data that doesn't own heap memory.\n\nLet's sum up. A class is a struct with an impl block. Init is new, property is a getter, a class method is an associated function. There is no inheritance: there are composition and traits. Traits come with static dispatch and with dynamic dispatch. Str and repr are Display and Debug, comparison and hashing are derive, operators are traits from ops. Iterator and Drop replace the iteration methods and context managers. A dataclass is a set of derive attributes. In the next chapter we will compare Python dictionaries with the Rust hash map and add sets. After that we will move on to borrowing.
