#CHAPTER 4 | Functions and returning values
Learning Rust. Chapter 4. Functions and returning values. A function is a named piece of code that you can call from different places. You have already written one: fn main, the entry point of every program. A declaration starts with the word fn, followed by the name, parentheses with parameters, and curly braces with the body. By convention, names of functions and variables in Rust are written in lowercase letters with underscores, which is called snake case. The order of declaration does not matter: you can call a function above the place where it is written, because the compiler reads the whole file first. That is more convenient than in Python, where a function has to be defined before it is called.\n\nParameters always have a type. After the parameter name you put a colon and the type: for example, a function greet that takes a parameter name of type string slice. In Python you can leave types out, but in Rust you cannot: a function signature is a contract between the caller and the callee, and the compiler checks it at every call. A call looks familiar: the name and the arguments in parentheses, separated by commas. The number of arguments and their types must match, or the build fails. Rust has no optional parameters and no named arguments, but then there is no confusion either.\n\nTo return a value, you write an arrow and a type after the parentheses: for example, a function add that takes two i32 parameters, a and b, and returns an i32. In the body, the last line without a semicolon becomes the result of the function. You do not need the word return for that: just write the expression a plus b at the end. The habit of putting a semicolon after every line is dangerous here: a semicolon turns an expression into a statement, and the result disappears. Then the compiler gives an error saying it expected an i32 but found the unit type.\n\nThe difference between an expression and a statement is fundamental in Rust. An expression evaluates to a value: a number, a sum, a function call, a block, a condition. A statement performs an action and returns no value; a declaration with let is an example. That is why you cannot write let x equals, in parentheses, let y equals six, but you can write let x equals a block whose last line has no semicolon. A block in curly braces is also an expression: its value is the last expression inside. This idea lets you write shorter code without extra temporary variables.\n\nRust does have the word return, and it is used for early exit. If you need to break out of a function in the middle, for example on a bad input value, you write return, a value, and a semicolon. Execution leaves the function immediately. As you have probably gathered, it is not customary to put return at the end of a function: it looks foreign and does not match Rust style. But in the branches of a condition, inside loops, and in checks at the start of a function, return is perfectly appropriate and keeps the code flat, without nested branching. The rule is this: return is for early exit, and the final value is the last expression.\n\nWhat does a function without an arrow return? It returns the unit, a type with a single value, written as empty parentheses. This is Rust's analogue of nothing, but it is a real type. The function main, println, and assignment all produce the unit. If you accidentally add a semicolon at the end of a function that is supposed to return a result, the compiler will say it expected one type but got the unit. Next to it there is the never type, written with an exclamation mark: it belongs to expressions that never hand control back. These are a panic, an infinite loop, and exiting the process. The never type fits anywhere, so a branch with a panic does not break the types.\n\nIf you need to return several values, you use a tuple. In Python you write return a, b and get a tuple; in Rust it is the same, except that the type is written explicitly: an arrow, then in parentheses i32, comma, i32. The result can be unpacked straight into two variables: let, in parentheses, quotient and remainder, equals divide, ten and three. The elements of a tuple are accessed by number with a dot: pair dot zero. Tuples are good for small pairs and triples, and if there are more values, it is better to define a struct, which we will cover later.\n\nConditions and loops are expressions too. The if-else construct returns the value of whichever branch ran: let sign equal if x is greater than zero, one, else, minus one. Both branches must have the same type, or the program will not build. That is why Rust has no ternary operator like other languages: it simply is not needed. A function can also consist entirely of an if-else, without return, and each branch returns its own result. That is how you write, for example, the absolute value of a number or the larger of two values in a single line.\n\nFunctions can call themselves: that is recursion. The classic example is the factorial: the function calls itself with an argument one smaller and multiplies the result. You have to take care of the stopping condition, otherwise the calls will go on forever and the program will crash with a stack overflow. Rust does not guarantee tail-call optimization, so for large depths a loop is often better. Functions can also be declared inside other functions: a nested function is visible only in the block where it is declared, and it cannot see the local variables of the outer one.\n\nA function receives its arguments by value. For simple numbers this means the function works with a copy, and changing the parameter does not affect the original variable. If you need to change a parameter inside the function itself, you write mut before its name: for example, a function count whose parameter is mut n of type i32. But only the local copy ends up changed. Later, when we meet references, we will see how a function can change the caller's variable. For now, remember this: numbers, characters, and booleans are copied freely, and each call gets its own.\n\nYou have already called println with an exclamation mark, and it is not a function but a macro. A macro is code that writes code at compile time, which is why it is allowed to take a varying number of arguments and a format string. Other macros of this kind are format, which builds a string instead of printing it, panic, which stops the program with a message, and assert, which checks a condition. The macro assert_eq with a and b compares two values and fails if they are not equal. You use macros like ordinary functions, only with an exclamation mark, and we will learn to write our own much later.\n\nLet us compare with Python. The word def becomes fn, the colon and indentation become curly braces, and type annotations become mandatory. There are no default argument values, no star args, and no keyword arguments, so one function does one thing. The result of a function is its last expression, and the word return is only for early exit. Python's None becomes the unit, and several values are returned as a tuple. Rust has lambdas and higher-order functions too, but they are called closures, and we will cover them later.\n\nLet us sum up. A function is declared with the word fn, types are mandatory for parameters and the result, and the result is written after an arrow. The final value is the last expression without a semicolon, and return is needed for early exit. Without an arrow the function returns the unit, and several values come back as a tuple. A condition and a block are expressions too. Functions receive arguments by value, and the order of declaration does not matter. In the next chapter we will add conditions and loops and write our first real algorithms: iteration, counting, searching, and accumulation.
