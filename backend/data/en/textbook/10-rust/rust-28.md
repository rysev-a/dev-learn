#CHAPTER 28 | Time, numbers and memory: Duration, Instant, num, mem
Learning Rust. Chapter 28. Time, numbers and memory: Duration, Instant, num and mem. In this chapter we gather together what is neither a collection nor text, but shows up in every program: measuring time, a rich set of numeric methods, special numeric types, and facts about how values lie in memory. Rust offers little here, but it is well thought out: duration and point in time as separate types, detailed methods on integers and floats, and functions for measuring sizes. Everything else, such as calendars, big numbers and randomness, lives in external crates.\n\nThe type Duration represents a span of time with nanosecond precision. You create it with the functions from_secs, from_millis, from_micros and from_nanos, and with from_secs_f64 for fractional seconds. You read it with the methods as_secs, as_millis, as_secs_f64 and subsec_nanos. Durations can be added, subtracted, multiplied by a number and compared like ordinary values, and for safe arithmetic there are checked_add, checked_sub and saturating_sub. There are no negative durations: subtracting a larger one from a smaller one gives a panic, or nothing in the checked version. Printing through Debug gives a human-readable form such as one point five seconds.\n\nA point in time is a separate story, and there are two kinds. Instant is a monotonic clock: its value only grows forward, does not depend on the clock being reset, and is suited to measuring. You create it with the function now, and the elapsed time comes from the method elapsed. System time is SystemTime, the reading of a wall clock, which can jump when it is synchronized. Its difference from the Unix epoch gives the seconds since the first of January, nineteen seventy. Always measure with Instant, and use system time for file stamps and events. A calendar, time zones and date formatting are missing from the standard library: for them you add the chrono or time crates.\n\nPauses. The function sleep from the thread module stops a thread for a given duration. In asynchronous programs you use an asynchronous sleep instead, otherwise the whole executor freezes. For timeouts you count time with Instant: remember the start, and at each step check whether the limit has passed. Measuring fast operations takes care: the compiler may throw away a computation whose result is not used. The function black_box from the hint module protects against that, and for serious measurements you use the criterion crate, which makes many runs and computes statistics. A single run on too small an amount of work proves nothing.\n\nIntegers are rich in methods. Arithmetic with overflow control: checked, wrapping, saturating and overflowing for every operation. Absolute value and distance: abs, abs_diff and signum. Euclidean division: div_euclid and rem_euclid. The power is pow, and checked_pow is the version with a check. Bits: count_ones counts the ones, leading_zeros and trailing_zeros count zeros at the edges, rotate_left and rotate_right rotate, and swap_bytes and reverse_bits flip. For bytes there are to_be_bytes and to_le_bytes. Whether a number is a power of two is checked with is_power_of_two, and next_power_of_two finds the next one.\n\nFloats have rounding methods: floor, ceil, round, trunc and fract. Powers and roots: powi, powf, sqrt and cbrt. Exponent and logarithms: exp, ln, log10 and log2. Trigonometry: sin, cos, tan, the arc versions, and atan2. The hypotenuse is hypot, and the method mul_add does a multiply-add without losing precision. Checks: is_nan, is_finite and is_infinite. Constants live in the consts module and in the type itself: EPSILON, MIN, MAX and INFINITY. The method to_bits shows the internal representation, and total_cmp sets a total order, NaN included.\n\nWhat the standard library does not have. There is no common trait for a "number", which would let you write a function for any numeric type: instead there are separate operator traits. The num-traits crate gives you zero, one, Num and a set of helper traits. There are no big integers: num-bigint takes care of them. There are no rational or complex numbers: they are in num-rational and num-complex. There are no random numbers: the rand crate brings them, because a generator needs a source of entropy from the operating system. This modesty of the standard library is a deliberate choice: everything else develops faster in crates.\n\nSpecial numeric types. Wrapping turns arithmetic into wrap-around arithmetic: Wrapping of two hundred fifty-five plus Wrapping of one gives zero even in debug mode. Saturating behaves like saturation. NonZeroU32, NonZeroUsize and others store a number that is not zero, and the compiler uses the zero value as a place for "nothing": an Option of such a type takes as much space as the number itself. This optimization is called a niche, and it also works with references, boxes and some enums. Conversion errors: ParseIntError, ParseFloatError and TryFromIntError.\n\nSizes and layout. The function size_of returns the size of a type, and align_of the requirement on its address. An Option of a reference is the size of the reference, a String takes three words, a slice two, a Box one, and a dyn trait object two: a pointer and a method table. An enum takes room for its largest variant plus a tag, but the compiler hides the tag in unused values when it can. The fields of a struct are reordered to reduce alignment padding, and the attribute repr C forbids that. Knowing sizes helps with cache optimization: structs that fit in one cache line are processed several times faster than scattered ones.\n\nLow-level tools from the mem module. The function transmute reinterprets the bytes of one type as another and requires an unsafe block. ManuallyDrop forbids the automatic call of the destructor. MaybeUninit lets you create a value without initializing it, which is needed in very rare cases. discriminant returns the number of an enum variant without looking at its data. You will hardly ever call almost any of this, but it is useful to know that at the bottom of Rust's abstractions lies a well-defined memory model. An unsafe block does not turn off type checking, it only allows a few extra operations, and they must be used deliberately.\n\nHashing and randomness. The hash module contains the Hash trait and Hasher. The default hasher, SipHash, is resistant to attacks, but its result cannot be stored: it changes randomly from run to run. For stable hashes you take crates such as blake3 or sha2. There are no random numbers in the standard library, apart from the internal random state of a hash map. A simple linear congruential generator takes five lines on integers with wrapping arithmetic, and real randomness comes from rand. For tests that are reproducible with one seed, always accept the generator as a parameter instead of creating it inside the function.\n\nMemory allocation. Everything you put in a Box, a vector or a String lives on the heap, and it is allocated by the global allocator. You can replace it: the attribute global_allocator and a type implementing the allocator trait swap it for, say, jemalloc or mimalloc, and many programs get faster from that. For many small objects people use arenas: one large allocation and fast offsets inside it. The crates bumpalo and typed-arena do this. You can measure consumption by counting allocations through your own allocator. All these techniques are needed at a late stage, but it is worth understanding right away where memory comes from.\n\nLet's sum up. Duration and a point in time are different types: measure with Instant, stamp with system time. Integers and floats have hundreds of methods, and numeric types with special behavior are Wrapping, Saturating and NonZero. Sizes and layout are visible through size_of, and niches make Option free. Randomness and big numbers live in external crates. The mem module gives tools for working with memory, and some of them are unsafe and rarely needed. In the next chapter we will go through the traits of the standard library systematically: Clone, Copy, Default, Eq, Ord, Hash, From, AsRef and others.
