#CHAPTER 8 | Structs, Enums and Option Without Fear
Learning Rust. Chapter 8. Structs, enums and Option without fear. Numbers, strings and vectors are enough for small programs. Bigger ones need their own types: a user, a point on a plane, a color, the status of an order. In Python you write classes for this. Rust has no classes, but it has two simple building blocks. A struct gathers several named values into one type. An enum describes a value that can be one of several variants. To these you add an impl block, where the methods live. Together they cover almost everything you are used to doing with classes.\n\nA struct is declared with the word struct, followed by a name starting with a capital letter and a list of fields with their types: struct User, in curly braces, name colon String, comma, age colon u thirty-two, comma. An instance is created by giving a value for each field by name: User, in curly braces, name colon String from Anya, comma, age colon thirty. You reach a field through a dot: user dot name. The order of the fields at creation does not matter, but you must give all of them. A struct is a new type, and the compiler will not let you mix up a user with an address.\n\nA struct can be changed only if it is declared with mut: then any field can be assigned to, and you cannot make a single field mutable on its own. There are two tricks that save code. The first is the short form: if a variable has the same name as a field, you write just the name. The second is the update syntax: two dots followed by the old instance copy the remaining fields from another instance. To make a struct printable for debugging, you add the attribute derive Debug above the declaration, and then the question mark format prints all the fields. Such attributes are called derived traits.\n\nMethods are written in an impl block: impl User, in curly braces, and inside it functions whose first parameter is called self. It means the instance the method was called on. Writing ampersand self says that the method only reads the data, and it is called in the familiar way: user dot greeting, with parentheses. In the body, fields are taken through self dot name. Methods return values the same way ordinary functions do. A struct and a method together give you a familiar picture: data and behavior side by side, only without inheritance and without hidden fields.\n\nIf a method has to change fields, its first parameter is written ampersand mut self. Then it can be called only on a mutable variable. There is also a third form, plain self: the method takes the whole instance away, and it cannot be used after the call. This is a rare case, and we will talk about it in the chapter on ownership. Besides methods, an impl can have associated functions without self. The best known is called new: User, two colons, new, with Anya and thirty. It is an ordinary constructor, but the language does not require a special name, and new is only a convention.\n\nThere are structs whose fields have no names, called tuple structs: struct Color, in parentheses, u eight, u eight, u eight. Their fields are numbered: color dot zero. They are useful when names would be redundant but you still need to tell the types apart. Meters and feet are both numbers, but they are different types, and you cannot add them by mistake. There are also structs with no fields at all, unit structs, which are used as markers. For ordinary data, use a struct with named fields: code with it reads much better than code with a pile of nameless values.\n\nAn enum describes a value that takes one of a list of variants given in advance. Enum Direction, in curly braces, Up, Down, Left, Right. A value is created through the type name and a variant: Direction, two colons, Up. This is more precise than strings or numbers: you cannot accidentally write something like upward or pass the number seven instead of a direction. The compiler knows all the variants and checks that you have handled every one. Enums in Rust are similar to enumerations in other languages, but they can do much more than simple constants.\n\nEach variant of an enum can carry data. Enum Shape, in curly braces: Circle with an f sixty-four in parentheses, Rect with two f sixty-fours in parentheses. A circle holds one radius, and a rectangle holds two sides. Different variants have different data, but together they are one type, Shape. In Python you would have to write several classes with a common ancestor. In Rust it is all in one place, and the compiler makes sure the data matches the variant. The size of the value equals the largest variant plus a tag.\n\nThe most convenient way to work with enums is match, which we met in the fifth chapter. Match shape: Circle with r gives pi times r squared, Rect with a and b gives a times b. In the pattern you can take the data of the variant straight into variables. The compiler checks that all the variants are covered: add a new variant, and every match that does not handle it stops compiling. This turns adding a new case from a risky job into a safe hint from the compiler: it shows you every place that needs a change.\n\nThe most important enum in Rust is called Option, and we have already seen it several times. It has two variants: Some, with a value inside, and None, with no value. It is the replacement for the null value. In most languages any reference can turn out to be empty, and the program crashes when somebody forgets about it. In Rust a value that may be missing has the type Option, and the compiler does not let you use it as an ordinary value until you have checked. You can work with an Option through match, through if let, and through the methods unwrap and unwrap or, which substitutes a default value.\n\nNext to Option there is its sibling, Result. Its variants are Ok, with a value, and Err, with an error. It is what parse returns when it turns a string into a number: five gives Ok with the number five, and five-five gives Err with a description of the problem. We will cover Result in detail in the chapter on error handling, and for now it is useful to know that it also works with match and with the unwrap method. The idea is the same: an operation that may fail says so right in its type, and you simply cannot forget to check the result, the way people forget error codes in C.\n\nLet us compare with Python. A class with fields turns into a struct, methods turn into an impl block, and the constructor turns into a function called new. A dataclass is similar to a struct with derive attributes. There is no inheritance, and in its place are traits, which we will study later. An enum in Python is a set of constants, while in Rust it is a full type with data in its variants. The value None turns into Option, and exceptions turn into Result. In Rust you will never get the error saying that None has no attribute: it will not come to that, because the compiler will not accept such a program.\n\nTo sum up. A struct has named fields, a method is written in an impl block, self reads and mut self changes. The associated function new creates an instance. An enum sets one of several variants, each variant can hold data, and match handles all of them. Option replaces the empty value, and Result replaces exceptions. This is the first part of getting to know the language: now you have variables, types, functions, branches, loops, strings, collections and your own types. In the next section we will compare Python and Rust on all of these topics one by one, to make the knowledge stick.
