#CHAPTER 1 | What Rust Is and Why You Need It
Learning Rust. Chapter 1. What Rust is and why you need it. Welcome to the Rust course. We will start calmly and without rushing: first we will find out where the language came from and what it is for, then write our first program, and after that go step by step through variables, types, functions, strings, and lists. By the end of this part you will read simple Rust code with confidence and write your own. You already know Python and have a little feel for how a computer works, and that will come in handy, but nothing beyond that is required. The main thing at the start is to get used to the syntax and not to be afraid of compiler messages.\n\nRust is a compiled, general-purpose programming language. It is statically typed: the type of every value is known before the program even runs. It has no garbage collector, and yet programs do not leak memory or crash by touching memory that has already been freed. Rust runs as fast as C and C plus plus, while the code you write is quite high level, with lists, strings, enums, and closures. Its idea can be put briefly like this: the speed of low-level languages and the safety of high-level ones, and the compiler checks all of it.\n\nWhere did it come from? In two thousand six, a Mozilla employee named Graydon Hoare started writing the language as a personal project, and in two thousand nine Mozilla began sponsoring it, because it wanted a safe and fast engine for its browser. The first stable version, one point oh, came out on May fifteenth, twenty fifteen. Since then a new version has come out every six weeks, while code compatibility is preserved: code from twenty fifteen still compiles today. Once every three years there is an edition, for example the twenty eighteen and twenty twenty-one editions. In twenty twenty-one the language was taken over by an independent organization, the Rust Foundation.\n\nWhy invent yet another language? A huge share of dangerous vulnerabilities in C and C plus plus programs come down to memory: going past the end of an array, using freed memory, freeing memory twice, data races between threads. According to estimates from Microsoft and the Chromium browser team, about seventy percent of serious vulnerabilities are exactly of this kind. Experienced programmers still make these mistakes, because nobody can keep all the rules in their head. Rust moves those rules into the compiler: a program with such a defect simply will not build, so the error is found on your computer and not in front of the user.\n\nWhere is Rust used? Components of Firefox, parts of Android and Windows, cloud services, for example the Firecracker virtual machines at Amazon and proxies at Cloudflare, databases, command-line tools like ripgrep, game engines, embedded devices, and web pages through WebAssembly. Since twenty twenty-two Rust is also allowed in the Linux kernel, where it is used to write drivers. That means learning it pays off both as a tool and as a way to better understand what the computer really does.\n\nRust is compiled ahead of time. In Python you run a file, and the interpreter reads it line by line. In Rust the program first goes through the compiler, rustc, which checks the types and the memory and produces a ready-made executable file full of machine instructions, the very ones you studied in the book about computer architecture. You can hand that file to another person, and they need neither Rust nor an interpreter. The price of this speed is a build step: until the code is built there is nothing to run, but in return most mistakes are caught before the program starts.\n\nRust has only a few tools, and they are all installed by a single program called rustup. It installs the rustc compiler, the package manager and build tool Cargo, and it can switch between versions and update itself. Cargo does most of the work: cargo new creates a project, cargo run builds and runs it, cargo build only builds, and cargo check quickly checks the code without producing a file. A project always has a file called Cargo dot toml with its description and a folder called src with a file called main dot r s. We will cover the structure of projects in detail later; for now it is enough to remember two commands: new and run.\n\nHere is the shortest possible program. The keyword f n declares a function, and the function named main is the entry point: execution starts there. Inside the curly braces there is a call to println, with an exclamation mark after the name. That is a macro, which prints a line to the console and moves to the next line. Every statement ends with a semicolon. The text is wrapped in double quotes and can contain any characters, including Russian letters. When you run the program you will see the printed text and find yourself back at the command line.\n\nThe println macro can do more than print ready-made text. In the string you can write a pair of curly braces, and in their place the value passed after the comma is inserted, for example a number or another string. You can also put names inside the braces and use variables right in the text. Two curly braces in a row print one real brace. The print macro without the l n does not move to the next line, and a new line is requested with the escape sequence backslash n. You will be printing a lot in the exercises, so getting used to these small details will pay off.\n\nComments in Rust start with two slashes: the compiler skips everything to the end of the line. For long explanations there is a version with an asterisk, and three slashes write documentation for the item that follows, which ends up in the generated pages. The code has one agreed style: four spaces of indentation, names of variables and functions written in lowercase with underscores, and types capitalized. The command cargo fmt can bring your code to this style automatically, so there is no need to argue about spaces.\n\nThe most important thing for a beginner is compiler messages. They are laid out like this: an error code in square brackets, a clear sentence, an arrow pointing to the file and line, and the underlined spot in the code. Often at the bottom there is the word help with a hint on how to fix it. Read them from the first line: most of the time the first error is the real one and the rest are its consequences. Warnings do not stop the build, but they are worth fixing. For any error code you can ask for a detailed explanation with the rustc command and the explain flag. Once you get used to it, you will see that the Rust compiler is the most patient teacher there is.\n\nHow does this course work? Every chapter has slides, a short talk behind the screen, questions for self-check, and exercises. In the exercises you write real code, and the checking system builds it with a real rustc in an isolated environment and compares the output with the expected one. If the code does not build, you will see the compiler's message. The introductory part starts with very simple exercises that gradually get longer. After it you will compare Rust with Python, then move on to ownership and borrowing, and after that threads, asynchronous code, and a server are waiting for us.\n\nLet's sum up. Rust is a compiled language without a garbage collector, created to remove a whole class of memory errors while staying fast. It grew out of a personal project at Mozilla, reached version one in twenty fifteen, and is used everywhere from browsers to the Linux kernel. You will be helped by rustup and Cargo, and the compiler messages are your best assistant. In the next chapter we will deal with variables: we will find out what an immutable variable is, how to make it mutable, and what shadowing means.
