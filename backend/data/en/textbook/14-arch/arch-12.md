#CHAPTER 12 | Memory
Computer Architecture. Chapter 12. Memory. A processor needs somewhere to keep its program and its data. Memory is an array of cells. Each cell has a number, its address, and contents: a word of several bits. Given an address, you can read the word, and with some kinds of memory you can also write a new one. Memory splits into two big groups. Read-only memory, ROM, holds contents that are wired into its circuit and never change. Random-access memory, RAM, can both read and write, but usually forgets everything when the power goes off.\n\nLet's see how a ROM is built. The address goes into a decoder, which lights one of the row lines. Across the rows run the data lines, one for each bit of the word. Wherever the word should have a one, the row is connected to the data line through an OR gate, and wherever it should have a zero, there is no connection. When a row is selected, the ones reach the output, and the remaining bits stay zero. Four words of two bits each in such a matrix take just a few connections, and the contents are determined only by where those connections are placed.\n\nA ROM can hold the processor's program. Each word is a machine instruction: a few bits of operation code and an operand. For example, take four-bit instructions: at address zero, zero-zero-one-zero; at address one, zero-one-zero-one; and so on. The processor takes the instructions one by one, increasing the address by one each time, and executes them. In the practice section you will write your own small program into a ROM, which the processor built from your blocks will run later.\n\nIn a computer, several devices share one address space, so we need a memory map. Say we have three address bits, which means addresses from zero to seven. Addresses zero to three go to the ROM, four to six go to the RAM, and address seven goes to the input-output ports. Now a decoder on the high address bits lights one of the select signals: ROM, RAM, or I-O. Exactly one is lit, and the access goes to the right device. Real processors have memory maps built the same way, just with much longer addresses.\n\nThree control signals go to a memory chip: chip select, read, and write. From them we derive the write enable, which is active when the chip is selected and a write arrives, and the output enable, which is active when the chip is selected and a read arrives. You can't read and write at the same time, so if the two conflict, the write wins and the output is blocked. Data travels over a shared bus, and while a device isn't selected it must not disturb the others: its output is disconnected, and the bus stays free for everyone else.\n\nNow let's build a memory cell for one bit. At its core is a latch. There are three control signals: write, write protect, and read. Writing works only when protection is off: if protection is on, then whatever arrives on the write signal, the cell stays as it was. Reading puts the cell's value on the bus when it is enabled, and the rest of the time the cell outputs zero and doesn't get in the way of the others. A protected cell like this models how the kernel fences off a region of memory against writes.\n\nTwo cells make a memory of two bits. The address selects a cell, a write goes only to that cell, and the output always shows the contents of the addressed cell. A memory that has just been powered on remembers nothing: the values in the latches haven't been set yet, and the output will be unknown. This is a very important property of real RAM: after power-up the contents are random, and a program must not count on zeros until it has written them itself.\n\nTo store words, each address needs several cells. A two-bit word is two cells with a shared address: a write updates both bits at once, and a read returns both. A memory is described by two numbers: the number of words and their width. An address of k bits can tell apart two to the power of k words. Three address bits give eight words, and thirty-two give four billion. The more words there are, the more cells you need and the more complicated the address decoder gets.\n\nIn real processors memory is synchronous: a write happens on the clock edge. A flip-flop cell accepts data only at the moment of the edge and only when the write signal is on, so there are no races. Physically, a cell of static memory, SRAM, is six transistors: a pair of inverters with two access switches. Dynamic memory, DRAM, is even more compact: one transistor and one capacitor, but the charge leaks away, so the memory has to be refreshed regularly. That's why DRAM is cheaper and bigger, while SRAM is faster.\n\nMemories of different kinds are combined into a hierarchy. The registers inside the processor are the fastest and the smallest. Next comes the cache built from SRAM, then main memory built from DRAM, and finally the disk, which is huge but millions of times slower. The principle is simple: the faster the memory, the smaller and more expensive it is. A program almost always works with a small amount of data at a time, and thanks to the hierarchy it looks as if all the memory were fast. We'll talk about this in more detail in the chapter on the cache.
