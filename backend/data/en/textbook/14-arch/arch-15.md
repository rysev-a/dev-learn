#CHAPTER 15 | Mini-8 assembler
Computer Architecture. Chapter 15. The Mini-8 assembler. A processor understands only numbers: every instruction is a pattern of zeros and ones. Writing programs as such numbers is impossible, so the assembler was invented: a language in which every instruction has a short name, and registers and places in memory have names too. A special program, also called an assembler, translates the text into machine code, while you study how the processor does its calculations. We will get to know assembly on the teaching processor Mini-8, which you can run both as an emulator and as a circuit of a thousand gates.\n\nMini-8 is simply built. The data is bytes, numbers from zero to two hundred fifty-five. There are eight registers, from r-zero to r-seven, and register r-zero is always zero: whatever you write there, it stays zero. The memory is a virtual disk of two hundred fifty-six bytes. Each instruction takes sixteen bits and is divided into fields: four bits of operation code and three fields, A, B, and C, which hold register numbers, a number, or an offset. It all fits in your head, and yet you can write real algorithms with it.\n\nLet's start with data processing. The instruction L-I loads a number into a register: L-I r-one, seventy-two. The instructions ADD, SUB, AND, OR, and XOR take two registers and write the result into a third: ADD r-three, r-one, r-two puts the sum of r-one and r-two into r-three. The instruction ADD-I adds a small number to a register, possibly a negative one. For common cases there are pseudo-instructions: INC increases a register by one, DEC decreases it, and MV copies. The assembler replaces them with real instructions on its own; for example, INC r-one turns into ADD-I r-one, r-one, one.\n\nWorking with memory takes two instructions. The instruction L-B reads a byte from memory into a register, and the instruction S-B writes a byte from a register into memory. The address is computed as the value of a base register plus a small offset: L-B r-one, zero in parentheses r-two reads the byte at the address held in r-two. To replace the first letter of the string "Hello" with a J, you need three actions: put the letter's code in a register, put the string's address in another register, and write the byte with S-B. At the end you must put HALT, otherwise the processor will run on through empty memory.\n\nFor a program to repeat actions and make decisions, we need branches. The instructions B-E-Q, B-N-E, B-L-T-U, and B-G-E-U compare two registers and jump to a label if the condition holds: equal, not equal, less than, or greater-or-equal, unsigned. The instruction JUMP jumps unconditionally. A label is just the name of a line: the assembler works out by itself how many instructions to skip. A classic counting loop is written like this: a label, the loop body, a decrement of the counter, and B-N-E-Z back to the label.\n\nLet's try processing a string. A string in memory is a sequence of bytes ending with a zero byte. We set up a pointer: a register that holds the address of the current letter. We read a letter with L-B and check whether it is zero, and if it is, we leave the loop. Otherwise we process the letter, write it back, advance the pointer with INC, and go around again. To make letters uppercase, it is enough to subtract thirty-two if the code lies between lowercase a and lowercase z.\n\nOur next task is to find the largest element of an array. We remember the first element as the largest, and then walk through the rest: if the current element is greater than the remembered one, we replace it. The comparison is done by B-L-T-U, and the jump skips the replacement when the new value is not greater. For two numbers it's one instruction, but the same technique works for a hundred elements: only the length of the loop changes. This is an example of how a small set of instructions turns into an algorithm.\n\nSorting is the next step. Bubble sort compares neighboring elements and swaps them if they are out of order. A swap needs two registers: we read the left element into one and the right into the other, and then write them back in the opposite order. Around this there are two nested loops: the outer one over passes and the inner one over pairs. The program gets longer, but every part of it is already familiar: reading, writing, comparing, and jumping. That is exactly why it's important to master the simple techniques first.\n\nWhat if a number doesn't fit in a byte? You add in parts: first the low bytes, then the high bytes, taking the carry into account. The carry is detected by comparison: if the sum turned out smaller than either of the addends, there was an overflow. This is how you add two-byte numbers and find the larger of them. The same ideas work for elements of any size: the address is computed as base plus index times size. Sorting such arrays is the hardest task of the chapter.\n\nThree things help you debug a program. The machine code in the listing shows what each line turned into: the operation-code and register fields are colored, and the current instruction is highlighted. The registers and the disk change color when an instruction touches them. And a switch lets you run the same program not in the emulator but on a processor built from gates: every step will be the work of a real circuit, and you can look into any of its blocks. This is a good way to connect a program to the hardware.
