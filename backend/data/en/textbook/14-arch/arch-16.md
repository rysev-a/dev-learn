#CHAPTER 16 | RISC-V
Computer Architecture. Chapter 16. RISC-V. Now let's move from the teaching processor to a real instruction set. RISC-V is the open architecture we talked about in chapter three, and we're going to write real thirty-two-bit programs for it. The processor in our trainer is software, but the instructions are exactly the ones a real chip executes: the base set, RV32I, plus the multiply and divide extension. Next to the processor there is memory and some simple peripherals: a console, LEDs, switches and a timer. The assembler is real too, and the programs look like what you will meet in real projects.\n\nRISC-V has thirty-two registers of thirty-two bits each, from x zero to x thirty-one. Register x zero is always zero, and it's called zero. The others are named after their roles. Registers a zero through a seven carry arguments to functions and bring back the result. Registers t zero through t six are temporaries: a function may change them freely. Registers s zero through s eleven are saved registers: if a function uses them, it must give them back unchanged. Register ra holds the return address, and sp is the top of the stack. These rules are called the ABI, and every compiler follows them.\n\nAll RISC-V instructions take exactly thirty-two bits, and they come in a few formats. The R format is for operations on three registers, with the fields funct seven, rs two, rs one, funct three, rd and the opcode. The I format carries a number: instead of rs two and funct seven it has a twelve-bit immediate value. The S format is for stores to memory, B is for conditional branches, U loads the upper twenty bits, and J is for jumps. The fields rd, rs one and rs two always sit in the same places, which makes the decoder much simpler. In the trainer's listing the fields are highlighted in color so you can see that.\n\nThe arithmetic is familiar. The instructions add and sub add and subtract registers, and, or and xor do bitwise operations, and sll, srl and sra shift left and right, with sra preserving the sign. The variants with a number are called addi, andi, slli and so on. The M extension adds mul, div and rem. You can add a value to a zero, for example, like this: addi a zero, a zero, one. And a shift left by two bits is a multiplication by four, which is often used to compute addresses.\n\nMemory is addressed by bytes. The instructions lw and sw read and write a word of four bytes, lb and sb handle a single byte, and an address is a register plus an offset. Words are stored with the least significant byte first; that's little-endian order. Data is described in sections: in the data section you write the values, and a label marks where they start. The instruction la loads the address of a label into a register, and li loads a number. Once you've prepared the registers with the address and the data, all that's left is to run lw or sw, and the value ends up where you need it.\n\nBranches are done with the instructions beq, bne, blt and bge: compare two registers and jump to a label. For unconditional jumps you use jal, which also saves the address of the next instruction in register ra, and ret, which returns to that address. Pseudo-instructions such as li, mv, j and bnez make the code shorter. A typical loop adds up the numbers from one to a hundred: initialization, a body that adds and increments the counter, a comparison, and a jump back. At the end the register holds five thousand fifty.\n\nPeripherals are connected to the same buses as memory, and to a program they look like ordinary addresses. Writing a byte to the UART address prints a character to the console. Writing a number to the LED address lights the lamps bit by bit. Reading from the switches address returns their state, and reading the timer tells you how many instructions have been executed so far. Such a device needs no special instructions: lw and sw are enough. The program Hello from the UART is just a loop that writes the bytes of a string, one at a time, to the right address.\n\nSubroutines follow the ABI. Arguments are passed in a zero and onward, and the result is returned in a zero. A function that calls other functions, or keeps data in s registers, first makes room on the stack: it subtracts from sp, saves ra and the registers it needs there, and before returning it restores everything and gives sp back. A factorial calls itself: each call puts its own frame on the stack, and after the returns the frames are removed one by one.\n\nAn array of words sits in memory contiguously, with a step of four bytes. The address of the element with index i is the base plus four times i. The multiplication by four is replaced by a shift left by two bits, with the instruction slli. Then we add the base and read the word with lw. You can write, swap and sort in the same way. Swapping two neighboring words takes two reads and two writes. These same tricks are used in programs that turn lowercase letters into capitals right in memory.\n\nFinally, the timer. To make an LED blink visibly, you have to wait: a loop reads the timer, compares it with the moment of the next toggle, and waits until that moment arrives. Then it inverts the LED and sets a new time. This technique is called polling. Real systems use interrupts instead, but the principle is the same. Once you've mastered assembly in the trainer, the next step is real programs that are built with an ordinary compiler and run under Linux.
