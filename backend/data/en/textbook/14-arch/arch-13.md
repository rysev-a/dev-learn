#CHAPTER 13 | Instruction decoder and control
Computer Architecture. Chapter 13. Instruction decoder and control. A processor consists of two parts. The datapath is the registers, the ALU, and the memory: everything that stores and transforms numbers. The control unit is the circuit that, given the current instruction, decides what the datapath should do right now: which register to write, which operation to choose, where to jump. In this chapter we will build the control unit for a small teaching processor. Its main part is the instruction decoder: it turns the operation code into control signals.\n\nOur processor has just four instructions, and each takes four bits: two bits of operation code and two bits of operand. The instruction L-D-I k loads the number k into the accumulator. The instruction ADD k adds k to the accumulator. The instruction J-N-Z k jumps to instruction number k if the accumulator is not zero. The instruction HALT stops the processor. The set is tiny, but you can already write a loop with it: for example, the program L-D-I two, ADD one, J-N-Z one, HALT.\n\nThe first thing the decoder does is form the control word. From the two bits of the operation code it produces four signals. Load means write the result into the accumulator; L-D-I and ADD need it. Add means add to the current value; only ADD needs it. Take means jump; that's J-N-Z. Halt means stop; that's HALT. We get a table of four rows, and each column is a simple function of two variables. A few AND and NOT gates are enough to implement each signal.\n\nA conditional jump depends not only on the instruction code but also on the state of the processor. The J-N-Z instruction jumps only when the accumulator is not zero. The Z flag, which the ALU produces, equals one when the accumulator is zero. The Take signal equals one if the instruction is J-N-Z and Z equals zero. If the accumulator is zero, J-N-Z does nothing, and execution continues. It is exactly this condition that turns a set of instructions into a language in which you can write loops.\n\nNow for the data. What exactly should be written into the accumulator? For L-D-I, simply the operand k. For ADD, the sum of the current accumulator value and k. The only difference is whether to add the accumulator. The Add signal goes to AND gates that either pass the accumulator value to the adder or feed it zeros. The result equals k plus the accumulator times Add. A single adder circuit is enough for both instructions, and one bit from the decoder makes the choice.\n\nA separate question is which instruction comes next. The program counter, the P-C, holds the address of the current instruction. Normally the next address is one greater, and an incrementer provides it. But on a jump, the new address is the operand k. A multiplexer chooses between "address plus one" and "jump address", and the select input is the Take signal. The result is written into the program counter on the clock, and the processor moves on to the next instruction.\n\nAn instruction doesn't execute in a single clock cycle. First it has to be fetched from memory. Then it has to be decoded. Then the action is carried out, for example computing a sum; that's execution. And finally the result is written to the registers; that's writeback. To make the steps follow one another, we build a sequencer: a two-bit counter whose output goes through a decoder. On each clock the counter advances to the next value, and four signals light up in turn: Fetch, Decode, Execute, and Writeback.\n\nThe control signals are not active all the time, only in their own phase. The instruction register is loaded in the fetch phase. The accumulator is written in the writeback phase, and only for the L-D-I and ADD instructions. The program counter is updated in the writeback phase, both for an ordinary step and for a jump. Each such signal is an AND of the phase signal and a condition from the decoder. If the control signals were applied without phases, the registers would be updated on every clock, and the order of events would be lost.\n\nWhat happens on the HALT instruction? The processor has to stop for good, not just for as long as the instruction sits on the bus. For this we build a latch called Run. Reset sets it to one, and the processor runs. The Halt signal clears it to zero, and from then on it stays zero even after Halt is gone. The only way to start the processor again is a new reset. While Run is zero, no register is updated.\n\nLet's put it all together. The full decoder takes the operation code, the zero flag, and the writeback phase, and produces five signals: accumulator load, use-add, take, program counter load, and halt. That is all the control logic of our processor. In the next chapter we will place the fetch block, the decoder, and the execute block side by side, connect them with buses, and get a processor that runs a program by itself. All you will have to do is supply the clock signal and watch the program work.
