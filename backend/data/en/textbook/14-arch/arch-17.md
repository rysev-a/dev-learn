Computer Architecture. Chapter 17. RISC-V in practice. So far we've been running programs in the trainer. Now let's deal with real ones: an assembly file that is built with an ordinary compiler and runs under Linux without any library at all. The entry point is the label start. A program like this has no way to print to the screen at all: the only way to reach the system is a system call. So after this chapter you'll understand what printf really does when you call it in a C program.\n\nA system call is set up with registers. You put the call number in a seven: sixty-four is write, and ninety-three is exit. The first argument goes in a zero, the second in a one, the third in a two. Then you execute the instruction ecall, and control passes to the kernel. Write needs three arguments: the file number, where one means standard output, the address of the buffer, and the length. The kernel prints the given bytes and returns the number of bytes written in a zero. Exit takes one argument: the return code.\n\nThe string to print has to be stored somewhere. That's what the sections of the file are for: text for code, rodata for constants, and data for changeable data. The directive ascii lays characters out one after another, and a label marks where they begin. The instruction la puts the address of a label in a register. If the length of the string is constant, you can simply write it as a number. Now the Hello program is about ten lines: load the parameters, call write, then exit with zero. That's all it takes to print text.\n\nPrinting a number is a slightly more interesting task: a system call can only print bytes, not numbers. The function print uint divides the number by ten and takes the remainder, which is the last digit. The remainder is turned into a character by adding the code of zero, and it goes into the buffer. The digits come out from least significant to most significant, so the buffer is filled from right to left. When the quotient becomes zero, all that's left is to print the filled part of the buffer with a single write call. Division and remainder need the instructions div and rem from the M extension.\n\nPrint uint is the building block for printing everything else. The classic FizzBuzz goes through the numbers from one up to a given limit. For each one it checks the remainder of division by fifteen, by three and by five: if it divides by fifteen, it prints FizzBuzz, by three, Fizz, by five, Buzz, and otherwise it prints the number itself. The program turns out compact: a loop, three comparisons and four lines of data. Branching in assembly is built from the same instructions, beq, bne, and a jump to a label.\n\nFibonacci numbers need two registers: the current number and the previous one. At each step the new number is the sum of the two, and the old ones shift along: the previous becomes the current. Printing the numbers one by one gives us the familiar sequence. This is an example of a program whose whole state fits in two registers, and all the work is a single loop. Programs like this are easy to debug step by step: you can see the register values at every step and check them by hand.\n\nLet's combine our skills: sort an array of words in memory and print the result. The array sits in the data section, and the sort uses the same nested loops as in the teaching Mini-8, only with the instructions lw and sw and a shift to compute the address. After sorting, a loop walks over the array and prints each element through print uint, separated by spaces. We've got a program that uses almost every technique we've learned: data, loops, functions, the stack and system calls.\n\nNot every program prints something. A result can be passed through the exit code: the number that exit is called with. The shell shows it with the command echo, dollar sign, question mark. The exit code is a single byte, so large values are taken modulo two hundred fifty-six. In the exercise, the program counts the vowels in a string and returns their number. This is exactly how programs tell the shell and each other whether everything went well: through the exit code.\n\nAny program like this can be built on your own computer. You need the clang compiler with the LLD linker, and the QEMU emulator, which runs programs built for another architecture. The compiler is given the target RISC-V thirty-two and the extensions, and flags say there's no standard library, and it produces an executable file. The command qemu-riscv32 runs it, and llvm-objdump shows the real machine words. The trainer lets you download a project with a Makefile, and you can check that the result matches.\n\nWe've come the whole way. A transistor is a switch; switches make gates, gates make memory, an adder and registers, those make a processor, and the processor executes RISC-V instructions, which programs run on. What remains is to understand why modern computers are fast: how a cache hides slow memory, how a pipeline executes several instructions at once, how virtual memory and parallelism turn one processor into many. That's what the closing chapters of the course are about.
