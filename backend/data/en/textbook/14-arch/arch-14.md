#CHAPTER 14 | A processor from blocks
Computer Architecture. Chapter 14. A processor from blocks. We have built all the parts: gates, registers, an adder, memory, a decoder. What's left is to assemble them into a processor. In this chapter, every exercise you solved earlier turns into a ready-made block with inputs and outputs. You can place blocks on the board, connect them with buses, and look inside, all the way down to the individual gates. We will work the way real processors are designed: small, verified modules are assembled into bigger ones, and nobody thinks about what's inside them.\n\nSo that blocks don't get connected at random, every port has a type. A port is a named group of wires: for example, a two-bit address, a four-bit instruction word, a set of control signals. A wire can be connected only to a port of the same type: a two-bit word can't be plugged into an address, even if the number of wires is the same. If you really need that, you insert an adapter that simply renames the wires. The principle is simple: a block's interface is a contract, and it is checked before the circuit ever runs.\n\nThe first block is a two-bit register with write enable. It consists of two D flip-flops sharing a clock. On the edge, if the load signal equals one, the register takes the word from its input, and if it equals zero, it keeps the old value. Later, these registers will become the accumulator and the program counter. Once you've built the register, you use it from then on as a ready-made part: you don't recall how a flip-flop works or why there's a multiplexer in there.\n\nIn the second exercise, you connect a ROM with the program and an instruction decoder to the bus. The ROM receives an address and outputs an instruction word. The instruction word is a compound type: it has two fields, the operation code and the operand. A port can be expanded, and a bus run from just the field you need. The operation code goes to the decoder, which outputs a set of control signals. Change the address, and the control signals change along with the instruction: at address zero, load; at address one, add.\n\nThe fetch block combines the program counter, the next-address circuit, and the ROM with the program. The program counter holds the current address. The ROM continuously outputs the instruction at that address. On the clock, if load is enabled, the next address is written into the counter: either the current one plus one, or the jump address from the operand if the take signal arrives. The block's outputs are the instruction itself and the address. The block doesn't know what the instruction is for; it just carefully pulls it out of memory.\n\nThe execute block contains the accumulator, the operand-select circuit, and the flags. If the write signal arrives, then on the clock the accumulator receives either the operand or the sum of the accumulator and the operand, depending on the use-add signal. The block's outputs are the current accumulator value and the zero flag. The flag goes back to the decoder so that it can decide whether to take a jump. The execute block doesn't know what program is running. It simply carries out the signals it is given.\n\nThe phase sequencer is the fourth block. It is a two-bit counter with a decoder that lights one of the phases on each clock: fetch, decode, execute, writeback. The phases are needed by the decoder so that it can issue control signals at the right moment. The sequencer has only one input, the clock, and nothing else. That makes the processor as a whole the simplest possible: the only external signal is the clock, and the program sits in the ROM inside the fetch block.\n\nNow we can assemble the processor. The sequencer feeds the phases to the decoder. The fetch block outputs an instruction, and the operation code and the operand are split off from it. The decoder produces signals for the fetch block, so that it updates the counter, and for the execute block, so that it updates the accumulator. The zero flag from the execute block returns to the decoder. Four blocks and a few buses between them: that's all. The whole circuit turns out simple precisely because each part was debugged separately.\n\nLet's run a program. L-D-I two puts a two into the accumulator. ADD one makes it three. J-N-Z one sees that the accumulator is not zero and returns control to address one. ADD one adds one again, and in a two-bit accumulator the result is zero, because four doesn't fit. Now J-N-Z does nothing, and execution reaches HALT. Each instruction takes four clock cycles, so the program runs for more than twenty cycles. You can look into any block and see the live values on the wires.\n\nOur processor is tiny: four instructions and two-bit numbers. But the principle is exactly the same as in real processors. The next step is to extend it: more registers, more instructions, and wider words. That's how Mini-8 is built, the processor we will write assembly programs for. Further still is RISC-V: thirty-two registers and thirty-two-bit instructions. The idea is the same: fetch an instruction from memory, decode it, execute it, write back the result, and move on to the next one.
