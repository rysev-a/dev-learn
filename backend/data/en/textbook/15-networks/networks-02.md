#CHAPTER 2 | The OSI and TCP/IP Models: Layers and Encapsulation
Computer Networks. Chapter 2. The OSI and TCP/IP models: layers and encapsulation. A network is a very complicated system: wires and radio waves, addresses, routes, reliable delivery, web pages, encryption. If you try to hold all of it in your head at once, nothing works. Engineers did what they do with complex programs: they cut the problem into layers. In this chapter we will see how the layered architecture of a network is organized, why one model has seven layers and the other four or five, and what happens to data as it goes down the stack.\n\nHere is the main idea. Each layer solves one task and uses the services of the layer below it. The top layer does not know whether the data travels over a wire or over radio. The bottom layer does not know what is in the data: a web page or a video. At the same time, layers with the same name on two computers seem to talk to each other directly, using their own protocol, while in fact they pass messages down, and the messages make their way through all the lower layers. The agreement between neighboring layers is called an interface, and the rules of conversation inside one layer are called a protocol.\n\nThe OSI model, the Open Systems Interconnection reference model, divides a network into seven layers. The first, physical, turns bits into signals. The second, data link, carries frames between neighbors. The third, network, finds a path between networks. The fourth, transport, delivers data between programs. The fifth, session, keeps up a dialogue. The sixth, presentation, agrees on the form of the data. The seventh, application, is the network services themselves. OSI is an excellent vocabulary for conversation, but the real internet was built differently.\n\nThe real stack is called TCP/IP. It has four layers: the link layer, which combines the physics and the frames; the network layer with the IP protocol; the transport layer with TCP and UDP; and the application layer, which absorbed the session, presentation, and application layers of OSI. Textbooks often draw five layers, separating the physical layer from the link layer, and we will do the same. The mapping is simple: Ethernet and Wi-Fi are layers one and two, IP is the third, TCP is the fourth, and HTTP, DNS, and mail are the fifth.\n\nNow let's see how data travels. An application hands a message to the transport layer. It cuts the message into segments and adds a header with port numbers. The network layer sticks on its own header with the sender and receiver addresses, and we get a packet. The link layer adds a header with MAC addresses, and often a trailer with a checksum, and we get a frame. The physical layer sends the bits. This process is called encapsulation: at each layer the data is wrapped in a new envelope.\n\nOn the receiving side everything goes in reverse order: decapsulation. The network card checks the frame, strips off the link header, and passes the packet up. IP checks the address and strips its own header. Transport uses the port to decide which program gets the segment. But along the way the frame also passes through intermediate devices. A switch unwraps it only up to the link layer and looks at the MAC address. A router unwraps it up to the network layer: it looks at the IP address and decreases the time to live. They do not read the application data.\n\nAn important detail: at every hop the link header changes, while the network header stays the same. MAC addresses work only within a single hop: from the computer to the router, then from the router to the next one. IP addresses are end to end, from the original sender to the final receiver. That is why a single request carries several addresses at once: a MAC address for the next step, an IP address for the whole road, a port for the program, and the site name that a person typed into the browser's address bar.\n\nHow does the receiver know what is inside the envelope? For this, every header has a field that says what comes next. In an Ethernet frame it is the protocol type: one value means IP, another means ARP. In an IP packet there is a protocol number: six for TCP, seventeen for UDP, one for ICMP. In a TCP segment there is a port number, which sends the data to the right program. That is how the same link serves mail, a browser, and a messenger at the same time, and this is called multiplexing. Thanks to this separation, Ethernet can be replaced with Wi-Fi without touching IP, and a browser hardly cares which version of IP is underneath.\n\nThe layer model is also the main tool for troubleshooting. When something does not work, go from the bottom up. Is the indicator light on, and is the cable plugged in? That is the physical layer. Does the computer see its neighbor? That is the link layer: the port, the MAC address, the switch. Do the addresses and masks match, and is there a route? That is the network layer. Is the server listening on the right port, and is a firewall cutting it off? That is the transport layer. And only then look at the application itself. In the exercises you will walk this path on a network you build.\n\nLet's sum up. The network is split into layers, and each one solves one task and uses the one below. The OSI model is a vocabulary of seven layers, while the real TCP/IP stack has four or five. When sending, data is encapsulated; when receiving, it is unwrapped. A switch works with frames, a router works with packets, and the MAC address changes on every hop, while the IP address does not. Layers are sometimes broken on purpose, with tunnels, firewalls, and NAT, but as a map they are indispensable. Next we will go down to the link layer: Ethernet, MAC addresses, switches, and Wi-Fi.
