#CHAPTER 5 | Routing: Tables, ARP, ICMP, and Traceroute
Chapter 5. Routing: tables, ARP, ICMP, and traceroute. A packet has a destination address, but it doesn't know the way. Each router chooses the way in turn, looking into its own table. In this chapter we will look at how a routing table is built and why the longest prefix wins, how a packet passes through the network step by step, how ARP finds the MAC address of the next hop, why we need the time to live, and how traceroute works with it.\n\nA routing table is a list of rules. Each one has a destination network, that is, a prefix, a next hop, and the interface through which the packet should be sent. Some entries appear on their own: a host knows its own subnets, and they are called connected. Others are entered by the administrator by hand: static routes. Still others are learned from neighbors by routing protocols. If there is no next hop, the destination is in the same network, and all we need is to find its MAC address and send the frame straight to it.\n\nWhat if several entries match? The router picks the most specific one, with the longest prefix. An entry for a slash twenty-four network is more specific than one for a slash sixteen, and that one is more specific than one for a slash eight. The special entry zero dot zero dot zero dot zero slash zero is the default route. Any address matches it, and that is why it is chosen last. It is what sends everything unknown to the provider. Thanks to this rule, you can set one general route and separately override the exceptions.\n\nNow let's follow a single packet. The router receives a frame, checks the checksum, and strips the link-layer header. It looks at the time to live: if one is left, the packet dies. Otherwise it decreases it by one and looks in the table for the longest matching entry. It determines the next hop and the outgoing interface. It finds out the MAC address of the next hop and builds a new frame, with this router as the sender. The IP header stays the same; only the time to live and the checksum change. And so on at every hop.\n\nHow do we find the MAC address of the next hop? That is what ARP, the Address Resolution Protocol, is for. A host sends a broadcast request: who has the address ten dot zero dot zero dot one? Please tell me your MAC. The owner replies, this time to the sender alone. The reply is stored in the ARP cache for a few minutes, so later packets go without requests. The first packet to a new neighbor is always a little slower. You can check the cache with the arp command or ip neigh. ARP is not protected, and on a local network it can be forged; more on that later.\n\nThe time to live, TTL, protects against loops. If, because of a configuration mistake, two routers keep sending a packet to each other, it would travel forever. But every router decreases the time to live, and when it reaches zero, the packet is discarded. The initial value is usually sixty-four or one hundred twenty-eight. The router that discarded the packet tells the sender: time is up. This message is called ICMP time exceeded. That way a routing mistake does not turn into an endless storm.\n\nICMP is a service protocol of the network layer. It lives inside IP packets and reports errors and the state of the network. Echo request and echo reply are ping: a host checks whether an address is alive and how long a packet takes to go there and back. A destination unreachable message says that there is no route, the host is off, or the port is closed. There are other types too, for example redirect. ICMP doesn't deliver user data, but without it the network is blind. So you shouldn't ban it completely on a firewall.\n\nTraceroute uses the time to live as a flashlight. First it sends a packet with the value one: the first router decreases it to zero and sends back an ICMP time exceeded, from which we learn its address. Then it sends one with the value two, three, and so on, until the packet reaches the target. The result is a list of all the hops with their delays. Stars mean no reply came: the router forbids ICMP, or the packet was lost. It is the main tool for seeing where the path breaks.\n\nWhere do the entries of large networks come from? They can't be written by hand, so routers exchange information on their own. Inside an organization, protocols like OSPF are used: each router learns the map of the network and computes the shortest paths. Between providers, BGP works: it passes not a map but the reachability of prefixes and a policy, that is, what we are willing to give to whom. When a link breaks, routers recompute the paths, and the time it takes for the network to settle down is called convergence.\n\nLet's sum up. A router looks in its table for the longest matching entry and sends the packet to the next hop, and it learns the MAC address through ARP. The default route catches everything else. The time to live breaks loops, and ICMP reports errors; ping and traceroute are built on this. Large networks build their tables automatically with the protocols OSPF and BGP. Now we move on to the transport layer: UDP and sockets.
