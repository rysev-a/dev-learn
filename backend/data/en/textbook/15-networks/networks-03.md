#CHAPTER 3 | The Data Link Layer: Ethernet, MAC Addresses, Switches, and Wi-Fi
Chapter 3. The data link layer: Ethernet, MAC addresses, switches, and Wi-Fi. So far we have drawn the network as a graph. Now we go down to the lowest working layer and look at how data crosses a single link, from a computer to its nearest neighbor. We will look at how an Ethernet frame is built, at MAC addresses, at how a switch learns on its own where to forward frames, why we need virtual networks, and why Wi-Fi works so differently from a wire.\n\nThe job of the data link layer is modest: move a frame between two neighbors over one link. To do that, it has to settle a few small questions. Where does a frame begin and end in a stream of bits? Who exactly is it addressed to, if there are several stations on the medium? Was it damaged on the way? And who is allowed to talk right now, if the medium is shared? Everything else, choosing a path, reliability, encryption, is done by other layers. The data link layer knows only its neighbors and knows nothing about the network as a whole.\n\nEthernet has come a long way. In the eighties, computers hung on a single coaxial cable, and each one, before speaking, listened to see whether the cable was free. If two started at the same moment, there was a collision, and both waited a random time. Later the cable was replaced by twisted pair, and a hub, and then a switch, was put in the center. Today every connection is its own wire, communication is full duplex, and there are no collisions. Speeds have grown from a hundred megabits to tens and hundreds of gigabits per second, while the frame format has stayed almost the same.\n\nLet's look at the frame itself. It starts with the destination MAC address, followed by the source MAC address. Next comes the type field, which says, for example, IP or ARP. Then comes the data itself, from forty-six to fifteen hundred bytes. The frame ends with a checksum, which the receiver uses to tell whether the frame was damaged: if the sum doesn't match, the frame is silently thrown away. There is also a preamble in front of the frame, so the receiver has time to synchronize its clock. That is why the minimum frame is sixty-four bytes.\n\nA MAC address is an identifier of a network card, forty-eight bits long, written as six pairs of hexadecimal digits. The first three bytes are assigned to the manufacturer and are called the OUI, so you can tell who made the card. The other three are a serial number within that manufacturer. An address of all ones, F F separated by colons, is the broadcast address, and everyone accepts it. There are also multicast addresses. A MAC address can be changed in software, so you can't trust it like a passport, but for delivery inside one network it is enough.\n\nNow the main device: the switch. It needs no configuration and learns by itself. When a frame arrives on a port, the switch remembers that the sender's MAC address is behind this port. That is how the table gets filled. Then it looks at the destination address. If it is in the table, the frame goes strictly to the right port, and nobody else sees it. If the address isn't there, or the frame is a broadcast, the switch sends copies to all the other ports. This is called flooding. Entries in the table age out if nothing has arrived from an address for a long time.\n\nAll the switch ports that a broadcast frame reaches form a broadcast domain. If you connect switches in a ring, you get a loop: a broadcast frame will go around forever and multiply, and the network will choke. This is called a storm. Loops are prevented by the Spanning Tree Protocol, STP. The switches elect a root, build a tree with no cycles, and block the extra ports, but keep them in reserve: if a working cable breaks, the spare one switches on.\n\nTo avoid buying a separate switch for every department, people invented virtual networks, VLANs. The switch ports are sorted by number: the accounting ports go into one virtual network, the developers' ports into another. Frames from different VLANs never mix, even though the hardware is the same. Between switches you run one cable, a trunk, and every frame on it gets a tag with the VLAN number, according to the standard 802.1Q. It's cheap, convenient, and gives you isolation at layer two.\n\nWi-Fi is the same data link layer, but over radio waves. The medium is shared and half duplex: while one device is talking, the others must stay silent, and it cannot listen while it transmits, because its own signal drowns out everyone else's. So instead of collision detection, Wi-Fi uses collision avoidance: a device waits for a free channel, holds a random pause, and the receiver acknowledges every frame. Clients connect to an access point by network name, and the channels and speed are shared among everyone nearby. Encryption is mandatory here: WPA2 or WPA3.\n\nSo, the data link layer delivers a frame between neighbors over one link. An Ethernet frame contains MAC addresses, a type, data, and a checksum. A switch learns from sender addresses, and floods unknown or broadcast frames to all ports. Loops kill a network, and STP forbids them. A VLAN splits one switch into several independent networks, and a trunk carries them over one cable. Wi-Fi solves the same task on a shared radio medium.
