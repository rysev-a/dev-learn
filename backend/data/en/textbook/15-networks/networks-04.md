#CHAPTER 4 | IP Addressing: IPv4, Masks, CIDR, NAT, and IPv6
Chapter 4. IP addressing: version four, masks, CIDR, NAT, and version six. MAC addresses work inside a single link, but for a packet to find its way through dozens of networks, we need network-layer addresses. We will look at how an address is built and what a mask is, how to split networks into parts, which addresses are reserved, how hosts get their addresses, why NAT was invented, and how version six differs from version four. In the exercises you will hand out addresses yourself, find mistakes, and set up access to the internet.\n\nA version four address consists of thirty-two bits. For people it is written as four decimal numbers from zero to two hundred fifty-five, separated by dots. In total there are a little over four billion such addresses. The address is split into two parts: the network number and the host number within it. The network number is shared by everyone on the same link, and routers use it to choose a path. The host number tells a computer apart from its neighbors. The question of where the boundary between the two parts lies is answered by the subnet mask.\n\nA mask is also thirty-two bits: ones where the network part is, zeros where the host part is. The mask two fifty-five, two fifty-five, two fifty-five, zero means twenty-four ones, and it is written briefly as slash twenty-four. If you apply the mask to an address with a bitwise AND, you get the network address. The first address in a network, with zeros in the host part, denotes the network itself, and the last one, with ones, is the broadcast address. The number of addresses available to hosts is two to the power of the number of zeros, minus two. For slash twenty-four, that is two hundred fifty-four hosts.\n\nNetworks used to be divided into rigid classes: A, B, and C. This quickly led to waste, and in nineteen ninety-three classless addressing appeared, CIDR. The boundary between network and host can lie anywhere. A slash twenty-four network is easy to split into two slash twenty-fives or four slash twenty-sixes, giving each the number of hosts it needs; this is called variable length subnet masking. And the other way around, several neighboring networks can be merged into one entry, so that router tables don't keep growing.\n\nSome addresses are reserved. The private addresses, ten dot zero slash eight, one seventy-two dot sixteen slash twelve, and one ninety-two dot one sixty-eight slash sixteen, are freely used inside organizations and are not routed on the internet. The addresses one twenty-seven dot zero slash eight mean the computer itself, the loopback interface. The addresses one sixty-nine dot two fifty-four are link-local: a host assigns one to itself if it found no settings. Starting at two twenty-four come the multicast addresses. The block one hundred dot sixty-four slash ten is set aside for service providers.\n\nWhere does a host get its address? It can be set by hand, as is done on servers and routers. On clients, DHCP is more common. A new computer broadcasts a request, a server offers an address, the client accepts it, and the server confirms. Along with the address come the mask, the default gateway, the addresses of DNS servers, and the lease time. If two devices get the same address, there is a conflict: ARP replies arrive from both, and communication becomes random. That is why addresses have to be planned.\n\nNow about the gateway. Before sending a packet, a host checks: is the destination address in my subnet? If yes, it looks up the destination's MAC address and sends the frame straight to it. If not, it sends the packet to the gateway's MAC address, while the destination address stays the same. That is why the gateway must lie in the same subnet as the host itself. Typical mistakes: a wrong mask, because of which a host thinks a stranger is its neighbor or the other way around; an address from another subnet; a typo in the gateway. You will find all three in practice.\n\nThere were not enough version four addresses for everyone, and NAT became the lifeline. Inside the network, private addresses are used, and on the way out the router replaces the sender's address with its own public one and remembers the correspondence in a table: internal address and port, external port. The reply arrives at the public address, the router finds the entry and hands it back to the real recipient. One public address serves hundreds of devices. NAT has a price: from outside you cannot simply connect to an internal computer, and for that you set up port forwarding.\n\nVersion six solves the problem radically: its address has one hundred twenty-eight bits, enough for every grain of sand. It is written as eight groups of four hexadecimal digits separated by colons; zeros can be shortened, and one run of zero groups can be replaced with two colons. The usual subnet is slash sixty-four. Hosts configure themselves from the prefix that the router announces. There is no broadcast, no NAT is needed, and every interface has a link-local address starting with F E eighty. Today both versions live in networks side by side: dual stack.\n\nLet's sum up. An IP address is split into a network and a host, and the mask sets the boundary. Classless addressing lets you split and merge networks however you like. Private addresses don't go out to the internet, NAT replaces them with a public one, and port forwarding lets guests in. A host first checks whether the destination is in its subnet, and if not, sends the packet to the gateway. Version six removes the shortage of addresses. Next we will see how routers build their tables and find a path between networks.
