Linux Administration. Chapter 25. libvirt-python: start, stop, snapshots, events, monitoring. The virsh tool from chapter 24 is a thin client over the libvirt API, and the libvirt module for Python is another thin client over the same API. Open a connection with libvirt.open and a URI such as qemu:///system, or use openReadOnly when you only watch. Everything else hangs off the connection object, and every failure arrives as a libvirtError exception. VDSM, the oVirt host agent, is a Python daemon that does exactly this. Always close the connection yourself.\n\nThe connection lists domains with listAllDomains, which returns objects for running and stopped domains alike, and flags narrow the list, for example to active ones only. Find a single domain with lookupByName or lookupByUUIDString, and prefer the UUID, because a name can be changed. A domain object is a handle, not a copy: name, activity, persistence and the XML description are asked from the daemon every time. Unlike the command output we parsed in chapter 21, these calls return ready Python values. Only the XML comes back as text, and ElementTree reads it.\n\nThe info method returns a list of five numbers: state, maximum memory in KiB, current memory in KiB, number of virtual CPUs, and total CPU time in nanoseconds. The state method returns a pair, the state and the reason. States are numbered constants: 0 no state, 1 running, 2 blocked, 3 paused, 4 shutting down, 5 shut off, 6 crashed, 7 suspended by guest power management. Reasons are numbered separately for each state: 1 means a normal boot for a running domain but a user request for a paused one. Log names, not bare numbers.\n\nA persistent domain is made by defineXML and started with create. createXML starts a transient domain that disappears when it stops. There are two ways to stop. shutdown only sends the guest a request and returns at once, and the guest may ignore it. destroy pulls the virtual power cord: the disks may be left inconsistent, and the GRACEFUL flag of destroyFlags sends only SIGTERM. A careful script calls shutdown, polls the state until a deadline, and calls destroy only after the deadline. suspend and resume pause the guest and let it continue.\n\nAny libvirt failure raises libvirtError. Its message is for people; a script branches on the code from get_error_code. Common codes: 42, no such domain; 55, operation invalid, which libvirt usually raises when the call does not fit the state, such as starting a running domain; 9, operation failed; 68, timeout; and 5, cannot connect. Write a table of code to action. Some errors mean the work is already done, some mean retry, some mean reconnect, the rest mean fail loudly. Never compare message text: it changes between versions and languages.\n\nsnapshotCreateXML takes a short XML document with a name and a description; flags choose a disk-only snapshot, freezing the filesystems through the guest agent, or no metadata. Snapshots form a tree: getParent on a root raises error 72, no such snapshot. listAllSnapshots returns objects, and its topological flag puts parents before children. revertToSnapshot goes back and delete removes one. For the qcow2 images of chapter 19, an internal snapshot lives inside the file, and an external one is an overlay file with a backing chain. Support depends on the hypervisor.\n\nCPU load is the difference of two readings. The CPU time from info, like cpu_time from getCPUStats, counts nanoseconds of host CPU time; the second also includes hypervisor work. Divide the growth by the elapsed nanoseconds to get busy cores, and also by the vCPU count for a percentage. memoryStats returns KiB: actual is the balloon size; available and unused come from the guest and need the balloon driver and a nonzero statistics period; rss is what QEMU holds on the host. blockStats gives five numbers per disk, interfaceStats eight per interface; minus one means not supported.\n\nPolling domains one by one costs a round trip per call. getAllDomainStats on the connection asks about all domains at once and returns a list of pairs: the domain object and a flat dictionary. Keys are dotted: state.state, cpu.time, balloon.current, vcpu.current, and arrays come with a counter. block.count says how many disks there are; block.0.name, block.0.rd.bytes and block.0.wr.bytes describe the first; net.count and net.0.rx.bytes work the same way. A group can be missing, as for a stopped domain, so read values with get and a default. Flags keep only active or only running domains.\n\nPolling finds out late; libvirt can tell you itself. Register the event loop before opening the connection: call virEventRegisterDefaultImpl, then run virEventRunDefaultImpl in a loop in a daemon thread. Then call domainEventRegisterAny with the lifecycle event id and a callback receiving the connection, domain, event, detail and opaque value. Events are numbered: 0 defined, 1 undefined, 2 started, 3 suspended, 4 resumed, 5 stopped, 6 shutdown, 7 pm-suspended, 8 crashed; the detail refines them. The callback runs in the loop thread, so only put the event on a queue and return.\n\nConnections break: the libvirt daemon restarts, the network drops. Register a close callback and, when it fires, reconnect with a growing pause, register the events again, and rebuild your picture from listAllDomains, because events during the gap may be lost. To change a configuration, read XMLDesc, edit it with ElementTree, parse the result again to check it, and pass it to defineXML; memory is in KiB unless a unit is given, and vcpu has an optional current attribute. Read with info and stats, act with lifecycle calls, react to events. VDSM runs this loop on every oVirt host.
