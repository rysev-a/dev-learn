Linux Administration. Chapter 21. subprocess and parsing command output. A Python script that controls a host rarely does the work itself: it runs the very utilities we met in earlier chapters, reads their answers, and decides what to do next. VDSM, the oVirt host agent, works this way; it is a Python daemon that runs LVM commands and parses their text. The reliability of such a script rests on two things: how you launch a command and how you read its result. A mistake in either looks like a working script until the first bad day.\n\nThe basic tool is the run function from the subprocess module. Pass the command as a list: the program name first, then one argument per element, and no shell takes part. The capture_output flag collects standard output and standard error, a timeout limits the running time, and the result object carries returncode, stdout, and stderr. With check enabled, a non-zero code becomes an exception. Set the encoding explicitly, for example UTF-8: otherwise Python picks one itself, usually from the locale, and a job started by cron may have a different locale from your terminal.\n\nNever build a command as a string. If a volume name comes from a configuration file or a user and you paste it into a shell string, a semicolon, a space, or a dollar sign in it becomes someone else's command. A list of arguments with the shell off prevents that: each element reaches the program unchanged. One danger remains: a name that starts with a hyphen looks like an option, so validate names against a whitelist, such as the LVM naming rules. Quote with shlex only when a string is unavoidable, like a remote command sent through SSH.\n\nA command can let you down in three ways. First, a non-zero return code: with check enabled it becomes CalledProcessError, which carries the code, the command, and the captured stderr. Second, the program is missing or cannot be started: Python raises FileNotFoundError or PermissionError, while through a shell you get code 127 or 126 instead. Third, a hang: when the timeout expires the child is killed and TimeoutExpired is raised. A negative code minus N means the process died from signal N. These are different situations, and not every one deserves a retry.\n\nThe environment often explains why a script behaves differently in a terminal and in cron. The env argument replaces the environment, so copy the current one and add what you need. Set LC_ALL to C to freeze number and message formats, and set the program search path explicitly, since cron and systemd services usually start with a short one. For long output use Popen and read lines as they appear. Never call wait while the pipe fills up: the child waits for you to read and you wait for it. Use communicate; standard input goes in the input argument.\n\nWhen a tool has a machine-readable format, do not parse its human text. LVS with reportformat json prints an object with a report array; in it are objects keyed by report type, such as lv, holding the table rows. One detail matters: in the plain json mode every value is a string, even sizes and percentages, and an empty field is an empty string. Ask for sizes in bytes with units b and nosuffix; by default they look like 10.00g, sometimes with a less-than sign in front. Hidden volumes appear only with the all option.\n\nFor networking there is ip with the j option. Each interface is an object with a name, a state, and a list of addresses, each with a family, a value, and a prefix length. Routes are also a list of objects: destination, gateway, device, metric. Not every key is always present, so read them with get and a fallback. Block devices come from lsblk with a capital J: a tree where nested devices sit in the children field and mount points in a list. Always choose columns with the o option, or the fields depend on the version.\n\nNot every tool speaks JSON. The df command with the P option prints one line per filesystem with six columns, and the header tells you what the blocks are counted in. The mount point comes last and may contain spaces, so split the line with a limit on the number of splits. Add the k option to be sure about kilobytes. For lvs there are noheadings and separator, which is how VDSM reads it. And systemctl show with the p option gives key equals value pairs: split at the first equals sign, and an empty line separates the units.\n\nCode that runs commands is tested without a host. Do not patch subprocess; pass a run function as a parameter. By default it calls the real command, while a test hands in one that returns a prepared code and text. Then you check the parsing, the exact argument list, and error branches you cannot reproduce on a live machine: a failed disk, a hung call, an empty answer. Retries are tested the same way, with the clock and the sleep passed in, so the test never waits. Retry only transient failures, not an error in your arguments.\n\nLet us sum up. A command is a list of arguments, not a string, and names are validated, not glued in. A return code, an exception, and a timeout are three different failures with different reactions. The environment is explicit. If a tool offers JSON, read JSON, and remember that values may be strings and keys may be missing. For the rest use fixed columns or key-value pairs. Launching is separated from parsing, so it can be tested without a host. Next we move from running commands to handling files safely: permissions, atomic writes, and locks.
