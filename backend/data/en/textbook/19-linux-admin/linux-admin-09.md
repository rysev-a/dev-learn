#CHAPTER 9 | iproute2: addresses, routes, rules, neighbors
Linux Administration. Chapter 9. iproute2: addresses, routes, rules, neighbors. The old commands ifconfig, route and arp have long been replaced by a single command, ip, from the iproute2 package. It talks to the kernel over netlink and manages a handful of objects: links, addresses, routes, rules and neighbors. A change takes effect at once but lives only until the next reboot; permanent configuration is the subject of chapter 14. For reading, the command has convenient output forms: brief, JSON and detailed. This is exactly the kind of text we will parse in the exercises.\n\nLet us start with the interface and its addresses. A link is the interface itself; an address is attached to it separately, and there can be several. An address has a scope: global, link or host. The brief form shows the name, the state and all addresses on one line. UP means the interface is working, DOWN that it is switched off, and LOWERLAYERDOWN that it is on but the layer beneath is not up, for example there is no cable. When you add an address with a prefix length, the kernel creates the route for that subnet by itself.\n\nWe read the routing table from left to right. The first word is the destination: a subnet or the word default. Then via names the gateway, dev the interface, and src the source address the kernel puts into outgoing packets. The proto field says who installed the route: kernel means the kernel itself, static the administrator explicitly, and boot is assumed when you add a route by hand without a protocol; dynamic configuration usually leaves dhcp or ra. Scope link means the target is reachable directly. The metric at the end chooses between competing routes.\n\nHow the kernel chooses a route. The longest prefix wins first: a route for slash 24 beats a route for slash 8, and the default gateway is slash 0, the weakest of all. Among routes with the same prefix, the lower metric wins, so two gateways with different metrics work as a primary and a backup. The gateway normally has to lie in a directly reachable network, otherwise the kernel refuses; the onlink keyword lifts that restriction. Routes of type blackhole, unreachable and prohibit lead nowhere: they forbid traffic or silently discard packets.\n\nThere is no need to guess from the table: ip route get asks the kernel. It prints the route as the kernel sees it: the gateway, the interface and the source address that will be chosen, and sends no packet. You can substitute another source address, an input interface or a mark, and the kernel answers as it would for a real packet. If there is no path, you get an error instead: network is unreachable, no route to host, permission denied, or invalid argument for a blackhole. This is the first check when a service cannot reach an address.\n\nRoutes can live in several sets, called tables. The main table has number 254 and holds the ordinary routes. The local table, 255, is maintained by the kernel itself: it holds the host's own addresses and the broadcast addresses. Which tables are consulted, and in what order, is decided by rules, the command ip rule. There are three by default: priority 0 leads to local, 32766 to main, and 32767 to default, which is normally empty. Rules are scanned in increasing order of their number, and if a table finds nothing, the scan goes on to the next rule.\n\nWhy write your own rules? A server has two providers. The reply to a packet that came in over the second link must leave the same way, but main has a single default gateway. The solution: create a table, put a default route through the second provider's gateway into it, and add a rule, from the address, lookup that table. Table names come from rt_tables in the iproute2 directory under etc. A rule can also match a firewall mark, the input interface or a port. A virtualization host with separate management and storage networks often faces the same situation.\n\nNeighbors are the link-layer cache: the mapping of an IP address to a network card address. For IPv4 it is ARP, for IPv6 neighbor discovery. The command ip neigh shows the entries. REACHABLE means a reply came in recently, within about thirty seconds. Then the entry becomes STALE: usable, but suspicious. The first packet to it moves it to DELAY, after five seconds to PROBE, and after three unanswered probes to FAILED. PERMANENT is set by the administrator and never ages. FAILED almost always means the neighbor is switched off, sits in another network, or stays silent.\n\nWe look at sockets with ss. The keys: t and u select TCP and UDP, l shows only listening sockets, n keeps numbers numeric, and p shows the process; other users' processes are usually visible only to root. The columns are the protocol, the state, the receive and send queues, the local address and port, the remote address and the process. For a listening TCP socket the first queue usually counts connections waiting to be accepted, the second is the queue size. The address 0.0.0.0, brackets with colons and an asterisk mean all interfaces; 127.0.0.1 means the host only.\n\nThree settings remain that break a network quietly. First, forwarding, net.ipv4.ip_forward: off by default, so Linux does not route until you turn it on; the permanent value goes into a file in sysctl.d. Second, rp_filter, the reverse path check: 0 is off, 1 strict, 2 loose, and the larger of the all value and the interface's own value applies. With two providers, strict mode silently drops replies. Third, counters: ip -s link shows errors and dropped packets. The order of search is: link, address, route get, neighbor, socket.
