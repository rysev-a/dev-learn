#CHAPTER 18 | Multipath, iSCSI and FC
Linux Administration. Chapter 18. Multipath, iSCSI and FC. A virtualization host rarely keeps virtual disks on its own drives. They live on a storage array shared by many servers, which hands out block devices called LUNs. The server using a LUN is the initiator, the array side is the target. Every LUN has a worldwide identifier, the WWID, and you recognize a disk by it, not by a name like sdb. The wire is Ethernet with iSCSI or a Fibre Channel fabric. An oVirt block storage domain is a volume group built on such LUNs.\n\niSCSI carries SCSI commands inside TCP, by default on port 3260. Both sides have a name, an IQN: the letters iqn, a year and month, a reversed domain name, and an optional string after a colon. The host's own name sits in a one-line file under /etc/iscsi and must be unique per host, so check cloned images. The target is reached through portals, each an address with a port and a small portal group tag. A login creates a session between the initiator and a portal, managed by the daemon iscsid.\n\nConnecting takes three steps. First, discovery: you ask one portal which targets it offers, using the SendTargets method, and get a list of portal and target name pairs. Discovery only writes records into a database under /var/lib/iscsi; nothing is connected yet. Second, login to a record creates a session, and new disks appear. Third, the record's startup field decides whether the login repeats at boot: the default is manual, and a host that needs its disks wants automatic. If the array demands a password, CHAP is enabled in the iscsid configuration or the record.\n\nTo see what is connected, list the sessions. The short form prints the transport, a session number, the portal with its tag, and the target name. Print level one groups everything by target and shows the state of the connection and of the session; level three also lists the SCSI disks behind each session. A healthy session says LOGGED IN. When the link drops, the kernel does not fail I/O at once: the replacement timeout, 120 seconds by default, is how long it waits for the session to return. Distribution guides usually suggest lowering it with multipath.\n\nFibre Channel is a separate network. The host has an adapter, an HBA; each port has a worldwide name, and the port name, the WWPN, acts as an address, as a MAC address does on Ethernet. Switches form a fabric, and zoning decides which initiator port may see which target port, roughly like a firewall. Masking on the array picks the LUNs it shows. On Linux the ports appear under /sys/class/fc_host. Two timers matter: how long a lost remote port is kept, and how soon I/O starts failing. New LUNs appear after a rescan.\n\nNow the trap. If a LUN is reachable through two adapter ports or two iSCSI portals, the kernel creates two disks, say sdb and sdc, for the same LUN. Using both without coordination is dangerous. The multipath layer fixes this: the daemon multipathd reads each path's WWID, notices that sdb and sdc are one device, and builds a single map over them under /dev/mapper. You use the map, not the paths. By default the map is named after the WWID; with friendly names it becomes mpatha. The package is multipath-tools on Debian and Ubuntu, device-mapper-multipath in the RHEL family.\n\nThe command multipath -ll shows the topology. The first line has the map name, the WWID in parentheses, the device-mapper number and the vendor with the product. The second gives size, features, hardware handler and write protection. Then come path groups, each with a policy, a priority and a status: active carries I/O now, enabled is a standby group, disabled has no usable path. Under a group are the paths: host, channel, target, LUN, disk name, major and minor, and three states. A healthy path reads active ready running; a dead one reads failed faulty offline.\n\nPaths are split into groups by the path grouping policy. Failover puts each path in its own group: one works, the others wait. Multibus puts all paths in one group and spreads the load. Group by priority collects paths of equal priority, which suits ALUA arrays: paths to the controller owning the LUN get 50, the other controller's paths get 10. Inside a group the selector chooses: round-robin cycles, queue-length picks the fewest requests in flight, service-time the fewest outstanding bytes, which is the default. Failback decides what happens when a better group recovers: stay put, or return immediately.\n\nWhat happens when every path of a map is down? The parameter no_path_retry decides. The value fail, the default, fails I/O at once. A number queues requests for that many polling intervals, five seconds each by default, and then returns errors. The value queue waits forever, and processes may hang in uninterruptible sleep, so it is dangerous. The older queue_if_no_path means the same thing. The logs tell the story: the kernel reports a failing path, multipathd reports the failed check and the remaining paths, then disabled queueing, and finally the reinstated path.\n\nThe settings live in multipath.conf, whose sections are defaults, blacklist with exceptions, devices, overrides and multipaths. The more specific the section, the higher its priority: multipaths beats overrides, overrides beat devices, devices beat defaults. The host's system disk goes onto the blacklist by device name or WWID so multipath leaves it alone. Friendly names come from a bindings file, and an alias in the multipaths section outranks it. The parameter find_multipaths chooses which devices become maps. In oVirt, VDSM usually manages this file, so put your own settings into separate files under conf.d.
