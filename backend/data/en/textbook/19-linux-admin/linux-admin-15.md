#CHAPTER 15 | Block devices and filesystems
Linux Administration. Chapter 15. Block devices and filesystems. Storage begins here, and the first question is what the system sees when you attach a disk. To the kernel it is a block device with a name. An ordinary disk is sda, the next one sdb, and partitions get numbers: sda1. Virtual machines have disks called vda, NVMe drives are nvme0n1, and a partition gets the letter p: nvme0n1p1. A logical volume appears as dm-0. Remember the main point: these names are handed out in order of detection, and after a reboot they may change.\n\nThe main tool for looking around is lsblk. It draws a tree: a disk, its partitions, and the volumes under them. The columns show the name, major and minor numbers, a removable flag, the size, a read-only flag, the type, and the mount points. The type says what you are looking at: a disk, a partition, a logical volume, or a loop device. The f option adds the filesystem type, label, UUID, and free space, J gives JSON for scripts, and b shows exact bytes. For reliable facts about a filesystem, ask blkid, which reads the device's metadata.\n\nEvery disk is divided by a partition table. The old MBR scheme keeps addresses in 32 bits, so with a 512-byte sector the limit is two tebibytes per disk, and there are only four entries. One of them can be made an extended partition holding logical partitions. The modern GPT scheme addresses 64 bits, holds 128 entries by default, and keeps a second copy of its header at the end of the disk. The first sector retains a protective MBR record so that old utilities do not take the disk for empty and overwrite it. For new disks, choose GPT.\n\nPartitioning is done with parted, fdisk, and sfdisk. The print command of parted shows the model, sector size, table type, and partitions, while sfdisk can dump a layout to text and apply it to another disk. The start of the first partition is usually aligned to one mebibyte, sector 2048, so that it lies on the block boundaries of an SSD or an array; the align-check command verifies this. And remember: a partition table creates no filesystem. A new partition is empty, and the kernel must be told that the table changed.\n\nThe mkfs command creates a filesystem. On Debian and Ubuntu the usual default is ext4, in the Red Hat family it is XFS. Both are journaling and dependable. A label and an identifier can be set at creation or changed later: tune2fs for ext4 and xfs_admin for XFS, and the XFS one must be unmounted for that. On ext4 the number of inodes is fixed at creation, and five percent of the blocks are reserved for root by default. On XFS, inodes are created as needed, up to a set share of the disk.\n\nResizing is a classic trap. Both systems can grow: first you enlarge the partition or volume, then the filesystem itself. For ext4 that is resize2fs, which also works on a mounted filesystem. For XFS it is xfs_growfs, and it needs a mounted filesystem. Shrinking goes in reverse: first the filesystem, then the partition, otherwise you cut off live data. ext4 is shrunk only unmounted and after a check with e2fsck. XFS cannot be shrunk in ordinary use at all: you must copy the data to a new, smaller filesystem.\n\nHow do you name a disk so that it is found in any order of attachment? The identifiers are stored on the disk itself. The filesystem UUID is created by mkfs, the label is set by a person, and the PARTUUID belongs to a GPT partition. blkid shows them all. Udev places links in the directory dev disk: by-uuid, by-label, by-partuuid, by-id from the serial number, and by-path from the bus path. A dangerous situation is a clone: if a disk image was copied whole, two devices carry one UUID, and mounting by it is no longer unambiguous.\n\nThe fstab file is read at boot. Each line has six fields: what to mount, where, the type, the options, a dump flag, and the check order. For the first field, prefer a UUID or a label to an sdb name. The root gets check order one, the rest two or zero. Under systemd each line becomes a mount unit. If a required volume is missing, the system waits for the device, by default ninety seconds, and drops into emergency mode. Nofail means not critical, and x-systemd.device-timeout shortens the wait. Before rebooting, check with findmnt verify and mount a.\n\nA classic puzzle: the disk is full, yet du shows little. There are three causes. First, a deleted file that a process keeps open: its space is freed only when the process closes the file or exits, and lsof with plus L one finds such files. Second, the reserve for root, five percent on ext4 by default, so available space is less than size minus used. Third, the inodes ran out: df with the i option then shows one hundred percent while blocks remain free. A filesystem with millions of small files hits the inodes first.\n\nLet us put it all in order. See the disk in lsblk, partition it with GPT, create a filesystem, record it in fstab by UUID, check it with findmnt, mount it, and then keep watching df, inodes included. For a virtualization host this is the foundation: machine images live on filesystems and volumes, and a mistake in fstab drops the host into emergency mode. In oVirt a block storage domain is a volume group on top of a multipath device, and a file domain is a shared directory over NFS. We will cover logical volumes in the next chapter.
