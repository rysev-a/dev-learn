Modern Frontend. Chapter 14. HTML: images, media and tables. The text of a page arrives together with the markup, while pictures, video and sound come as separate files, and the browser requests each of them over the network again. That is why media is the heaviest part of any page and the most common place where it breaks: the layout jumps, extra stuff gets loaded, something does not work for some people. Let us start with the main image tag, img. It has two required attributes: src with the address of the file and alt with a text replacement. Without an address there is no picture, and without alt the page is incomplete.\n\nWhat should you write in alt? The text you would say over the phone if the other person could not see the picture. Not the word picture and not the file name, but the meaning: chart, revenue doubled over the year. If an image only decorates the page, leave alt empty, but do not remove the attribute: an empty string tells a screen reader to skip the picture, while with no attribute it reads the file name aloud. If the picture works as a link or a button, alt describes the action: open the cart. A complex chart is described in the text nearby, and in alt we give a short title.\n\nNow about the jumping. Until the file arrives, the browser does not know how tall the picture will be, and leaves zero space for it. When the file loads, all the content below shifts down: the reader misses the button, and the layout shift metric, C L S, grows. The cure is simple: put width and height attributes on the tag with the real size of the file in pixels. The browser computes the proportions from them and reserves the space in advance. For flexible layouts, add a max width of one hundred percent and height auto in the styles, and where there are no dimensions, set the aspect ratio property.\n\nOne and the same file does not suit every screen. A phone needs four hundred pixels, a laptop needs a thousand, and a screen with double density needs twice as much. The srcset attribute lists the options: the address of a file and its real width, for example eight hundred w. The sizes attribute tells how wide the picture will be in the layout: on a narrow screen the whole window, on a wide one a third. The browser knows the window size, the pixel density and the network speed, so it picks the suitable file itself. You describe the options, and it decides.\n\nWhen you need not just a different size but a different format or a different crop, the picture tag comes on stage. Inside it there are several source tags, and the browser takes the first suitable one. The condition may be a format: first AVIF, then WebP, which weigh half as much as JPEG. Or the screen: for a narrow window its own shot, cropped around the face, and for a wide one a panorama. The last one is an ordinary img: it is required, serves as the fallback, and carries the alt and the dimensions. All the selection logic lives in the sources, but it is still img that shows the picture.\n\nNot everything needs to be loaded at once. The loading attribute with the value lazy postpones loading until the picture is near the screen: frames at the end of a long feed spend neither traffic nor time. But for the first big picture on the page, laziness is harmful: it should arrive as early as possible, so we give it fetch priority with the value high. The decoding attribute with the value async allows the image to be decoded without blocking the rest of the page. The rule is this: what is visible immediately we load eagerly, and everything below the first screen, lazily.\n\nA picture is rarely fine on its own: it needs a caption. There is a pair of tags for that. Figure is a self-contained block: an illustration, a diagram or a listing that can be moved out of the text without changing the meaning of the article. Inside lies the content itself, and the figcaption tag gives a caption that the reader sees and that a screen reader links to the block. A caption does not replace alt: alt describes what is shown, while the caption says why it is here. A gallery is convenient to build as a list of figures, and a captioned quote or piece of code with the same technique.\n\nVideo and sound are embedded with the video and audio tags. The controls attribute turns on the native control panel, which is already accessible from the keyboard. Several nested sources provide different formats, and the text inside the tag will be seen by those whose browser does not support media. A video has a poster, a picture shown before playback. Subtitles are attached with the track tag, with a language and the kind subtitles, and a transcript of the audio should always be provided. Autoplay is annoying and wastes traffic, so browsers allow it only for silent video: autoplay, muted and playsinline. Never turn on sound from the start.\n\nThe iframe tag embeds someone else's page inside yours: a map, a video player, a payment form. This is convenient and dangerous, because foreign code runs inside the window. So we form three habits. First: the title attribute with a clear name, otherwise a screen reader will just announce frame. Second: the sandbox attribute, which by default forbids scripts, forms and navigation; we add permissions one at a time, and only the needed ones. Third: loading lazy, so that a frame below the screen does not slow the page down. And each time ask yourself whether a plain link would be enough.\n\nVector graphics can be attached in two ways. Through img, the file behaves like an ordinary picture: it is cached and easy to attach, but the page styles do not reach into it. SVG placed directly in the markup becomes part of the document: its shapes can change color, be animated and listen to events, and the fill can inherit from the text through the keyword current color. Icons are usually inserted the second way, logos and large illustrations the first. Do not forget the role img and a title element, and hide purely decorative icons with aria hidden.\n\nA table is for data that has rows and columns: a schedule, a price list, results. It is not suitable for laying out a page in columns: that was done in the nineties, and today there are flex and grid for that. Here is how it is built. The table tag is the container, the caption is the name, it comes first and is read like a heading. T head holds the header, t body the data rows, t foot the totals. Inside lie the rows, t r, and in them the cells: t d for values and t h for headings. Dividing into sections gives hooks for styles and lets the browser repeat the header when printing.\n\nA header cell means nothing by itself: you have to explain what it relates to. The scope attribute with the value col says that the cell names a column, and row says it names a row. Then a screen reader, landing on a number, reads it together with both headers: Moscow, January, minus six. If the header has two levels, cells are merged: colspan stretches one across several columns, rowspan across several rows. For complex layouts there is the headers attribute with a list of identifiers. The simpler the table, the more accessible it is: avoid empty cells and nested tables, and wrap a wide one in a block with scrolling.\n\nSome widgets the browser provides ready-made. The details tag with a nested summary is an expandable block: the heading is always visible, and the content shows on a click or a key press. No scripts and no aria attributes are needed, and a shared name on several details turns them into an accordion. The dialog tag opens with the show modal method: the browser itself dims the background, keeps focus inside and closes the window on Escape. Before release, go through the checklist: every picture has alt and dimensions, below the screen is lazy, captions and subtitles are in place, frames have a title, and tables have a header and scope.
