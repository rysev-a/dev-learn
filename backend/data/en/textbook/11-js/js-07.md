#CHAPTER 7 | Objects, Arrays and Collections
Modern Frontend. Chapter 7. Objects, Arrays and Collections. Data in JavaScript is built from objects and arrays, and their text notation, JSON, has become the common language of web services. That is why everything we do from here on depends on this chapter: a server reply will arrive as JSON, turn into an object, and we will keep the state of the interface in arrays and dictionaries. We will go through objects and how to copy them, destructuring, array methods, sorting, the Map and Set collections, JSON, and finally the habit of updating data without changing the original, which modern libraries rely on.\n\nAn object is a set of key and value pairs. A literal is written in curly braces; you can reach a field with a dot or with square brackets and an arbitrary string, and a computed key in square brackets lets you build names on the fly while creating the object. If a variable name matches the key, it is enough to write it once. Functions in fields are written as methods, without the function keyword. The delete operator removes a field, while the in operator and the hasOwn method check whether one exists. The Object keys, values and entries methods return arrays of keys, values and pairs, and Object fromEntries builds an object back from pairs.\n\nOrdinary assignment of an object copies only a reference, so a real copy takes extra effort. The spread operator with three dots creates a shallow copy: top-level fields are copied, but nested objects stay shared with the original. The Object assign method does the same thing. For a deep copy there is the built-in structuredClone function: it copies nested objects, dates, maps, sets and even circular references, but it cannot copy functions. If you need an object that cannot be changed, you freeze it with Object freeze; freezing is also shallow, and in strict mode writing to a frozen object throws an error.\n\nDestructuring takes a value apart in a single line. For an object, you list the fields you need in curly braces, rename them with a colon if you like, and give default values with an equals sign. For an array, you list positions in square brackets and skip the unneeded ones with commas. The rest operator with three dots collects everything that remains into a new object or array. You can unpack nested structures and function parameters, and swapping two variables is written without a temporary variable: in square brackets, b and a are assigned from square brackets a and b. If a value is missing, the default is used, but for null you will have to add a check.\n\nAn array is an ordered collection of elements, and technically it is an object with numeric keys and a special length field. The elements can be of any types, and the size changes on the fly. The push and pop methods work with the end, while shift and unshift work with the start, but they are slower because they move everything else. The at method accepts negative indexes: at minus one returns the last element. Slice returns a copy of a part, while splice removes and inserts in place, changing the original array. If you assign an element far past the end, holes appear in the array. To check that a value is an array, use Array isArray, because typeof returns object.\n\nThe modern style does not use indexes but applies methods that take a callback. The forEach method simply calls a function for each element. Map transforms, filter selects, find returns the first matching element, and findIndex returns its position. Some and every answer the questions "is there at least one" and "do all of them match". Includes checks for a value, and indexOf returns a position. Flat flattens nested arrays to a given depth, and flatMap combines transformation and flattening. All of them except forEach return a result, so they are easy to join into chains: the data passes step by step through a series of small steps.\n\nSorting changes the original array and by default compares elements as strings, so numbers must be sorted with a compare function. The function returns a negative number, zero or a positive number, and the order of equal elements is preserved: the sort is stable. Recent versions added methods that do not change the original: toSorted, toReversed, toSpliced and with. For strings with Russian letters, use localeCompare, which takes the alphabet into account. The reduce method folds an array into a number, a string or an object: sums, counts and groupings are written with it. For grouping there is also a ready-made Object groupBy, which takes a key callback.\n\nStrings and arrays easily turn into each other. Split cuts a string by a separator into an array, and join glues it back. Array from builds an array from any iterable object or an object with a length: from a string, a set, a map, or the result of querySelectorAll, and as its second argument it takes a transform function. This is how you create an array of a given length: Array from with a length object and an index function. The Array constructor with a number creates empty holes, not zeros, and this is confusing. The spread operator also unpacks any iterable object, and the Array of method creates an array from the listed arguments.\n\nA Map is a dictionary whose key can be any value: a number, an object, a function. Unlike an ordinary object, it has no inherited fields such as constructor, the key order equals the insertion order, and the size is returned by the size property. The set, get, has and delete methods work in constant time, and you can iterate with for of, getting pairs. A Map is more reliable than an object when the keys are not known in advance or are not strings: counters, caches, indexes by identifier. To turn a map into an array, use Array from or the spread operator, and to go back, use the constructor with an array of pairs. A WeakMap holds keys weakly, without getting in the way of the garbage collector.\n\nA Set is a collection of unique values. Adding a repeated element changes nothing, and checking for presence takes constant time, so a unique list is obtained like this: the Set constructor applied to an array, and then the spread operator back. Equality in a set follows the SameValueZero rule, so NaN appears in it only once, while two objects with identical content are told apart, because they are different references. Intersection and difference of sets are obtained by filtering with a has check, and newer versions of the engine have the intersection, union and difference methods for them. A WeakSet holds objects weakly and is used for marks that do not create memory leaks.\n\nJSON is a text format for exchanging data, and the JSON object does two things with it. The stringify method turns a value into a string, and parse reads the string back and throws a SyntaxError on invalid text. The format is stricter than JavaScript literals: keys only in double quotes, no comments and no trailing commas. During serialization, functions, undefined and symbols are skipped, NaN and infinity turn into null, and a date becomes a string in the ISO format. A circular reference causes an error. As its second and third arguments, stringify takes a filter and an indent for pretty output, and a toJSON method in a class defines its own representation.\n\nModern libraries require updating data without changing the original. Instead of changing a field of an object, you create a copy with the new value: an object with spread, an array with map or filter. Adding to the end of an array is the spread operator with a new element, removal is filter, and replacement is map. Nested updates copy every level along the chain. Why is it done this way? Comparing references is cheap, and the interface understands from a changed reference that the data has changed. Besides, the original object stays unchanged, which makes debugging and rollback easier. For deep structures, helper libraries are used, but for small ones spreads are enough.\n\nLet us sum up. An object is a set of pairs, and keys and values are obtained through Object keys, values and entries. A copy via spread is shallow, and a deep one is structuredClone. Destructuring takes objects and arrays apart, and rest collects the remainder. Arrays are processed with map, filter and reduce, and sorting is always written with a compare function. Map and Set are more reliable than objects for dictionaries and sets. JSON carries data as text, and updates in the modern style create new copies instead of changing the originals. In the next chapter we will move on to classes, prototypes and iterators.
