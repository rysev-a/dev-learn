#CHAPTER 5 | Operators, Type Coercion and Comparison
Modern Frontend. Chapter 5. Operators, Type Coercion and Comparison. This is the chapter where JavaScript surprises you the most. In Python, adding a string to a number is not allowed and you get an error; in C, such an addition turns into pointer arithmetic. Here you simply get a result, quietly, and always by strict rules. Once you learn those rules, the behavior stops looking random. We will go through arithmetic, explicit and implicit coercion, the two kinds of equality, comparison, bitwise operations and assignment operators, and at the end we will put together a short list of habits that saves you from most mistakes.\n\nArithmetic is familiar: plus, minus, multiply, divide, remainder, and exponentiation with a double asterisk. But division is always fractional: seven divided by two is three and a half, and to get the whole part you use math functions. Math dot floor rounds down, trunc drops the fraction, and round goes to the nearest integer. The remainder takes the sign of the dividend, as in C, so minus seven modulo three gives minus one, not two as in Python. Dividing by zero does not crash the program, it gives Infinity, and zero divided by zero gives NaN. The double plus and double minus operators increase and decrease a variable by one.\n\nThe plus operator is the trickiest one. If at least one operand is a string, it concatenates; otherwise it adds. So the string five plus the number one gives the string fifty-one, while minus, multiplication and division always work with numbers: the string five minus one equals four. This leads to a well-known trap: in a form, an input field always hands you a string, so you cannot add the values of two fields without converting them first. The unary plus in front of a value turns it into a number: plus the string forty-two equals the number forty-two. If one of the values is an array or an object, it is first turned into a string, and that is why an empty array plus an empty object gives a string, not a number.\n\nExplicit coercion is better than implicit. The Number function turns a value into a number: a string of digits becomes a number, an empty string or a string of spaces becomes zero, and a word becomes NaN. Null becomes zero, while undefined becomes NaN, and this difference often comes as a surprise. The String function gives text, and Boolean gives true or false by the rules from the previous chapter. For parsing strings from user input there are parseInt and parseFloat: they read a number from the start of the string and stop at the first unsuitable character, so a string like twelve pixels, with the digits at the beginning, gives twelve. Always pass the radix, the base of the number system, as the second argument to parseInt.\n\nImplicit coercion happens when an operator expects one type but receives another. For objects, the engine calls methods: first valueOf if it needs a number, or toString if it needs a string. An array in a string turns into its elements separated by commas, and a plain object turns into the text object Object. Your own classes can override both methods and behave like a number or like text. There is a subtlety with dates too: a date prefers a string when you add and a number when you subtract. The modern way to control coercion is the Symbol dot toPrimitive method, but in practice people more often write an explicit method and do not rely on hidden conversions, because they make code harder to read.\n\nEquality comes in two kinds. Strict equality, with three equals signs, compares without coercion: different types are never equal. Loose equality, with two signs, tries to bring the operands to a common type, and there are many rules: zero equals an empty string, zero equals false, null equals undefined, but does not equal zero. Because of this, loose equality is not transitive: zero equals an empty string and also equals the string zero, but the empty string does not equal the string zero. The project rule is simple: use strict comparison everywhere. The only reasonable exception is checking for null and undefined at once by comparing with null using two equals signs, and even that not every team accepts.\n\nComparison by magnitude, the greater-than and less-than signs, follows different rules. If both operands are strings, they are compared character by character by their codes, so the string ten is less than the string nine, because one is less than nine. If at least one operand is a number, the other is converted to a number, and then ten is greater than nine. Any comparison with NaN gives false, so both NaN less than one and NaN greater than one are false. A chain like zero less than x less than ten does not check a range: the first pair is evaluated first, producing a boolean, and that boolean is then compared with ten. You need to write two comparisons joined with a logical and. When sorting numbers, always pass a comparison function, otherwise the array is sorted as strings.\n\nEquality through Object dot is and the SameValueZero algorithm. The strict equality operator considers NaN unequal to itself and does not tell plus zero from minus zero. The Object dot is method does the opposite: it considers NaN equal to NaN and tells the two zeros apart. Searching an array with the includes method, as well as keys in a Map and elements in a Set, use an in-between variant: NaN is found in them, and the zeros are not distinguished. The indexOf method works by strict equality, and so it will not find NaN. These details rarely matter, but when you write tests or generic data structures, they decide which values count as the same, and it is worth keeping them in mind.\n\nLogical operators return operands, not booleans. The double ampersand returns the first falsy operand or the last one, the double bar returns the first truthy one, and the double question mark returns the first one that is not null and not undefined. Assignments are built on them: or-equals assigns if the value is falsy, and-equals assigns if it is truthy, and the double question mark with equals assigns only if there is null or undefined. The last form is especially useful for default values, because it does not overwrite zero or an empty string. The ternary operator picks one of two expressions and is handy in templates. Evaluation is lazy: the right side runs only when needed.\n\nBitwise operators are familiar from C, but with an important feature: they work with thirty-two signed bits, not sixty-four. Before the operation, the number drops its fractional part and wraps around modulo two to the thirty-second power. So x or zero is a quick but crude way to drop the fraction, and it breaks large numbers. The right shift with three greater-than signs fills with zeros and gives an unsigned result. Masks and flags are written just as in C: one shifted left, the and operator, the or operator, the exclusive or operator. For numbers wider than thirty-two bits, use BigInt, whose bitwise operators work without that limit.\n\nSome useful number methods. The toFixed method rounds a number to a given count of digits and returns a string, not a number. The round function rounds halves toward plus infinity: minus two and a half becomes minus two, while plus two and a half becomes three, and this differs from rounding in Python. To compare fractional values, use a tolerance, for example the Epsilon constant. Money is safer to store in whole cents. For formatting by the rules of a language there is the built-in Intl object with a formatter for numbers and dates: it knows thousands separators and currencies for different locales and beats hand-made constructions with strings.\n\nA few more operators. The typeof operator returns the name of a type, and instanceof checks whether an object was created by a given constructor or its descendant. The in operator checks for the presence of a property, including inherited ones, so toString in an empty object gives true; for own fields there is the Object dot hasOwn method. The delete operator removes a property, and void always gives undefined. The comma evaluates several expressions and returns the last, but it is rarely used. The operator precedence table is big, and instead of memorizing it, it is easier to add parentheses: clarity matters more than brevity, especially when you mix the double bar and the double question mark, which are not allowed together without parentheses.\n\nLet us sum up. Plus adds numbers or concatenates strings; the other arithmetic operators work with numbers. Convert values explicitly: Number, String, Boolean. Compare only with strict equality, and comparison by magnitude looks at types: two strings are compared by codes, everything else by numbers. Comparison chains do not work, and sort with a comparison function. The double question mark with equals sets default values, and bitwise operators work with thirty-two bits. In the next chapter we will deal with functions: how they are declared, what scope is, and why closures underlie all of JavaScript.
