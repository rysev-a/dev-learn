#CHAPTER 4 | The First Program: Browser, Node and Values
Modern Frontend. Chapter 4. The First Program: browser, Node and values. JavaScript is the only language that runs in every browser without installing anything. Everything interactive you see on a page, from a dropdown menu to a chat, is brought to life by it. After Python, C and Rust it will seem both familiar and strange: types are dynamic, as in Python, but numbers work differently; the syntax looks like C, but the memory is not yours to manage. This is the fourth chapter: we have already covered the history of the language and its tools, and now we get to know the language itself, for now without the browser. Ahead of us are the browser, Node, bundlers and, at the end, our own mini-framework. But we start with the essentials: where this program runs and what kinds of values it has.\n\nJavaScript does not work on its own, but inside an engine. In Chrome and in Node this is V8: it reads the text, parses it into a tree, turns it into bytecode, and often compiles frequently executed functions straight into the processor's machine code. This compilation at run time is called JIT. The same language lives in two environments. The browser gives you the page, its tree of elements, the network and user events. Node, that is, the server and the command line, gives you files, processes and packages. The language itself is standardized under the name ECMAScript, and new features appear every year: arrow functions, classes, promises and much more.\n\nThe first program looks like this: a call to console log with some text. In the browser its output goes to the console tab in the developer tools, in Node straight to the terminal. You run a file with the command node and the file name, and you open a page with a script tag. A semicolon at the end of a statement is optional: the engine inserts it itself by the rules of automatic semicolon insertion, but those rules are tricky, so in this book semicolons are always written. Comments are two slashes or a pair of slash-star markers. A string in backticks, a template string, substitutes values right inside the text through a dollar sign and curly braces.\n\nVariables are declared with the keywords let and const. Let creates a variable that can be assigned a new value, and const creates a binding that cannot be reassigned. An important subtlety: const does not make an object immutable, it only forbids replacing the whole value, and the fields of the object can still be changed. The old word var comes from early versions: it is visible in the whole function, not just in a block, and it gets hoisted to the top, which causes strange bugs, so it is not used. Names are written in camel case, and constants in upper case. The rule of practice is this: write const by default, and take let only when the value really changes.\n\nThere are seven primitive types: number, string, boolean, null, undefined, bigint and symbol. The type of an expression is returned by the typeof operator. There are some well-known oddities here: typeof of null is the string object, a historical mistake, and an array also gives object. Undefined means the value is not set, for example for a variable with no initial value or for a missing field. Null is set deliberately when there is no value. Everything else, from arrays to functions, is an object. Unlike Rust and C, there are no type declarations here: the type belongs to the value, not to the variable, and the same variable can hold a number first and then a string.\n\nThere is always just one kind of number in JavaScript: a double-precision floating-point number, the IEEE seven fifty-four standard, the same sixty-four bits as a double in C. There is no separate integer type. That is why zero point one plus zero point two is not equal to zero point three, and integers are exact only up to two to the power of fifty-three: beyond that limit neighboring numbers start to merge. The limit is given by the constant Max Safe Integer. There are special values: NaN, not a number, which is not equal even to itself, and Infinity. For exact large integers there is BigInt: a number with the letter n at the end, with no limit on digits. You cannot mix BigInt and ordinary numbers in one expression.\n\nStrings in JavaScript are immutable and stored in the UTF-16 encoding: each character takes one or two sixteen-bit units. That is why the length of a string with an emoji can surprise you: one visible character gives a length of two. To walk over real characters, use a for-of loop rather than indexes. String methods return new strings: slice cuts out a part, split cuts by a separator, includes checks for a substring, trim removes whitespace at the edges. You can join strings with a plus, but a template is more convenient. Strings are compared by code units, and the order of letters in different languages may not match what people expect.\n\nConditions work not only with boolean values: any value is turned into true or false when checked. Six values count as falsy: false, zero, the empty string, null, undefined and NaN; everything else is truthy, including an empty array and the string with a zero. The operators double ampersand and double bar return not a boolean but one of the operands, and idioms like a default value are based on that. The double question mark operator picks the right operand only for null and undefined, not for zero and the empty string. A chain with a question mark and a dot walks safely through nested fields. There are also the familiar if, switch and the ternary operator.\n\nLoops are familiar: for with three parts, while, do-while, break and continue. To walk over collections, for-of is more convenient, producing the values of an array, the characters of a string, the elements of a set. Do not confuse it with for-in: that one goes over property names, as strings, and for arrays it is almost always a mistake. Labels let you break out of nested loops. There is no Python-style range, so a range is built by hand or with an array method. Note that looping with an index is needed much less often than in C, because there are methods that take a function and walk over the elements themselves. We will talk about that in the chapter on arrays.\n\nNow about memory. Primitives are copied by value: assign a number to another variable and the two are independent. Objects, arrays and functions live in the heap, and the variable holds a reference, so assignment copies only the reference, like a pointer in C: a change made through one variable is visible through the other. You do not need to free memory by hand: the garbage collector periodically finds objects that cannot be reached from the roots and takes them away. This algorithm is called mark and sweep. Leaks are still possible if you keep a reference to something you no longer need, for example in a global array or a forgotten handler. Unlike Rust, there is no ownership here: the collector is in charge of order, and you do not know exactly when it will run.\n\nWhat happens on an error? Using a variable that does not exist gives a reference error, calling something that is not a function or reading a field of undefined gives a type error, and a number going outside the allowed range gives a range error. You will see the familiar message cannot read properties of undefined thousands of times: it means the chain of accesses stumbled on an empty value. Exceptions are caught with a try and catch block and thrown with the throw operator. An unhandled exception stops the program in Node and is printed to the browser console, but the page keeps working. Types in JavaScript are not checked in advance, and many errors surface only at run time.\n\nDebugging tools are built into the browser. Console log prints values, console table shows an array of objects as a table, console error prints errors in red, and the debugger statement stops execution at that spot. The Sources tab lets you set breakpoints and step through lines, and the Network tab shows every request. In Node the inspect flag works, and the debugger connects to the same browser tools. Get used to checking values and types at every step instead of guessing: in a dynamic language, attention takes the place of the compiler, and types come later, with TypeScript.\n\nLet's sum up. JavaScript is run by the V8 engine in the browser and in Node, and console log is your first tool. Declare const by default and let when the value changes; forget about var. There are seven primitives, there is one number type and it is floating-point, big integers are BigInt, and strings are immutable and laid out in UTF-16. A value becomes true or false in a check by strict rules, and objects are passed by reference and cleaned up by the garbage collector. Errors surface while the program runs, and the console helps you see them. In the next chapter we will deal with operators, type coercion and comparison, where JavaScript has the most surprises.
