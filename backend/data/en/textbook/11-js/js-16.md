#CHAPTER 16 | CSS: selectors, states and specificity
Modern Frontend. Chapter 16. CSS: selectors, states and specificity. We are starting the part about how a page looks. Markup says what kind of content this is, and Cascading Style Sheets say how it looks. The language is declarative: you do not write steps, you describe the result you want, and the browser decides how to get it. The unit of the language is the rule. It consists of a selector, which answers the question which elements, and a block of declarations, which answer the question what to do with them. Each declaration is a pair of a property and a value.\n\nStyles are attached in three ways. The main one is the link element in the head of the document, pointing to a separate file: the browser caches it, and one file serves all the pages of the site. The second is the style element right in the document, handy for small pages and for the most important styles of the first screen. The third is the style attribute on the element itself: it is good for temporary experiments and for values computed by a script. Remember that a stylesheet blocks rendering: the browser will not show the page until it has loaded and parsed the styles, otherwise you would see a flash of unstyled text.\n\nThe syntax is simple: a selector, curly braces, and inside them the declarations: a property, a colon, a value and a semicolon. Spaces and line breaks mean nothing, and comments are written between a slash with an asterisk and an asterisk with a slash. The main feature of the language is that the browser forgives mistakes. If a declaration is broken, say a typo in the property name or an invalid value, the browser drops only that declaration, and the other declarations of the rule keep working. A broken selector is worse: the whole rule disappears. Errors are silent, so if there is no effect, open the developer tools and look at what exactly was dropped.\n\nThe simplest selector is by the name of the element type: it picks all paragraphs or all links. A class selector starts with a dot and picks the elements with that class; an element may have several classes, and this is the main working tool. An ID selector starts with a hash sign and picks the single element with that id. The asterisk is the universal selector, and it matches any element. To give one style to different elements, you list them separated by commas: this is just a short form of several rules. And if you glue simple selectors together without spaces, you get the condition both at once: for example, a paragraph with such and such a class.\n\nSelectors are joined by combinators, and they describe the position of elements in the tree. A space means a descendant: an element at any depth inside another. The greater-than sign picks only a direct child. The plus picks the sibling that comes right after the element under the same parent, and the tilde picks all following siblings. For example, a heading plus a paragraph picks only the paragraph standing right under the heading. The more precisely you describe the relationship, the less chance you hit something extra, but the more tightly the rule is tied to the structure. Long chains are fragile: change the markup a little, and the styles fall off.\n\nAttribute selectors pick elements by properties in the markup itself. A name alone in square brackets matches everything that has the attribute set. With an equals sign, the value must match entirely. The caret means the value starts with a substring, the dollar sign means it ends with it, the asterisk means it contains it anywhere, and the tilde looks for a whole word in a space-separated list, as in the class attribute. This is how you pick external links by the beginning of the address, files by extension, and fields by type. If you do not need to distinguish case, add the Latin letter i before the closing bracket.\n\nPseudo-classes are conditions that start with a colon. The structural ones look at the position of an element among its siblings. First child and last child pick the extreme ones. The nth-child pseudo-class accepts the words even and odd or a formula: two n plus one gives every second element, starting from the first. There are variants by tag type: last of type counts only siblings with the same name. The empty pseudo-class matches elements with no children and no text, and root is the HTML element itself, where variables are usually declared. This is how you get a striped table without a single extra class.\n\nFunctional pseudo-classes take other selectors in parentheses. Not excludes what matched: for example, buttons except the disabled ones. Is lets you write a long list briefly: a heading, a paragraph and a list inside an article or a sidebar, without repeating the common part. Where does the same thing, but its specificity is always zero, so such rules are easy to override. The newest and most powerful is has: it picks an element by what lies inside it, which is why it is called the parent selector. For example, a card that contains an image, or a label that contains a checked checkbox. Before this, it could not be done without scripts.\n\nStates created by the user are also described by pseudo-classes. Hover turns on when the cursor is over the element; but a phone has no cursor, so hover must not be the only way to reveal something. Focus-visible turns on when the element has focus and the browser considers an outline appropriate: when navigating with the Tab key, but not with a mouse click. Focus-within fires on a parent when focus is inside it. Checked, disabled, required and invalid describe the state of form fields. The main accessibility rule: never remove the focus outline without replacing it with something at least as noticeable.\n\nPseudo-elements are written with two colons and refer not to elements of the markup but to their parts or to virtual insertions. Before and after create content ahead of the element's text and after it; without the content property they will not appear, and this text is not in the markup, so you cannot store meaning in it, only decorations: arrows, icons, underlines. Marker styles the bullet of a list item, placeholder styles the hint inside an empty field, selection styles the text selected with the mouse, and first-line styles the first line of a paragraph. All of them pick a part of what is already on the page.\n\nWhen several rules apply to one element, the most specific one wins. Specificity is three numbers. The first counts ids, the second counts classes, attributes and pseudo-classes, and the third counts type names and pseudo-elements. They are compared left to right: one id outweighs any number of classes. The universal selector and combinators weigh zero, for not, is and has the heaviest argument counts, and where is always zero. Above all stands the style attribute, and above it the exclamation mark, important. If the specificity is equal, the rule written lower wins, so the order in the file matters too.\n\nGood selectors are flat and light. Rely on classes: one class, one role, rather than a position in the tree. Avoid ids in styles and the exclamation mark, important: they inflate specificity, and afterwards they can be overridden only by a heavier rule, which starts an arms race. Conventions help. The BEM methodology names a block, an element after two underscores, and a modifier after two hyphens: for example, a card, a card title, and a highlighted card. Then every rule weighs exactly one class, and a dispute between rules is settled by the order in the file, not by a clever selector.\n\nLet us sum up. The selector picks elements, the declaration changes them, and the cascade settles disputes. Check yourself against the list. Are the styles linked in the head of the page. Do you select by classes rather than by tag names and ids. Are there no long chains of descendants. Is there no important. Do interactive elements have a noticeable focus state, not only a hover state. Do pseudo-elements hold no meaning. If a style did not apply, open the developer tools: the styles tab shows all the rules of the element, the struck-out ones were dropped, and it tells you where the winning one came from.
