#CHAPTER 18 | CSS: the Box Model, Styling and Positioning
Modern Frontend. Chapter 18. CSS: the box model, styling and positioning. To the browser, any page is a set of rectangles: even a round button and a single word inside a line each get their own rectangular box. How a box takes its place among its neighbors is decided by the display property. A block box takes the full width and pushes its neighbors onto a new line. An inline box lives inside a line, and you cannot set its width or height. An inline-block can do both: it sits in the line but listens to sizes. And the value none removes the element from the layout entirely, as if it had never existed.\n\nInside a box there are four layers, like an onion. In the center is the content. Around it is the inner spacing, padding, which is painted with the element's background. Next comes the border. And on the outside is the outer spacing, margin: it is transparent and pushes the neighbors away. By default, a given width applies only to the content, so a hundred pixels with padding and a border grow to a hundred and forty-four. To avoid counting in your head, you set the box-sizing property to border-box: then the width includes both the padding and the border. This rule is usually applied to all elements at once, at the very start of the styles.\n\nOuter margins have a non-obvious quirk: the vertical margins of adjacent blocks collapse. If a paragraph has twenty pixels below it and the next one has thirty above, the gap between them will be thirty, not fifty: the larger one wins. The same happens with a parent and its first child, if there is no border or padding between them: the child's margin spills out and shifts the parent. Horizontal margins never collapse. The effect is easy to avoid: give the parent a border or padding, make it a flex or grid container, or set margins in one direction only, say only downward.\n\nSizes can be rigid or flexible. Width and height set them exactly, while minimum and maximum values set bounds: a maximum width of forty rems keeps a line readable on a big screen, and a minimum height keeps a block from collapsing. The aspect-ratio property keeps proportions, for example sixteen to nine, and needs no tricks with padding. If the content does not fit, overflow takes control: visible lets it spill out, hidden clips it, and scroll and auto add scrollbars. It is better not to set a rigid height without need: the text itself knows how much room it requires.\n\nA border is defined by a width, a style and a color, and without a style it will not appear at all. The border-radius property rounds the corners: fifty percent on a square gives a circle. Box-shadow draws a shadow: an offset horizontally and vertically, a blur and a color, and the word inset makes it an inner one. A shadow takes no room and does not move its neighbors. Separately there is the outline: it also takes no part in the layout, and it is exactly what the browser draws around a focused element. You must not remove it without a replacement: a person using a keyboard needs to see where they are.\n\nA background is a color plus several images stacked in layers: the color lies at the bottom, the images on top. An image can be a file or a gradient, linear, radial or conic. A gradient is also an image, and you control its size the same way. The value cover of the background-size property fills the whole area with cropping, while contain fits the whole image inside. Background-position picks the anchor point, background-repeat decides whether to tile the pattern, and for a single image you turn repetition off. If an image carries meaning rather than decoration, its place is in the markup, with a description, not in the background.\n\nText is styled with a font family: you list a stack from your favorite to a fallback and finish with a generic family, for example sans-serif. It is better to set the size in rems, so that it respects the user's settings. Weight runs from one hundred to nine hundred. Line height, set as a number around one and a half, makes a paragraph readable. Letter-spacing spreads the letters apart, text-align aligns the lines, text-transform changes the case, and text-decoration draws an underline. To end a long line with an ellipsis, you need a combination of three properties: no wrapping, hidden overflow, and text-overflow ellipsis.\n\nA list is made of ordinary elements whose display value is special: list-item. This is what produces the marker. The list-style-type property picks its look: a disc, a circle, a square, decimal numbers, Roman numerals or nothing. When a list is turned into a menu, the markers are removed, and so is the left padding that the browser adds by itself. The marker pseudo-element lets you recolor the marker or change its size without touching the item's text. List-style-position decides whether the marker sits outside the block or inside. And the meaning of the list remains: a screen reader will still announce that this is a list.\n\nPositioning answers the question of where a box ends up. By default, static applies: the element stays where the flow puts it, and top, right, bottom and left do not work. Relative shifts the box from its normal place, but its place in the flow stays occupied. The main use of relative is different: it turns the element into a reference point. Absolute takes the box out of the flow and places it by coordinates measured from the nearest ancestor whose position is not static, called the containing block. That is how a badge ends up in the corner of a card: the card gets relative, the badge gets absolute and offsets.\n\nFixed attaches a box to the browser window: when you scroll, it stays in place, like a back-to-top button or a floating chat. It also frees its place in the flow, so the rest of the content has to be moved aside in advance. Sticky is a hybrid of relative and fixed. While the block fits, it behaves like an ordinary one, but once it reaches the given offset from the window edge, it sticks and travels with the page, though not beyond its parent. This is how sticky table headers and section titles are made. Sticking breaks if an ancestor has an overflow other than visible.\n\nWhen boxes overlap, the order of layers is decided by z-index. A higher number lies on top, and without it, whoever comes later in the markup wins. The property works only on positioned elements, as well as on children of flex and grid. The subtlety is stacking contexts: a parent with a position and a z-index, with opacity below one, or with a transform creates a closed world, and its descendants are compared with each other inside it. That is why a thousand on a nested element may not help. It is better to keep a small scale of layers than to chase ever bigger numbers.\n\nCentering boxes is done in different ways. A block with a limited width is centered with automatic outer margins on the left and right. Text and inline elements are aligned by text-align. Content on both axes is easiest to center with grid or flex. The old technique with floats was invented to let text wrap around a picture, and was then used for ten years to make columns. A floated box drops out of its parent's height, and the parent collapses, which is why the clearfix trick was used: an empty pseudo-element with a clear. Today, wrapping text around a picture is the only honest job a float has.\n\nLet us sum up the chapter with a short check. Box-sizing border-box is set on all elements. Sizes are flexible: a maximum width and proportions instead of rigid numbers. Vertical margins go in one direction, with collapsing taken into account. The focus outline is not removed, but replaced. Font stacks end with a generic family, and line height is set as a number. For a badge in the corner of a card there are relative and absolute, and for pinned elements sticky or fixed is enough. Layers are a small scale of z-indexes, and a stacking context is created on purpose. Float stays for wrapping, and for layout there are flex and grid, which we cover in the next chapter.
