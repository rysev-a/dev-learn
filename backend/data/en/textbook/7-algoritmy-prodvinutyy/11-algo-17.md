Graphs and Strategies. Chapter 17. Disjoint Sets and Backtracking. This chapter covers two tools that at first glance seem unrelated. The first is the disjoint-set structure: it remembers which elements have been merged into one group, and answers the question "are these two in the same group" almost instantly. The second is backtracking: a way to walk through all the options honestly, but cleverly, cutting off the branches that are clearly hopeless. The first builds components and spanning trees; the second places queens and solves sudoku. At the end, twenty exercises are waiting for you. What unites the two is one thing: in both cases the main job is not to do extra work.\n\nLet's begin with the dynamic connectivity problem. There are elements, and two kinds of queries arrive: merge the groups of two elements, and check whether two elements are in the same group. A graph that gains edges one at a time, a network of computers, friends of friends in a social network, pixels of the same color: all of these are this problem. Running a graph traversal after every new edge is too expensive: it takes linear time per query. Storing a group number for every element and repainting on every merge is linear too. The disjoint-set structure answers both questions in almost constant time, and all it needs is a single array.\n\nIt is built as a forest. Every element has a parent, and the parent of a root is the root itself. The root represents the group. To find the group of an element, we climb the parents up to the root; two elements are in the same group if their roots are the same. To merge two groups, we find their roots and hang one root under the other. All of this fits in ten lines. But the naive version has a problem: the tree can stretch into a chain, and then finding the root takes linear time. Two simple ideas cure it: path compression, and union by size or by rank, and each of them already helps on its own.\n\nThe first idea is path compression. Once we have climbed to the root, we re-hang everyone we passed straight onto the root, so the next search for them takes a single step. It is written as a one-line recursion: the parent becomes the result of the search on the parent. Without compression, a chain of n elements is walked n times over; with compression, the first search is expensive, but it also straightens the tree. Amortized, this gives about a logarithm per operation even on its own. In practice the recursion is replaced by a loop, so you don't hit the call depth limit: first find the root, then walk the path a second time and rewrite the parents.\n\nThe second idea is to merge sensibly. If we always hang the smaller tree under the larger one, the height grows only when the trees are equal, and it never exceeds the logarithm of the number of elements. The root stores the size of the group, or the rank, which is an estimate of the height. On a union we compare sizes and hang the smaller one. Together with path compression, these tricks give an amortized time of the order of the inverse Ackermann function per operation. This function grows so slowly that for any conceivable number of elements it is no more than four. In practice it is a constant, and the disjoint-set structure behaves almost like an ordinary array.\n\nThere are many applications. Counting connected components: each edge merges two vertices, and the counter goes down with every successful merge. Finding a cycle in an undirected graph: an edge whose ends are already in the same group closes a cycle. Kruskal's algorithm builds a minimum spanning tree by adding edges in increasing order of weight, if they connect different groups. The islands problem merges neighboring land cells. Problems with equalities and inequalities put variables into groups by the equals relations, and then check the not-equals ones. Whenever things only merge and are never split apart, think of this structure.\n\nThe structure is easy to enrich. The root can hold any information about the group: its size, the sum of values, the minimum, the number of edges. On a merge they are simply combined. There is also a version with weights on the edges to the parent: it stores the distance to the root, and can answer how much one element is greater than another, or check the parity of a distance. This solves bipartiteness checks and problems of the kind "a is three more than b, b is five more than c: is the data contradictory". The structure cannot undo merges by itself, but a rollback can be built if you give up path compression and keep a stack of changes.\n\nNow for the second half. Brute force is an attempt to honestly walk through all the options. The solution is assembled step by step: at each step there are several ways to continue, and all the options form a tree. For subsets, each step is a choice between two options, take the element or not, and there are two to the power of n leaves. For permutations, there are fewer and fewer options at each step, and there are n factorial leaves. Such a tree is huge already at twenty elements. So brute force is not a method for large inputs, but a universal way to get a correct answer when nothing better exists, and a basis for checking fast solutions.\n\nThe recursive template is called backtracking. The function receives the current partial answer. If it is already complete, the function records it. Otherwise it goes over the options for the next step: it chooses an option by adding it to the answer, recurses deeper, and then undoes the choice, restoring the state as it was. The undo is the heart of the technique: the shared list is changed in place, not copied at every step. Three words, choose, explore, undo, describe the whole template. A beginner's mistake is to forget the undo, or to store the mutable list itself in the results instead of a copy of it.\n\nThe strength of brute force is in pruning. If a partial answer already shows that no complete answer will come out of it, the branch is cut off immediately. In the queens problem on an n by n board, we place a queen in each row, and if the new queen attacks the previous ones, we go no further; three sets, the occupied columns and the two diagonals, check this in constant time. In sudoku, you pick the cell with the fewest candidates. In the sum problem, branches are dropped as soon as the sum exceeds the target. Successful pruning turns an astronomical number of options into millions, although the worst case stays the same.\n\nThe classic problems for this template are subsets, permutations and combinations. Subsets: at each element we decide whether to take it, and there are two to the power of n leaves. Permutations: at each step we choose any element not yet used, marking the used ones. Combinations of k: we take elements in increasing order of their indices, never going back. If the input has duplicates, to avoid getting identical results, we sort the input and skip an element equal to the previous one, if the previous one was not taken on this level. The output comes out in lexicographic order if the options are tried in increasing order.\n\nSum problems show how pruning helps. We need to reach a target using numbers from a list, possibly with repeats. We sort the numbers and pass into the recursion the remainder of the target and a starting index: if a number is greater than the remainder, all the following ones are too, so the loop can be cut off. For small inputs, up to twenty elements, it is convenient to enumerate subsets with masks: a number from zero to two to the power of n minus one defines a subset, and the sum can be computed in one pass. For forty elements, meet in the middle is used: enumerate the two halves and join the answers, which gives two to the power of n over two instead of two to the power of n.\n\nLet's sum up. The disjoint-set structure is an array of parents, root search with path compression, and union by size; together they give almost constant time per operation, and you should use them when groups only merge. Backtracking is the template of choose, explore, undo, which works on subsets, permutations and combinations; branches are cut off as soon as they become hopeless. In the exercises you will write a disjoint-set structure, count islands and components, build Kruskal's algorithm, and solve problems about queens, sudoku and combination sums.
