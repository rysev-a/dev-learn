#CHAPTER 5 | Aggregate functions
Databases. Chapter 5. Aggregate functions. So far a query has returned as many rows as it found. But often what you need is a summary: how many orders, what the total revenue is, which product is the most expensive. That is what aggregate functions are for: they take many rows and collapse them into a single value. There are five main ones: count counts rows, sum adds up, average takes the mean, and min and max find the smallest and the largest. A query with an aggregate and no grouping always returns exactly one row, even if the source table is huge.\n\nThe most common aggregate function is count. The asterisk in the parentheses means count whole rows, regardless of what is in the columns. The query count star from orders returns the number of orders. If you add a condition, only the matching rows are counted: how many orders are paid, how many customers are from Moscow. The where clause runs before the aggregate, so the filter first cuts out what you do not need, and only then does the counting happen. The result is always a number, and for an empty table it is zero, not a gap.\n\nThe sum function adds up the values of a numeric column: the total of all orders, the number of items sold. Average computes the arithmetic mean: the sum divided by the number of values. The mean is usually fractional, and for a tidy report you round it with the round function, giving the number of decimal places. You can also sum expressions: the sum of price times quantity gives you revenue per order line. Remember that summing a text column makes no sense, and in SQLite the strings will be turned into numbers, usually zeros.\n\nMin and max return the smallest and the largest value of a column. They work not only with numbers: the smallest date is the earliest order, and the greatest string alphabetically is the last name in the dictionary. These functions pick the value itself, but not the whole row. If you need to know which exact product is the most expensive, one function is not enough: you either have to sort and take the first row, or use a nested query, which we will talk about later. For an empty set the result is null.\n\nThe count function has a variant with a column inside the parentheses. Unlike the asterisk, it counts only the rows where that column is not null. This is how you find out how many customers have an email on file: count of email. And the difference, count star minus count of email, shows the number of gaps. This is an important distinction that often leads to mistakes: two seemingly identical counts give different numbers. So always decide what you want to count, rows or values, and pick the matching form.\n\nAggregate functions ignore empty values. The average of ten, a gap, and thirty is twenty, not thirteen and a third: a gap is not a zero and does not take part in the divisor. Sum simply skips the empty values. But if no rows were found at all, sum returns null, while count returns zero. To get a zero instead of a gap in a report, you wrap the sum in coalesce. This quirk easily breaks reports, so get into the habit of checking what happens on an empty result.\n\nSometimes you need to know not how many rows there are, but how many different values. The word distinct inside count removes duplicates before counting. How many different cities the customers live in, how many different categories the products have, how many customers placed at least one order: all of these are count distinct. Gaps, as always, are not counted. You can apply distinct to sum and average too, but such a calculation is rarely useful. Note that distinct inside an aggregate and distinct after the word select are different things.\n\nThe order of execution matters. First where selects the rows, and only then does the aggregate collapse what is left. That is why the question how many orders were paid in May is written simply: a condition on status and date, and then count. But you cannot put a condition on the aggregate itself in where: the phrase where the sum is greater than a thousand does not work, because at the moment of filtering the sum does not exist yet. For such conditions there is a special mechanism, having, and we will study it in the chapter on grouping.\n\nWhat happens if you select a plain column next to an aggregate: the customer name and the number of orders? The aggregate gives one value for the whole set, while there are many names. The standard forbids such a query. SQLite allows it, but returns one arbitrary name from the set: the result looks plausible, but it is wrong. For min and max there is an exception: the database takes the columns of the same row where the extreme value was found. To get totals for each customer you need grouping, which we will get to very soon.\n\nIn a single query you can compute as many aggregates as you like: the number of orders, the total amount, the average check, the smallest and the largest order. Each aggregate gets an alias, so that the result columns have clear names. All of them work over the same set of rows, selected by the condition. It is best to round the average, and when computing shares, remember integer division: the sum of some rows divided by the sum of all rows will give zero unless you convert one of the numbers to a fraction.\n\nYou can write expressions inside an aggregate. Revenue per order line is the sum of quantity multiplied by price. The share of expensive orders is the sum of an expression that gives one or zero. Compare two ways to compute the average: average over a column, and sum divided by count star. They match as long as there are no gaps, and with gaps they diverge, because the divisor is different. Choose what you need by meaning, and do not swap one for the other mechanically.\n\nThere is an aggregate function for text. Group concat glues the values of a column into a single string with a separator. If you output all customer cities this way, you get one string with a listing. The separator is given as the second argument, and by default it is a comma. The order of values inside the string is not guaranteed in SQLite, although in recent versions you can set it right inside the parentheses. In other databases this function is called string agg or list agg. It is usually used together with grouping, to get, for example, the list of products in each order.\n\nLet us sum up. Aggregate functions collapse a set of rows into one value: count counts, sum adds up, average takes the mean, min and max find the extremes, group concat glues. Remember the five traps: count star and count of a column differ, sum on an empty set gives null, gaps are ignored, integer division drops the fraction, and a plain column next to an aggregate gives a random row. To get totals per group, you need grouping, and we will talk about it in chapter twelve. But first we will learn to join tables.
