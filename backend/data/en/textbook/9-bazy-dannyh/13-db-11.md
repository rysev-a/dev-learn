#CHAPTER 11 | Built-in functions: strings, numbers and dates
Databases. Chapter 11. Built-in functions: strings, numbers and dates. Functions come in two kinds. Aggregate ones, like sum and count, collapse a set of rows into a single value. Scalar ones are computed separately for each row and return a value for that same row: round a price, cut a piece out of a title, shift a date. You can use them anywhere a value is allowed: in the column list, in a condition, in sorting. SQLite has hundreds of built-in functions. We will go through the most useful ones, and you can always look up the rest in the documentation.\n\nThe abs function returns the absolute value of a number: its distance from zero, without the sign. Round rounds to a given number of decimal places, and if you don't give the number of places, it rounds to a whole number. The remainder of a division is given by the percent sign: five percent three equals two. It is handy for checking parity, for cyclic numbering, and for splitting rows into groups. We have already talked about integer division: an integer divided by an integer gives an integer, and to get a fractional result, you make one of the numbers fractional. Modern versions of SQLite also have ceiling, floor and power functions, but they depend on how the build was compiled.\n\nRounding differs from system to system, and it is important to know how. In SQLite, round sends halves away from zero: two and a half gives three, minus two and a half gives minus three. Banker's rounding, which picks the nearest even number, is not used here. Round returns a floating-point number even when there is no fractional part: three point zero. If you need an integer, add a cast. When you calculate money, it is safer to store cents as whole numbers and round only when you display the result, so that errors don't pile up.\n\nFor nicely formatted output there is the printf function, which mirrors the function of the same name in the C language. In the format string, percent, dot, two, f prints a fractional number with two decimal places, percent d prints an integer, and percent s prints a string. Width and alignment are set by a number after the percent sign: percent five d takes five positions, right-aligned. This is how you build labels such as order number seven for a total of one hundred and fifty rubles, without gluing the pieces together by hand. Printf is more convenient than concatenation when you need a well-formatted number.\n\nThe date function returns a date as year, month, day. Time returns the time of day, and datetime returns both. The word now means the current moment in Greenwich time. If you need local time, you add the localtime modifier. You can also get a date from a text value: the function checks the format and returns null if it is wrong. This is useful for validating data. Remember that dates don't have a type of their own: the result of these functions is an ordinary string, so all the text functions and comparisons work on it.\n\nYou can pass modifiers to the date functions, and they shift the value. Plus seven days, minus one month, plus two years. There are also start-of-period modifiers: start of month moves the date to the first day of the month, and start of year moves it to the first of January. You can chain them together. For example, the start of last month: first move to the first day, then subtract one month. With this kind of arithmetic it is easy to get the boundaries of any period and to write a condition like orders from last month without hardcoding any dates.\n\nTo get individual parts of a date, there is the strftime function. In the format string, percent capital Y is the year, percent m is the month, percent d is the day, and percent w is the day of the week. The format year, dash, month turns any date into a month key, which is convenient for grouping: revenue by month. Another useful option gives the week number or the day of the year. The result of strftime is a string, so if you need a number, you add a cast. You will use this function every time you need to build reports by period.\n\nYou can't subtract dates directly, because they are strings. To find a difference, there is the julianday function, which turns a date into a number of days since the start of the Julian calendar. The difference between two such numbers is the number of days between the dates, possibly with a fractional part if the values include a time. This is how you calculate delivery time, the age of an order, or how long ago the last purchase was. For a difference in other units, you divide the result or use strftime. This is one of the most common tricks for working with dates in SQLite, and it is worth remembering.\n\nA typical task is to select records for the last thirty days. The condition says the date is greater than or equal to the current date with the modifier minus thirty days. In the same way you get orders for this year, this month, or yesterday. The condition stays correct on every run, because it is recalculated each time. For reproducible reports and tests, the current date is sometimes passed in as a parameter, so that the result doesn't change from day to day. In our exercises the dates are fixed in the data, so that the answers stay the same.\n\nDates stored as text cause problems. A value like the fifth of May, twenty twenty-four, written with dots, is not recognized by the functions and returns null. Strings without leading zeros compare incorrectly: the tenth will come before the second. Time without a time zone is ambiguous: the server and the client may live in different zones. A sensible practice is to store the moment in ISO format in Greenwich time, and to convert to local time only when displaying it. And validate the data on insert, so that garbage doesn't get into the table.\n\nSQLite functions often return values of a different type than you expect. Strftime returns a string, not a number; round returns a float; division of integers returns an integer. To avoid guessing, look at typeof and convert types explicitly with the cast function. Remember concatenation too: a number automatically becomes text, and comparing a number with a string follows the rules of type affinity. If the result of a query surprises you, start by checking the types: in half of the cases the answer is right there. This matters especially for data that came from files.\n\nFunctions work together. The result of one serves as the argument of another: round of an average, lower case of a trimmed string, strftime of a date with a modifier. Such expressions have to be read from the inside out. If the nesting gets deep, break the expression into steps, for example with a subquery or a common table expression, and give the intermediate values names. Readability matters more than brevity. A well-formatted query with functions is easy to check by eye, but a pile of nested calls on one line is not.\n\nLet's sum up. Scalar functions are computed for each row separately. For numbers these are abs, round and the remainder, and for formatting, printf. Dates in SQLite are ISO-format strings: the date, time and datetime functions with modifiers shift them, strftime cuts out parts, and julianday computes the difference. A wrong format gives null, and types are worth checking with typeof and converting with cast. We have finished the third part of the course.
