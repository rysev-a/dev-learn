#CHAPTER 3 | Pointers and Arrays: Addresses You Already Know How to Read
From Assembler to C. Chapter 3. Pointers and Arrays: Addresses You Already Know How to Read. When you wrote assembly, you worked with addresses all the time: load a word from an address in a register plus an offset, store a byte into memory. C makes the address a first-class value. A pointer is a variable that holds the address of another object, and the pointer's type tells the compiler how to read whatever lives at that address and how far to step. If you know assembly, pointers are no mystery, just a convenient notation for instructions you already know. But there are no safety checks: the compiler trusts you, and every mistake turns into reading someone else's memory.\n\nTwo operators define everything. The ampersand takes the address of an object, and the asterisk dereferences a pointer, that is, reaches the object at that address. The declaration int star p means that p holds the address of an integer. In assembly, taking the address of a local variable is adding an offset to the stack pointer, and dereferencing is a load or store through a register. The special pointer value is NULL, which is zero, and it says there is no object. You must not follow it, and the processor answers with a crash and the message segmentation fault. Before dereferencing a pointer that came from outside, it is always worth checking it.\n\nWhy do we need pointers as parameters? A function receives a copy of its argument, and it has no way to change somebody else's variable. If you pass an address instead, the function writes a value there, and the caller sees the result. That is how you write a swap of two variables, and also functions that must return several values: one through the return value, the rest through pointer parameters. This is what a mutable object does in Python, and a mutable reference does in Rust. The difference is that here there are no checks: nothing stops you from passing a pointer to a variable that is already destroyed, or to NULL.\n\nAn array in C is a run of elements of the same type, lying one after another in memory. Its size is known at compile time, and in an expression its name turns into the address of the first element. Accessing an element by index is just notation for dereferencing a shifted pointer: a, index i, equals asterisk, open parenthesis, a plus i. There are no bounds checks, so writing past the end of an array corrupts neighboring data, and reading gives garbage. The number of elements is computed as the size of the array divided by the size of one element, but only in the place where the array is declared in full. Curly-brace initialization sets the starting values, and any missing ones are filled with zeros.\n\nPointer arithmetic takes the size of the object into account. Adding one to a pointer to int means moving four bytes ahead, and to a pointer to long, eight. The compiler multiplies by the type size for you, whereas in assembly you would write that out explicitly. The difference between two pointers to elements of the same array gives the number of elements between them. You may compare only pointers within one array, including the address one past the last element, which is allowed, but must never be dereferenced. To walk through memory byte by byte, you take a pointer to char or to unsigned char, because its element size is one: such a pointer lets you read any object as a set of bytes.\n\nWhen you pass an array to a function, it decays into a pointer to its first element. Declaring the parameter with brackets or with an asterisk means the same thing, and the length information is lost: the size of the parameter is the size of a pointer, eight bytes, not the size of the array. That is why the length is always passed as a second parameter, usually of type size_t. This is a well-known trap: code that computes the length inside the function using sizeof quietly does the wrong thing. Unlike Python and Rust, there is no object here that stores the length together with the data, and keeping the length and the pointer consistent is the programmer's job.\n\nThe word const in pointer declarations is read from right to left. A pointer to const int forbids changing the data through it, but the pointer itself may move. A const pointer to int forbids changing the pointer itself, but the data is accessible. You can combine both. The habit of writing const for parameters that a function only reads makes your intent visible and lets the compiler catch mistakes: an attempt to write through such a pointer simply will not compile. String literals live in read-only memory, so a pointer to one is declared as a pointer to const char. The restrict qualifier promises that two pointers do not overlap, and allows the compiler to optimize.\n\nA multidimensional array lies in memory row by row: first all the elements of the first row, then of the second. Accessing the element a, bracket i, bracket j, is a shift by i times the number of columns, plus j. The number of columns must be part of the type when such an array is passed to a function. Two-dimensional data is often stored in a single flat array, with the index computed by hand: that makes it easier to allocate memory and to pass parameters. Don't confuse this with an array of pointers to rows, where each row lives separately and may have its own length. A row-by-row walk goes through memory sequentially and is friendly to the cache, while a walk down the columns jumps across whole rows.\n\nA pointer to a pointer turns up more often than you would think. The list of command-line arguments is an array of pointers to strings, that is, char double-star. When a function needs to change the pointer itself, for example to advance it, or to allocate memory and return the address, you pass it the address of the pointer. The same trick works for an array of strings and for linked structures, where you need to rewrite the link to the head of a list. It reads simply: every asterisk in a declaration is one level of indirection, and every dereference removes one level. The main thing is not to lose track of who owns what and what points to what.\n\nThe universal pointer in C is called void star. A pointer of any type converts to it implicitly, and back again, but you cannot dereference it, because the type is unknown. This is how functions like memcpy and qsort are built, knowing nothing about the type of the data. To read the data, you first cast the pointer to the right type. Casting between incompatible types and then reading through the result violates the strict aliasing rule: the compiler is entitled to assume that pointers of different types do not point at the same place. The safe way to reinterpret bytes is to copy them with memcpy, and access through a pointer to char is always allowed. Watch out for alignment too: on some processors, reading from a misaligned address is impossible.\n\nNow let's look at how these mechanisms break. A dangling pointer points to an object that has been destroyed, for example to a local variable of a function that has returned. Dereferencing NULL or an uninitialized pointer, going out of array bounds, reading past the end, writing into a constant area: all of this is undefined behavior. A crash with a segmentation fault is the best outcome: it means virtual memory reported that there is no page at that address, or that access is forbidden. It is worse when the program quietly corrupts neighboring data. That is why you should run your tests with the address sanitizer: it inserts checks around every access and shows you the line and the variable where everything went wrong.\n\nFour functions of the standard library work with blocks of memory regardless of type. Memcpy copies a given number of bytes and requires that the areas do not overlap, while memmove allows overlap and picks the copy direction itself. Memset fills memory with a single byte, and memcmp compares two blocks and returns the sign of the first difference. The size is always given in bytes: the mistake of passing the number of elements instead of bytes is very common. These functions are implemented very efficiently, and on modern processors copying goes by words and vectors, so your own byte-by-byte version is usually slower, but writing one is useful for understanding.\n\nLet's sum up. A pointer is a variable that holds an address: the ampersand takes an address, the asterisk dereferences. An array is elements lying one after another, an index is an offset, and nobody checks the bounds. Pointer arithmetic accounts for the type size, an array in a parameter turns into a pointer, and the length is passed separately. Const protects data, a pointer to a pointer lets you change pointers themselves, and void star makes code generic. Pointer errors lead to undefined behavior, and the sanitizer is your best friend. In the next chapter, we will apply this knowledge to strings and structures.
