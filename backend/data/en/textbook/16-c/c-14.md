#CHAPTER 14 | Modern C: C11 and C23
From Assembler to the C Language. Chapter 14. Modern C: the C11 and C23 standards. C is older than most programmers, yet it keeps evolving: after C89 came C99, C11, C17 and C23. The standards add features that make code safer and shorter, and they stay compatible, so an old program still builds. You choose the edition with the std option: std equals c11, std equals c17, std equals c23. The option gnu11 also allows the compiler extensions we used in this book, for example typeof and statement expressions.\n\nLet's start with the features of 1999 that many people still don't know. Variables are declared where they are needed, including in the loop header. There are one-line comments, the bool type from the stdbool header, integer types of exact size from stdint, long long, inline functions, snprintf and macros with a variable number of arguments. Restrict appeared, along with variable length arrays, which C11 made optional: because of stack overflow, many people avoid them. This is the minimum that any modern code starts from.\n\nCompound literals and designated initializers let you create values right inside an expression. Writing a struct point in braces, with dot x equals one and dot y equals two, builds a temporary structure, and the fields you didn't write are zeroed. For arrays you can name the element index: square bracket three equals five. This is handy for tables with gaps and for passing parameters that have many default values. A compound literal lives until the end of its block, which means you must never return a pointer to it from a function. Empty braces as an initializer, the zero struct, arrived in the C23 standard.\n\nA flexible array member lets you store a variable-size structure in a single block. You declare the last member as an array with no length: char data, empty brackets. Then you allocate memory for the header plus the number of elements you need, and the data sits right after the fields. This is better than the old trick with a one-element array, because the size is honest and you don't have to subtract the extra by hand. Strings with a length, packets and records with a tail are made this way. A structure like that can't be copied fully by assignment: only the header is copied.\n\nThe keyword restrict is a promise to the compiler: nobody else will change this memory through another pointer. It lets the compiler optimize without worrying about aliasing, which is why memcpy is declared with restrict and memmove is not, and overlapping regions gave undefined behavior. You must never break the promise: the compiler won't check it, and the result will simply be wrong. Inline got well-defined semantics in C99: in headers you write static inline, so every file has its own copy of the function, and the compiler is free to decide whether to substitute the body.\n\nC11 added compile-time checks and alignment. Static assert stops the build if a condition is false, for example if the size of a structure isn't what you expect. Selection by type comes from Generic, which we met in the chapter on the preprocessor. Alignas sets the alignment of an object, Alignof reads it, and Noreturn says that a function never returns control. Anonymous structures and unions can be nested inside others without a name, and their fields become fields of the outer structure directly. All of these tools reduce the number of mistakes without costing anything at run time.\n\nThe C11 standard described threads and atomic operations in the language itself for the first time. The atomic int type guarantees that reads and writes happen as a whole, while atomic fetch add and atomic compare exchange perform a read-modify-write indivisibly. On a RISC-V processor they turn into the AMO family of instructions and the pair of LR and SC that you saw in the book on computer architecture. Simultaneous access to an ordinary variable from two threads, if at least one of them writes, is a data race and undefined behavior. The threads header gives a simple portable interface for creating threads.\n\nThe memory model defines in what order one thread sees the actions of another. Atomic operations take an order: relaxed guarantees only indivisibility, acquire and release create "after the write, before the read" pairs, and sequentially consistent is the strictest and the default. The classic example: one thread prepares data, then writes a flag with release; another thread reads the flag with acquire and after that safely sees the data. The compare-and-exchange loop lets you build your own indivisible operations: read the value, compute the new one, try to swap it in, and if that fails, repeat.\n\nUnicode got support at the level of types. The uchar header introduces the characters char sixteen and char thirty-two, and the u8 prefix in front of a literal guarantees UTF-8 encoding. The C23 edition added the char eight type and character literals with the u8 prefix. Still, strings in C remain arrays of bytes, and the length in bytes is not the number of characters, as we discussed in the chapter on data representation. Wide characters, wchar t, depend on the platform and are not suitable for exchanging data.\n\nThe C23 standard removed many rough edges. Nullptr replaced the ambiguous zero and null pointer with a separate type. The words bool, true and false became keywords instead of macros. Constexpr declares named constants usable in expressions. Typeof and a restricted auto deduce the type from the initializer. Binary literals start with zero b, and an apostrophe separates the digits of long numbers. Attributes in double square brackets, nodiscard, maybe unused, deprecated and fallthrough, bring compiler hints into standard syntax. The embed directive inserts a file as an array of bytes.\n\nThe new headers of C23 solve old problems. The stdckdint header gives you ckd add, sub and mul, arithmetic with overflow checking that returns a flag and the result. The stdbit header provides counting of ones, leading and trailing zeros, finding the first one, and rotations. Enumerations can be declared with a given base type, and bit int creates integers of arbitrary width. The functions strdup and strndup entered the standard. The elifdef directive simplifies conditional compilation, and the VA opt macro solves the problem of an empty list of variable arguments.\n\nHow do you use all this in everyday work? Take a standard no older than C11 and turn on Wall, Wextra and Wpedantic. Use stdint types and bool, and keep sizes in size t. Apply designated initializers, const, restrict, static assert and attributes. Avoid variable length arrays, register and unsafe functions like gets. Don't rely on compiler extensions where you need portability, and with C23 check support for each feature: compilers adopt it gradually. Modern C code is the same language, but with compile-time checks and fewer traps.\n\nLet's sum up not the chapter, but the whole book. We started with assembler: registers, instructions, the stack and memory. On that foundation we built the C language: types and operators, functions and pointers, strings and structures, dynamic memory and data structures. Then we added the tools of real work: the preprocessor and modules, input and output, data representation, builds and libraries, sanitizers and the debugger, testing and style. From here the path leads to the book on systems programming in Unix, where C meets the operating system, then to networks and virtualization, and for safe systems code, to the Rust language, which takes the best from C and closes its main traps.
