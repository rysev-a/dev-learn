#CHAPTER 4 | Strings, Structs and Unions: Data in Memory
From Assembler to C. Chapter 4. Strings, Structs and Unions: Data in Memory. C has no string type. A string is an ordinary array of bytes with a zero byte at the end, the end marker. There is no object with a header either: a struct only describes the layout of fields in memory, and a union lets you interpret the same place in different ways. For a programmer who knows assembly, this is the familiar talk of bytes and offsets, only with names instead of numbers. This chapter is about how data is laid out in memory: how strings work and what traps they hold, how the compiler places the fields of a struct, and where it inserts empty bytes.\n\nLet's start with the character. The type char takes one byte and holds a code: for Latin letters and digits that is the ASCII code, and for other text it is the bytes of UTF-8 encoding, where one character takes from one to four bytes. The language knows nothing about encoding: a Russian letter is two elements of the array. A string literal in double quotes is an array of bytes with a terminating zero, and it lives in read-only memory. Escape sequences, for example backslash n, stand for special characters. Remember that a character in single quotes is a number, its code, while a character in double quotes is a string of two bytes: the character itself and a zero.\n\nWorking with strings goes through the functions of the string header. Strlen walks from the beginning to the zero byte and returns the length, so it takes linear time: calling it in a loop condition turns a single pass into a quadratic one. Strcpy copies up to and including the zero, strcat glues one buffer onto another, and strcmp compares by byte codes and returns a negative number, zero, or a positive number. Strncpy looks safe, but it does not write the zero byte if the string didn't fit, and many people have tripped on it. It is more reliable to write through snprintf, which always terminates the string with a zero, and to check its result: it returns the length that would have been needed.\n\nThe main source of vulnerabilities in C programs is buffer overflow. An array of eight bytes holds a string of seven characters, because the eighth byte is taken by the zero. Copying a long string into such an array writes data past its end, over neighboring variables and the return address in the frame. That is how people took control of programs, by changing the address a function would return to: this attack is called stack smashing. The defense is simple: know the size of the buffer and always pass it to the function, use snprintf and fgets instead of dangerous functions, and check the length of the input. An enabled sanitizer catches such errors in tests.\n\nConverting text to numbers and back needs care. The function atoi returns zero both for a zero and for garbage, so you cannot tell one from the other. Strtol takes a pointer into which it stores the place where parsing stopped, and sets an error code on overflow. The correct check goes like this: reset the error, call strtol, make sure that at least one digit was parsed, that there is a zero byte at the end, and that no overflow error occurred. Formatting goes the other way, through snprintf. For reading numbers from a string there is also sscanf, but it handles errors poorly and does not protect against overly long input unless you limit the width.\n\nA struct combines fields of different types under one name. The fields lie in memory in the order of declaration, you access them with a dot, and through a pointer to a struct with an arrow. It is convenient to initialize it with field names: the ones you don't set get zeros. A struct can be assigned and passed by value: the compiler copies all the bytes, and for large structs this passing is expensive, so you usually pass a pointer to const. Structs can contain arrays and other structs, and can refer to themselves through a pointer. That is exactly how linked lists and trees are made, which we will discuss in the next chapter.\n\nCopying and comparing structs works in a non-obvious way. Assigning one struct to another copies all the bytes, including the padding, which is why you can return a struct from a function by value. But you cannot compare structs with the equals operator: the language does not define it, and a byte-by-byte comparison with memcmp is unreliable, because the padding values are arbitrary. You compare field by field, with a function that describes what “equal” means for your type. An array of structs lies in memory contiguously, and each element takes the size of the struct including padding. Accessing a field of an array element is a shift by the element number times the size, plus the field offset, that is, the same address arithmetic.\n\nThe size of a struct is not the sum of the sizes of its fields. The processor needs aligned addresses: a four-byte word must lie at an address divisible by four. The compiler places fields so that each one is aligned, and inserts empty bytes, which are called padding. The struct as a whole is aligned to its strictest field, and padding is added at the end too, so that the next element in an array is aligned. The offset of a field is given by the offsetof macro, and the size by sizeof. The order of fields affects the size: put the large fields first. Unlike Rust, C does not reorder fields by itself, and guarantees the order of declaration.\n\nBit fields let you specify the width of a field in bits: an unsigned integer, a colon, and a number. They are handy for describing compact formats, but the layout of bits inside a word depends on the compiler and on byte order, so for exchanging data with the outside world, manual masks and shifts are more reliable. Flags are often defined with an enumeration whose values are powers of two, combined with or and tested with and. This approach is familiar from system headers: a set of independent switches in one integer, where every bit is a separate decision. It is compact, fast, and goes well with the bitwise operations from the first chapter.\n\nA union places all its fields at one address, and its size equals the largest field. Write one field, and you read the same place as another. In C, reading a different field than the one you wrote is allowed, and it lets you peek at the representation of a number: for example, read the bits of a floating-point number as an integer. But you lose type safety: you need extra information about what exactly is in the union right now. That is how the tagged union appears: a struct made of an enumeration tag and a union with the data. It is a manual counterpart of an enum with data in Rust, and working with it, checking the tag and choosing the right field, is entirely on your conscience.\n\nTypedef gives a type a short name. A typical trick is to declare a struct and immediately make a type out of it, so you don't have to write the word struct every time. For self-referencing structs, the tag name is needed until the type is complete. An opaque type is declared in a header without a definition: the user sees only a pointer, and the fields are hidden in the source file, which is a way to implement encapsulation. Anonymous structs and unions inside other ones let you shorten the notation. A flexible array member at the end of a struct, an array without a size for which memory is allocated together with the struct, implements a header with a variable-length payload.\n\nYou must not write a struct to a file or to the network as is. It contains padding whose values are undefined, and multibyte fields are written in the byte order of your processor, which may differ at the receiver. The right way is to serialize the fields one at a time in a known order, for example the most significant byte first, and to parse them back the same way. Sizes come from fixed-width types. For network data and file formats the big-endian order is the accepted one, while processors are usually built the other way around, so a conversion is needed. This habit will save you hours of debugging when exchanging data between different platforms.\n\nLet's sum up. A string is an array of bytes with a zero at the end; functions work up to the zero, they find the length by walking, and buffer overflow is the main danger. You need to know buffer sizes and pass them along, and safe writing means snprintf. A struct lays out fields in a row with alignment and padding, the order of fields affects the size, and bit fields and masks define flags. A union stores values at one address, and a tagged union is a manual counterpart of an enum. For exchanging data, serialize fields explicitly. In the next chapter, we will learn to allocate memory dynamically and build our first data structures.
