#CHAPTER 2 | Branches, Loops, and Functions: What They Compile Into
From assembler to C. Chapter 2. Branches, loops, and functions: what they compile into. In assembler you had no if, no while, and no functions: you had labels, conditional jumps, and a couple of registers for calls. C gives you the familiar structured constructs, but each of them compiles into exactly what you used to write by hand. So in this chapter we will look at pairs: C code and processor instructions. Once you understand the correspondence, you can always say what a construct costs and why a program behaves the way it does. We will pay special attention to the traps: unsigned counters, side effects, and the order of evaluation.\n\nThe if statement compares values and jumps either to the then branch or to the else branch. The compiler emits a compare-and-branch instruction: if the condition is false, jump over the body. Else-if constructs line up into a chain of checks. Curly braces around the body are formally optional when it is a single statement, but don't write it without them. Real disasters have happened because of that kind of saving: an extra indented line without braces ran every time, and the certificate check in one well-known system was effectively switched off. The rule of always putting braces saves you from such mistakes.\n\nThe switch statement picks a branch by an integer value. If there are many cases and they are dense, the compiler builds a table of addresses and makes one indirect jump, and if they are sparse, it makes a chain of comparisons or a binary search. Every branch starts with case and ends with break. If you forget the break, execution falls through into the next branch: this is called fall-through, and it is sometimes useful, for example to combine cases, but more often it is a bug. The default branch handles everything else. With enumerations the compiler can warn you that you forgot one of the values: turn on the dash W switch flag.\n\nC has three loops: while checks the condition at the start, do-while checks it at the end, and for gathers the initialization, the condition, and the step into one line. For the compiler this is a single pattern: a label at the top, a condition check, the body, the step, and a jump back. A loop variable declared right in the header is visible only inside the loop. The break statement leaves the loop, and continue goes to the next iteration. An infinite loop is written as a for with empty parts or a while with a one. Watch the boundaries: the off-by-one error, when a loop runs one step too far or one too short, remains the most popular bug in every language.\n\nA function in C consists of a result type, a name, a parameter list, and a body. Before a call, the compiler must know the signature, so you declare it ahead of time with a prototype, and the definition can be lower down or in another file. Parameters are passed by value: a copy goes into the function, and changing the copy does not affect the original. For a function to change someone else's variable, you pass it an address, but we will talk about pointers in the next chapter. A function with no parameters is written with void in the parentheses, because empty parentheses in the old syntax mean anything at all. A function can return nothing, and then the result type is void too.\n\nWhat happens on a call? The caller puts the arguments into registers a zero and onward, up to a seven, and with the jump-and-link instruction saves the return address in the ra register. The called function moves sp down and creates a frame, where it keeps the saved registers and local variables, and on exit it restores everything and returns with the ret instruction. The result is passed in register a zero. These agreements are called the calling convention, and they are what lets separately compiled code work together. If a function has more arguments than registers, the rest go onto the stack.\n\nScope says where a name is accessible, and lifetime says when the object itself exists. Local variables are visible in their block and live while the block runs: after you leave it, their place on the stack will be taken by someone else's frame. That is why you must not return the address of a local variable, and the compiler will give a warning. Global variables are visible in the whole file and live for the whole program. The static keyword on a global variable or function limits its visibility to the file, and on a local variable it extends the lifetime. An inner block can shadow an outer name, which makes code hard to read, so this trick is rarely used.\n\nRecursion is a function that calls itself, and each call gets its own frame on the stack. The classic example is the factorial, where each level multiplies the result by the value of its argument. The depth is limited by the size of the stack, usually a few megabytes, and infinite recursion ends in a crash. If the recursive call is the last thing in the function, it is called a tail call, and an optimizing compiler replaces the call with a jump, turning the recursion into a loop. But the standard does not let you rely on this, and with optimization turned off the frames will pile up. If the depth depends on the input data, write a loop.\n\nNow, the order of evaluation. An expression like i plus plus plus plus i, or an assignment to an array element with a side effect in the index, changes a variable twice between sequence points, and the behavior is undefined. The standard does not say in what order function arguments and the operands of most operators are evaluated, so you cannot rely on left to right. The order is guaranteed for the double ampersand, the double vertical bar, the comma, the question mark in the ternary operator, and at the end of a full expression. The rule is simple: write things so that each variable changes at most once in an expression, and don't pile up side effects.\n\nOne of the trickiest traps is an unsigned loop counter. The size type is always unsigned, and a loop that counts down to zero becomes infinite: an unsigned number is never less than zero, and zero minus one gives the maximum value. The ways out: count down to one and access the element at the index one lower, use a condition with a postfix decrement, or use a signed type. Mixing signed and unsigned in a comparison converts the signed value to unsigned, and minus one turns out to be bigger than any size. Turn on the dash W sign compare flag, which warns about such comparisons.\n\nFunctions with a variable number of arguments, like printf, have an ellipsis in the parameter list, and inside they work with the macros from the stdarg header. The va start macro remembers the place after the last named parameter, va arg fetches the next argument of the specified type, and va end finishes the reading. The function does not know how many arguments were passed or of what types: that has to be agreed separately, for example by a format string or by a counter. A mistake in this agreement reads random values from registers and the stack. So for your own functions it is better to write explicit parameters and leave the ellipsis for wrappers around formatting.\n\nModularity in C is achieved by separating declarations from definitions. Functions with the static modifier are visible only in their own file, and this is the main way to hide details. The inline keyword hints to the compiler to substitute the function body in place of the call, avoiding the cost of a frame, but the compiler still decides for itself. Short helper functions are worth making static and inline. Declarations meant for other files go into header files with protection against repeated inclusion. The fewer external names, the easier it is to understand the program, and the easier it is for the compiler to optimize: it knows all the places the function is called from.\n\nLet's sum up. Conditions, loops, and function calls are labels, jumps, and frames, and you can picture the assembler for any line. A switch with breaks, always curly braces, parameters by value, the result returned in register a zero. Local objects die with their frame, recursion is limited by the stack, and tail recursion depends on optimization. Be careful with side effects in expressions, with unsigned counters, and with functions with a variable number of arguments. In the next chapter we will tackle the most important mechanism of the language: pointers and arrays.
