#CHAPTER 6 | Function Pointers and Generic Code: qsort and Callbacks
From Assembler to C. Chapter 6. Function Pointers and Generic Code: qsort and Callbacks. In Python you can pass a function to another function as easily as a number, and Rust gives you closures for that. C is humbler and more honest: a function is just code sitting at some address, and a function pointer is a variable that stores that address. In assembly you did the very same thing when you loaded the address of a label into a register and jumped through it with an indirect jump. This chapter shows how such a simple mechanism grows into command tables, callbacks, sorting of arbitrary data, and even an object-oriented style.\n\nA function pointer declaration is read from the inside out. Take int, then a star in parentheses, then op, then parentheses with two ints. It means: op is a pointer to a function that takes two ints and returns an int. The parentheses around the star are mandatory; without them you would get a function that returns a pointer. To save yourself the pain, you introduce a typedef and give the type a short name. The name of a function turns into its address by itself, so you can simply assign the name, and to call it you just put parentheses after the variable. The address-of operator and the star are allowed in a call, but unnecessary. And an array of such pointers is an ordinary array.\n\nThe most common use is a function table. Instead of a long switch over an operation code, you create an array where the command number is the index and the cell holds the address of a handler. A call turns into loading an address from the table and making one indirect jump: the time does not depend on the number of variants, and adding a new one means adding a line to the table. This is how virtual machine interpreters, command dispatchers, and interrupt tables are built. The price is that the function body cannot be inlined at the call site: the compiler does not know in advance where the jump will go, so optimizations are limited.\n\nA callback is a function that you hand to another function so that it calls it at the right moment. The simplest template is walking over an array: the function takes an array, a length, and a function pointer, and calls that function for every element. This separates how to walk from what to do with each element. But such a function has no memory. To give the callback some data, such as a counter or a buffer, you pass a generic context pointer alongside the function pointer. This is a manual version of a closure: code and data travel as a pair, and the caller is responsible for making sure the context lives long enough.\n\nThe best-known example is the sorting function qsort from the standard library. It knows nothing about the type of the elements: it takes the address of the start, the number of elements, the size of one element, and a comparison function. The comparison receives two pointers to elements and returns a negative number, zero, or a positive number. Inside it, you cast the void pointers to the type you need. A common mistake is to compare integers by subtraction: the difference can overflow and give the wrong sign, so you write an explicit comparison, greater minus less. Also, qsort does not guarantee stability, which means equal elements may swap places.\n\nThe same technique is used by bsearch and other search functions: the array is sorted, at every step the comparison function is called with the key you are looking for, and the search runs in logarithmic time. It is important that the key and the element do not have to be of the same type: the comparison gets a pointer to the key and a pointer to an element and decides for itself how to match them. This lets you find a structure by a single field, for example by its number, without building a second instance. If you need to pass extra data to the comparison, such as the sort order, you use an extension with a context, but in standard C you have to do this yourself, through a global variable or your own sort.\n\nTo write a container that works with any type, you need three things: a pointer to the data as bytes, the element size, and a set of operations on an element. The size tells you how far to step and how much memcpy should copy. Comparison lets you sort and search. Destruction frees whatever the element owns, for example a string inside a structure. It is convenient to keep these operations together in a structure that you pass in when you create the container. There is no type safety here: the compiler will not notice if you put a number into a vector of strings, so keeping the sizes consistent is the author's responsibility.\n\nA structure made of function pointers is an operations table, an interface. If every object stores a pointer to such a table, you get polymorphism: a shape knows how to compute its own area, and generic code calls area through the table without knowing whether it is a circle or a rectangle. This is exactly how file operations, drivers, and dozens of libraries are built in C: an object begins with a pointer to the table, and the concrete types continue it with their own fields. Converting a pointer to a concrete structure into a pointer to its first field is allowed, and that is the basis of inheritance in the C style.\n\nFunction pointers demand discipline. The pointer's type must match the function's type: casting to a foreign type and calling it is undefined behavior, even if the code happens to work. You should check the pointer for NULL before calling it if it is optional. The function you point to cannot be destroyed, so there are no dangling references there, but the context passed alongside it can already be gone if the callback is called later than the function that created it returns. To document the agreements, write a comment: who owns the context, how long the callback lives, and whether it can be called from other places.\n\nA function can return a function pointer. The syntax looks frightening, so once again a typedef comes to the rescue: the handler type gets a name, and then a function that picks a handler by a string looks like an ordinary function returning a value of that type. This is the basis of finite state machines: each state is a function that reads the next character and returns the next state, that is, a pointer to another function. Since C cannot directly express the type of a function that returns itself, the pointer is wrapped in a small structure. The loop simply calls the current state until it receives an empty value. Such a machine reads like a transition table and is easy to extend by adding a new function.\n\nGeneric code costs money. Every call through a pointer is an indirect jump, which is harder for the processor to predict than an ordinary one. A comparison called from qsort millions of times is more expensive than the same comparison placed directly in a loop. That is why, for hot spots, people sometimes write the sort again for a specific type or generate it with a macro. But in most programs the difference is not critical, while the gain in simplicity and reuse is huge. The rule is this: first write it generically and correctly, then measure, and only if needed, specialize.\n\nSorting composite data needs care with types. If you sort an array of strings, that is, an array of pointers to characters, the comparison function receives not the strings but pointers to the array cells, that is, a pointer to a pointer: first you cast, then you dereference, and only then do you call strcmp. If you sort structures by several fields, the comparison works as a cascade: first the main field, and only if they are equal, the next one, and the result of the first unequal comparison is returned immediately. For reverse order it is enough to swap the arguments. The comparison must be consistent: if a is less than b, then b must be greater than a, otherwise the sort may behave unpredictably.\n\nLet us sum up. A function pointer stores the address of code and lets you call it indirectly. Function tables replace branching, callbacks separate the walk from the action, and a generic pointer together with an element size gives you generic containers. qsort and bsearch are the classic examples of this style, and a structure of function pointers is an interface that allows polymorphism in plain C. Watch for matching types, for the lifetime of the context, and for the cost of indirect calls.
