#CHAPTER 6 | Lists
Python as a first language. Chapter 6. Lists. So far, every variable in our programs has held exactly one value: one number, one string, one flag. But real development lives on collections. A mailbox holds not one email but hundreds. A shopping cart holds not one item but a whole set. A user on a social network has not one friend but a long list of names. Storing all that in separate variables is impossible: who would declare three hundred variables and keep track of each one? For this, Python has the list, the central data type of the language. One name, many values: put something in, take it out, add, remove, loop over it. It is the most widely used container in the whole language: open any real project and you will see lists at every step. Today we will learn the list from end to end, from creating one to sorting it.\n\nCreating a list is very simple: values separated by commas, with square brackets around them. Write ten, twenty, thirty in square brackets and you have a list of three numbers, which you usually store in a variable, say one called nums. An empty list looks even simpler: just two square brackets in a row, with nothing inside. It is far from useless: almost every real program starts this way, with an empty list that gets filled as the work goes on. Technically, Python lets you mix types: numbers and strings can sit in the same list, and the language will not complain. But good programs do not do that. A list should hold things of one kind: numbers with numbers, strings with strings. Consistency is a gift to your future self: when you open the list six months from now, you know exactly what is in it. A mixed list is almost always a bug disguised as data.\n\nYou can get an element out of a list by its number, written in square brackets right after the name. But here is the main rule of all of Python, the one every beginner trips over: counting starts from zero. The first element of the list has index zero, the second has index one, the third has index two. For a list of three numbers, the valid indexes are zero, one and two, and trying to take the third one causes an index out of range error. This is not the language being picky, it is honest arithmetic: an index is not a position in a count, it is a distance from the start, that is, how many elements you have to skip. Programmers in every language live by counting from zero, so the habit of thinking that the first one is zero will pay off in any of them. On the slides for this lesson there is a list called nums with the numbers ten, twenty and thirty: nums in square brackets zero is ten. Check it on the slide, and the rule will stick on its own.\n\nPython has a nice feature that many other languages lack: negative indexes. Minus one is the last element, minus two is the second to last, minus three is third from the end, and so on back to the start. The idea is transparent: minus one means one from the end, minus two means two from the end, and there are no tricks. The most common use is taking the last element without knowing the length of the list: nums in square brackets minus one works for three elements and for three million alike. Without negative indexes, you would first have to ask for the length, subtract one and plug in the result: three steps instead of one. And the length, by the way, can change at any moment, because the list keeps growing. A negative index removes that fragility: it always points to the end, however long the list becomes. It is a small feature, but it saves both lines of code and nerves.\n\nReplacing an element in a list is easy: assign a new value at an index, just like an ordinary variable. Nums in square brackets zero equals ninety-nine, and where the ten used to be, the list now holds ninety-nine, while the other elements stay untouched. Here there is an important new word: mutability. Lists in Python can be changed in place, without rebuilding them. Strings were different: in chapter two we said that a string cannot be changed, you can only build a new one from pieces of the old one. A list is the opposite: it is alive, you can edit it as much as you like, and it is still the same list. That is exactly why lists are perfect for accumulating things: the program adds, removes and rearranges data as it works. Remember this pair: strings are immutable, lists are mutable. Almost every language has this distinction, and Python shows it in a particularly clear way.\n\nHow many elements a list has is told by the function len, short for length. Pass it a list and you get the number of elements: for our ten, twenty and thirty, that is three. You have already met it in chapter two, where len counted the characters in a string, and now it counts the elements in a list. That is Python for you: one function works with any container, so you do not need to memorize separate commands for each type. In practice, len constantly goes together with indexes: the last position of a list is always len minus one. It also comes in handy in loops: first you count, then you iterate. One useful detail: len of an empty list is zero, and that is perfectly legal, not an error. An empty list is a full-fledged list too, just without contents for now.\n\nA list can grow on the fly, and the method append takes care of that. A method is a command that you call with a dot after the name of the list: nums dot append, and in parentheses forty, and the list has a fourth element. Append always puts the new value at the end and does not touch the order of the existing elements. A typical scenario from real development: the first line of the program declares an empty list, and by line one hundred it already holds a hundred values. This is how you collect the results of loops: run through the data, append each suitable value, and the list grows. You will use this technique all the time: collecting logs, accumulating sums, picking out matching files. Notice that append returns nothing and prints nothing, it silently changes the list itself. One line of a call, and the data is richer by one element.\n\nThe main gift of the list and loop pair is iteration without any counters. The for loop, which you learned in the previous chapter, walks over a list directly: for each element x in the list nums, do this. No indexes by hand and no square brackets inside the loop: Python itself takes the elements out one at a time, from the first to the last. The loop header itself reads almost like an English sentence, and this readability is exactly why people love the language. In the body of the loop, the variable x will in turn be each element: first ten, then twenty, then thirty. Printing every element, computing a sum, finding the largest one: it is the same frame with a different body. In other languages iteration needs counters and lengths, but here it is all built in. Remember the three pillars: a list, a for loop, and an indented body. Half of all practical tasks stand on them.\n\nTo answer the question of whether an element is in a list, an old friend helps: in code, it is the word in. In chapter three, it checked whether a substring occurs in a string, and now it checks whether an element is in a list. The notation is simple: on the left is what we are looking for, on the right is where we are looking, and Python answers true or false. One word, two uses, and both work with the same transparency. In real code this is a check before an action: is the email among the unread ones, is the item in the cart, is the name on the guest list. Notice that in the loop header the same word in plays a different role: there it enumerates elements, and here it checks for presence. Do not confuse these two roles: in a loop it means for each of, in a condition it means is contained in. One line of checking replaces a whole loop with a flag, which in other languages you would have to write by hand.\n\nYou can delete from a list in two ways, and each has its own logic. The method remove deletes the first element with a given value: nums dot remove, and in parentheses twenty, and the list searches for twenty from left to right and crosses out the first match. If there is no such value in the list, Python will honestly report an error, so when in doubt, check for membership first. The second way is the method pop: it takes an element off the end and returns it, like a plate from a stack. The plate you took off can be used right away: put it in a variable, pass it on, print it. Pop also has a version with an index: pass a position number in parentheses, and you take the element from exactly that position rather than from the end. Remove searches by value, pop works by position: choose according to the task. This way the same list can work as an event log or as a stack of tasks, where the last one to arrive is the first to leave.\n\nA list can be cut into pieces, and such pieces are called slices. The notation nums in square brackets, one, colon, three means: take the elements from index one up to three, but the right boundary is not included. You get the elements with indexes one and two, twenty and thirty, and the element with index three does not make it into the slice. The logic is the same as the function range from the previous chapter: the right boundary is always outside the result, and you simply have to get used to it. A slice has shortened forms: an empty place on the left means from the start, an empty place on the right means to the end. And a slice with no boundaries at all, just a colon, is a full copy of the list: a simple way to copy data before changing it. Slices read easily, from such-and-such to such-and-such, and that is one more reason to love counting from zero. Indexes, slices and range all obey one rule, so you keep one logic in your head instead of three.\n\nFor numeric lists, Python has ready-made tools for ordering and summaries. The method sort arranges the elements in ascending order right in place: nums dot sort, and the list has rearranged itself internally, without creating a new one. After sort, the elements go from smallest to largest, and this order stays forever: you cannot get the old one back, so keep that in mind. For summaries there are three functions at once: max returns the largest element, min the smallest, and sum adds up everything there is. One line, and you know the sales peak, the cheapest item, the grand total. But remember our tradition: in exercises we often ask you to write max and sum yourself with a loop, without the built-in functions. This is not bureaucracy: until you have walked through the elements by hand with a loop, you do not feel the mechanics. Built-in functions are for real projects, hand-written loops are for practice, and both should be in your toolbox.\n\nLet us sum up. The list is the central container of Python: values in square brackets separated by commas, one name for the whole collection. Indexing starts from zero, negative indexes count from the end, and assignment by index changes an element in place, so lists are mutable, unlike strings. The function len counts elements, the method append adds to the end and grows the list on the fly, the for loop iterates without counters, and the word in checks membership. Remove deletes by value, pop takes off the end like a plate from a stack, slices cut out pieces with an excluded right boundary, and sort arranges in ascending order in place. For numeric lists there are the ready-made max, min and sum, although in exercises we often write them with a loop ourselves to feel the mechanics. The list is ideal when elements are looked up by number: first, second, last. This topic is too important to end in one chapter: in the next two we will learn to iterate over lists with numbers, nest them inside each other, copy them correctly, sort them and build them in one line. And when you need a meaningful name instead of a number, dictionaries step in: key-value pairs, on which all work with data rests.
