#CHAPTER 11 | Tuples
Python as a first language. Chapter 11. Tuples. You've already met tuples without knowing their name: every pair from enumerate, from zip, and from items is a tuple. A tuple is the immutable sibling of the list: an ordered collection of values that can't be changed once it's created. It sounds like a limitation, but it's a useful one. Immutability gives you a guarantee: whatever happens in the program, the contents of a tuple will stay the same. That's why tuples can be dictionary keys, why functions hand back results as tuples, and why fixed structures like coordinates and dates are written as tuples. Today we'll see how to create them, how to unpack them, where to use them, and how they differ from lists. And we'll wrap up the topic of Python's basic containers.\n\nA tuple is created with parentheses: values separated by commas. One, two, three in parentheses is a tuple of three numbers. In fact, the parentheses aren't the main thing: it's the comma that creates a tuple, and the parentheses only help with reading. So writing a equals one, two also gives you a tuple. Which brings us to a well-known catch: a tuple with a single element. A one in parentheses is just a one in parentheses, like in arithmetic. To get a tuple, you need a comma after the element: one, comma, all in parentheses. An empty tuple is simply two parentheses. To turn something into a tuple, there's the tuple function: tuple of a list gives a tuple with the same elements, and tuple of a string gives a tuple of characters.\n\nEverything you can do with a list without changing it, a tuple can do too. Indexes starting from zero, and negative ones, slices, the len function, the word in to check membership, the for loop to iterate, maximum, minimum, and sum all work the same way. A slice of a tuple is also a tuple. The methods index and count are there too. But there are no methods that change the contents: no append, no remove, no sort. An attempt to assign a value by index ends in a type error, saying the object doesn't support item assignment. That's not an oversight, it's the point: a tuple is meant to be a record that can't be spoiled by accident. If you need a changeable collection, use a list; if the collection shouldn't change by its meaning, use a tuple.\n\nSo how do you "change" a tuple if you really have to? Only by building a new one. Plus glues two tuples into a third, multiplication by a number repeats, and slices cut out pieces. Want to replace the second element? Take a slice up to it, the value you need, and a slice after it, and glue them together. Writing tuple plus-equals a new element works too, but it creates a new tuple and attaches the old name to it. Inconvenient? Maybe, but it's safe, and that's the benefit. Immutability protects you from two troubles: from an accidental edit through a second reference, which we discussed in the chapter on copying, and from quiet corruption of data in a big program. On top of that, tuples are a little faster and take less memory than lists, and most importantly, you can use them wherever immutable data is required: in dictionary keys.\n\nNow for the main technique of working with tuples: unpacking. Writing a, b equals a tuple of two lays its elements out into variables: the first goes to a, the second to b. The number of names on the left must match the length of the tuple, otherwise you get a value error: too many values or not enough. Unpacking works not only with tuples, but with lists, strings, and any other collections. If you need only part of the sequence, put a star in front of one of the names: it will gather all the extras into a list. First, star rest, equals a collection: the first name gets the beginning, and rest gets everything else. And to ignore a value you don't need, the tradition is to use a name made of a single underscore. You've used unpacking many times already: in a loop over pairs from items, it works quietly behind the scenes.\n\nThe best-known beauty of unpacking is swapping values. In other languages, to swap two variables you need a third, temporary one. In Python it's one line: a, b equals b, a. On the right, Python builds a tuple from the current values, and on the left it unpacks it into the names. Because the whole right side is evaluated before the assignment, there's no mix-up. The same technique works in sorting algorithms: bubble sort swaps neighboring list elements in one line, the element at one index and its neighbor trade places. It works with any number of values, too: a, b, c equals b, c, a is a circular shift. It's a small detail, but it saves both lines and bugs: you can no longer forget the temporary variable.\n\nTuples are the standard way to return several values from a function. You already know how to write functions: the word def, a name, parameters in parentheses, and a return command with the result. If you list values separated by commas after return, the function returns a tuple. Say, a function that takes a list of numbers and returns the minimum and the maximum in a single answer. The calling code immediately unpacks the result into two variables: smallest, largest equals the function of the numbers. It reads naturally: the function returned two values. Technically, one tuple came back, and the comma in return built it. This technique is found everywhere: a function for division with remainder, a function that parses a date, a function that returns a value along with a success flag.\n\nNow let's gather what's already familiar. The enumerate function gives you tuples of a number and an element; zip gives tuples of elements from different lists; the items method of a dictionary gives tuples of a key and a value. In all these cases the loop header contains unpacking: for number, value in enumerate; for name, grade in zip; for key, value in items. Now you understand the magic: there's no magic, the loop simply takes the next tuple and spreads it across the variables. You can also skip unpacking: then the variable holds the whole tuple, and you reach the parts by index, like with any tuple. That's where the sort-by-value function from the previous chapter comes from: a pair is a tuple, and its second element is reached with index one.\n\nThe main practical advantage of immutability is that you can use a tuple as a dictionary key. Recall that a list can't be a key, but a tuple can. This solves the problem of a composite key. For example, a cell on a board is defined by two numbers, a row and a column. A dictionary whose key is a tuple of two numbers and whose value is the contents of the cell stores the entire board. To get a cell: the board in square brackets, and inside, two numbers separated by a comma, which is exactly a tuple. To check whether a cell exists: the word in. A map is stored the same way: latitude and longitude as the key, the name of the place as the value. Or the pair "person and date" with the number of records. A composite key turns a dictionary into a universal table over several attributes.\n\nWhen should you pick a list, and when a tuple? There's a simple rule. A list is for a homogeneous collection of variable length: students' grades, file names, sensor readings. There can be more or fewer elements, and that's fine. A tuple is for a record with a fixed structure, where position has meaning: name, age, city; latitude and longitude; red, green, blue. The number and roles of the elements are known in advance. Converting one to the other is easy: tuple of a list, and list of a tuple. By the way, the sorted function always returns a list, even if you give it a tuple. A practical tip: if nobody should write into the data, make it a tuple. If you keep wanting to add elements, you need a list. The choice reflects the meaning of the data, and whoever reads the code understands it without comments.\n\nTuples can be compared with each other, and the comparison goes element by element from left to right. First the first elements are compared; if they're equal, the second ones are compared, and so on. So the tuple one, five is less than the tuple two, zero, and the tuple one, five is less than the tuple one, seven. This is how alphabetical order in a dictionary works too: first the first letter, then the second. A useful consequence follows: a list of tuples sorts itself, by the first element, and on a tie, by the second. Maximum and minimum understand tuples as well. And this gives rise to a technique for sorting by several attributes: pass the key parameter a function that returns a tuple. For example, by descending frequency and then alphabetically on a tie: a tuple of minus the frequency and the word. The first attribute is the main one, the second settles the ties.\n\nPitfalls. First: a tuple of one element without a comma. Parentheses without a comma don't create a tuple, you just get an ordinary value, and strange errors later in the code. Second: immutability is shallow. If a list lies inside a tuple, the list itself stays changeable: you can add an element to it, and the tuple formally remains the same. That's why a tuple with a list inside can't be used as a dictionary key: Python can't hash it. Third: unpacking with the wrong number of names is a value error. If the number of elements can vary, use a star. Fourth: plus-equals on a tuple doesn't change the old tuple, it creates a new one. Another name pointing to the old one will still see the old value. Fifth: mixing up a tuple and parentheses in arithmetic. The comma decides.\n\nLet's sum up. A tuple is an ordered immutable collection in parentheses; it's the comma that creates it, and for a single element you need a trailing comma. Indexes, slices, len, in, loops, and summary functions work as they do for lists, but there are no methods for editing. A tuple can be changed only by rebuilding it. Unpacking lays a tuple out into names, a star gathers the extras, and swapping values takes one line. A function returns several values as a tuple, and enumerate, zip, and items hand out tuples. A tuple works as a dictionary key, and a composite key turns a dictionary into a table over several attributes. Tuples are compared from left to right, which gives rise to sorting by several attributes. A list is for a homogeneous collection, a tuple is for a record with a fixed structure. We're done with Python's basic containers: lists, dictionaries, and tuples. Next up are classes: a way to describe your own data types that have both values and behavior. See you there.
