Python as a first language. Chapter 25. Higher-order functions. Functional programming is a style in which a program is built from small functions, and data flows through them like water through pipes. Python is not a purely functional language, but it takes the most useful parts of this style. The main idea is simple: a function is a value just like a number or a string. You can put it in a variable, store it in a list, pass it to another function and return it from a function. Functions that take or return other functions are called higher-order functions. You have already used them: the key parameter of sorted takes a function. Today we will see how this works, and meet lambda, map and filter, arguments with stars, pure functions and composition. This is the foundation for the next chapters, on closures and decorators.\n\nThe name of a function without parentheses is the function itself, as an object. You can assign it to another name just like a number: f equals print, and now f of the word hello prints it. You can also put functions in a list or a dictionary: a dictionary of operation names to functions replaces a long chain of conditions, and the call looks like the operations dictionary indexed with a name, followed by the arguments in parentheses. You can write a function that takes another function: apply of f and a value returns f of the value. This is exactly how the key parameter works: you pass a function, and sorted calls it on every element itself. Parentheses decide everything: with them the function is called and we get a result, without them the function itself is passed along. Remember this difference forever.\n\nIf you need a function for just a moment, inventing a name for it and writing def is tedious. For such cases there is lambda, an anonymous function written as a single expression. The word lambda, then the parameters, a colon, and an expression whose value will be the result: lambda x colon x times two. You do not need to write return, it is implied. The limitation is serious: a lambda holds only one expression, with no assignments and no multi-line blocks. That is why lambdas are usually short and live where they are passed in: in key, in map, in filter. If a lambda has grown long, or you have to explain something in it, turn it into an ordinary named function: the code becomes more readable and errors become clearer, because the traceback will show a real name.\n\nThe most common use of lambda is the key parameter of sorting and of finding extreme values. To sort words by length: sorted of words, with key equal to lambda s, len of s. To find the oldest person in a list of dictionaries: max of users, with key equal to lambda u, u indexed with the age. To sort by several criteria, return a tuple, as we did in the chapter on tuples. Min and max take the same parameter, and they also have a default value for the case of an empty collection. Before, we wrote separate helper functions with def; now the same thing fits on one line. But do not overdo it: a couple of short lambdas on a line is fine, while a chain of nested ones is a cipher.\n\nThe map function applies another function to every element and returns a lazy iterator of the results. Map of str and a list of numbers turns the numbers into strings. Map with a lambda doubles every element. If you pass two iterables, the function gets one element from each: map of a two-argument lambda and two lists adds them pairwise. The result of map is an iterator, which means it is single-use and lazy: to see the values, wrap it in list or go through it with a loop. This is the same technique we know from the chapter on iterators. Map is good when you already have a ready-made function: map of int and strings reads better than a list comprehension with an explicit call. But if you need a lambda, a list comprehension is usually more convenient: it reads like a sentence.\n\nThe filter function selects the elements for which the given function returns true. Filter of a lambda x greater than zero and a list keeps only the positive ones. The result is also a lazy iterator. Here is a trick: if you pass None as the function, filter selects the elements that are true by themselves, dropping zeros, empty strings and empty lists. This is a short way to remove the empty values from data. For the opposite selection there is filterfalse in the itertools module. As with map, the choice between filter and a list comprehension with a condition is a matter of taste and readability. Most Python programmers prefer list comprehensions in most cases: they are more expressive and need no lambda. But filter with a ready-made function, for example the string method isalpha, looks elegant.\n\nHow do you choose between map, filter and comprehensions? The rule is this. If you have a ready-made named function and need to apply it to the elements, use map and filter. If you need an expression with conditions and a transformation, use a list comprehension. If you need a single pass and want to save memory, use a generator expression. If you need to keep the result and access it several times, use a list. The main thing is to keep things readable: if a colleague does not understand a line the first time, it is too clever. The goal of the functional style is not to write as little as possible, but to break the processing into clear steps: select, transform, fold. These three verbs describe a huge number of programs, from analyzing tables to parsing logs.\n\nThe third verb is fold, that is, to build one value out of a collection. We already know such functions: sum, max, min, any and all, each of which folds a collection into a number or a boolean value. In general form, a fold is when an accumulator walks over the elements and updates itself at every step: we have written this with a loop many times. In the functional style there is the reduce function from the functools module: it takes a function of two arguments, a collection and an initial value. The first argument of the function is the accumulated result, the second is the next element. Reduce is useful for rare folds that have no ready-made function; for sums and maximums use the built-ins. We will study it in detail in the following chapters, and for now remember the idea: select, transform, fold.\n\nIn higher-order functions you often need to pass arbitrary arguments on. For this there are stars in the function header. One star before a name collects all the extra positional arguments into a tuple, usually called args. Two stars collect the keyword arguments into a dictionary, usually called kwargs. A function with stars accepts any number of arguments, and inside you use them like an ordinary tuple and dictionary. In a call, the stars work the other way around: a call with one star and a list unpacks the list into positional arguments, and with two stars and a dictionary it unpacks into keyword arguments. Parameters after a single star become keyword-only. This is exactly how universal wrappers are written: they pass on everything they received without knowing in advance what it is.\n\nThe functional style loves pure functions. A pure function depends only on its arguments and changes nothing around it: the same arguments give the same result, and the world stays as it was. It is easy to test, easy to understand and safe to call from anywhere. Side effects, such as printing, writing to a file, changing arguments, reading the time or random numbers, make a function unpredictable. Of course, a program without side effects is useless, so people try to gather them at the edges: the core of the computation is kept pure, and input and output are kept apart. An important rule: a function must not change the mutable arguments passed to it, unless that is its explicit purpose. Returning a new list is safer than fixing somebody else's. And here is a trap that it is time to mention: a mutable default value, a list or a dictionary in the function header, is created once and lives on between calls.\n\nFunctions can be stacked like bricks. Composition is the creation of a new function out of two: first apply one, then the other. Let us write a function compose that takes f and g and returns a new function computing f of g of x. Inside, we define a nested function and return it. This technique is called a closure, and the next chapter is devoted to it. Composition lets you build pipelines out of small transformations: strip the spaces, convert to lower case, replace hyphens. Each function is simple and testable, and together they solve a non-trivial task. String method chains and generator pipelines are built the same way: the data passes through a series of transformations, and each of them can be replaced or moved.\n\nCommon mistakes. The first: you forgot the parentheses and pass a result instead of a function, or you put parentheses where the function itself was needed. The second: a lambda in a loop remembers not the value of the variable but the variable itself, and all the lambdas see its last value. The third: map and filter returned an iterator, and you try to take its length or an index. The fourth: overly clever lambdas that are impossible to read. The fifth: a mutable default value. The sixth: a key function that returns values that cannot be compared, for example a number for some elements and a string for others. The seventh: a function that looks pure but reads a global variable and therefore behaves differently. Most of these problems disappear if you remember three rules: functions are values, purity is better than side effects, and readability matters more than brevity.\n\nLet us sum up. Functions in Python are ordinary values: you assign them, keep them in collections, pass them and return them. A lambda is an anonymous function made of one expression, and its place is in the key parameter and nearby. Map and filter transform and select lazily, but list comprehensions usually read better. The three verbs of the functional style are select, transform and fold. Stars collect and unpack arbitrary arguments. Pure functions depend only on their arguments and do not change their surroundings. Composition builds new functions from simple ones. In the next chapter: closures and decorators, functions that create and wrap other functions.
