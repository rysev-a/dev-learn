Python as a first language. Chapter 28. itertools. In the chapters on iterators and generators we saw that streams of values are a handy abstraction: lazy, frugal, and easy to connect into pipelines. For working with such streams, the standard library has a whole set of ready-made tools, the itertools module. It collects infinite counters, ways to chain and slice streams, running totals, grouping, and combinatorics: permutations, combinations, the Cartesian product. All of it works lazily and very fast, because it is written in C. The names look strange until you realize that behind each one stands a simple idea. Today we will walk through the module in order and see how a single short line can replace a loop with several variables. This is one of those modules that, once you know it, makes other people's code much easier to read.\n\nLet's start with infinite streams. count, given a starting value and a step, produces numbers forever: zero, one, two, and so on. It is handy as a counter that you can pair with something else through zip. cycle takes a collection and repeats it around and around without end: red, yellow, green, red again. repeat repeats a single value, and if you give it a number, exactly that many times. Three infinite sources, three tools: numbering from any starting point, alternation, and constants. All of them are lazy, so they take up only a few bytes. But as with every infinite stream, remember the main thing: you must never turn one into a list, and you must always limit how much you iterate over it. There are special tools for that limit, and we will turn to them right now.\n\nislice is a slice for iterators. Ordinary slices work only on lists and strings, and you cannot cut an iterator with square brackets. itertools fixes that: islice takes an iterator and boundaries, just like range: a stop, or a start and a stop, or a start, a stop, and a step. It is lazy: it reads exactly as many elements as it needs and then stops. islice of an infinite generator and ten gives you the first ten values, and the stream never has to be computed in full. This is how you take the first items from a file, from a server response, or from an endless sequence. One important detail: after the slice, the iterator has moved forward, and both the skipped and the taken elements are used up. Newer versions of Python also add the function batched, which cuts a stream into tuples of a given size, which is handy for batch processing.\n\nchain joins several iterables into a single stream: chain of a list, a tuple, and a string goes through them one after another without creating a new list. For joining a list of lists there is the variant chain.from_iterable, which takes one argument: an iterable of iterables. It is convenient when the number of parts to join is not known in advance, for example when walking through pages of results. zip_longest is a relative of zip: when the lists have different lengths, ordinary zip stops at the shortest one, while zip_longest fills the missing places with a value you choose. This is how you align columns and how you merge data that has gaps. The result is an ordinary lazy iterator of tuples. Remember the difference: zip loses the tail, zip_longest keeps everything. Which one you need depends on the task, and it is better to choose deliberately than out of habit.\n\naccumulate returns the accumulated results, by default the sums. For the numbers one, two, three, four you get one, three, six, ten. These are the very running totals from the generator exercise, and now they fit on one line. If you pass a function as the second argument, you get other kinds of accumulation: products, maximums, concatenations. The initial parameter sets a starting value, which also appears in the result. A running maximum is accumulate with the function max: from a handful of numbers you get a series of records. accumulate is a close sibling of reduce: reduce hands back only the final answer, while accumulate gives every intermediate step, and that is exactly why it is so good, and lazy, for analyzing time series, balances, and running statistics.\n\nNext comes selection by a condition, but in streams. takewhile takes elements while the condition is true and stops at the first false one. dropwhile does the opposite: it skips elements while the condition is true and hands over everything else, starting from the first false one. This pair works well on sorted data and on infinite streams: take the numbers while they are less than one hundred. filterfalse is the mirror image of filter: it returns the elements for which the function is false. compress takes the data and a set of flags, and keeps only those elements whose flag is true. The difference from an ordinary filter is fundamental: takewhile stops and reads no further, while filter checks the entire stream. For infinite sequences, that is the difference between finishing and looping forever.\n\ngroupby groups consecutive identical values. It takes a collection and a key function and returns pairs: a key and an iterator over the elements of the group. Here is the most important rule, and it must never be forgotten: only neighboring elements are grouped, so the data must first be sorted by the same key, otherwise one and the same category will fall apart into several pieces. The second subtlety: a group's iterator is valid only until you move on to the next group, so if you need to keep it, turn it into a list right away. Typical uses are grouping records by date or category, measuring the length of consecutive runs, and compressing repeats. For the common task of counting how many times something occurred, an ordinary dictionary or a Counter from collections is more convenient, but groupby is irreplaceable when the sequence itself matters.\n\nCombinatorics is a gift for anyone who has studied discrete mathematics. product is the Cartesian product: all pairs from two collections, all triples from three. This is what used to be done with two nested loops. permutations gives all permutations: ordered selections without repeats, and you can specify the length. combinations gives all combinations: unordered selections where the order does not matter and each combination appears once. combinations_with_replacement allows elements to repeat. The number of results grows explosively: the combinations of fifty taken twenty at a time cannot be counted out, and the permutations of twenty elements would not fit into any memory. But since all of these functions are lazy, you can go through them one at a time and stop as soon as you find what you need.\n\nA few more useful tools. starmap takes a function and a collection of tuples and unpacks each tuple into arguments: starmap of mul over pairs of numbers multiplies the numbers in each pair. pairwise, in newer versions of Python, gives neighboring pairs: from three elements you get two pairs, and from one element, none. It is a ready-made sliding window of length two, which used to be built with zip and a shift. tee copies an iterator into several independent ones, but it must be used carefully: after that you must not touch the original iterator, and memory grows if the copies drift far apart. More recipes are in the module's documentation: skipping, iterating over several, splitting by a condition. Get used to opening that page whenever a task looks like processing a stream.\n\nThe module's documentation has a section of recipes: short functions built from itertools primitives. Take the first n elements: islice. Flatten a list of lists: chain.from_iterable. Remove duplicates while keeping order: a loop that checks what has already been seen. Cut a stream into groups: zip of several copies of the same iterator. A sliding window: tee, a shift, and zip. Split a stream into two by a condition: tee and two filterings. These recipes show the spirit of the module: small bricks that snap together into whatever you need. They also show that many tricky tasks are actually trivial if you know the right brick. Open the recipes page and skim through it: it works as a reference of techniques.\n\nLet's look at some combinations. Given a list of names, all possible pairs for games: combinations of two. Given a set of letters, all passwords of length three: product with repeat. Given a list of numbers, the running maximum: accumulate with max. Given a file, the first ten lines: islice. Given a stream of events, group them by minute: groupby after sorting. Given a string, remove characters that repeat in a row: groupby, taking the key from each group. Without itertools, each of these tasks needs a loop with flags and counters, and with it, a single clear line. That is exactly why programmers who know the module write shorter code and make fewer mistakes. Your main task for the near future is to learn to recognize a problem that has one of these tools behind it.\n\nCommon mistakes. The first: groupby without sorting first, so the groups get split up. The second: keeping a group's iterator and using it later, when it is no longer valid. The third: turning an infinite stream into a list, or forgetting to limit it with islice or takewhile. The fourth: reusing an exhausted iterator, such as one you got from tee or permutations. The fifth: underestimating the size of combinatorics: the functions are lazy, but as long as you ask for all the results, the memory runs out. The sixth: mixing up permutations and combinations. The seventh: expecting islice to support negative indexes. It does not, because an iterator does not know its own length. The eighth: using itertools where an ordinary loop is simpler. The tool is good when it makes the code clearer.\n\nLet's sum up. count, cycle, and repeat give infinite streams, while islice and takewhile limit them. chain joins streams, and zip_longest aligns streams of different lengths. accumulate gives running totals, while dropwhile, filterfalse, and compress select by a condition. groupby groups neighboring elements and requires sorting. product, permutations, and combinations solve combinatorics tasks lazily. starmap, pairwise, and tee cover small needs. The main rule: lazy streams must be limited and must not be reused. That finishes functional programming.
