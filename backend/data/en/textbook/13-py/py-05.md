#CHAPTER 5 | Loops
Python as a first language. Chapter 5. Loops. Conditions taught the program to choose, and functions taught us to gather code into blocks. But such a program has a weak spot: it performs every action exactly once. If you want to print a hundred greeting lines, you would have to write the print command a hundred times. Meanwhile, in real development repetition waits at every step: process a thousand emails with a single piece of code, give the user three attempts to enter a password, check every file in a folder. Writing a separate copy of the code for each task is a path to bugs and boredom. Today we meet the loop, an idea that solves this once and for all: the action is written once, and executed as many times as needed. Loops are the second half of the foundation: together with conditions, they turn a list of commands into a real program.\n\nThe first Python loop is called while, which means exactly that: as long as. The deal is this: as long as the condition is true, the body of the loop repeats again and again. You already know how to build a condition, it is the same thing as in the word if, only here it stands in the loop header. Let us take the classic example, a countdown. Create a variable n with the value three, and say: while n is greater than zero, print it on the screen and decrease it by one. The first pass prints three, the second two, the third one. As soon as n becomes zero, the condition turns false, and the loop calmly ends. Indentation works exactly as in conditions: the loop body is everything shifted to the right. Forget the indentation, and Python will honestly tell you that the body is empty.\n\nThe main danger of while lies where the condition never becomes false. Imagine that in our countdown you forgot the line that decreases the counter. The variable n will stay three forever, the condition will stay true forever, and the loop will spin endlessly. This mistake is called an infinite loop, and it looks depressing: the program seems to freeze, prints nothing and does not respond. In fact it is working as hard as it can, just without any progress. Hence the rule: something inside the loop body must change, such as a counter, a file or the user's answer. Then the condition has a chance to become false someday. By the way, in our trainer infinite loops are handled by a timeout: if the code did not finish in the allotted time, the check stops it and honestly says so. So feel free to experiment: nothing worse than a timeout will happen.\n\nThe second Python loop is for, and it reads as for each element of. It is easiest to feel it on a string. Say: for each character of the word privet, which is Russian for hello, print that character. Python takes the first letter and runs the body with it, then the second, then the third, and so on to the end of the word. On every pass the loop variable receives the next character, and by the end the body will have worked with every letter. Notice how neatly this code reads aloud: for each character in the word, print the character. No counters, no bounds, no manual stepping, only the essence of the task. It is for this readability that people love Python.\n\nAnd what about repeating with numbers, say, doing something exactly five times? For that there is range, a generator of number series. The for loop together with range of five goes through the numbers zero, one, two, three, four, so the body runs exactly five times. Remember the main property: the right bound in range is never included. If you want from one to five, write range from one to six, and six will not be part of the iteration. There is also a third argument, the step: range from zero to ten with step two goes through the even numbers: zero, two, four, six, eight. The right bound is not included here either: you will not see ten. The habit of double-checking the bounds of range will save you from a lot of small surprises.\n\nNow the classic of the genre, the accumulator. The task: compute the sum of all numbers from one to one hundred. We create a variable total and set it to zero; this is our piggy bank. Then comes a for loop with range from one to one hundred and one: on every pass the next number is added to the piggy bank, which in code is plus equals. The plus equals operation is a short way to say add and write back into the same variable. After the last pass, the finished answer is in total: five thousand fifty. This pattern is universal: this is how sums, counters and products are computed, and only the starting value and the action change. For a sum we start from zero, for a product from one. Remember this technique firmly: you will meet it a thousand more times.\n\nSometimes you need to leave a loop not on schedule but immediately, as soon as the goal is reached. For that there is break, the command for an immediate exit. A typical task: find the first digit in a string. We go with a for loop over all the characters and check each one: is it a digit? As soon as we find one, we print it and call break: there is no reason to check further, the answer is already received. Without break, the loop would honestly run to the end of the string, even though all the necessary work was done on the very first step. On a short string the difference is invisible, but on a file of a million characters it is very noticeable. Break not only saves passes: it makes the intention explicit. The reader of the code sees at once that there is no need to go on, the task is solved.\n\nThere is also a command that is the opposite in spirit: continue. It does not close the loop, but skips the rest of the body and goes straight to the next pass. An example: print only the odd numbers from one to ten. We go through range, and for each number we look at the remainder of division by two. If the remainder is zero, the number is even and we do not need it, so we call continue, and printing is skipped. Only the odd numbers reach the print line: one, three, five, seven, nine. It reads like this: skip the even ones, print the rest. The difference from break is fundamental: break closes the whole loop, continue only a single pass. Both commands usually live inside a condition, otherwise the whole point of the loop is lost.\n\nNow let us combine two things that at first glance contradict each other: the infinite loop and break. The line while True means repeat always: on its own, such a condition never becomes false. It seems like a recipe for freezing, but together with break it becomes a powerful and honest pattern. Inside the body we ask something and read the answer: if it equals the word stop, we call break. The loop ends when the user wants it to, and not when a condition stretched in advance at the top has run out of things to do. This is how menus and surveys are built: read a command until stop is entered. An exit in the middle of the body is more honest than an artificial condition at the top: the exit point is visible to the eye, not computed. Remember the pair while True and break: you will see it in other people's code all the time.\n\nLoops can be put inside each other, and here the real magic begins. The scheme is this: on each of its passes, the outer loop starts the inner one, and the inner one runs completely. The classic demonstration is the multiplication table. The outer loop goes through the rows, say from one to five, and the inner one through the columns, also from one to five. On the first pass of the outer loop, the inner one runs through all five columns, on the second again all five, and so on for every row. In total, the body of the inner loop will run twenty five times, although the code has only two commands. Every row meets every column: one with one, one with two, and on down the list. Nesting multiplies the work: three outer passes of four inner ones give twelve. This is how people go through the cells of a board, pairs of products, combinations of folders and files, and there are plenty of other scenarios.\n\nThe accumulator can work not only with numbers but also with strings. The task: reverse a word, so that privet becomes tevirp. We create an empty result string and go with a for loop through the letters of the original word. On every pass we attach the next letter not to the end but to the beginning of the result: letter plus result. The first letter will travel to the very end, the last will end up at the start, and the word will be reversed. A fundamental thing matters here: strings in Python are immutable. You cannot take a word and fix a letter in it; you can only build a new string from pieces. That is why the accumulator is needed: we do not edit the old string, but every time create a new one, from the old one and the next letter. The same technique is used to build names separated by commas and strings for reports.\n\nLet us collect the typical mistakes. Everyone stumbles on them, so it is better to see them in advance. The first one you already know: forgetting to change the counter in while and getting an infinite loop. Ask yourself the question, does anything at all change in this body? It saves you more often than you might think. The second is trickier: the off-by-one error. We want the numbers from one to n, we write range from one to n, and quietly lose the last number, because the right bound is not included. The correct form is range from one to n plus one, and at first it looks wrong to everybody. The third mistake is the choice of tool. The rule is simple: for is for when we know what we are going over, a word or the numbers of a range; while is for when we go until something happens, say, until the password is guessed. You can almost always mix them up, but the code becomes clearer when the loop is chosen to fit the task.\n\nLet us sum up. We have while, repetition as long as a condition is true, and for, going through elements, with range for number series. Break leaves the loop immediately, continue skips a single pass. Loops can be nested into each other and multiply the work. Accumulators collect sums, counters and new strings. And we know how to avoid the two main traps: the infinite loop from an unchanging condition, and the off-by-one error in the bounds of range. Loops need room: going one character at a time is pleasant, but real data lives in groups. In the next chapter, lists, the central data type of Python: hundreds of values in a single variable, and going through all of them with one for. See you then.
