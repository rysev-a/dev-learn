#CHAPTER 2 | Variables and types
Python as a first language. Chapter 2. Variables and types. In the last chapter every print command lived for a single moment: it printed something and immediately forgot it forever. You could not ask the program to remember your name or your age, because it simply had no memory. Today we give it one, and it is called variables. A variable is a labeled box: you put a value inside, and you write a name on the side so you can find it later. A calculator computes and forgets; a program computes, remembers, and keeps using the result. The difference between them is exactly one idea, and today you will master it. This is the big step from a calculator to a real program, so make yourself comfortable.\n\nLet's start with assignment. It is written very briefly: a name, an equals sign, a value, for example age equals twenty. Only here the equals sign is not read as equals, but as put: into the box named age, put the value twenty. On the right is always what we put in, and on the left is the name of the box we put it into. And the order is strict: Python first evaluates the right-hand side all the way, and only then drops the finished result into the box. Like on a conveyor belt: on the right the part is assembled, on the left the crate is labeled. Remember this direction, because it will help you out many more times in this chapter.\n\nThe box is full, so now we can use it. The print command with the name age in parentheses will print what is inside: twenty. It is nice that in code you write only the name, and Python itself looks inside and takes out whatever is there. A name in a program is always a reference to the current contents of a box. Put twenty-one into age, and twenty is gone: everyone who asks about age now gets twenty-one. No ghosts of the past, there is always exactly one value in the box. This keeps you disciplined: whatever is there right now is the only truth of the program.\n\nNot every name suits a box, and there are rules about that. A name may contain Latin letters, digits, and the underscore, but it must not start with a digit: Python will accept age underscore two, but it will not accept two age. The underscore is a full citizen of names, and a bit later it will play the main role. The second rule is harsher and sneakier: case matters, and Age with a capital letter is a completely different box from age with a small one. Python will honestly create two different boxes and give you no warning at all. This is exactly where the classic beginner's nightmare comes from: half an hour of debugging, and the culprit is one accidental capital letter. So before you blame your logic, check the case.\n\nThe rules allow a lot, but Python culture asks for more. In the Python world the snake case name is the norm: all words in lowercase, with an underscore between them. A counter of users becomes user underscore count: two words joined by an underscore, and the name reads like a phrase. Names should speak: user underscore count is better than a faceless x, and email underscore address is better than a short s. A short name saves three seconds of typing, but costs three minutes when you try to remember what it meant. Programs are read ten times more often than they are written, and the reader is often you yourself a month later. Write so that this reader will thank you.\n\nNow let's talk about what exactly lies in the boxes. Values come in different kinds, and Python tells them apart clearly, like a sorter at a post office. The first kind is whole numbers, which Python calls int: zero, one, minus five, a million. Their element is counting: how many users, how many attempts, how many times a button was pressed. The second kind is fractional numbers, called float: numbers with a decimal point, like one point seven six. Their element is measurement: height, weight, temperature, speed. Python can mix them in calculations on its own, but you must always understand which kind you are working with.\n\nThe third kind is strings, which Python calls str: any text taken in quotes. A username, an email address, a chat message are all strings, even if there are only digits inside. Every string has a length, the number of characters, and you can ask for it from the function len: pass it a string, and it returns a number. Pay attention to detail: a space is also a character, so len of a phrase of six letters and a space returns not six, but seven. Quotes can be double or single; the main thing is that the opening and closing ones match. Strings surround us in every interface: button labels, headings, emails. This is the most talkative data type, and you will be working with it all the time.\n\nThe fourth kind is the most laconic: the logical type, which Python calls bool. It has only two values: true and false, and both must be written with a capital letter. A bool is the answer to a closed question to which there is only a yes or a no. Is the age over eighteen? If yes, the value will be True; if no, False. No maybes and almost-es: a bool has no third value. We will talk about it in detail later: a bool really comes into its own in the chapter on conditions, where the program starts making decisions. For now, remember the main thing: True and False are values just like any other, and they can be put into variables.\n\nHow do you find out what kind of value lies in a box? Ask Python itself: the function type takes a value and returns its kind. Ask type about twenty, and you get int; ask it about the word twenty in quotes, and you get str. Outwardly these two values look alike, like two identical boxes, but the cargo inside is different: a number and a text. Mixing up whether something is a number or a string is one of the most common mistakes for beginners. Build a useful habit: if in doubt, call type and face the truth. It helps especially when the value came from somewhere outside: from a form, from a file, from a server response. One second of checking saves minutes of surprise.\n\nStrings often need to be assembled from pieces, and here Python has its main tool: the f-string. You do it like this: before the opening quote you put the letter f, and inside the string, in curly braces, you write the name of a variable. When Python meets such a construct, it substitutes the current value in place of the braces: an f-string saying I am, then age in braces, then years old, turns into the phrase I am twenty years old. You can have as many braces as you like; they will simply land in different places of the phrase. A greeting with a name, a counter with a number, a report with totals: all of this is convenient to do with f-strings. Without them every text would have to be glued together by hand, which is slow and full of mistakes. One letter before the quotes, and the text comes alive.\n\nA variable is not only read, it is also changed. The value inside a box can change as many times as you like, and the box is not harmed. The classic notation looks like this: count equals count plus one. Let's read it by the rules of assignment: first the right-hand side is evaluated, we take the old contents of the box count and add one, then the result is put back into the same box. The old value dissolved, and the new one became bigger by one. For this frequent move Python has a short form: a name, plus-equals, a number, which reads as add and put back. This is how the likes under a post are counted, and steps in a day, and attempts in a game. Every click you make on a heart is plus-equals in action.\n\nSometimes a value needs to be converted from one kind to another, and there are translator functions for that. Int applied to the string forty-two turns the text into a real number you can calculate with. Str applied to the number forty-two, on the contrary, wraps the number into a string, for example to insert it into a text. Why is this needed? Because only like things can be added: a number to a number, a string to a string. An attempt to add the string five to the number five ends with a type error, and this is not a whim: Python does not guess for you whether to glue text or add numbers. In such a situation the error is a gift: the program crashes immediately and loudly, instead of quietly calculating nonsense. Convert values to the form you need yourself, explicitly and consciously.\n\nLet's sum up. A variable is a labeled box for a value; the equals sign reads as put, and a name always points to the current contents. We write names with Latin letters, digits and the underscore, watch the case, and choose snake case names that speak for themselves. Values come in four kinds: whole numbers, int; fractional numbers, float; strings, str; and the logical bool with its True and False. A string has a length given by the function len, the kind of a value is shown by the function type, and f-strings assemble text from variables. Variables change on the go, count plus-equals one, and the functions int and str convert values between kinds. The program now remembers, but so far it walks a single road without turning. In the next chapter we cover conditions: we will teach it to choose.
