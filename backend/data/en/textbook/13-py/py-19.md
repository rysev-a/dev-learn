Python as a first language. Chapter 19. Operator overloading. When you add two numbers, Python performs addition. When you add two lists, you get concatenation. Two strings are concatenated too, and sets have no addition at all. Where does such variety come from? The plus operator is just a notation for calling a special method on the left operand. So your class can teach its objects to add, subtract, multiply, and compare, and they will behave like numbers, vectors, money, or matrices. This is called operator overloading, and in this chapter we will go through it.\n\nEach arithmetic operator has its own method: addition, subtraction, multiplication, division, floor division, remainder, and exponentiation. The expression "a plus b" turns into a call of the addition method on a, with b as the argument. The main rule: an arithmetic method returns a new object and does not change the operands. Numbers and strings behave this way, and so you avoid unexpected side effects when the same value sits in several places of the program at once.\n\nWhat if the left operand does not know how to work with the right one? A vector can be multiplied by a number, but what about "number times vector"? The number knows nothing about vectors, so its multiplication method returns the value NotImplemented. Then Python flips the expression and calls the reflected method on the right operand: for multiplication its name starts with the letter r. Reflected methods are also what make the built-in sum work: it starts from zero, which means you need to be able to add a number to your object.\n\nAssignment operators, such as plus-equals, have their own in-place methods. If you do not write them, Python falls back to ordinary addition and stores the result in the same variable. But for mutable objects, for example lists, plus-equals changes the object itself and returns it. If you implement such a method, it must return self, otherwise the variable will end up holding None. This explains a well-known effect: if a list has two names, plus-equals changes the list for both of them, while for a tuple it creates a new object.\n\nUnary operators can be overloaded too: negation, unary plus, absolute value, and bitwise inversion. For a vector, negation reverses it, and the built-in absolute value function naturally returns its length. A separate group is type conversions: to integer, to float, and to complex, as well as rounding. They are called on an explicit conversion, and your object can pretend to be a number where that makes sense. The same rule holds everywhere: the method is looked up on the type and returns a new value.\n\nThe index method holds a special place. Unlike conversion to integer, it declares that the object is by its nature an integer. It is exactly what list indexes and slices require, as do the hexadecimal and binary notation functions and range. So an enumeration member or a step number can serve as an index without extra conversions. Conversion to integer allows loss of data, as with floats, while index must be exact, so fractions and floats do not have it, and a list cannot be indexed by them.\n\nThe remaining operators work the same way. Bitwise and, or, exclusive or, shifts, and inversion suit flags and masks. Matrix multiplication got its own sign, the at sign, and its method is called matmul. For sets in the standard library, the vertical bar means union, the ampersand means intersection, and minus means difference. The membership operator calls the contains method, which we will discuss in the next chapter. Choose the sign that reads naturally: plus for joining and accumulating, the asterisk for repetition and scaling.\n\nA good example is a vector class. It stores two coordinates and supports addition, subtraction, multiplication by a number, negation, absolute value, and comparison. All the methods return new vectors, and so that subclasses keep working, instead of a hard-coded class name they use the type of the object itself. If you make the vector immutable and add a hash, it can sit in sets and serve as a dictionary key, which is handy, for example, for coordinates on a map. That is how a few methods turn an ordinary class into a full-fledged quantity.\n\nHow should you check the type of the right operand? A strict check with isinstance rejects foreign types, but it gets in the way of duck typing: an object from another library might have been a fit. A common compromise: try to work, and if the type is clearly wrong, return NotImplemented. Do not raise a type error yourself until both operands have been tried: Python will raise it with a clear message. Decimal numbers behave this way: they gladly add to integers but refuse floats, and you immediately learn about the mixing of types.\n\nLook at how the standard library uses overloading. The difference of two dates gives a time interval, and a date plus an interval gives a new date. A path from the pathlib module is built with a slash, as in a command shell. A counter from the collections module can be added and subtracted, combining the counts. Fractions and decimal numbers behave like ordinary numbers. In all these cases you can see the common rule: an operator should mean what the reader intuitively expects, and the result is usually of the same or a related type.\n\nTypical mistakes. You must not change an operand in an ordinary arithmetic method. You must not forget reflected methods if the operation should work from both sides. You must not return anything but self from an in-place method. You must not give an operator a meaning nobody expects: for example, using a shift for writing to a stream. In some languages that is customary, but in Python the reader will stumble at once. And do not forget to keep equality, hash, and ordering consistent with arithmetic, so that values behave coherently.\n\nThere is a subtle rule of order. Usually Python first tries the method of the left operand, then the reflected method of the right one. But if the right operand belongs to a subclass of the left operand's type and overrides the reflected method, it is tried first. This gives the subclass a chance to intercept the operation. That is why reflected methods are written symmetrically, and a subclass returns the subclass type. Tricky cases are easy to check in the console by printing which method fired: that is faster than holding the rule in your head.\n\nLet's sum up. Every operator is a call of a special method: addition, subtraction, multiplication, and division return a new object. If the left operand could not cope, return NotImplemented, and Python will try the reflected method of the right one. In-place methods must return self. Unary operators, conversions, and index complete the picture, while the bitwise signs and matmul are for flags and matrices. Choose an operator by meaning, not by brevity.
