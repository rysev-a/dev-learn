#CHAPTER 36 | Regular expressions
Python as a first language. Chapter 36. Regular expressions. String methods, such as find, replace and split, solve simple problems. But what do you do when you need to find every phone number in a text, check that a string looks like an email address, pull a date and an error code out of a log, or replace all the repeated spaces? For tasks like these there is a pattern language called regular expressions. A pattern describes not one particular string but a whole family of strings: three digits, a hyphen, four digits. The engine walks through the text and finds every place that fits the description. In Python this is the job of the re module. Regular expressions look scary until you learn a handful of basic building blocks, and after that they become a powerful and very compact tool. Today we will learn those blocks and see where regular expressions shine and where they are dangerous.\n\nLet's start with the simplest case. A pattern made of ordinary letters means exactly those letters. Special characters extend the language: a dot means any character except a newline. Square brackets define a set of allowed characters: square brackets with a, dash, z mean any lowercase letter in that range. There are shortcuts for common sets: backslash d is a digit, backslash w is a letter, a digit or an underscore, and backslash s is a whitespace character. Their capital versions mean the opposite. A caret at the start of a pattern anchors it to the beginning of the string, and a dollar sign at the end anchors it to the end. The search function looks for the pattern anywhere in the string, match only at the very beginning, and fullmatch requires the whole string to fit. The result is either a match object or nothing.\n\nThe number of repetitions is described by quantifiers. A star means zero or more times, a plus means one or more, and a question mark means zero or one. Curly braces let you set an exact number or a range: backslash d with three in braces means exactly three digits, and two comma four means from two to four. A quantifier applies to the nearest element on its left. Pay attention to an important property called greediness: by default, a pattern grabs as much as it can. A dot followed by a star, applied to a string with two pairs of angle brackets, will capture everything from the first opening bracket to the last closing one. To become lazy and take the minimum, you add a question mark after the quantifier. Greediness is the source of half of all the surprising results that beginners run into.\n\nParentheses create groups. They do two jobs: they let you apply a quantifier to a whole fragment, and they remember the piece of text that matched. The findall function returns a list of all non-overlapping matches, and if the pattern contains groups, it returns a list of tuples made of those groups. The finditer function hands out match objects one at a time, and each one has the methods group, groups, span, start and end. Group zero is the whole match, and group one is the first group. Span reports the positions in the string. So, from the string order number one hundred twenty three from the fifth of March, you can get the number by taking the first group of the pattern. Groups are the main way not just to check a string but to extract the data you need from a text.\n\nGroups can be given names: an opening parenthesis, a question mark, the letter P, and the name in angle brackets. Then you refer to the group by name instead of by number, and the pattern reads better: year, month, day instead of group one, two, three. The groupdict method returns all the named groups as a dictionary. If you do not need to remember the text, the group is made non-capturing: an opening parenthesis, a question mark, a colon. Alternatives are written with a vertical bar: cat or dog. It has the lowest priority, so it is usually wrapped in a group. A useful habit is to build a complex pattern out of parts and add comments to it, which we will mention when we get to flags. After all, reading somebody else's pattern is hard, and reading your own a month later is not much easier.\n\nFor replacement there is the sub function: it takes a pattern, what to replace it with, and the text. The replacement can refer to the remembered groups: backslash one inserts the first one. For example, you can swap a last name and a first name. Instead of a string you can pass a function: it receives the match object and returns the replacement, which lets you do calculations right in the middle of the replacement. The count parameter limits the number of replacements. The subn function additionally returns how many replacements were made. The split function cuts a text by a pattern, which is handy when the separators vary: a comma with or without spaces, a semicolon. This is something the plain split method cannot do. Together, findall, sub and split cover the vast majority of text cleaning and parsing tasks.\n\nIt is customary to write a pattern as a raw string: the letter r stands before the opening quote, and Python does not process backslashes. Without it, you would have to double every backslash d, and the pattern would turn into a cipher. If a pattern is used many times, you compile it: the compile function returns a pattern object with the same methods: search, findall, sub. It is faster and more readable. Flags change the behavior: ignoring case, a multiline mode where the caret and the dollar work on every line, a dot that also matches a newline, and verbose mode, in which spaces and comments inside the pattern are ignored. Verbose mode is the best way to write complex patterns: each part on its own line and with an explanation.\n\nSome elements do not capture characters but check the context. Backslash b is a word boundary: the pattern backslash b, cat, backslash b will find the whole word cat, but not cats and not kettle. A lookahead asks what comes next: a number followed by a percent sign. A lookbehind asks what came before: digits after a dollar sign. They do not become part of the result, but they influence whether a match is accepted. The negative versions check that something is absent. This is an advanced but extremely useful tool, especially when parsing complicated formats. Do not be afraid to experiment: the most convenient way to learn regular expressions is to paste an example into an online checker or a console and watch what gets highlighted as you change the pattern one character at a time.\n\nExamples from practice. Checking a format: a date as day, dot, month, dot, year, a phone number, a postal code. Extraction: all the numbers in a text, all the words with a capital letter, all the hashtags, email addresses. Cleaning: squeeze consecutive spaces into one, remove everything except letters and digits. Parsing a log: take a line with a date, a level and a message, pull out the parts with named groups and turn them into a dictionary. Counting words while taking case and punctuation into account: find all the words with the pattern backslash w plus and hand them to a counter. All of this takes a couple of lines, while writing the same thing without regular expressions would take dozens of lines of loops and conditions. But note that there are no perfect patterns for an email address or a phone number: a pattern check only filters out obvious garbage.\n\nRegular expressions have limits. First: do not use them to parse a language with nested structure, such as HTML, JSON or expressions in parentheses. There are real parsers for that, and a pattern breaks down on nesting. Second: a badly written pattern can hang on a long string, because the engine tries countless variants. This is called catastrophic backtracking, and it has caused real service outages. Avoid nested quantifiers, such as a group with a plus inside and another plus outside. Third: solve simple tasks with simple methods. To check the start of a string there is startswith, to check for containment there is the word in, and for replacement there is the replace method. A regular expression is appropriate when you need flexibility: variants, repetitions, groups. If a pattern takes more than a couple of lines, think about whether two simple steps would be better.\n\nA word about Russian text. Strings in Python are Unicode, and backslash w by default recognizes Russian letters too, not only Latin ones. The range from the Cyrillic a to the Cyrillic ya does not include the letter yo: you have to add it separately, which is an old and unpleasant quirk of the encoding. Capital and lowercase letters are different, and the ignore-case flag works for Cyrillic too. To make backslash w recognize only Latin characters, there is the ASCII flag. Backslash d also recognizes digits from other alphabets, for example Arabic-Indic ones, which can be unexpected: if you need only ordinary digits, you write the range zero to nine. These details are not obvious, but knowing them saves you from confusion when you parse real texts, especially user-written ones, where you will see everything.\n\nTypical mistakes. First: not using raw strings. Second: mixing up match and search, since match looks only at the start of the string. Third: forgetting about greediness and getting a match that is too long. Fourth: not escaping special characters, such as the dot, parentheses and the plus, with a backslash when you need exactly those characters; for this there is the escape function. Fifth: accessing a group when there is no match: the result is empty and the method call will fail, so you must check the result. Sixth: trying to validate with regular expressions something that is harder to validate, such as a truly valid email address or a real phone number. Seventh: unreadable monsters instead of verbose mode. Eighth: forgetting about catastrophic backtracking and feeding user input to a dangerous pattern.\n\nLet's sum up. A regular expression is a pattern for a family of strings. The basic elements are the dot, sets in square brackets, backslash d, backslash w, backslash s, and the anchors caret and dollar. The quantifiers star, plus, question mark and curly braces set the repetitions, and by default they are greedy. Parentheses create groups, and named groups are easier to read. Search, match and fullmatch look for a pattern, findall and finditer collect matches, sub replaces and split cuts. Raw strings, compile and verbose mode make patterns readable. Backslash b and context checks refine the boundaries. Do not use regular expressions for nested formats.
