#CHAPTER 35 | Date and time
Python as a first language. Chapter 35. Date and time. Time is one of the trickiest topics in programming. Months of different lengths, leap years, time zones, daylight saving time, notation formats that differ in every country: these details have broken the programs of the best companies. The good news is that Python's standard library takes most of the complexity on itself. The datetime module provides types for dates, times, and the intervals between them, the time module gives access to the system clock and the timer, zoneinfo knows the time zones, and calendar answers questions about months. Today we will learn to create and parse dates, calculate the difference, format, work with time zones, and avoid the typical traps that people usually find out about too late.\n\nThe four main types of datetime. Date stores only the date: year, month, day. Time stores only the time of day: hours, minutes, seconds. Datetime stores the date and time together. Timedelta is an interval of time. They are easy to create: date from a year, a month, and a day; datetime with hours and minutes added. The current moment is returned by datetime dot now and date dot today. The objects have the attributes year, month, day, hour, minute, second, and the method weekday returns the day of the week as a number from zero, where zero is Monday. All of these objects are immutable: to change a field, you use the method replace, which returns a copy. They can be compared, sorted, and used as dictionary keys, and they understand neatly what “earlier” and “later” mean.\n\nA timedelta describes an interval: days, seconds, hours, minutes, weeks. You can add a date and an interval: tomorrow is today plus a timedelta of one day. Subtracting two dates gives a timedelta: how many days between two dates, how many until a birthday. The result has the attribute days and the method total_seconds for converting to seconds. Intervals can be added to each other, multiplied by a number, and compared. There is an important limitation: a timedelta has no months or years, because their length is not constant. You cannot add a month with ordinary arithmetic: you have to count the month number by hand or use external libraries. It is worth remembering this limitation: it explains where many beginners' mistakes come from when they calculate deadlines.\n\nFormatting a date into a string is done by the method strftime, and the way of writing is given by a template with percent signs. Percent capital Y is the four-digit year, percent lowercase m is the month, lowercase d is the day, capital H is the hours, capital M is the minutes, and capital S is the seconds. You get the familiar day, dot, month, dot, year. For machine exchange, there is a standard representation under the international standard: the method isoformat returns a string of the form year, month, day, the letter T, and then the time. This notation sorts as text in the same order as by time, so it is the best one for storing dates in files and databases. The names of months and weekdays depend on the locale and may come out in English, so for an interface in another language people usually use their own dictionaries of names or external libraries.\n\nParsing a string into a date is done by strptime: it takes a string and the same template. If the string does not match the template, a value error is raised, and you need to catch it when the data comes from a user. For the standard notation there is a shorter way: the method fromisoformat, which is isoformat in reverse, parses such strings without a template. One of the most reliable practices is to store and pass dates in the standard format and turn them into a human-readable form only at the output. There is an extra check as well: Python will not create a nonexistent date such as the thirtieth of February, and will report an error instead. So parsing and creating a date is already a check that the date exists.\n\nTime zones are the main source of confusion. A datetime object can be naive, with no information about the zone, or aware, with a zone. You can compare and subtract only objects of the same kind, otherwise a type error is raised. Naive time means “somewhere, local”: it is fine for a calendar in one country and dangerous for everything else. An aware time is created with the timezone argument: UTC is the universal point of reference. The zoneinfo module knows zones by names like Europe slash Moscow: a datetime with this zone shows the local time and knows the offset. The method astimezone converts a moment from one zone to another. The golden rule: store and calculate in UTC, and convert to local time only when showing it to the user.\n\nThe time module works with the system clock in the form of numbers. The function time returns the number of seconds since the start of the epoch, the first of January, nineteen seventy, in UTC. This is the so-called Unix time, and many systems store time exactly this way. The function sleep pauses the program for a given number of seconds. To measure how long code runs, there is perf_counter: the most precise timer, which does not depend on adjustments of the system clock. Monotonic also never goes backward. A typical pattern: take perf_counter before, take it after, and subtract. The method timestamp turns an aware datetime into a number of seconds, and fromtimestamp turns it back. Timing is useful when you compare two solutions to the same problem: you cannot judge speed by feel, the numbers do not lie.\n\nDates can be compared, which means they can be sorted and used in min and max. The earliest date in a list is the minimum, the last one is the maximum. A range of dates is built with a loop or a generator: the start plus a timedelta of one day, until you reach the end. The method isocalendar gives the week number in the year, and the method weekday gives the day of the week. To get the working days, it is enough to drop those for which weekday is greater than four. The days until an event are a subtraction of dates. All of these operations are combinations of things you already know: arithmetic, comparison, generators. Only the set of types is new. Once you invest time in learning it, you will start solving real-life problems: schedules, reminders, statistics by day of the week, reports by month.\n\nThe calendar module answers questions about the calendar. The function isleap reports whether a year is a leap year, leapdays counts the leap years in a range, and monthrange returns the weekday of the first day and the number of days in a month. With it, it is easy to find the last day of a month: take the second part of the answer. The Calendar class can print nice calendars for a month and for a year. And the first day of the week is configurable: in some countries the week starts on Monday, in others on Sunday. A useful task about a date of birth is to compute the age in years. Simply dividing the days by three hundred sixty-five gives wrong results because of leap years; the right way is to subtract the years and adjust if the birthday has not yet come this year.\n\nTypical tasks. How many days are left until New Year: the difference of two dates. What day of the week it was on your birthday: the method weekday and a list of names. How many working days are in a month: a loop over the days with a filter. How long a function ran: perf_counter before and after. When a reminder will fire if you add ninety minutes to the current time. Grouping log entries by date. Sorting events by time. In logs, you most often meet lines with a date at the start: we parse it with fromisoformat or strptime, and then we count. All of this is solved with one module and a couple of lines, if you do not forget the main rules about zones and the standard notation format.\n\nDates and the JSON format. JSON does not know a date type, and an attempt to write a datetime causes a type error. The way out is to write a string: the method isoformat, and when reading, turn it back with fromisoformat. For an automatic solution, the function dumps has a parameter default, where you pass a function that turns unknown objects into strings. The same goes for databases and CSV: text or a number is stored, and the types are restored on reading. A good habit is to describe in one place a “to string” function and a “from string” function for all the dates in your program, so that the format never diverges. As a result, the storage format becomes part of the contract, and nobody has to guess what kind of record is in front of them.\n\nCommon mistakes. The first: mixing naive and aware dates and getting a type error on comparison. The second: storing local time instead of UTC, especially around daylight saving transitions: one hour may not exist, and another may repeat twice. The third: trying to add months with a timedelta. The fourth: computing age by dividing days by three hundred sixty-five. The fifth: not accounting for the fact that date formats differ between countries: day and month get mixed up. The sixth: using the current-time function without a zone and being surprised by errors when you deploy to a server in another zone. The seventh: relying on month names in a given language without setting the locale. The eighth: comparing date strings in a nonstandard format: the order comes out wrong. The ninth: using the deprecated function utcnow, which returns naive time.\n\nLet's sum up. The datetime module contains date, time, datetime, and timedelta: immutable objects that can be compared and sorted. The difference of dates gives a timedelta, and it has no months or years. Strftime formats, strptime and fromisoformat parse, and the standard notation is convenient for storage. You must not mix naive and aware dates; store in UTC, and convert to local time through zoneinfo and astimezone. The time module gives Unix time, sleep, and the precise perf_counter. The calendar module knows about leap years and the lengths of months. Dates are written to JSON as strings. In the next chapter, regular expressions: a language for searching text by pattern.
