#CHAPTER 7 | Lists: iteration and copying
Python as a first language. Chapter 7. Lists: iteration and copying. In the previous chapter you learned the list as a container: how to create it, index it, grow it and slice it. But the real life of a list begins when you start working with it seriously. You need not only an element but also its number. You need to walk through two lists at once, like two columns of a table. You need lists inside lists. And you need to know how to copy data so that editing the copy does not spoil the original. That is the trickiest topic of the chapter, and even experienced programmers stumble on it. Today we will cover iteration with numbers, pairing lists up, adding many elements at once, nested lists, references and copies, and at the end we will collect the typical traps. Master this chapter, and lists will stop surprising you.\n\nLet us start with iteration. The for loop over a list hands you the elements, but sometimes you need the number too: to print a list with numbering, to find the position of the largest element, to show exactly where an element was found. Beginners do it like this: they take range from zero to len of the list and fetch elements by index. That works, but it looks clumsy and opens the door to off-by-one errors. For such cases Python has the function enumerate, which means to number. It hands you pairs: first the number, then the element. In the loop header you write two names separated by a comma, say i and name, and on every pass Python unpacks the pair into these two variables. The numbering, as always, starts from zero. But enumerate has a second argument called start: pass one, and the count begins at one, like in an ordinary numbered list. One loop header instead of a counter, len and indexing.\n\nNow imagine two columns of a table: one list has the students' names, the other has their grades, and you need to walk through both at once. For this there is the function zip, and the comparison is exact: it closes two lists tooth by tooth, like a zipper. On every pass zip hands you a pair of elements with the same number: the first name with the first grade, the second with the second. In the loop header there are again two names separated by a comma: for name, grade in zip of names and grades. No indexes, no ranges. There is an important detail: if the lists have different lengths, zip stops at the shortest one and silently drops the tail of the longer one. Sometimes that is convenient, and sometimes it is treacherous: the mistake shows up not as a crash but as lost data. So when the lists must be the same length, it is better to compare their lengths first. Zip can also glue together three lists or more, just list them separated by commas.\n\nNow for the pattern that appears most often in data processing: building one list from another. The first variety is called filtering: pick out of the list only what fits. The scheme is familiar from the previous chapter: create an empty result list, loop over the source with for, and if the element meets the condition, call append. This is how you pick even numbers, long words, unread emails. The second variety is transformation: make something new out of each element and put it in the result. Squares of numbers, lengths of words, names in capital letters. Both can be combined in one loop: select and transform right away. An important point: the source list stays untouched, because we build a new one. This is safer than editing in place: nobody can spoil the original data, and code that changes nothing is predictable. Remember the pattern of four steps: an empty result, a loop, a condition, append.\n\nAppend adds exactly one element to the end, whatever it is. If you give it a whole list, that list lies inside as a single element, and you get a list with a list inside. Often that is not what you want. To pour many elements onto the end at once, there is the method extend: it takes any collection and adds its elements one by one. The difference is simple: append puts the box in whole, extend pours out the contents of the box. For inserting in the middle there is the method insert: the position comes first, the value second, and the old elements to the right shift over. Inserting at the start means position zero. There are operators too: plus glues two lists into a new third one, and multiplying a list by a number repeats it that many times. A list with one zero, multiplied by five, gives five zeros. Remember the difference: append, extend and insert change the list in place, while plus builds a new one.\n\nAn element of a list can be anything, including another list. That is how tables appear: a list of rows, where each row is also a list of numbers. For example, a tic-tac-toe board is three rows of three cells. To get one particular cell, you need two indexes in a row: the first picks the row, the second picks the column within that row. It reads from left to right: from the board we take row number one, and from it, element number two. You can change a cell through two indexes as well: the assignment reaches the right place. It is convenient to walk through a table with two nested loops: the outer one goes over the rows, the inner one over the elements of a row. This is the same nesting technique as in the multiplication table from the chapter on loops. The rows do not have to be the same length: a row can be empty, or longer than its neighbor. But for tables you usually keep a regular shape, with all rows the same length.\n\nAnd now the most important topic of the chapter. What does the assignment b equals a do, if a is a list? Many people expect a second list with the same numbers to appear. But in fact Python copies nothing: it merely hangs a second name tag on the very same list. The names a and b now point to the same object, and this is called a reference. Check it by experiment: add the number four through b, and if you look at a, you will find it there too. No surprise: there is one list and two names. For numbers and strings there is no such effect, because they cannot be changed in place, only rebuilt. But mutable objects, lists first of all, behave exactly this way. A handy picture: the list is a house, the name is the address on an envelope. You copied the envelope, and the house is still one. Because of this effect, the most mysterious bugs are born in other people's programs: data changes by itself.\n\nSo how do you get a real copy, that is, a new list with the same elements? There are three ways, and you already know the first: a slice with no boundaries, just a colon in square brackets. The second is the method copy: a dot copy, with empty parentheses. The third is the function list: list of a builds a new list from the elements of any collection. All three give an independent list: add an element to the copy, and the original does not notice. But these ways have a limitation that is important to know: the copy is shallow. It copies only the outer list, while its elements that are lists remain shared. If you copy the outer list of a table, the rows stay the very same rows in both copies. Editing a cell in the copy will show up in the original too. For nested data there is a deep copy, the function deepcopy from the standard library, which copies all levels at once. We will meet it when we get to libraries. For now it is enough to remember that a shallow copy does not save you from nesting.\n\nHow do you find out whether two lists are the same? For that there is the double equals operator: it compares the contents element by element. Two different lists with the same numbers in the same order it will call equal, and the order matters: the same numbers in a different order make unequal lists. There is another operator, the word is. It checks not the contents but the identity: whether it is the same object. For two references to one list the answer is true, and for a real copy it is false, even though the contents are the same. The rule is this: for the question of whether the data is the same, always use double equals. And keep the word is for the question of whether this is the very same object. Mixing them up is a classic mistake: code may accidentally work on small examples and break on big ones. Now you have a tool to tell a copy from a second name: on a copy, double equals says true and is says false.\n\nNow a trap that everyone falls into. The task: remove all negative numbers from a list. The straightforward solution: loop over the list with for, and if an element is negative, call remove. It looks reasonable, and it breaks. The reason is that the loop goes by position numbers, and a deletion shifts everything else to the left. You deleted an element, the next one took its place, and the loop has already stepped further and jumped over it. If two negatives come in a row, the second one stays in the list. The bug is treacherous: on short tests it may not show up. There are two honest ways. The first: build a new list from the suitable elements, as in our filtering pattern. It is the cleanest and the most common. The second: go over a copy but change the original, that is, a for over a slice, a colon in the brackets. The general rule: never add or remove elements of a list that you are currently looping over.\n\nHere are a few more useful methods worth knowing. The method index answers the question of which position an element is at: it returns the number of the first occurrence. If there is no such element, Python reports an error, so check membership with the word in first. The method count answers the question of how many times: it counts occurrences of a value. The method reverse flips the list in place: the first becomes the last. There is also a reversal with a slice: colon, colon, minus one is a step backwards, and it gives a reversed copy without touching the original. The method clear empties the list completely, leaving it empty but alive. Finally, the familiar max, min and sum work on slices too: the maximum of the first three, the sum of the last five. By combining slices and summaries, you can solve tasks in one line. But do not forget that behind every such line there is a loop, just hidden inside.\n\nLet us collect the typical traps of the chapter. The first: append returns nothing. Writing nums equals nums dot append of five wipes the list out with nothing: the method changed the list in place and returned nothing. Just call append on a line of its own. The second: a table built by multiplication. Writing a list of a list of zero multiplied by three, all multiplied by three, seems like a quick way to make a three by three board. But the outer multiplication repeats the same inner row three times, and all three rows are one list. Fix one cell, and a whole column changes. The right way is to build the rows with a loop: a fresh list on every pass. The third: taking an element from an empty list. Index zero or pop on an empty list is an error. If the list might turn out empty, check its length first; an empty list counts as false in a condition. The fourth: confusing the index with the value. A for loop over a list hands you values, not numbers.\n\nLet us sum up. Enumerate adds numbers to iteration, and start lets you begin counting at one. Zip walks through several lists at once and stops at the shortest. The pattern of an empty result, a loop, a condition and append builds one list from another. Append puts in one element, extend pours in many, insert puts one at a position, and plus glues into a new list. Lists nest inside each other, and a cell of a table is reached with two indexes in a row. The main discovery of the chapter: assignment does not copy, it hangs a second name tag on the same list, so a real copy is made with a slice, the method copy or the function list, and remember that it is shallow. Double equals compares contents, and is compares the identity of objects. Do not delete elements from a list that you are looping over.
