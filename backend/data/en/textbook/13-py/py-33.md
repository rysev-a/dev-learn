Python as a first language. Chapter 33. Collections: collections, heapq and bisect. We have covered the main built-in containers: the list, the dictionary and the tuple. But in real tasks they often need a wrapper: counting frequencies, grouping without checking keys, building a queue without losing speed, storing records with named fields, keeping data ordered. For this the standard library has the collections module, a set of specialized containers built on top of the built-in ones. Next to it live two small but important modules: heapq, which keeps data as a heap, and bisect, which searches and inserts into sorted lists using binary search. Today we will meet them: the counter, the dictionary with a default, the double-ended queue, the named tuple, the heap and binary search. These are tools you meet in algorithm problems and in everyday code.\n\nCounter is a dictionary designed for counting. Give it any iterable, and it counts by itself how many times each element occurred: a counter built from the string abracadabra returns pairs of a letter and a number. Accessing a missing key does not fail, it gives zero, so you don't need the usual get with a zero, plus one pattern. The most common method, given a number, returns the pairs with the largest counts in descending order: the most frequent words of a text in a single line. Counters can be added and subtracted: the sum merges the counts, the difference keeps only the positive remainders. The update method adds new data to an existing counter. It is more powerful than an ordinary dictionary and just as easy to use: a counter is set up in one line and removes a whole loop.\n\nThis is where a counter really shines. Counting words in a text: split it, pass it to a counter, ask for the top three. Checking anagrams: two words are anagrams if their letter counters are equal. Counting characters, digits, grades, votes. Checking whether you have enough letters to build a word: subtract the counters, and if the difference is empty, you have enough. Compare this with what we wrote by hand several chapters ago: a loop, a dictionary, a key check. The counter takes all of that on, leaving only the essence of the task. This habit of looking for a ready-made tool pays off twice: the code is shorter and there are fewer bugs, because the standard library has been tested by millions of users. But don't forget that a counter is still a dictionary: its keys must be hashable.\n\nDefaultdict is a dictionary with a factory for default values. You give it a function with no arguments, for example list, int or set, and when you read a missing key, the dictionary creates the value by calling that function and stores it under the key. Grouping turns into two lines: a defaultdict of list, then groups by key, dot append of the element. You need neither an existence check nor setdefault. For counting, a defaultdict of int fits: the default value is zero. There is also a catch to keep in mind: even simply reading a missing key creates it. A check with the word in is safe and creates nothing, while square brackets create an empty entry. If you only need to read, use get or the word in.\n\nA deque is a double-ended queue: a structure from which elements can be quickly added and removed at both ends. For a list, appending at the end and removing from the end are fast, but operations at the front are slow, because all the other elements have to be shifted. A deque doesn't have this problem: append and appendleft add on the right and on the left, pop and popleft remove from the same places, and it all works almost instantly regardless of size. The maxlen parameter makes a deque bounded: when it overflows, elements from the opposite end are pushed out automatically. The rotate method shifts the elements in a circle. A deque is the basis of queues in algorithms: breadth-first graph traversal, schedulers, buffers. There is one drawback: accessing elements in the middle by index is slower than in a list.\n\nLet's see a deque in action. A job queue: add at the right end, process from the left, and the order is fair: first in, first out. A sliding window of the latest values: a deque with a maximum length of three keeps the last three numbers, new ones push out old ones, and the average over the window is computed without manual removal. A bounded history of user actions. A circular game where players take turns: that is rotate. Breadth-first traversal of a graph: a queue of vertices, from which we take neighbors and put new ones at the tail. All of this can be done with a list, but you will lose speed on large data. The rule is simple: if you need a queue, take a deque; if you need a stack, a list with append and pop is enough.\n\nNamedtuple is a named tuple. You describe it with a class name and field names, and you get an immutable record whose values can be accessed both by index and by name. A dot instead of an index makes the code readable: point dot x instead of element zero. Such a tuple takes the same memory as an ordinary one, and it can be unpacked, compared and used as a dictionary key. The replace method returns a copy with some fields changed, and the as dict method turns the record into a dictionary. A named tuple sits halfway between a tuple and a class: you don't need to write a constructor or a repr method, but you can't add behavior either. For records without logic, such as points, colors or table rows, a named tuple is the best choice. A more modern variant with types lives in the typing module.\n\nTwo more containers. ChainMap glues several dictionaries into one view without copying: lookup goes through the layers from left to right, and the first key found wins. The ideal example is settings: a layer of environment variables, a layer of user settings, a layer of defaults. Writing goes to the first layer, and the others stay untouched. OrderedDict is a dictionary that remembers insertion order. Modern ordinary dictionaries remember the order too, so OrderedDict is needed less often, but it has the move to end method for rearranging keys, and comparing two such dictionaries takes the order into account. Caches that throw out the least recently used entry are built on it. There are also wrapper classes for inheritance: UserDict, UserList and UserString. They are useful when you want to change the behavior of a built-in container.\n\nHeapq is a module for a heap, or priority queue: a structure from which you can always quickly take the smallest element. The heap lives in an ordinary list, and the module provides functions: heappush puts an element in, heappop takes out the smallest, and heapify turns a ready-made list into a heap. Getting the smallest in very little time, and adding a new one quickly too, is exactly the balance that neither a sorted nor an unsorted list gives. If you need the largest element, you store numbers with the opposite sign. For records with priorities, tuples are used: the priority goes first, the value itself second, and tuples are compared from left to right. The nsmallest and nlargest functions return several smallest or largest values of a collection without a full sort, and merge lazily merges several sorted streams.\n\nWhere do you need a heap? A task scheduler that always takes the most urgent one. The top k largest values from a large stream: keep a heap of k elements and throw out the smallest. Dijkstra's algorithm on graphs, which we discussed in the algorithms course, relies on it too. Merging several sorted files into one. The median of a data stream. Notice an important property: a heap is not fully sorted. There is only one guarantee: the minimum lies at the start of the list; the other elements are arranged by a special rule, and iterating over the heap's list will not give sorted values. To get the values in order, you have to pop them one by one or use the sorted function.\n\nBisect is binary search in a sorted list. The bisect left function returns the position where a value should be inserted to keep the order, and if the value is already there, the position before it. Bisect right does the same, but returns the position after the last equal value. The search takes time proportional to the logarithm of the size, so a million elements need only about twenty steps. The insort function inserts a value straight into the right place. A typical use is threshold tables: a grade from a score, a tax rate from an income. The list of boundaries is ordered, and bisect tells you which interval the value fell into. It is also a fast membership check in a sorted list and a way to find the nearest value. The main requirement: the data must already be sorted, otherwise the result is meaningless.\n\nCommon mistakes. First: when you subtract counters with the minus operation, negative values disappear, while the subtract method keeps them, and you need to take that into account. Second: reading a missing key of a defaultdict creates an entry, which makes the dictionary grow unexpectedly. Third: using a list as a queue on large data instead of a deque. Fourth: accessing the middle of a deque by index in a loop, which is slow. Fifth: assuming the heap is sorted and iterating over it in order. Sixth: putting items into a heap that can't be compared with each other, for example dictionaries; to fix this, add a unique number to the tuple. Seventh: applying bisect to an unsorted list. Eighth: trying to change a field of a named tuple: it is immutable, so you need replace.\n\nLet's sum up. A counter counts elements, returns the most frequent ones and can be added. Defaultdict creates a value when you access a new key, but reading creates an entry too. A deque is a double-ended queue with fast operations at both ends, and maxlen turns it into a window. A named tuple is an immutable record with field names. ChainMap glues dictionaries into layers, OrderedDict remembers insertion order. Heapq holds a heap: heappush, heappop, nsmallest and nlargest, and the heap is not fully sorted. Bisect searches and inserts into a sorted list in logarithmic time.
