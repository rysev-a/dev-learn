Python as a first language. Chapter 34. Numbers and randomness. Numbers are the foundation of any program, and in Python they come with surprisingly many subtleties. Floating-point numbers are calculated with a small error, division comes in different flavors, and rounding does not work the way you were taught at school. Money needs exact arithmetic, scientific calculations need functions like sine and logarithm, games and simulations need random numbers, and data analysis needs the average and the spread. All of this already lives in the standard library: the modules math, random, statistics, decimal, and fractions. We will also talk about security: random numbers for a game and for a password are two different things. Today we will see why zero point one plus zero point two is not equal to zero point three, how to round correctly, how to calculate exactly, and how to get randomness where you need it.\n\nThe math module contains mathematical functions. The square root is sqrt, the power is pow or the double asterisk operator, the ceiling and the floor are ceil and floor, and dropping the fractional part is trunc. There are the constants pi and e, the logarithm log, sine, cosine, and tangent, and the function hypot for the length of a hypotenuse. For integers there is gcd, the greatest common divisor, lcm, the least common multiple, factorial, and also comb and perm, which count combinations and permutations: exactly what we studied in discrete mathematics. The special values infinity and not-a-number live here too, and the functions isinf and isnan check whether you have got one of them. The math module is a surprisingly powerful toolkit: most calculations fit within its capabilities.\n\nWhy is zero point one plus zero point two not equal to zero point three? Because floating-point numbers are stored in binary, and one tenth in binary is an infinite fraction, like one third in decimal. The computer rounds it to the nearest representable value, and the error accumulates. This is a property not of Python but of any language and processor that uses standard floating-point numbers. From this follows a rule: never compare floating-point numbers for exact equality. Instead, ask whether they are close enough: the function isclose compares with a relative tolerance that you can set. Integers do not have this problem: in Python they are exact and of arbitrary length. A great thing to remember: integers are exact, floats are approximate.\n\nRounding in Python works in an unusual way. The function round rounds to the nearest even number when the value is exactly halfway: round of two and a half gives two, and round of three and a half gives four. This is called banker's rounding, and it reduces the accumulation of error in large calculations. If you need to round up by the school rules, use decimal or your own formula. The second argument of round sets the number of digits after the decimal point, and a negative one rounds to tens and hundreds. For output, formatting is more convenient: colon, dot, two, f gives two digits after the decimal point without changing the number itself. The functions floor and ceil round down and up, and converting to an integer with int drops the fractional part, which for negative numbers is different from floor. Division with two slashes rounds down, and the function divmod returns the quotient and the remainder together.\n\nFor money and for all calculations where precision matters, there is the decimal module. You create a number from a string: Decimal of the string zero point one, and then one tenth plus two tenths is exactly three tenths. You must not create one from a float: it already contains the error. Decimal numbers support all arithmetic operations, and the context sets the number of significant digits and the rounding mode. The quantize method rounds to a given number of places, for example to cents, and you can choose the rounding mode: up, down, to the nearest even, or by the school rules. The price of this precision is speed: decimal is noticeably slower than ordinary floats, so it is not used in scientific computing. For finance, taxes, and bookkeeping it is the standard choice, and rounding errors of a cent will not scare you anymore.\n\nThe fractions module stores ordinary fractions: a numerator and a denominator. One third plus one sixth is exactly one half, with no error at all. You can create a fraction from two integers, from a string like three slash four, or from a decimal notation. Fractions are reduced automatically, all arithmetic operations work on them, they can be compared and used as keys. The method limit_denominator finds the nearest simple fraction with a bounded denominator: from the number three point one four one you get twenty-two sevenths. Fraction is useful wherever you need exact rational arithmetic: in math problems, in musical rhythms, in recipes where portions matter. Like decimal, it is slower than ordinary numbers, but more reliable.\n\nRandom numbers come from the random module. The function random with no arguments returns a float from zero to one, not including one. The function randint takes the bounds and includes both: randint from one to six is a die. The function choice picks a random element of a sequence, choices picks several with replacement, and you can set weights. The function sample picks several different elements without repeats, and shuffle shuffles a list in place. The function uniform returns a float in a range. All of this is pseudo-random: the numbers are produced by a formula that starts from a seed. If you set the seed with the function seed, the sequence becomes reproducible: convenient for tests and debugging, because any random bug can be repeated by running the program with the same seed.\n\nRandomness is a wonderful tool for simulations. Flip a coin a thousand times: count the heads and see that there are about half. The sum of two dice: count the frequencies and see that seven comes up most often. Shuffling a deck and dealing cards with shuffle and slices. Choosing the winner of a prize draw with choice. The Monte Carlo method: estimating pi by throwing random points into a square and counting the share that land inside the inscribed circle is a classic that shows the power of the idea. Weighted choice with the weights parameter helps model unequal probabilities: rare and frequent events. Here the counter from the collections module comes in handy again: we count how many times each result came up and compare with the theory. The more trials, the closer the result is to the expectation.\n\nThe statistics module computes typical characteristics of data. The arithmetic mean is mean, and fmean for floats. The median is the number in the middle of the sorted data, and it is resistant to outliers: the average salary and the median salary can differ a lot. The mode is the most frequent value. Variance and standard deviation show the spread: stdev for a sample and pstdev for a whole population. The function quantiles splits the data into equal parts: for example into quarters or hundredths. Newer versions added correlation and linear regression. The module does not replace specialized libraries for big data, but for small datasets and learning tasks it is more than enough. It also teaches the right way to look at data: a single average is never enough, you have to look at the spread too.\n\nRandomness for security is a separate story. The random module is predictable: knowing a few of the values it produced, you can recover the internal state and learn the next ones. For a game that does not matter, for a password or a reset token it is a disaster. For security there is the secrets module: it uses the source of randomness of the operating system. The function token_hex returns a random string of the requested length, token_urlsafe is suitable for links, and choice picks characters so that the result cannot be guessed. A typical scenario is a password made of random letters and digits. Next to it lies the hashlib module, which computes hashes. The pattern is to store in the database not the password but a hash of the password with a salt. The rule is simple: games and tests use random; everything related to access and protection uses secrets.\n\nIntegers in Python are not limited in size: two to the power of a thousand is computed instantly and exactly, which is rare among languages. Number systems: the functions bin, oct, and hex turn a number into a string with a prefix, and formatting with the letters b, o, and x does the same without the prefix. In the other direction, int of a string with a base converts the notation back into a number. Bitwise operations treat integers as sets of bits: the ampersand is and, the vertical bar is or, the caret is exclusive or, and the shifts left and right multiply and divide by a power of two. Bit arithmetic is needed in network protocols, flags, encryption, and optimizations. You have already met these ideas in the computer architecture course: now you have a language to test them.\n\nCommon mistakes. The first: comparing floats for equality instead of using isclose. The second: being surprised by round, which rounds two and a half down. The third: creating a Decimal from a float instead of a string. The fourth: using floats for money. The fifth: confusing integer division with two slashes with the ordinary one, and forgetting that for negative numbers it rounds down. The sixth: using the random module for passwords and tokens. The seventh: forgetting about the seed and not being able to repeat a failure, and also forgetting that the seed in tests must be fixed. The eighth: computing a big combinatorial number by hand with functions when there are comb and perm. The ninth: taking the mean of an empty dataset: statistics will raise an error.\n\nLet's sum up. The math module gives roots, powers, trigonometry, logarithms, gcd, and combinatorics. Floats are approximate: compare them with isclose. Round rounds to the nearest even number, and formatting sets the digits after the decimal point. Decimal is created from strings and used for money, and fractions stores exact fractions. Random generates pseudo-random numbers: randint, choice, sample, shuffle, and seed makes them reproducible. Statistics computes the mean, median, mode, and spread. For passwords and tokens you need secrets. Integers have arbitrary length, and bitwise operations and number systems open up work with binary data. In the next chapter, date and time.
