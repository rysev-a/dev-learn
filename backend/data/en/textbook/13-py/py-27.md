#CHAPTER 27 | functools and operator
Python as a first language. Chapter 27. functools and operator. We've already learned to pass functions around, create closures and write decorators. The good news is that many typical techniques have already been written for us in the standard library. The functools module collects tools for working with functions: folding, fixing arguments, caching, overloading by type, and shortening comparisons. The operator module turns the language's operators into ordinary functions that are easy to pass to map, sorted and reduce. Together they let you do without lambdas where a lambda would look clumsy. Today we'll go through the most useful of them: reduce, partial, lru cache, single dispatch, total ordering, and then item getter, attribute getter and method caller. This is a case where knowing the library saves hours of work.\n\nLet's start with folding. Reduce takes a function of two arguments, a collection and an optional initial value. It takes the initial value, applies the function to it and the first item, applies the function again to that result and the next item, and so on to the end. That's how a product is computed: reduce of multiplication and the numbers. You can also glue strings together, find an item by a complicated rule, or merge dictionaries. The initial value is not only convenient but also protects you from an error: without it, reduce of an empty collection raises an exception, and with it, reduce returns that very value. The rule of choice is simple: for a sum, a maximum or a minimum there are ready-made functions, and reduce is for where there isn't one. If a fold gets complicated, an ordinary loop reads better.\n\nPartial fixes some of a function's arguments and returns a new function to which you only have to pass the rest. Say you need a function that converts a string from binary. The function int takes a parameter base: partial of int with base equal to two returns a new function with a single parameter, a string. Calling it with the string one-zero-one returns five. Partial replaces a lambda that merely plugs in ready-made values, and makes the code clearer. You can fix both positional and keyword arguments. The result is a callable object that remembers both the function and the parameters. Partial comes in handy when you need to pass a function to a place that calls it with one argument: into map, into event handlers, into a sort key.\n\nLRU cache is a ready-made decorator for caching results. All you do is put it above a function, and repeated calls with the same arguments return the remembered answer. The classic example is Fibonacci numbers computed by recursion. Without a cache, the function calls itself an exponential number of times, and with a cache each number is computed once, so computing the hundredth number becomes instant. The max size parameter limits the size of the cache: when it overflows, the least recently used results are thrown out. In newer versions of Python there is also a simple cache with no limit. The cache info method shows the number of hits and misses. There is just one condition: the arguments must be hashable, that is numbers, strings, tuples, but not lists. And the function's result must depend only on its arguments.\n\nWe've seen how a decorator is written, and we know that wraps preserves a function's name. Now let's add two more decorators, this time for classes. Total ordering saves you from having to define all six comparison methods. It's enough to define equals and one of the ordering operators, for example less than, and the decorator builds the rest. That's convenient when you need to compare your own objects as greater or less: versions, playing cards, ranks. Cached property from the same module turns a method into a property that is computed once on first access and then stored in the object. It suits heavy computations that aren't always needed. It requires the object to have an attribute dictionary, as ordinary classes do, and doesn't work for immutable objects.\n\nSingle dispatch gives you function overloading by the type of the first argument. In other languages you can define several functions with the same name for different types. In Python this role is played by the single dispatch decorator. We define a general function, and for specific types we register separate implementations through register, giving the type. A call picks the right one by itself: one for an integer, one for a string, one for a list. This is cleaner than a chain of isinstance checks inside one function, and it can be extended without touching the original code: a new type is added by registering it. For class methods there is a version called single dispatch method. The technique is especially good for serialization and formatting functions, where the behavior is determined by the data type. For two or three types, though, a chain of conditions is simpler.\n\nThe operator module turns operations into functions. Addition is the function add, multiplication is mul, comparison is eq and lt, indexing is get item, and the membership test is contains. Why? So that you don't have to write a lambda. Reduce of mul and the numbers is shorter and clearer than reduce with a lambda, and map of pow and two lists raises numbers to powers pairwise. This isn't just shorthand: the functions from this module are usually faster than lambdas, because they are written in C. If all you write in a lambda is an operator between the arguments, a ready-made function from operator will probably fit better. The full list is easy to find in the documentation, but a few are usually enough for you: add, mul, setter, item getter and attribute getter, which we'll cover separately.\n\nThe most popular functions of the module are item getter and attribute getter. Item getter of a key returns a function that fetches an element by that key or index. It's an ideal key parameter: sorted of users with key equal to item getter of the word age, instead of a lambda with indexing. If you pass several keys, the function returns a tuple of values, and you get sorting by several fields in a single line. Attribute getter does the same for the attributes of objects: sorted of books, key equal to attribute getter of year. Method caller calls a method by name: method caller of upper returns a function that calls upper on any object. That's how sorts and searches become readable: no arrows, indexes or brackets. Once you get used to them, you'll wonder how you lived without them.\n\nSometimes you come across an old comparison scheme: a function of two arguments that returns a negative number, zero or a positive number. Such functions show up in other people's code and in programs ported from other languages. The modern key parameter doesn't get along with them: it expects a function of one argument. For this, functools has an adapter called cmp to key: it wraps a comparison function so that sorted accepts it as an ordinary key. Usually you don't need to write new comparison functions, a key is enough, but when the order is set by complicated rules that are easier to express as a comparison of two items, the adapter comes to the rescue. Knowing this tool spares you the pain when you have to sort data someone else's way.\n\nBy combining these tools, you build neat data-analysis pipelines. Suppose you have a list of sales records, dictionaries with the fields department and amount. Filter out the large sales with filter, sort them with item getter by department and amount, group them by department, and fold the amounts with reduce or with the sum function. Every link is a ready-made function, and not a single lambda. Code like this reads like a recipe: select, order, group, add up. If you wrote the same task with loops, the code would be longer, but not always clearer. So there are no hard rules: use the tool that makes the text shorter without losing clarity. As soon as a line turns into a puzzle, it's perfectly fine to unroll it into a loop.\n\nLet's look at combinations. Partial and map: turn a list of strings into numbers in base sixteen, map of partial of int with base sixteen, and the list. Reduce and the operator or: combine several flags into one number, or several sets into one. LRU cache and recursion: turn a slow solution into a fast one with a single line above the function. Single dispatch and a dictionary: describe behavior for different types nicely. Item getter and sorted: sort a table by a column. Method caller and map: call the same method on every element. Ready-made combinations like these add up to a habit: first you check whether the standard library has the tool you need, and only then do you write your own.\n\nCommon mistakes. First: reduce over an empty collection without an initial value raises an exception. Second: LRU cache above a function with mutable arguments: lists aren't hashable, and the call will fail. Third: a cache on a function with side effects, or one that depends on time, will return stale results. Fourth: a cache with no size limit on an endless stream of different arguments, and memory keeps growing. Fifth: a partial where you forgot that the fixed arguments will go on the left. Sixth: item getter with several keys returns a tuple, not a single value, and that's easy to overlook. Seventh: total ordering without an equals method. Eighth: trying to apply cached property to an object with no attribute dictionary. Most mistakes are obvious right away if you first ask yourself what will happen to the function on a repeated call.\n\nLet's sum up. Reduce folds a collection with a function of two arguments, and an initial value protects against an empty collection. Partial fixes arguments and returns a new function, replacing simple lambdas. LRU cache remembers results, and max size limits memory. Total ordering builds the comparisons from equals and one ordering operator, and cached property computes a value once. Single dispatch chooses an implementation by the type of the first argument. The operator module gives you operators as functions: add, mul, item getter, attribute getter, method caller. Item getter and attribute getter are the best key parameters. In the next chapter: itertools, ready-made tools for working with streams of values.
