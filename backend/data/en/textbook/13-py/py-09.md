#CHAPTER 9 | Dictionaries
Python as a first language. Chapter 9. Dictionaries. A list is great when elements are found by position: first, second, last. But in real life we rarely look things up by number. We look up a friend's phone number by name, the price of a product by its title, the value of a setting by its keyword. You can keep such data in two lists, names in one and phone numbers in the other, but that is inconvenient and fragile: shift one list, and everything falls apart. For tasks like this, Python has the dictionary: a collection of key and value pairs. The key is the name we search by, and the value is what we found. The dictionary is the second most important container in the language after the list, and almost all work with data rests on it, from program settings to the responses of web services. Today we will master it, from creation to counting frequencies.\n\nA dictionary is created in curly braces: pairs separated by commas, and in each pair a key, a colon, and a value. Say, apple is fifty, banana is seventy, all in curly braces, and you have a price list of two products. An empty dictionary is just two curly braces in a row, and many programs start with one, just as they do with a list. The main rule: keys in a dictionary are unique. One key, one value, and you cannot repeat a key. The values, though, can be anything: numbers, strings, lists, even other dictionaries. The familiar analogy is a real dictionary or an address book: the word or the name is found right away, without flipping through pages, and its description lies right beside it. Remember the picture: the key on the left, the value on the right, and a colon between them.\n\nYou can get a value by its key, by putting the key in square brackets after the name of the dictionary. The price with the word apple in square brackets returns fifty. Notice the difference from a list: there the square brackets hold a number, but here it is a key that reads as a meaningful word. The code explains itself: price of apple, not price of zero. But this kind of access has a strict condition: the key must exist. If you ask for a key that is not there, Python stops the program with a key error. That is honest, but unpleasant: the program crashes out of nowhere if the user typed an unexpected word. So for unreliable keys there is a gentler way, which is the next step.\n\nThe get method is the polite version of access. Price dot get, with the key in parentheses, returns the value, and if the key is missing, it returns the special value that means nothing. But the most useful part is the second argument: the default value. Price dot get of kiwi and zero returns zero if kiwi is not in the price list, and the program does not crash. Choose by the task. Square brackets are for when the key must be there, and its absence means a bug, so let the program crash loudly. The get method is for when a missing key is an ordinary situation: not in the cart means zero items. This pair of approaches will come back to you in dozens of real tasks. And get will be especially useful in counting frequencies, which we will reach soon.\n\nYou can add a new pair or change an old one in a single action: assign a value by key. Price of kiwi in square brackets equals ninety, and a new pair has appeared in the dictionary. Price of apple equals fifty-five, and the old value is replaced. Python tells the cases apart itself: if the key did not exist, the pair is added, and if it did, it is overwritten. Dictionaries, like lists, are mutable: they are edited in place, without being created anew. One more feature of modern Python: a dictionary remembers the order in which the keys were added. When you loop over it, the pairs come in insertion order, and you can rely on that. But you still cannot get a pair by position: a dictionary has no indexes, only keys. This is an important difference in thinking: we do not ask what is in third place, we ask what lies under this name.\n\nTo check whether a key is in a dictionary, an old friend helps: the word in. The expression apple in price returns true or false. Here is an important detail that people stumble on: the word in, for a dictionary, looks at the keys, not at the values. Asking whether the number fifty is in price gives false, even though fifty is in the dictionary as a value. To search among the values you need a different technique, which we will see when we loop. And here is the answer to a natural question: is it fast? Very. A dictionary is built so that a key is found almost instantly, without going through all the pairs: whether the dictionary has ten pairs or ten million. In the algorithms course we studied hash tables and saw why this works. That is why the dictionary is the first choice wherever you need fast lookup by name.\n\nThere are several ways to delete from a dictionary. The del statement with a key in square brackets removes the pair, and if the key is missing, you get a key error again. The pop method does the same, but also returns the removed value: price dot pop of banana, and we got seventy, and the pair is gone. With pop you can pass a default value as the second argument, and then a missing key will not cause an error. The clear method empties the whole dictionary. And how many pairs are in the dictionary right now is told by the familiar len function: it counts exactly the pairs. Remember the analogy with a list: for a list, remove searches by value, while for a dictionary deletion works by key. The key is the main way of reaching a pair, and deletion is no exception.\n\nThere are three ways to loop over a dictionary, and each returns something different. A plain for loop over a dictionary gives the keys, one after another, in insertion order. The values method gives only the values, the keys method gives the keys explicitly, and the items method gives whole pairs. The most convenient is items: in the loop header you write two names separated by a comma, say key and value, and on each turn Python unpacks the pair into those variables. Remember unpacking in enumerate and zip? It is the same technique here, and we will talk about it in detail in the chapter on tuples. With items you print tables, search for values, and build new dictionaries. And if you need to check whether a value is among the values, ask in of values, and the search by values is ready.\n\nNow the classic: counting frequencies. The task: how many times each word occurred in a list. We create an empty frequency dictionary. We go through the words with a for loop, and for each word we increase its counter: frequencies of word equals frequencies dot get of word and zero, plus one. The get method saves us here: if the word is met for the first time, get returns zero, we add one, and the pair appears. If it has been met before, we take the accumulated count and add one. Two lines of code do what, without a dictionary, would need a separate counter for every word. This technique is one of the main ones in data processing: it is how you count visitors per page, words in a text, errors by type. Remember the template: get with zero, plus one.\n\nWhich values can be keys? Values can be anything, but keys obey a rule: they must be immutable. Numbers, strings, booleans, and tuples are fine. Lists are not: trying to use a list as a key ends with an unhashable type error. The reason is how lookup works: a key is turned into a number based on its contents, and if a key could be changed in place, finding it afterwards would be impossible. That is why strings and numbers are the favorite keys, and when you need a compound key, like a pair of coordinates, you use a tuple. One nuance: keys are compared exactly. The strings Apple and apple are different keys, a trailing space also makes a key different, and the same key written twice collapses into one pair, with the last value winning.\n\nDictionaries follow the same reference rules as lists. The statement b equals a, where a is a dictionary, copies nothing: there are two names but one dictionary, and a change through one name is visible through the other. A real copy is made with the copy method or the dict function. As with lists, the copy is shallow: if the values inside are lists, they stay shared between both copies. The same conclusion holds for functions: do not change a dictionary that came to you from outside unless that is part of the task. Returning a new dictionary is safer than fixing someone else's. Remember the trap from the chapter on copying: data changes on its own because there are more names than objects? It works the same way here, and the cure is the same: copy deliberately when you need independence.\n\nLet us collect the typical mistakes. The first: reading a nonexistent key with square brackets, which gives a key error. The cure: the get method, or a check with the word in. The second: mixing up keys and values in a check: the word in looks at keys. The third: changing the size of a dictionary during a loop. If you add or remove pairs inside a loop over a dictionary, Python stops the program with an error. As with lists, loop over a copy of the list of keys, or build a new dictionary. The fourth: expecting keys with different case or spaces to match: Apple and apple are different keys, so it is worth normalizing the data in advance. The fifth: counting on a position number: a dictionary has no indexes, and asking for the first element by number is impossible, only by key.\n\nLet us sum up. A dictionary stores key and value pairs in curly braces and finds by key almost instantly. Square brackets with a key read, add, and change, and a missing key on reading is an error. The get method reads gently, with a default value. The word in checks keys. The del statement and pop delete pairs by key, and len counts the pairs. A for loop goes over the keys, values gives the values, and items gives whole pairs. The template get with zero, plus one, counts frequencies. Keys must be immutable, and a copy of a dictionary must be made consciously. In the next chapter we cover dictionary techniques: merging, dictionary comprehensions, nested data, grouping, and sorting. See you then.
