#CHAPTER 8 | Lists: sorting and comprehensions
Python as a first language. Chapter 8. Lists: sorting and comprehensions. The previous chapters laid the foundation: you can create lists, loop over them, copy them, and pick out elements with a loop. Today we look at tools that turn ten lines into one. We will learn to sort exactly the way we need: by word length, in descending order, by any criterion at all. We will meet the list comprehension, a compact notation where filtering and transforming fit into a single line. We will go through the functions that ask whether at least one element fits, or whether all of them do, then collect the standard patterns for typical tasks, and finally see how a list can work as a stack. The promise is simple: after this chapter you will read other people's list code without stumbling, and you will write your own shorter and clearer.\n\nSorting comes in two kinds, and the difference is critical. The sort method, which you already know, changes the list in place and returns nothing, so the previous order is lost. The sorted function works differently: it accepts any collection, returns a new sorted list, and leaves the original untouched. Here is the rule for choosing. If you no longer need the original order, sort is fine. If you do need it, or the data came from somewhere else and must not be changed, use sorted. Here the idea from the previous chapter applies again: code that damages nothing is safer. And here is the most common mistake: writing nums equals nums dot sort puts nothing into the name, just as with append. Sorting in descending order is easy: both versions have a parameter called reverse. Set it to true, and the order flips. That is how you find the best sellers and the freshest records.\n\nYou can sort more than numbers. Python orders strings alphabetically, comparing characters one by one. But there is a catch that makes sorting look strange at times: capital letters come before lowercase ones. A word like Apple with a capital letter ends up ahead of a word like banana in lowercase, because to the machine every character has a numeric code, and capitals have smaller codes. In real data the case is mixed all the time, and the cure is a technique we are about to learn: bring the words to one case before comparing. Another catch: numbers written as strings sort as text. The string made of the digits one and zero lands before the string with a lone two, because the first characters are compared. So convert strings to numbers first. And one last thing: you cannot sort a mixture of types. Python refuses to compare numbers with strings and reports an error.\n\nThe main sorting parameter is called key. It is a way of saying: do not sort the elements themselves, sort by what I compute from each one. We pass a function as the key, and Python calls it for every element, then orders the elements by the results. To sort words by length, we pass key equals len, the familiar function, but without parentheses: we do not call it, we hand it over as a tool. The words line up from short to long. To sort without regard to case, the key is the string method lower, which converts to lowercase: key equals str dot lower. An important property: the sort is stable. Elements with equal keys stay in the same order they had originally. That is why you can sort in two passes: first by the secondary criterion, then by the main one. The key is computed only once per element, so it is fast.\n\nThree more techniques are related to order. The first is reversing. The reverse method flips a list in place, a slice with a step of minus one gives a reversed copy, and the reversed function gives a reversed traversal without copying. It is handy to put in the header of a for loop when you want to walk from the end. The second technique is taking several of the largest or smallest values. We sort and cut with a slice: the first three after sorting in descending order are the top three. The third is checking whether a list is sorted: we compare it with a sorted copy using double equals. All of this is a combination of things you already know: sorted, a slice, equality. Here you can see the beauty of the language: small bricks combine into complex solutions. Notice the limits too. Sorting costs time, so sorting a list just to find one maximum is wasteful. For that there is a simple pass, or the max function.\n\nNow the main novelty of the chapter: the list comprehension. Remember the pattern of an empty result, a loop, and an append? Python can write it in one line. Inside square brackets you first write the expression for each element, then the loop header. For example: x times x, for x in range from one to six, all inside square brackets. The result is the squares from one to twenty-five. The notation reads like a phrase: the square of x for each x in these numbers. Compare it with the old four-line version: an empty list, a loop, an append, and the result. Here the whole point sits in one line, and there is almost nowhere to make a mistake, because there is no extra state. A list comprehension always creates a new list and leaves the source alone. From any collection, whether a list, a string, or a range, you can get a list with one expression. It is hard to get used to at first, but in a week you will write them without thinking.\n\nYou can add a condition to a comprehension. It goes at the very end, after the loop header. The expression x, for x in nums, if x modulo two equals zero, picks out only the even numbers. This is the familiar filtering, just in one line. And if you need to both select and transform, the roles are shared: the expression at the start says what to put into the result, and the condition at the end says which elements to take at all. For example: the squares of only the even numbers from the source list. The convenient order for reading such expressions is this: first the loop header, then the condition, and only at the end the expression that we put in. The condition at the end filters, and the expression at the start transforms, so do not mix up their roles. If you need not to drop an element but to replace it with another, you write it differently, but that is a rare case. For now, hold on to the three-part template: what we put in, where we take it from, and under what condition.\n\nComprehensions are especially good for working with strings. Turn a list of words into a list of word lengths: len of word, for each word. Convert all the words to uppercase: the upper method on each word. Take the first letter of each word. Split a sentence into words with the split method and process each word. The reverse operation is the join method: it assembles a list of strings into one, inserting a separator between them, which you write before the dot. So split and join together with a comprehension make a text-processing pipeline: split, process, glue back together. Notice that join accepts only strings. If the list holds numbers, you must first turn them into strings, and this is where a list comprehension that calls the str function on every number comes in very handy. In real programs such pipelines are everywhere: logs, reports, file parsing.\n\nA list comprehension is not a silver bullet, and here is when it is better to stay with an ordinary loop. If the body is complex, with several actions, several conditions, printing, or writing to a file, a long one-line expression turns into a cipher. Readability matters more than brevity: code is read more often than it is written. If you need side effects, such as printing or changing other data, use a loop: a comprehension is meant for building a new list, not for performing actions. If the nesting goes deeper than two levels, the expression stops being readable. And do not create a list for a single pass: if you need to add up the result right away, you can do without the intermediate list. A good criterion is this: if the expression does not fit on one reasonable line, or you have to reread it, go back to the loop. Good code is not the shortest code, but the clearest.\n\nTwo helpers answer questions about a whole list. The any function answers: is there at least one fitting element in the collection? The all function answers: does every single element fit? You pass them a collection of boolean values, most often a comprehension written directly, just without the square brackets: any of x greater than one hundred, for x in nums. As soon as the first fitting element is found, we get true, and Python does not search any further, just like with break. For an empty collection, any gives false, because there are no fitting elements, while all gives true, because there are no violators either. This is the same logic as the quantifiers in discrete mathematics: there exists, and for all. Earlier we wrote such checks with a loop and a flag, and now we do it in one line. It is also handy for validating data: are all the fields filled in, and are there no ones among the grades.\n\nLet us collect the task patterns that come up again and again. Sum and product: an accumulator that starts from zero or from one. Maximum and minimum: start from the first element of the list, not from zero, otherwise a list of negative numbers will give a wrong answer. Counting by a condition: a counter that grows by one when the condition is true. Finding the first fitting element: a loop that exits as soon as it finds one. The arithmetic mean: the sum divided by the length, with a check for an empty list so we do not divide by zero. The second largest: remove the repeats, sort, and take the next to last. Removing repeats: walk through the list and add to the result only what is not there yet, checking with the word in. You have already met all these patterns in the exercises, and this is your toolkit: most list tasks come down to a combination of them.\n\nLet us show how a list works as a stack, a structure from which you always take the last element that was put in. Append puts on top, pop takes off the top, and nothing more is needed. This is called a stack, and it underlies many algorithms. The classic example is checking brackets. We walk along the string: when we meet an opening bracket, we put it on the stack; when we meet a closing one, we take an opening bracket off the stack. If a closing bracket arrives and the stack is empty, the brackets are placed wrongly. If something is left on the stack at the end, then some brackets are not closed. The same technique works in the browser for the back button, in an editor for undoing actions, and in parsing formulas. For a queue, where the oldest element leaves first, a list is a worse fit: removing from the front shifts all the others, and on big data that is slow. For queues the standard library has a special collection, and we will meet it later.\n\nLet us sum up. The sort method sorts in place and returns nothing, while the sorted function returns a new sorted list. The reverse parameter flips the order, the key parameter says what to compare by, and the sort is stable. A list comprehension turns a loop with an append into one line: an expression, a loop header, and an optional condition. The any function asks whether there is a fitting element, and the all function asks whether all of them fit. A list used as a stack, with append and pop, solves problems about brackets and undoing actions. Separate techniques, such as the maximum starting from the first element, counting, and removing repeats, combine into solutions for almost any list task. With this chapter, the topic of lists is complete. But a list has a weak spot: when you need a meaningful name instead of a number, it is inconvenient. In the next chapter we study dictionaries: key and value pairs, on which data handling rests. See you then.
