#CHAPTER 10 | Dictionary techniques
Python as a first language. Chapter 10. Dictionary techniques. In the previous chapter you learned the dictionary as a container: how to create it, read it, change it, delete from it, and loop over it. Now let's work with it the way people do in real projects. We'll learn to merge dictionaries and to build one from two lists. We'll meet the dictionary comprehension, a close sibling of the list comprehension. We'll build nested data: a dictionary inside a dictionary, and a list of dictionaries, which is exactly the shape data takes when it arrives from web services. We'll look at grouping, sorting, and picking the most frequent item. And at the end, we'll see how a dictionary can replace a long chain of conditions. After this chapter, dictionaries will be your main working tool.\n\nLet's start with merging. Say you have two dictionaries, for example default settings and the user's settings, and you need a single one. The update method takes another dictionary and pours its pairs into the current one: new keys are added, and for keys that match, the value is overwritten. This changes the dictionary in place, just like extend does for lists. There's also a variant that builds a new dictionary and leaves the originals alone: the pipe operator between two dictionaries. The right one wins: when a key appears in both, the value comes from the dictionary on the right. That gives you a handy settings scheme: defaults on the left, user settings on the right, and anything the user has set overrides the default. If the original dictionaries must not change, use the operator; if they may change, use update.\n\nOften data arrives as two lists: one with keys, the other with values. You can build a dictionary from them with a loop, but there's a shortcut. The zip function glues two lists into pairs, and the dict function turns pairs into a dictionary. Dict of zip of names and phone numbers, and you have a phone book. If the lists have different lengths, the extra tail is dropped, just like in a plain zip. Dict has another use, copying: dict of a dictionary builds a shallow copy. And dict also has a form with keyword arguments: dict with name equals Anya and age equals twenty. It's handy for short records where the keys are simple words. But for keys with spaces or numbers, you need ordinary curly braces.\n\nWe already know the list comprehension, and dictionaries have the same thing: the dictionary comprehension. You write it in curly braces: first the key, a colon, and the value, then the loop header. For example: word, colon, len of word, for word in words. You get a dictionary where each word maps to its length. You can add a condition at the end too, to keep only words longer than three letters. And if you need to flip a dictionary, swapping keys and values, it's one line: value, colon, key, for key and value in items. A flipped dictionary is useful when you need to look things up in the opposite direction. Just remember: the values become keys, so they must be unique and immutable, otherwise pairs will collapse into one, or you'll get an error.\n\nA classic task is grouping: sorting items into buckets. For example, words by their first letter, or grades by student. The result is a dictionary whose values are lists. The scheme goes like this: create an empty dictionary; for each item, compute its bucket key; if that key isn't there yet, create an empty list under it; then add the item to that list. In code, the check reads like this: if the key is not in the dictionary, put an empty list under it, and after that, append. It looks simple, but "create if missing, then add" is such a common pattern that Python has a shortcut for it, which is the next step. The main thing is to grasp the idea: a dictionary of lists is a set of buckets, and each new item lands in its own.\n\nThe shortcut is called setdefault, meaning "set a default". The method takes a key and a default value: if the key exists, it returns what's stored under it; if not, it stores the default value and returns it. So grouping turns into one line: buckets dot setdefault of the key and an empty list, and right away dot append of the item. The two checks we wrote by hand are now hidden inside the method. This is a good example of a principle: a frequent pattern gets its own name. For counting frequencies there's the same kind of shortcut with get, and the standard library has ready-made dictionaries with defaults and counters, which we'll meet later. For now, remember two patterns: get with zero for numbers, and setdefault with an empty list for groups.\n\nA value can be another dictionary, and that's how nested data appears. For example, a staff directory: the employee's name is the key, and the value is a dictionary with age and city. To get Anya's city, you need two keys in a row: first staff in brackets with Anya, then in brackets, city. It reads left to right, like a file path. Changing works the same way: an assignment with two keys. To loop over nested data, use nested loops, or items inside items. Be careful here: if a key is missing at some level, a key error will crash the program, so with untrusted data you use get at every level. Nested dictionaries are how program settings and web service responses look, so get used to them early.\n\nThe most common shape of data in practice is a list of dictionaries. Each dictionary is one record, for example a user with a name and an age, and the list collects the records into a table. This is almost exactly what comes from a database or a web service. We already know how to process such a list: filtering with a comprehension, counting with a loop. Say, the names of all users over eighteen: user name for each user in the list, if age is greater than eighteen. To sort by a field, we pass the key parameter a function that pulls the needed field out of a record. We write our own function with def: it takes a record and returns the age. Sorted of users with key equal to that function, and the records line up by age. That's how dictionaries and lists work together.\n\nA dictionary doesn't sort itself, but its contents can be sorted. The sorted function applied to a dictionary gives you a list of keys in order. To order the pairs by value, we take items and sort the pairs, giving a sort key: a function that returns the second element of a pair. We get a list of pairs from smallest to largest, and with reverse set to true, from largest to smallest. If you just need the key with the largest value, there's a shortcut: max of the dictionary with key equal to the dictionary's own get method. Here get acts as a ready-made function that returns the value for a key: you pass it without parentheses, just like len earlier. One line finds the best-selling product, the most frequent word, the oldest person. So sorting a dictionary is really sorting a list of pairs.\n\nLet's put it all together in one task: the three most frequent words in a text. Step one is to split the text into words with the split method. Step two is to count frequencies with the pattern get with zero, plus one. Step three is to sort the pairs by value, in descending order. Step four is to take a slice of the first three. Four small techniques, each of which you already know, add up to a working tool for text analysis. Such a pipeline is the essence of data processing: split, count, order, select. Notice that not a single new word of the language has appeared: the power is not in the number of commands but in the ability to combine them. And one important practice: before counting, convert the words to lowercase, otherwise "Hello" and "hello" will be counted as different words.\n\nA dictionary can replace a long chain of conditions. Suppose you need to turn a numeric grade into a word: five means excellent, four means good, three means satisfactory. A chain of if, elif, elif is awkward, and it's easy to get lost in it. A dictionary does the same thing more briefly: we look up the value by the grade, and for an unknown grade, get with a default value of "unknown". This is called a lookup table. Its advantage is not only brevity: the table can be stored separately from the logic, extended, loaded from a file. Use this technique when the conditions boil down to "if it's this, then that" with no calculations. If the branches are complex and require different actions, an if remains the right tool. The instinct comes with experience: if you see repeating branches that just assign a value, think about a dictionary.\n\nCommon pitfalls. First: changing the size of a dictionary while looping over it. You can't add or remove a pair in a loop over the same dictionary, because Python will stop the program. The cure: loop over a copy, like list of the dictionary's keys, or build a new dictionary. Second: a shared mutable object in the values. The fromkeys method builds a dictionary from keys that all get the same value, and if that value is an empty list, there will be one list for all the keys, which is the references problem again. The right way is to create the lists one at a time, with a loop or a comprehension. Third: overwriting when merging. The right dictionary overrides the left one, so check the order. Fourth: reading nested data without checking, since any level may lack a key. And fifth, the most human one: data with different letter case and stray spaces must be normalized before counting.\n\nLet's sum up. You can merge dictionaries in place with the update method, or into a new dictionary with the pipe operator, and the right one wins. Dict of zip builds a dictionary from two lists. The dictionary comprehension builds a dictionary in one expression, and it can flip one around. Grouping is a dictionary of lists, and setdefault shortens the "create if missing" pattern. Dictionaries nest inside each other, and a list of dictionaries is the main form of tabular data. A dictionary itself isn't sorted; instead you sort its pairs through items, and the maximum by value is found by max with key equal to get. A lookup table replaces a chain of conditions. And remember the pitfalls: resizing in a loop, shared lists in the values, and data that hasn't been normalized. In the next chapter: tuples, the immutable siblings of the list. They hide inside every items and zip, and it's time to get to know them. See you there.
