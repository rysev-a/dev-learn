Python as a first language. Chapter 17. Paths and formats. Knowing how to open a file gives you only half of the possibilities. Real work with the disk includes a path to a file that must work the same on different systems, and also folders that you need to create, walk through, and clean out. The second half is the data format: storing separate lines in a file is boring, but complex structures of dictionaries and lists written as text are exactly what any program needs. Today we will meet the pathlib module for working with paths, talk about the os and shutil modules, and then learn the two most common data exchange formats: JSON and CSV. They work in any language and are used in settings, web services, and spreadsheet exchange.\n\nIt used to be that paths were built as ordinary strings, gluing pieces together with slashes. But separators differ between systems, and the gluing became a source of bugs. The pathlib module solves this in an object-oriented way: the Path class represents a path, and you work with it through operators and methods. To join pieces you use the division operator: folder, slash, file name. The parts of a path are available as attributes: name is the file name with the extension, stem is the name without the extension, suffix is the extension with the dot, parent is the folder above, and parts is all the pieces. You can give a path as a string, and Path will sort out the separators. The result of joining is also a path, not a string, and it can be passed to open and to most functions of the standard library.\n\nA path has methods for checking and for acting. Exists tells whether such an object exists, and is file and is dir tell a file from a folder. Mkdir creates a folder; with the parameters parents and exist ok it creates the whole chain and does not fail if the folder is already there. The iterdir method walks through the contents of a folder, glob searches by pattern, for example all files with the txt extension, and rglob searches the nested folders too. Unlink deletes a file, and rename renames or moves it. All these methods work relative to the current folder if the path is relative, and the current folder is returned by Path dot cwd. For the user's home folder there is Path dot home. So a single module covers almost everything that used to require several.\n\nA path also has short methods for reading and writing. Read text reads the whole file as a string, write text writes a string, and both open and close the file themselves; the encoding can be given as a parameter. For binary data there are read bytes and write bytes. This is convenient for small files and one-line scripts. Another useful idiom: the path to the script file itself lives in a special variable with double underscores around the word file, and Path of it, dot parent, gives the folder where the script lives. From there it is easy to build paths to data next to the script, and they work no matter where the program is launched from. This solves the old problem of it works for me but not for you, which comes from the current folder.\n\nThe older ways turn up as well, and it is useful to recognize them. The os module contains os dot listdir, os dot getenv for environment variables, os dot makedirs, and so on. The os dot path submodule offers functions over strings: join, exists, basename. For operations on whole trees of folders there is the shutil module: copy copies a file, move moves it, copytree copies an entire folder, and rmtree deletes a folder with everything in it. That last function is dangerous: it does not ask for confirmation and does not send anything to the trash. Use it knowing that the result is irreversible, and in tests only on temporary folders. Environment variables are available through the os dot environ dictionary, and that is the standard way to pass passwords and settings to a program without writing them into the code.\n\nJSON is a text format for structured data, invented in the JavaScript language and became universal. It describes objects, arrays, strings, numbers, boolean values, and the empty value. The correspondence with Python is almost transparent: an object is a dictionary, an array is a list, null is None, and true and false are written in lowercase. The json module provides two pairs of functions. Dumps turns an object into a string, and loads parses a string into an object. Dump and load do the same thing directly with a file. The indent parameter makes the output pretty, with indentation, and the ensure ascii parameter set to false keeps Russian letters as they are rather than as escape codes. It is the most convenient way to save a program's state or to exchange data.\n\nJSON has quirks that people stumble over. The keys of objects are always strings: if a dictionary key is a number, after writing and reading it becomes a string. A tuple turns into a list and will not come back as a tuple. JSON cannot serialize ordinary objects of your classes, and you will get a type error. The solution is to give the class a method that turns it into a dictionary and write that dictionary, or to pass a function to the default parameter. Dates are not supported directly either: they are written as strings. Invalid text raises a decoding error on reading, and you need to catch it if the data came from a user. Everything else, though, numbers, strings, lists, and dictionaries in any combination, is written and read without any trouble.\n\nCSV is a format for tables: every line of the file is a row of the table, and the values are separated by commas or another character. It is what you get when you export data from spreadsheets. You read it with the csv module. The reader returns rows as lists of values, and DictReader returns them as dictionaries whose keys are taken from the first row with the headers. The writer writes rows, and DictWriter writes dictionaries, with the header written by a separate method. The file must be opened with the newline parameter set to an empty string, otherwise on some systems extra empty lines appear between rows. The module itself handles quotes and commas inside values, which a plain split will not. For Russian data, always state the encoding.\n\nThe main thing when working with tables: everything read from CSV is a string. An age of twenty arrives as a string of digits, and you cannot compare it with a number until you convert it with the int function. After that everything you know works: a loop over the rows, a list comprehension for filtering, a dictionary for grouping and counting, sorting by a key. The task of computing the average salary per department turns into ten lines: read, group by department, compute the sum and the count, divide. If the data is large, the reader goes through it line by line and does not need much memory. And if you need serious analytics, there are specialized libraries, but the essence stays the same: an understanding of strings, dictionaries, and loops never goes away.\n\nPrograms need to store settings and state. The simplest way is a JSON file. On startup the program reads it, substituting defaults for missing keys: merging dictionaries from the chapter on techniques comes in very handy here. On exit it writes the state back. An important subtlety is reliable writing. If the program crashes in the middle of writing, the file ends up half overwritten and corrupted. So the data is first written to a temporary file next to it, and then it replaces the real one in a single operation: a rename at the system level either happens entirely or does not happen at all. This kind of writing is called atomic, and Path dot replace does it in one line. This technique saves you from data loss during power failures and when a process is killed.\n\nJSON and CSV have other relatives too. Pickle saves almost any Python objects in binary form, but it is dangerous: loading someone else's file can execute arbitrary code, so you must never read a pickle from an untrusted source. The sqlite3 module supports a real database in a single file, and you know it from the databases course. Configparser reads settings files in the old INI format, and the tomllib module reads the also popular TOML format. There are modules for parsing HTML and XML too. The rule of choice is simple: for exchanging data and for settings, take JSON; for tables, CSV; for complex related data, a database; and keep pickle for your own, fully trusted files.\n\nTypical mistakes. The first is gluing paths from strings with slashes by hand and breaking the program on another system. The second is forgetting that a relative path is counted from the folder the program was launched from. The third is calling write text over an important file: it silently overwrites. The fourth is saving objects of your own classes or tuples into JSON and being surprised by the result. The fifth is opening a CSV without the newline parameter or without an encoding. The sixth is forgetting that a table gives you strings, not numbers. The seventh is using rmtree without checking the path. The eighth is loading a pickle from someone else's file. The ninth is writing to the real file directly, without an atomic replacement. Most of these traps are avoided if you remember: paths are Path objects, data is JSON, tables are CSV.\n\nLet's sum up. Pathlib turns paths into objects: the slash joins, the attributes name, stem, suffix, and parent take them apart, the methods exists, mkdir, iterdir, glob, and unlink work with the disk, and read text and write text read and write whole files. The os and shutil modules are needed for environment variables and operations on trees of folders, and caution with rmtree is a must. JSON stores dictionaries and lists: dumps and loads work with strings, dump and load with files; keys are always strings, and tuples become lists. CSV stores tables: reader and DictReader read, writer and DictWriter write, and everything read is a string. Atomic writing protects data from crashes, and a pickle must never be opened from someone else's sources. We are done with files. In the next chapter: iterators, and how the for loop works inside.
