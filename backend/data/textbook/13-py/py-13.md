#SECTION Классы
#CHAPTER 13 | Классы: методы и свойства
Питон как первый язык. Глава 13. Классы: методы и свойства. Вы уже умеете описывать класс, создавать объекты и вызывать методы. Но настоящая красота Питона проявляется, когда собственные объекты начинают вести себя как встроенные: их можно складывать знаком плюс, сравнивать, сортировать, спрашивать у них длину, брать из них элемент по индексу. Всё это делается с помощью специальных методов, названия которых окружены двойными подчёркиваниями, — их называют магическими. Сегодня разберём самые нужные из них. Затем познакомимся со свойствами — способом сделать из метода обычный атрибут с проверкой данных. И закончим методами класса и статическими методами. После этой главы ваши классы начнут выглядеть как части самого языка.\n\nМагический метод вызывается не вами, а самим Питоном в ответ на операцию. Когда вы пишете «а плюс б», Питон ищет у объекта а метод адд и вызывает его с аргументом б. Получается, что оператор плюс — просто красивая запись вызова метода. Разберём на примере вектора на плоскости: у него два числа, икс и игрек. Метод адд принимает другой вектор и возвращает новый, сложив координаты попарно. После этого вектор плюс вектор работает так, как мы привыкли в математике. Так же устроены вычитание, умножение, деление: у каждого оператора свой магический метод. Правило хорошего тона: метод оператора не меняет исходные объекты, а возвращает новый, как делает плюс у чисел и у строк.\n\nПо умолчанию двойное равно для объектов проверяет, один ли это объект. Две точки с одинаковыми координатами оказываются разными, и это не то, чего ждёшь от точки. Чтобы сравнивать по значению, описывают метод эк: он принимает другой объект и возвращает истину, если данные совпадают. Здесь есть важная связь. Объекты, которые можно использовать как ключи словаря или хранить в множествах, должны иметь хеш — число, вычисляемое по содержимому. Если описать метод эк и ничего не сказать про хеш, Питон отключает хеширование: такой объект нельзя будет взять в ключ. Чтобы вернуть эту возможность, описывают метод хеш, который строится из тех же данных: хеш от кортежа из икс и игрек.\n\nЧтобы объекты можно было сортировать, достаточно научить их сравниваться на «меньше»: метод лт возвращает истину, если текущий объект меньше другого. Тогда функция сортед и метод сорт умеют упорядочивать список таких объектов без всякого параметра ки, а функции минимум и максимум — искать крайние значения. Можно описать и остальные методы сравнения: ле, гт, ге. Но писать все четыре утомительно, и в стандартной библиотеке для этого есть декоратор тотал ордеринг, о котором мы поговорим позже: достаточно определить эк и один оператор порядка, а остальные он достроит. Альтернатива для разовых случаев — сортировать по ключу, указав параметр ки с функцией, которая достаёт нужный атрибут: не нужно менять сам класс.\n\nТеперь научим свой объект притворяться контейнером. Метод лен возвращает длину, и тогда функция лэн работает с вашим объектом, а заодно пустой объект с нулевой длиной считается ложью. Метод гетитем принимает индекс и возвращает элемент, и тогда работают квадратные скобки: объект в квадратных скобках ноль. Метод контейнс отвечает на вопрос слова in: лежит ли значение внутри. Если определён гетитем, Питон по умолчанию умеет даже перебирать объект циклом фор, дёргая индексы по порядку. Правило простое: хотите, чтобы объект вёл себя как список, реализуйте нужные методы. Например, класс Плейлист хранит список песен внутри, а наружу показывает длину, элементы по номеру и проверку вхождения.\n\nСвойство — это метод, который выглядит как атрибут. Допустим, у прямоугольника есть ширина и высота, а площадь вычисляется из них. Можно сделать метод площадь и вызывать его со скобками, а можно превратить в свойство: поставить над методом декоратор пропёрти — и обращаться без скобок, как к обычному атрибуту. Площадь теперь всегда актуальна: изменили ширину — и площадь пересчиталась сама, потому что хранится не значение, а способ его получить. Свойства удобны для вычисляемых значений, и пользователю не нужно знать, хранится ли значение внутри или считается на лету. Если завтра класс изменится, код снаружи не придётся переписывать — интерфейс остался прежним.\n\nУ свойства может быть и запись, и тут оно становится стражем данных. Хранить значение принято в атрибуте с подчёркиванием, а доступ открывать через свойство. Для записи описывают второй метод с тем же именем и декоратором имя точка сеттер. В нём проверяют значение: возраст не может быть отрицательным, температура не ниже абсолютного нуля. Если значение неверно, поднимают ошибку, и объект остаётся целым. Снаружи всё выглядит как простое присваивание: человек точка возраст равно двадцать, но под капотом Питон вызывает проверку. Если сеттера нет, попытка присвоить значение закончится ошибкой атрибута: свойство только для чтения. Это отличный способ делать неизменяемые поля без лишних слов.\n\nМетод класса — это метод, который получает не экземпляр, а сам класс, и описывается декоратором класс-метод. Первый параметр принято называть цлс. Главное применение — альтернативные конструкторы. Например, у класса Точка есть обычный конструктор от двух чисел, и добавим метод класса из строки: он принимает строку вроде «три запятая четыре», разбирает её и возвращает новый объект через цлс. Благодаря цлс метод работает и для наследников: вернёт объект именно того класса, у которого его вызвали. Так в стандартной библиотеке устроены, например, создание даты из строки или из метки времени. Правило: нужно создать объект другим способом, чем основной конструктор, — пишите метод класса с названием вида «из чего-то».\n\nСтатический метод — это обычная функция, которая лежит внутри класса ради порядка. Он не получает ни сэлф, ни цлс и описывается декоратором статик-метод. Например, у класса Температура может быть статический метод для перевода градусов, который не зависит от конкретного объекта. Вызывается он через класс или через экземпляр. Зачем это нужно, если можно написать функцию рядом? Чтобы сгруппировать вспомогательный код с тем, к чему он относится, и не засорять общее пространство имён. Однако в Питоне модули — достаточно хорошая группировка, и статические методы нужны реже, чем в других языках. Сравним три вида: обычный метод знает объект, метод класса знает класс, статический не знает никого.\n\nЕщё одна тема — подчёркивания в именах. Одно подчёркивание в начале — договорённость «это внутреннее, снаружи не трогайте»; Питон ничего не запрещает, но читатели поймут намёк. Два подчёркивания в начале включают так называемое искажение имён: Питон незаметно переименовывает атрибут, добавляя к нему имя класса, чтобы наследники случайно его не затёрли. Это не защита, а страховка от конфликтов. Два подчёркивания с обеих сторон зарезервированы под магические методы, и придумывать собственные такие имена нельзя. Одинокое подчёркивание в роли имени переменной говорит «значение мне не нужно». Эти мелкие соглашения делают код предсказуемым для любого, кто знает язык, и стоит приучить себя им следовать с первых дней.\n\nСоберём всё в один пример: библиотека книг. Класс Книга хранит название, автора и год и умеет себя печатать методом стр. Класс Библиотека хранит книги в списке, умеет добавлять книгу, искать по автору, и благодаря методам лен и контейнс отвечает на вопросы «сколько книг» и «есть ли такая». Книги сравниваются по значению и сортируются по году, поэтому список можно упорядочить одной функцией. Свойство позволяет получить самую старую книгу. Получился небольшой, но цельный кусок программы, который читается как описание предметной области: ничего лишнего, только понятия задачи и действия над ними. К такому стилю и надо стремиться: код, который объясняет сам себя.\n\nТипичные ошибки главы. Первая: описали метод эк и не описали хеш, а объект затем не берётся в ключ словаря. Вторая: метод оператора меняет исходный объект вместо того, чтобы вернуть новый. Вопрос на проверку: что вернёт метод, если ему передали объект другого типа? Для этого есть специальное значение ноут-имплементед. Третья: свойство без сеттера, а присваивание всё равно пытаются выполнить — ошибка атрибута. Четвёртая, коварная: внутри сеттера присваивают значение тому же имени без подчёркивания, и получается бесконечная рекурсия. Хранить нужно в атрибуте с подчёркиванием. Пятая: путаница метода класса и обычного метода: забыть декоратор или спутать сэлф с цлс. Шестая: слишком много магии — не нужно реализовывать все методы подряд, только те, что нужны.\n\nПодведём итог. Магические методы вызываются самим Питоном: адд для плюса, эк для двойного равно, лт для меньше, лен для длины, гетитем для квадратных скобок, контейнс для слова in. Если описываете эк, описывайте и хеш, иначе объект нельзя будет взять в ключ. Свойство превращает метод в атрибут, а сеттер добавляет проверку значения. Метод класса получает цлс и годится для альтернативных конструкторов, статический метод — обычная функция внутри класса. Одно подчёркивание — внутреннее, два в начале — искажение имён. Всё вместе позволяет делать собственные типы, неотличимые от встроенных. В следующей главе — наследование и композиция: как строить из классов целые иерархии.
