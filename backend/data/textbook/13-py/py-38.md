#BOOK 13
#SECTION Стандартная библиотека
#CHAPTER 38 | Данные и типы: dataclasses, enum, typing, copy
Питон как первый язык. Глава 38. Данные и типы: датаклассы, перечисления, подсказки типов и копирование. В больших программах всё больше данных, и описывать их приходится аккуратно. Обычный класс с конструктором, репром и сравнением требует много однотипного кода: перечислить поля, присвоить их, вывести, сравнить. Датаклассы пишут этот код за вас. Перечисления дают осмысленные имена фиксированным наборам значений: статусы, дни недели, цвета. Подсказки типов превращают код в самодокументируемый и позволяют инструментам находить ошибки до запуска. Модуль копи отвечает за правильное копирование сложных объектов. Это то, что отличает аккуратный проект от беспорядочного набора функций. Сегодня разберём каждую из этих тем, а в конце познакомимся со структурным сопоставлением, которое делает разбор данных выразительным.\n\nДатакласс создаётся декоратором над обычным классом, в котором перечислены поля с аннотациями типов: имя, строка; возраст, целое. Больше писать ничего не нужно: декоратор сам сгенерирует конструктор, текстовое представление, сравнение на равенство. Две записи с одинаковыми значениями полей окажутся равны, а печать покажет аккуратное «имя класса со скобками и значениями». Поля можно снабжать значениями по умолчанию, после которых обязательные поля идти уже не могут. Вместо двадцати строк с конструктором и методами получается пять строк объявления. Именно поэтому датаклассы стали стандартным способом описывать записи: заказ, пользователь, настройка. Аннотации типов здесь служат описанием, а не проверкой: значение другого типа Питон не отвергнет.\n\nУ датаклассов есть параметры и инструменты. Для изменяемых значений по умолчанию, вроде списка, используют функцию филд с параметром дифолт-фэктори: каждый экземпляр получает собственный список, и ловушка общего списка исчезает. Параметр фрозен делает экземпляры неизменяемыми, и тогда их можно использовать как ключи словаря. Параметр ордер генерирует сравнения на меньше и больше по порядку полей, и записи можно сортировать. Параметр слотс экономит память. Специальный метод постинит выполняется после конструктора и годится для проверок и вычисляемых полей. Функции асдикт и асткортеж превращают запись в словарь или кортеж, а реплейс создаёт копию с изменёнными полями. Это та самая работа, которую мы вручную делали с именованными кортежами и классами.\n\nКак выбрать между словарём, кортежем, именованным кортежем, классом и датаклассом? Словарь подходит для данных со свободной структурой: ответ сервиса, настройки. Кортеж — для маленькой записи из нескольких значений, возвращаемых из функции. Именованный кортеж — для неизменяемой записи без логики. Датакласс — для записи, у которой есть типизированные поля, возможно изменяемые, и, при желании, методы. Обычный класс — когда важно поведение и сложная инициализация. Выбор определяется смыслом: что важнее, структура или поведение. Хороший показатель — как вы собираетесь использовать запись: если почти всегда читаете поля, подойдёт датакласс, а если вокруг неё много методов, пора переходить на полноценный класс, и датакласс по-прежнему можно использовать как основу.\n\nПеречисление — набор именованных констант. Класс наследуют от Энум и перечисляют члены: красный, зелёный, синий. Каждый член имеет имя и значение, доступны они как атрибуты класса: цвет точка красный. Перебрать все можно циклом по самому классу. Получить член по значению — вызовом класса с числом, по имени — квадратными скобками со строкой. Сравнение работает через оператор «is» и равенство. Функция авто выдаёт значения автоматически. Зачем это нужно, если можно взять строки или числа? Чтобы код был читаем и безопасен. Вместо магического числа три пишется статус точка отправлен, опечатка вызовет ошибку сразу, а редактор подскажет варианты. Невозможно создать несуществующее значение: вызов с неверным числом вызовет ошибку значения.\n\nУ перечислений есть варианты. Инт-энум — члены ведут себя как целые числа и сравниваются с ними. Флаг — члены можно объединять побитовыми операциями, что подходит для наборов прав: чтение, запись, исполнение. Строковые перечисления хранят строки и удобны при обмене через джейсон. К перечислению можно добавлять методы и свойства, и тогда каждый член умеет что-то делать: например, у дня недели метод «это выходной». Члены неизменяемы и существуют в единственном экземпляре, поэтому их можно использовать как ключи словаря. Перечисления отлично сочетаются с датаклассами: поле статус заказа имеет тип перечисления, и читатель сразу видит допустимые значения. Это пример того, как типы описывают предметную область.\n\nПодсказки типов — это аннотации, которые описывают, какие значения ожидаются. Параметр функции получает двоеточие и тип, результат — стрелку и тип: дэф сложить от а двоеточие инт и б двоеточие инт стрелка инт. Для коллекций пишут список из целых, словарь из строк в целые, кортеж; для необязательных значений — тип или ничего, через вертикальную черту. В модуле тайпинг лежат вспомогательные средства: коллебл для функций, эни для любого типа, литерал для набора допустимых значений, тайп-вар для обобщений. Подсказки ничего не проверяют во время работы: Питон выполнит код и с неверными типами. Их читают человек, редактор и специальные программы, например май-пай, которые находят ошибки статически. Для читателя функция с аннотациями говорит больше, чем десяток комментариев.\n\nЗачем подсказки, если они не проверяются? Три причины. Документация, которая не врёт: аннотация описывает ожидания, и редактор показывает их при вызове. Поиск ошибок до запуска: статический анализатор заметит, что вы передали строку, где нужно число, или забыли обработать пустое значение. Помощь инструментам: автодополнение и рефакторинг работают заметно лучше. Постепенность — ещё одно достоинство: подсказки можно добавлять в код частями, начиная с самых важных функций. Не нужно усложнять: простые аннотации лучше, чем идеальные. Помните, что любая аннотация — обещание, и её нужно поддерживать: устаревшая подсказка хуже, чем её отсутствие. Для данных из внешнего мира всё равно нужна проверка во время выполнения.\n\nТипизированные структуры. Типизированный словарь описывает, какие ключи и какого типа лежат в словаре: он служит документацией для данных вроде ответов сервиса. Типизированный именованный кортеж — современная запись именованного кортежа через класс с аннотациями. Протокол описывает интерфейс: объект подходит, если у него есть нужные методы, наследование не требуется — это формализованная утиная типизация. Обобщения позволяют описывать контейнеры, не зная типа элементов. Всё это развивает идею: типы — не наказание, а язык описания структуры данных. Вы можете пользоваться ими минимально и всё равно получать пользу, а можете довести до строгой проверки при сборке проекта. Выбирайте глубину по размеру команды и сроку жизни проекта: чем дольше живёт код, тем полезнее подсказки.\n\nСтруктурное сопоставление — оператор матч и кейс — позволяет разбирать данные по форме. Вместо цепочки условий вы описываете образцы. Образец-литерал сравнивает со значением. Образец-кортеж или список раскладывает последовательность: первый элемент, остальные. Образец-словарь проверяет наличие ключей. Образец-класс проверяет тип и атрибуты. К любому образцу можно добавить условие через иф и запомнить кусок под именем. Подчёркивание — образец «подходит всё», его ставят последним. Сопоставление отлично подходит для разбора команд, сообщений, синтаксических деревьев. Например, команда «двигаться на десять» — кортеж из слова и числа, и один кейс отлавливает её сразу вместе с числом. Это ещё один способ делать код выразительнее без потери ясности.\n\nМодуль копи отвечает за копирование. Мы выяснили, что присваивание не копирует объект. Функция копи делает поверхностную копию: создаётся новый внешний объект, а вложенные остаются общими. Функция дипкопи копирует рекурсивно: все уровни, вложенные списки и словари получают собственные копии. Она умеет обрабатывать циклические ссылки. Для своих классов можно переопределить методы копирования. Правило выбора: для плоских данных хватает поверхностной копии, для вложенных нужна глубокая. Глубокая копия медленнее и занимает больше памяти, поэтому применяйте её осознанно. Для датаклассов есть реплейс, для списков — срез, для словарей — метод копи. Только когда внутри лежат изменяемые объекты, которые должны быть независимы, понадобится дипкопи.\n\nТипичные ошибки. Первая: изменяемое значение по умолчанию в датаклассе вместо филд с фэктори, Питон даже запретит такую запись для списка. Вторая: считать, что аннотации проверяются, и не проверять внешние данные. Третья: изменить поле фрозен-датакласса и получить ошибку. Четвёртая: сравнивать члены перечисления по значению там, где нужно по самим членам, и наоборот. Пятая: использовать строки вместо перечисления и допускать опечатки. Шестая: переусложнить подсказки так, что они мешают читать. Седьмая: забыть, что поверхностная копия делит вложенные объекты. Восьмая: забыть образец «всё остальное» в операторе матч, и значение не обработано. Девятая: ставить значение по умолчанию раньше обязательного поля датакласса.\n\nПодведём итог. Датакласс генерирует конструктор, репр и сравнение по полям; филд с фэктори решает проблему изменяемых умолчаний, фрозен и ордер расширяют возможности. Выбор между словарём, кортежем, именованным кортежем, датаклассом и классом определяется смыслом данных. Перечисления дают осмысленные имена фиксированным наборам и защищают от опечаток. Подсказки типов документируют и позволяют находить ошибки статическим анализатором, но во время работы не проверяются. Типизированный словарь, протокол и обобщения расширяют язык описания. Структурное сопоставление разбирает данные по форме. Копи и дипкопи делают поверхностную и глубокую копии. В следующей главе — тестирование: как убедиться, что код работает, и не бояться его менять.
