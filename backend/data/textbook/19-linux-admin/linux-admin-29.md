#SECTION Исходники QEMU и ядра
#CHAPTER 29 | Как читать большой проект: git grep, ctags, gdb, perf
Администрирование Linux. Глава двадцать девять. Как читать большой проект: гит грэп, си-тэгс, джи-ди-би, перф. Это четвёртый шаг дорожной карты: склонировать исходники кьюму и проследить, как он запускает виртуальные процессоры и диски. Кьюму — огромный проект на Си, и никто не читает его файл за файлом с самого начала. Нужен метод: взять то, что видно снаружи, например системный вызов, имя потока или строку журнала, и дойти от этого до кода, который её порождает. Примеры проверены по исходникам кьюму одиннадцать точка один; имена между версиями меняются, сверяйтесь со своим деревом.\n\nНачинайте с наблюдаемого. В главе двадцать восемь вы видели в эс-трейс вызов ай-о-контрол с кей-ви-эм-ран. В пэ-эс с ключом тэ или в топ с ключом эйч потоки кьюму имеют имена вроде «си-пи-ю ноль, косая черта, кей-ви-эм». Команда кью-эм-пи квери-си-пи-ю-эс-фаст сообщает номер потока хоста для каждого виртуального процессора. У события трассировки тоже есть имя. Всё это строки, а строку можно искать. Поиск формата «си-пи-ю процент-д косая черта кей-ви-эм» по дереву приводит к одной функции, которая строит имя и запускает поток. Дальше читайте вперёд от неё, а не от главной функции.\n\nГит грэп ищет только по отслеживаемым файлам, поэтому не заходит в каталог сборки и работает быстро. Ключ эн печатает номера строк, а несколько шаблонов с ключом «е», соединённых словом «энд», должны встретиться на одной строке. Ключ пэ показывает имя функции, в которой нашлось совпадение, а большой дабл-ю — всю функцию целиком. Ключ «хэдинг» печатает имя файла один раз. Можно искать и в старой версии: достаточно дописать в конце имя тега. Сначала ищите определение, потом места вызова и записывайте цепочку, по которой идёте.\n\nУ кода есть история, и она часто объясняет, почему всё устроено именно так. Гит лог с ключом эс и строкой находит коммиты, которые изменили число вхождений этой строки, то есть добавили или убрали её; ключ гэ принимает регулярное выражение по изменённым строкам. Ключ фоллоу ведёт историю одного файла через переименования, а ключ эл следит за одной функцией. Гит блэйм с ключами дабл-ю и си не обращает внимания на пробелы и замечает перенесённые строки. Ключ порцелейн даёт стабильный формат для скриптов, а файл из настройки блэйм-игнор-ревс-файл прячет коммиты массового форматирования; у кьюму он есть. Потом гит шоу открывает сам коммит.\n\nЧтобы прыгать между определениями, нужен индекс. Си-тэгс строит файл tags: одна строка на символ, в ней имя, файл, адрес и поля, главное из которых — вид. В Си функция имеет вид эф, структура — эс, определение типа — тэ, а поле «файл» с двоеточием помечает статический символ, видимый только в своём файле. В мейкфайле кьюму есть цели ctags, TAGS и cscope. Для Си умнее навигация у клэнгд: ему нужна база команд компиляции, файл compile_commands точка джейсон, и мезон обычно пишет его в каталог сборки. Индексы ошибаются на макросах и указателях на функции, поэтому проверяйте гит грэпом.\n\nНужна карта. В кьюму одиннадцать точка один каталог ускорителя кей-ви-эм содержит код, который запускает виртуальные процессоры, каталоги устройств virtio и блочных устройств — сами устройства, каталог block — форматы образов и блочный слой, каталог util — вспомогательный код и цикл событий, каталог system — машину и главный цикл, а каталог target — архитектуры процессоров. Имена несут смысл: обычно кьюму-подчёркивание для общих помощников, эй-ай-о для цикла событий, блк для блочного слоя, виртио для virtio. Макросы прячут структуру: контейнер-оф лежит в файле compiler, списки кью-тейл-кью — в файле queue, а типы объявляются через имена TYPE в объектной модели кью-о-эм.\n\nРаботающий процесс показывает свою структуру. Эс-трейс с ключами эф и пэ подключается ко всем потокам, и видно, какой поток какие вызовы делает. Пэ-эс с ключом тэ перечисляет потоки с номерами, топ с ключом эйч показывает их в движении. Кьюму даёт потокам имена: «си-пи-ю, номер, кей-ви-эм» для виртуального процессора, «ай-о» и идентификатор для ай-о-трэда, «воркер» для пула рабочих потоков, «колл-эр-си-ю» для отложенного освобождения. Поток ядра называется «вхост», дефис и число. Имя потока вмещает не больше пятнадцати символов. Главный поток — тот, чей номер равен номеру процесса.\n\nДжи-ди-би останавливает потоки процесса, пока смотрит внутрь, поэтому к боевой виртуальной машине подключайтесь осторожно. Ключ пэ с номером процесса подключает отладчик, ключи «бэтч» и «е-икс» выполняют команды и выходят. Команда инфо тредс перечисляет потоки с номерами и именами, а тред эплай олл бэ-тэ печатает стек каждого. Строка кадра содержит номер, адрес, функцию с аргументами и файл со строкой, если есть отладочная информация; без неё вы увидите вопросительные знаки или имя библиотеки. Дистрибутивы кладут символы в отдельные пакеты, а дебаг-инфо-д умеет скачивать их по требованию. Команда джи-кор, как и файл core, сохраняет состояние на потом.\n\nПерф показывает, куда уходит время. Перф топ — живая картина. Перф рекорд с ключами джи и пэ записывает образцы вместе со стеками вызовов процесса, а перф репорт с ключом стдио печатает таблицу. Если стеки записаны, в таблице две колонки: Self — время в самой функции, и Children — время в ней и во всём, что она вызвала. Перф скрипт печатает сырые образцы, и их сворачивают в одну строку на стек для флэйм-графа. Перф трейс — инструмент, похожий на эс-трейс. Найдите самый тяжёлый стек, а потом читайте именно этот код.\n\nУ кьюму есть своя трассировка. Каждый каталог объявляет события в файле трейс-ивентс, например кей-ви-эм-ран-экзит рядом с ускорителем. Ключ трейс с шаблоном вроде «кей-ви-эм, подчёркивание, звёздочка» включает события, а ключ ди включает другие сообщения журнала, и ключ большое ди выбирает файл для них. Теперь соберём всё вместе: по строке кей-ви-эм-ран из эс-трейс гит грэп находит функцию кей-ви-эм-си-пи-ю-экзек; джи-ди-би показывает стеки потоков; перф показывает, где время; событие трассировки подтверждает причину выхода. В следующей главе мы тем же путём пройдём главный цикл и виртио-блк.
