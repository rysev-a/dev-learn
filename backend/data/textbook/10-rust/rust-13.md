#CHAPTER 13 | Классы, трейты и перегрузка операторов
Изучаем Rust. Глава 13. Классы, трейты и перегрузка операторов. Питон — объектно-ориентированный язык: данные и методы лежат в классе, поведение расширяют наследованием, а особые методы с двойными подчёркиваниями позволяют объектам работать со сложением, печатью и циклами. Раст устроен иначе. Данные описывает структура, методы — блок имплементации, поведение, общее для разных типов, — трейт, а перегрузка операторов — это тоже трейты из стандартной библиотеки. Наследования нет, но почти всё, что вы делаете им в питоне, можно сделать проще. В этой главе мы пройдём по порядку и сопоставим каждую конструкцию.\n\nНачнём с класса. Класс из питона с полями и методами превращается в структуру и блок имплементации. Метод «инит» заменяется ассоциированной функцией, которую по договорённости называют нью. Конструкторов в расте нет, любой экземпляр можно создать литералом структуры. Первый параметр метода селф перечисляется явно и сообщает, что именно метод делает с объектом: читает его, меняет или забирает. Приватность задаётся иначе: поля и методы по умолчанию приватные и видны только внутри модуля, а слово паб открывает доступ. Нижнее подчёркивание как договорённость не нужно.\n\nСвойства и методы класса. Декоратор проперти в питоне делает из метода атрибут, который читают без скобок. В расте таких нет: для чтения пишут метод-геттер с амперсанд селф, а для записи — метод-сеттер с амперсанд мут селф. Имя геттера обычно совпадает с именем поля, но без слова гет. Классовые методы и статические методы питона превращаются в ассоциированные функции без селф: они вызываются через имя типа и двойное двоеточие. Например, «юзер двоеточие двоеточие нью». Такая же запись используется и для констант, объявленных внутри имплементации, и для вспомогательных функций.\n\nНаследование. В питоне класс-потомок наследует поля и методы родителя, а порядок поиска метода определён сложным правилом. В расте наследования структур нет. Вместо него есть композиция: структура содержит другую структуру в поле и вызывает её методы. Общее поведение выносится в трейт. Это решает знаменитую проблему алмаза, когда непонятно, чей метод вызывать, а изменение базового класса не ломает потомков, потому что их нет. Для повторного использования кода вам придётся придумывать хорошие маленькие типы и трейты, а не глубокие иерархии. Практика показывает, что код получается проще.\n\nТрейт — это описание поведения. Внутри него перечисляют сигнатуры методов, которые обязан реализовать любой тип с этим трейтом. «Трейт фигура, скобка, фн площадь скобка амперсанд селф скобка стрелка эф-шестьдесят-четыре точка с запятой, скобка». Реализация записывается отдельно: «импл фигура фор круг, скобка, фн площадь, тело, скобка». Раст-трейт похож на абстрактный базовый класс или на протокол питона, но реализуют его после объявления типа, и можно даже реализовать свой трейт для чужого типа, например для числа. Это делает код гибким, и вместе с тем компилятор следит, чтобы реализация была полной.\n\nТрейты могут иметь методы по умолчанию. Если в трейте метод дан с телом, любой тип получает его бесплатно, но может заменить. Через трейты работает полиморфизм двух видов. Статический, когда функция принимает «импл фигура» или обобщённый тип с ограничением, и компилятор создаёт отдельную версию для каждого типа: это быстро, и вызов можно встроить. Динамический, когда хранят «бокс дин фигура», то есть ссылку на объект с таблицей методов, как у питона. Он нужен, чтобы положить в один вектор разные типы. Выбирайте статический, пока нет нужды в динамическом.\n\nСтроковое представление. Методы стр и репр из питона заменяются двумя трейтами. Трейт дисплей отвечает за красивый вывод для пользователя: его реализуют вручную и вызывают через формат с фигурными скобками. Трейт дебаг отвечает за отладочный вывод: его выводят автоматически атрибутом дерайв и вызывают через формат с вопросом. Реализация дисплей использует макрос врайт и принимает форматтер. Как только трейт реализован, метод ту-стринг доступен автоматически. Выбор простой: для людей — дисплей, для программистов — дебаг, и дерайв даёт его в одну строку.\n\nСравнение. Методы эк, лт, ле и остальные превращаются в трейты партиал-экв и партиал-орд. Для структур, у которых сравниваются все поля по порядку, достаточно атрибута дерайв: поля сравниваются лексикографически. Если нужен особый порядок, реализуют метод партиал-кмп вручную. Для хеширования, которое питон делает методом хэш, есть трейт хэш, и тоже дерайв. Трейты эк и орд отличаются от партиал-вариантов тем, что для них сравнение определено для всех значений: у дробных чисел есть нан, поэтому они реализуют только партиал.\n\nПерегрузка операторов. Питоновские методы «адд», «саб», «мул» и другие в расте — трейты из модуля оупс: эдд, саб, мул, див, рем и нег. Реализация выглядит так: «импл эдд фор вектор, тип аутпут равно вектор, фн эдд скобка селф запятая другой скобка стрелка вектор». Для составных операторов вроде плюс-равно есть трейты эдд-эсайн и аналогичные. Для индексации — индекс и индекс-мут. Для вызова — фн, фн-мут и фн-ванс, но реализовать их вручную пока нельзя, а замыкания получают их автоматически. Все операторы раст разрешает только для существующего набора, придумать новые нельзя.\n\nПрактичные детали. Для арифметики над векторами и матрицами обычно реализуют операторы для значений и для ссылок, чтобы выражения вроде «а плюс амперсанд б» работали без лишних копий. Тип результата записывают в ассоциированном типе аутпут, он необязательно равен исходному: скалярное произведение двух векторов вернёт число. Правила согласованности запрещают реализовывать чужой трейт для чужого типа, чтобы две библиотеки не конфликтовали. Обходят это с помощью обёртки: структуры с единственным полем, для которой трейт реализовать можно. Паттерн называется ньютайп и встречается постоянно.\n\nИтераторы и контекстные менеджеры. Методы «итер» и «некст» из питона превращаются в трейт итератор. Достаточно реализовать метод некст, и ваш тип получит цикл фор и десятки готовых методов. Чтобы цикл мог взять тип по значению или по ссылке, реализуют ещё и инту-итератор. Контекстные менеджеры с методами «энтер» и «экзит», благодаря которым файл закрывается сам, заменяет трейт дроп: его метод вызывается автоматически, когда значение выходит из области видимости. Поэтому в расте не нужны блоки виз, ресурсы освобождаются без явных команд, а порядок освобождения полностью предсказуем.\n\nДатаклассы и значения по умолчанию. Питоновский датакласс создаёт метод инит, сравнение и печать по описанию полей. В расте то же даёт набор атрибутов: дерайв дебаг, клон, партиал-экв и дефолт. Дефолт заменяет значения по умолчанию в конструкторе: «юзер двоеточие двоеточие дефолт скобки» заполнит все поля стандартными значениями, а синтаксис «точка точка дефолт скобки» позволяет задать только нужные. Клон создаёт глубокую копию, как копи-дип-копи. Копи делает тип копируемым при присваивании, как это происходит с числами, и годится только для простых данных без владения кучей.\n\nПодведём итоги. Класс — это структура с блоком имплементации. Инит — это нью, проперти — геттер, классовый метод — ассоциированная функция. Наследования нет: есть композиция и трейты. Трейты бывают со статической диспетчеризацией и с динамической. Стр и репр — это дисплей и дебаг, сравнение и хеш — дерайв, операторы — трейты из оупс. Итератор и дроп заменяют методы итерации и контекстные менеджеры. Датакласс — набор дерайв-атрибутов. В следующей главе сравним словари питона с хеш-картой раста и добавим множества. После неё мы перейдём к заимствованию.
